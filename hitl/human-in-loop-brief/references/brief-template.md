# 中文方案评审简报模板

生成简报时，必须使用以下结构，删除所有占位符，并用资产包中的具体信息填充。信息缺失时写明“未在资产包中找到明确依据”及其影响。

# 方案评审简报：方案名称

> 结论先行区,针对每项给出一句话作总结性评价: 代码量/影响范围/风险程度/测试工作量

## 1. 背景、目标与方案边界

### 背景

说明问题背景。

### 目标

- 目标 1
- 目标 2
- 目标 3

### 范围内

- 本次必须解决的问题
- 本次包含的系统 / 模块 / 用户路径
- 本次包含的数据流 / 接口 / 配置变化

### 不改的内容

| 内容                     | 不改的原因      | 如需纳入范围的处理方式             |
|------------------------|------------|-------------------------|
| 不改的模块 / 行为 / 数据 / 用户路径 | 为什么不属于本次范围 | 记录为后续需求 / 需要重新评审 / 单独立项 |

### 关键事实

| 事实   | 来源     | 对方案的影响 |
|------|--------|--------|
| fact | source | impact |

### 当前假设

| 假设         | 风险   | 如果假设不成立怎么办 |
|------------|------|------------|
| assumption | risk | action     |

## 3. 实施计划

### 实施策略

说明整体如何落地。重点讲实现路径，不进入代码级细节。

### 受影响模块

| 模块 / 接口 / 数据流 / 用户路径 | 变化类型              | 影响功能        | 说明          |
|----------------------|-------------------|-------------|-------------|
| item                 | 新增 / 修改 / 删除 / 迁移 | 罗列会受影响的系统功能 | description |

### 实施步骤总览

| 步骤 | 名称   | 目标 | 依赖 |
|----|------|----|----|
| 1  | 步骤名称 | 目标 | 依赖 |

### 步骤实现摘要

#### 步骤 1：步骤名称

**目标**：这一步要达成什么。

**计划做法**：

- 具体做法 1，保持方案级描述。
- 具体做法 2，说明关键逻辑、接口、数据流或交互变化。
- 具体做法 3，说明与其他步骤的关系。

**主要影响范围**：

- 模块 / 接口 / 数据流 / 用户路径

### 仍需确认的问题

## 5. 验收方式

> 验收重点是 `验收重点摘要`；提测资料状态为 `提测资料状态摘要`；核心通过标准为 `核心通过标准摘要`。

### 提测信息摘要

| 字段      | 内容                                       |
|---------|------------------------------------------|
| 提测申请    | 申请状态 / 申请链接 / 未在资产包中找到明确依据               |
| 提测项目    | 项目名 / 服务名 / 系统名                          |
| 提测需求    | 功能点列表 / PRD 或需求资料链接                      |
| 自测版本    | 版本号 / 分支 / 构建号；如无则写明未提供                  |
| 自测用例地址  | 用例链接；提测方式为预演时填写【预演通过】                    |
| 改动功能点   | 本次新增、修改或移除的功能点                           |
| 影响范围    | 受影响的模块、接口、数据流、配置、用户路径                    |
| 服务上下游依赖 | 上游服务、下游服务、内部模块、第三方服务，以及依赖状态、对接同步状态、待适配内容 |
| 接口文档    | 接口文档、契约、Mock、联调说明或未提供原因                  |

### 功能验收项

| 验收项 | 对应需求 / 功能点 | 验收场景                | 验收方法                             | 通过标准 | 证据来源 |
|-----|------------|---------------------|----------------------------------|------|------|
| 验收项 | 需求或功能点     | 正常 / 异常 / 边界 / 兼容场景 | 人工检查 / 接口验证 / 日志检查 / 对比验证 / 预演验证 | 通过标准 | 资料来源 |

### 影响范围验证

| 影响对象                      | 需验证的行为           | 验证方法                             | 通过标准 |
|---------------------------|------------------|----------------------------------|------|
| 模块 / 接口 / 数据流 / 配置 / 用户路径 | 需要证明未破坏或已正确变化的行为 | 人工检查 / 接口验证 / 日志检查 / 对比验证 / 预演验证 | 通过标准 |

### 依赖与联调验收

| 依赖对象                       | 依赖类型               | 当前状态            | 对接同步状态          | 待适配内容   | 验收关注点                |
|----------------------------|--------------------|-----------------|-----------------|---------|----------------------|
| 上游服务 / 下游服务 / 内部模块 / 第三方服务 | 上游 / 下游 / 内部 / 第三方 | 已就绪 / 未就绪 / 不适用 | 已同步 / 未同步 / 不适用 | 待适配内容或无 | 需要重点验证的交互、协议、数据或错误处理 |

### 接口与数据验证

| 对象            | 变更点               | 文档或契约来源 | 验证方法                      | 通过标准 |
|---------------|-------------------|---------|---------------------------|------|
| 接口 / 数据流 / 配置 | 新增 / 修改 / 删除 / 迁移 | 链接 / 来源 | 接口验证 / 日志检查 / 对比验证 / 预演验证 | 通过标准 |
