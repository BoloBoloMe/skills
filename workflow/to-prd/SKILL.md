获取当前对话上下文和代码库理解, 产出 PRD. 不做需求访谈, 不因未知项中断. 未知但会影响实现的内容写入 `未确认假设`.
你应该已获得本地议题跟踪器约定. 如果没有, 使用 `setup-workspace` skill.

## 流程

### 1. 收集已知输入

读取当前对话, 用户提供的文档, 原型产物, issue 或计划. 用户给出输出位置时使用该位置; 否则按 `docs/changes/<feature-slug>/PRD.md` 输出, `<feature-slug>` 从功能标题推断.
完成标准: 已得到 PRD 来源材料清单, 已确定输出路径, 无法确认的信息已进入待假设列表而非追问用户.

### 2. 聚焦探索代码库

如果尚未探索仓库, 先做聚焦探索以了解当前状态. 使用项目领域术语, 并遵守触及区域的 ADR. 勾勒完成实现所需构建或修改的主要模块, 主动寻找可隔离测试的深模块.
深模块指用简单, 可测试且很少变化的接口封装大量功能的模块.
完成标准: 已形成模块候选, 测试候选, 相关 ADR/领域语言引用. 不确定模块或测试范围写入 `未确认假设`, 不向用户确认.

### 3. 编写并发布 PRD

使用下方模板编写 PRD, 发布到本地议题跟踪器. 如果存在 `DECISIONS.md` 或需要记录决策, 先调用 `decision-ledger` skill. PRD 只摘要关键取舍并引用决策账本, 不复制完整设计树, 不记录执行状态, 不写 `Status:` 或等价状态行.
完成标准: PRD 已写入目标路径, `未确认假设` 单独成节, 最终回复展示路径, 需求范围摘要, 关键假设, 风险.

<prd-template>

# <PRD 标题>

## 问题陈述

用户所面临的问题, 从用户视角描述.

## 解决方案

问题的解决方案, 从用户视角描述.

## 用户故事

一份编号用户故事列表. 每个用户故事使用以下格式:

1. 作为一个 <actor>, 我想要 <feature>, 以便 <benefit>

<user-story-example>
1. 作为一名手机银行客户, 我想查看账户余额, 以便我能对自己的消费做出更明智的决策
</user-story-example>

用户故事应覆盖该功能的主要场景, 边界场景, 失败场景.

## 决策引用

完整决策账本: `DECISIONS.md` (如存在).

只列出对理解 PRD 必要的关键取舍摘要和决策 ID. 不复制完整设计树. 不包含具体文件路径或实现步骤.
例外: 如果原型产出的片段比文字描述更精确地表达某个外部契约决策 (状态机, reducer, schema, 类型形状), 可在摘要中内联该片段, 并简要说明它来自原型. 只保留决策含量高的部分, 不是可运行演示.

## 未确认假设

列出当前上下文无法确认, 但 PRD 为继续推进而采用的假设. 每项写清影响范围和后续验证方式.

## 范围外

描述此 PRD 范围外的事项, 用下面这个模板编写:
```text
不做 ?  , 它不在本 PRD 范围内
```

## 补充说明

关于该功能的任何补充说明.

</prd-template>
