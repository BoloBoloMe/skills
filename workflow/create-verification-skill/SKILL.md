# 生成项目级验证 skill

你按已确认产品说明与运行事实编写项目本地操作配方. 开始前调用 `verification-contract` skill, 只遵守共用底线; 产品通过判据仍取 `PRODUCT.md`. 配方让陌生 agent 照着真实入口实跑, 不靠代码现状另立标准.

## 输入

- 必需: 已确认的 `PRODUCT.md`. 它确定本轮功能, 入口与通过判据. 缺文件或仍为草稿/待确认时, 报告缺失文件或未确认条款. 然后停止. 不从源码现状推断产品判据.
- 可选: `TECHNICAL.md`, `EXECUTION.md`, 项目 README, 测试入口. 缺任何一份都继续, 报告注明未提供.
- 你自行观察应用名, 启动命令, 端口与数据目录. 再查用户入口, 前置数据与现有测试入口.

完成标准: 已列本轮入口. 每项有启动方式, 操作与满足判据的可见结果. 观察不到的事实标未确认, 不写成断言.

## 覆盖范围

只覆盖 `PRODUCT.md` 本轮入口与必要共用规则:

- 从空数据启动到可用.
- 只读实例检查: 进程, 端口归属与版本.
- 隔离测试环境中的真实入口操作, 取证与数据保留, 按已调用的共用底线执行.

其余功能不进配方或功能地图. 报告写明覆盖的功能与入口, 以及排除项与理由.

完成标准: 地图每项都能追到 `PRODUCT.md` 的判据. 删掉追不到的项.

## 写入授权

调查阶段默认只读. 写文件前说明以下范围, 交我批准. 批准前不写配方或建辅助脚本:

- 资源与对象: 本地验证目录, 文件与辅助脚本. 以及运行期临时数据, 实例, 端口与数据目录.
- 操作: 每个对象做什么, 是新建还是改写. 是否覆盖已有文件.
- 数据保留: 运行期数据的位置, 查看方法与占用, 优先放仓库外; 只能放仓库内时单列路径. 其余按共用底线, 并说明配方文件是否保留.
- 验证办法: 范围检查命令, 加载实跑方式与数据可访问性检查; 区分应保留的测试数据与意外残留.

**共用批准规则.** 生成与维护配方共用以下三条. 规则只在此处维护.

- 批准绑定资源, 对象, 操作与保留范围. 同范围的后续写入与复跑直接执行, 可对照原批准复查. 换范围先停下请求新批准, 旧批准不作新范围的依据. 项目信任, 容器免审批或脚本自称会自动清理, 都不授予写入权限.
- 生成或修配方的批准不覆盖运行期数据. 子会话创建测试数据, 启动实例或占端口, 也须先获批.
- 派工单原样写入批准范围与授权, 要求子会话调用 `verification-contract` skill 遵守共用底线. 子会话逐次记录写入对象, 命令, 时间, 结果与数据位置; 需超范围才能跑通时停下报告, 你转给我决定, 不替它扩权.

完成标准: 写配方前已有上述范围与验证办法的批准记录. 派工单范围一致, 写入与数据保留记录可对照复查. 否则已停在批准之前.

## 写什么

产物落在目标项目 `.agents/skills/verify-<应用名>/`:

- `SKILL.md`: `name` 与目录名一致. `description` 是一行人类摘要. 设置 `disable-model-invocation: true`. 正文先写共用规则, 含隔离测试环境, 生产禁令和实跑数据保留, 再按功能分节写入口与操作. 宿主用 YAML 解析 frontmatter. 字段写坏会导致整份文件无法加载. 摘要含冒号时, 用引号包住整个值, 或换标点.
- 必要辅助脚本放同目录, 正文写调用方式, 不让读者猜.

每条配方写明前置数据, 工具链与端口. 再写具体命令或交互, 期望结果, 证据文件与可查看的数据位置. 只写实跑过的步骤, 或标明未验证及原因的步骤.

完成标准: 每节都有前置, 操作, 可见结果与证据位置. 陌生读者能照着执行, 无需回问.

## 改动边界

只新增或修改项目本地验证目录 `.agents/skills/verify-<应用名>/` 及自带脚本. 产品代码, 配置, 既有测试与全局副本字节不变. 为跑通配方而改产品, 就不再是观察原产品.
应用无法构建或启动时, 报告现象与尝试路径. 原样保留受影响配方, 标为未验证. 不装工具链绕过, 不用替身冒充构建结果. 不改产品, 配置或测试来跑通配方.

完成标准: 已在目标项目做范围对照. 用 `git status --porcelain`, `git diff --stat` 或等价方式. 除验证目录和事先获批的运行期数据路径外没有改动, 原始输出已入证据. 仓库内的运行期数据单列, 不冒充成品源码改动.

## 交付前实跑

派一名未参与编写的会话实跑. 在目标项目用 `/skill:verify-<应用名>` 加载当前配方. 跑完本次新增或修改的全部入口. 作者熟悉项目, 可能绕过漏写条件, 所以你自己跑不算证明.

- 派工单写目标项目路径, 入口清单与批准范围. 再写预期证据, 数据保留要求与报告格式.
- 核对宿主 location 与展开正文, 确认来自项目当前文件. 每个入口都要有操作, 取证与数据保留记录. 粘贴正文不算按名加载.
- 加载失败, 同名冲突或来源不符时, 记录宿主原文与冲突诊断. 修配方后重跑, 直到加载当前文件. 修不好就报缺口. 不改项目配置或写全局部署绕过. 加载报错时 `/skill:` 会原样交出正文. 看似执行过, 实际跑的是会话找到的旧副本.
- 跑不通或缺前置数据时, 原样保留配方并标未验证. 写明前置缺口与尝试路径. 不删步骤或降标准来跑通.

完成标准: 每条新改配方都有本轮操作, 取证与数据保留记录. 否则在未验证清单写明原因. 报告已列实跑覆盖的入口.

## 交付报告

报告列出生成路径与文件清单. 覆盖与排除项按前文记录, 附实跑覆盖与加载 location. 再列未验证原因, 范围对照原始输出与未提供的可选输入.
只交文件路径, 差异与证据. 不提交, 不推送, 不开 PR.
完成标准: 报告各项齐全, 文件与证据路径可复核.
