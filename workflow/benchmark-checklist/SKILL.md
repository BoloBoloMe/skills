# 性能测量核查

你用实际运行证据核对性能数字, 不靠读代码猜. 适用于新旧比较, 回归结论与库/配置选型. 正式比较只判更快/更慢/无可测差异/无法下结论.

七问按阶段分节, 引用编号时按以下对照查阅:

- 第 1 问在 `## 测量前`.
- 第 2 问在 `## 两侧按生产方式调优`.
- 第 3 与第 6 问在 `## 收益上限与端到端`.
- 第 4 与第 7 问在 `## 错误计数与工作是否真的发生`.
- 第 5 问在 `## 重复与波动`.

## 输入与授权

输入为待核验的对外主张与测量脚本. 另需两侧版本, 运行条件与已有可复核材料. 你可以亲自检查与运行, 不必另开调查层.
本清单不授予修改冻结源码或新增正式用例的能力. 也不授予新权限. 缺权限就报缺口, 不自行取权限.
完成标准: 输入可定位, 所需操作在已有权限内; 否则已列缺口.

## 一次性实验的边界

项目没有正式测试而需核实机制时, 可做一次性实验. 仅限已批准的独立实验范围. 它是调查手段, 不是新正式用例.

- 记录标明非正式 TC, 授权范围与实验覆盖.
- 只动独立实验脚本与临时数据. 不改产品源码, 既有测试或项目配置. 脚本放仓库外临时目录, 或在记录附全文.
- 按批准范围清理临时数据与后台进程, 记录实际结果.
- 内部函数在给定输入下的证明, 不等于成品入口通过. 成品真实入口未跑, 对应场景仍记未运行, 不用内部结果顶替.
- 可信数字只能靠给冻结目标加计数代码取得时, 停下报缺口. 冻结目标不改, 计数代码不进产品.
- 需要新正式测试或接缝才能观察时, 停下. 交回既有用例确认流程. 不自行新增未经确认的用例或接缝.

影响调查的一次性证明脚本, 沿用 blast-radius 的证据级别与授权边界. 本节只规定测量实验条件, 不重写调查方法.
完成标准: 记录有非正式 TC 标记与授权范围. 清理结果与未运行场景齐全. 需改冻结目标或新增正式接缝时, 已停下报缺口, 未改产品.

## 测量前

先写准备原样对外给出的结论, 带对象与单位. 例如 "6 万行数据上导出 p50 从 41ms 降到 33ms". 后续检查核验这句主张. 说不清就先确认问题, 否则测量没有明确目标.
再读脚本, 记录计时范围, 计数项与忽略项. 计时漏掉工作就算不出成本, 缺计数就答不了对应问题. 记录随机扰动或固定种子, 避免数字仅看似可复现.
核对 `uptime` 负载, `nproc` 核心数与负载来源. 机器忙且无权停其他任务时, 交替测两侧并报告噪声. 不停止别人的工作.
分析器或追踪器会拖慢工作, 须单独运行. 该次数字不进正式报告.
完成标准: 已记录待核验结论与脚本计时/计数/忽略项. 机器负载与核心数可复核.

## 两侧按生产方式调优

每侧都按生产方式等价运行, 核对以下条件:

- 构建类型, 如发布版与调试版.
- 生产标志与环境变量, 批处理与事务设置, 连接池.
- 与生产同样冷热的缓存, 同样的版本与数据.

一侧用默认值时比的是配置, 不是实现. 限制来自设置时, 先调优再测.
有权限补调优时, 首轮不选赢家, 注明这轮在比配置. 补调另一侧后重新交替测量, 结论取调优后那轮. 缺配置或部署权限等原因导致无法补齐时, 判无法下结论. 写清缺口, 不据首轮选赢家.
完成标准: 两侧构建, 配置与数据条件已记录. 调优已补齐或已写明缺口.

## 重复与波动

每侧至少 5 次, 按 A,B,A,B... 交替. 避免预热, 懒初始化, 缓存或机器漂移偏向一侧. 报每侧中位数与极差, 不只报单个数或平均值. 否则看不出测量是否稳定.
差距小于两侧观测波动时, 判无可测差异, 不判更快或更慢. 给两组数值, 中位数与波动.
两侧接近时, 用工具自带统计或秩和检验. 给结论与显著性信息. 不新建统一显著性阈值, 不凭中位数大小或单次结果选赢家.
完成标准: 已记录交替序列, 每侧次数, 中位数与极差. 附波动或统计判定.

## 错误计数与工作是否真的发生

计失败与非成功响应, 核对输出正确性与输入是否相符. 不能只确认结果存在. 失败响应往往快, 超时与重试往往慢. 只计耗时会将错误当作提速.
脚本缺计数时, 只在获授权的独立实验脚本补齐. 同时补正确性校验. 不改冻结产品源码取数.
再确认工作发生在计时区内, 结果确实用上了. 以下情形都会产出没有工作的快数字:

- 无人迭代的生成器, 无人 await 的异步任务.
- 算完又丢弃的结果, 运行时优化掉的计算.
- 主要计算发生在计时区外.

这类数字判无法下结论, 不用于宣称变快.
计数或正确性证据需改冻结源码时, 判无法下结论. 写明缺口. 本清单不授予源码写入权限, 不靠改产品取数.
完成标准: 已记录失败与非成功响应的定义及计数. 输出正确性结果与计时区实际工作可复核. 拿不到时已写缺口.

## 收益上限与端到端

先用占比算收益上限, 再判断能否将局部数字用于整条路径.
计算改动段占用户路径耗时的比例 r, 保留可复核材料. 完全移除该段时, 路径最多快 r / (1 - r). 占 10% 的段全删, 上限约 11%. 上限不是实测结果, 实际收益通常更低.
核对三组物理上限:

- 每秒字节数与磁盘/网络带宽.
- 每秒操作数乘每操作成本与核心数.
- 节省时间与改动段自身耗时.

数字对不上说明测到的不是那段工作.
路径收益超限时, 先按测量错误线索排查:

- 缓存命中, 如第二次直接返回.
- 空操作, 如写入 0 条或跳过工作.
- 错误响应, 如失败请求更快.
- 计时区外的计算.

查完仍超限就判无法下结论, 写明缺口.
微基准只说明函数自身. 微结果旁边必须附用户端到端路径的实测. 实测走真实入口, 带真实数据规模与并发. 给出微优化占整条路径的比例. 只发函数层结论也须附这组数, 避免读者误当整条路径收益. 授权内补不齐时列缺口, 结论只限函数层. 不宣称整条路径收益.
分析器运行的耗时不进报告, 因为它会拖慢工作. 限制因素单独下结论, 用正式运行数字支撑.
正式数字没变时, 先查计时区, 缓存冷热与机器负载. 再查固定等待与限制因素. 再判断优化是否无效, 不直接断言没用.
应用吞吐停涨而负载生成器 CPU 饱和时, 标为负载生成器饱和. 不算应用测量结果. 授权内改用预生成负载或独立进程等方式, 再测应用. 无法调整就报缺口.
完成标准: 已记录占比, 上限算式与端到端数据规模/并发. 缺端到端时已列缺口, 结论只限函数层. 已剔除分析器数字. 数字没变或生成器饱和时有单独的限制因素结论.

## 基线与脚本固定前

基线与固定脚本会影响后续全部比较, 规划或固定前先审查.
用旧基线规划前, 核对计时范围, 单次/多次与机器核数. 再查数据规模, 版本与缓存冷热. 条件不适用就重测, 或说明哪些结论不能用. 不直接沿用未审查的旧数字.
固定为团队入口前, 脚本必须自带错误数与工作量输出. 错误数包括失败与非成功响应. 工作量指处理的数据条数. 缺就补入脚本并重跑, 补好且跑过才认可固定.
只有改冻结源码才能补齐时, 报缺口, 不认可固定. 不由本清单取得源码写入权限, 也不为此自行取权限.
完成标准: 已记录基线方法与适用条件的审查结论. 每个待固定脚本都有两项输出或明确缺口. 只认可通过检查的脚本.

## 粗估与选型

我明确只要粗略量级时, 可单次测量, 但检查不省:

- 声明单次粗估与单位. 同一轮只强制查两件事. 第 4 问的失败计数与输出正确性. 第 7 问的工作是否发生在计时区. 其余五问不额外强制, 选型与对外比较除外. 失败或没干活的快数字没有意义.
- 只报大致量级, 不用于选型, 不比两侧快慢或写正式比较结论. 粗估不动用 `## 两侧按生产方式调优`, `## 重复与波动`, `## 收益上限与端到端` 的完成标准.
- 规划与固定脚本检查不因粗估豁免. 用于规划时仍按 `## 基线与脚本固定前` 审查基线方法与适用条件. 粗估脚本固定成团队入口前, 仍须补齐两项输出. 即错误数与工作量.
- 有异常就查原因, 暂不下结论. 非成功响应或输出不符预期都算异常. 数字不符实现常量或已知量级也算. 查清并补齐检查后重测, 报告首次结果为何不能用.

选型不算粗估. 两库或两套配置的取舍须完整对照. 核对两侧版本, 数据, 缓存, 构建与配置. 默认值一侧先调优再测, 交替重复后按判定词下结论. 我只要大致数字也不豁免: 选错的代价会持续影响后续运行. 授权内补不齐就判无法下结论并写缺口, 不凭单次选赢家.
完成标准: 粗估有单次声明, 单位与第 4, 7 问结果. 已说明其余五问不强制, 结果只表量级. 异常已查因重测. 选型两侧条件与次数齐全, 未用粗估选赢家. 规划或固定脚本已做对应节检查.

## 判定

先用一个判定词: 更快/更慢/无可测差异/无法下结论. 正式比较附单位, 每侧次数, 极差与实测限制因素. 缺任一项, 读者就无法判断差距在其他环境是否成立.
无可测差异附两组数值, 中位数与波动. 无法下结论须指出具体缺口.
以下任一情况一律判无法下结论:

- 说不出限制因素.
- 两侧条件不可比, 授权内补不齐.
- 单侧未调优且无权补齐.
- 第 4 问的错误计数或正确性缺失.
- 第 7 问的实际工作无法检查.
- 只凭单次, 中位数大小或未经核查的脚本输出选赢家.

这些情形下选赢家, 就是将噪声, 配置差或空转当结论.
完成标准: 判定词与证据一致, 正式比较四项材料齐全. 无法下结论时缺口明确.

## 对外报告

PR 正文只放一个主数字, 带单位, 前后对照与证据链接. 不再摆第二组中位数或极差. 避免正文变成测量报告而失去重点.
链接材料保留完整次数, 极差与方法. 失败数, 工作量, 限制因素与机器条件也保留. 内部验收证据不得因对外简短而缩减. 简短主张必须来自完整证据.
本清单只产出草稿与判定. 提交, 推送, 开 PR 与合并由我按自己的流程做.
完成标准: 正文只有一个主数字, 带单位与前后对照. 链接能读取完整次数与极差, 内部证据未删减. 未触发远端 Git 动作.
