# 性能测量核查

开始测量前若尚未读过 `verification-contract` skill, 调用它; 已读则复用其性能改进做法与共用底线, 不重复调用. 用同等规模的合成测试数据实测, 不靠读代码猜. 适用于新旧比较, 回归结论与库/配置选型. 正式比较只判更快/更慢/无可测差异/无法下结论.

原清单的七问按测量阶段拆进以下各节; 后文只按编号引用第 4 问 (错误计数与输出正确性) 与第 7 问 (实际工作发生在计时区), 其余按节名查阅.

## 输入与授权

输入为待核验的对外主张与测量脚本. 另需两侧版本, 运行条件与已有可复核材料. 你可以亲自检查与运行, 不必另开调查层.
本清单不授予修改冻结源码或新增正式用例的能力, 也不授予新权限, 这是本文件的权限边界. 缺权限就报缺口.
完成标准: 输入可定位, 所需操作在已有权限内; 否则已列缺口.

## 一次性实验的边界

任何一次性实验都适用 [blast-radius 的一次性实验边界](../blast-radius/SKILL.md#5-一次性实验的边界), 不限于影响调查的证明脚本; 影响调查另沿用其 [证据级别](../blast-radius/SKILL.md#3-给每个事实标证据级别). 本节只规定测量实验条件, 不重写调查方法.
停止自己启动的后台进程, 按 [verification-contract/SAFETY.md](../verification-contract/SAFETY.md) 留存可查看的数据; 记录位置及停止结果.
完成标准: 已按所引边界留存实验记录, 其中数据保留位置与自启进程停止结果齐全.

## 测量前

先写准备原样对外给出的结论, 带对象与单位. 例如 "6 万行数据上导出 p50 从 41ms 降到 33ms". 后续检查核验这句主张. 说不清就先确认问题, 否则测量没有明确目标.
再读脚本, 记录计时范围, 计数项与忽略项. 计时漏掉工作就算不出成本, 缺计数就答不了对应问题. 记录随机扰动或固定种子, 避免数字仅看似可复现.
核对 `uptime` 负载, `nproc` 核心数与负载来源. 机器忙且无权停其他任务时, 交替测两侧并报告噪声. 不停止别人的工作.
分析器或追踪器会拖慢工作, 须单独运行. 该次数字不进正式报告.
完成标准: 已记录待核验结论与脚本计时/计数/忽略项. 机器负载与核心数可复核.

## 两侧按生产方式调优

这里的生产方式只指可比的构建和配置, 不授权在生产环境测量. 每侧都在隔离测试环境按生产方式等价运行, 核对以下条件:

- 构建类型, 如发布版与调试版.
- 生产标志与环境变量, 批处理与事务设置, 连接池.
- 与生产同样冷热的缓存, 同样的版本与数据.

一侧用默认值时比的是配置, 不是实现. 限制来自设置时, 先调优再测.
有权限补调优时, 首轮不选赢家, 注明这轮在比配置. 补调另一侧后重新交替测量, 结论取调优后那轮. 缺配置或部署权限等原因导致无法补齐时, 判无法下结论, 不据首轮选赢家.
完成标准: 两侧构建, 配置与数据条件已记录. 调优已补齐或已写明缺口.

## 重复与波动

每侧至少 5 次, 按 A,B,A,B... 交替. 避免预热, 懒初始化, 缓存或机器漂移偏向一侧. 报每侧中位数与极差, 不只报单个数或平均值. 否则看不出测量是否稳定.
差距小于两侧观测波动时, 判无可测差异, 不判更快或更慢. 给两组数值, 中位数与波动.
两侧接近时, 用工具自带统计或秩和检验. 给结论与显著性信息. 不新建统一显著性阈值, 不凭中位数大小或单次结果选赢家.
完成标准: 已记录交替序列, 每侧次数, 中位数与极差. 附波动或统计判定.

## 错误计数与工作是否真的发生

计失败与非成功响应, 核对输出正确性与输入是否相符. 不能只确认结果存在. 失败响应往往快, 超时与重试往往慢. 只计耗时会将错误当作提速.
脚本缺计数时, 只在获授权的独立实验脚本补齐, 同时补正确性校验; 冻结源码按 输入与授权 节的权限边界处理.
再确认工作发生在计时区内, 结果确实用上了. 以下情形都会产出没有工作的快数字:

- 无人迭代的生成器, 无人 await 的异步任务.
- 算完又丢弃的结果, 运行时优化掉的计算.
- 主要计算发生在计时区外.

这类数字判无法下结论, 不用于宣称变快.
计数或正确性证据需改冻结源码时, 判无法下结论, 不靠改产品取数.
完成标准: 已记录失败与非成功响应的定义及计数. 输出正确性结果与计时区实际工作可复核. 拿不到时已写缺口.

## 收益上限与端到端

先用占比算收益上限, 再判断能否将局部数字用于整条路径.
计算改动段占用户路径耗时的比例 r, 保留可复核材料. 完全移除该段时, 路径最多快 r / (1 - r). 占 10% 的段全删, 上限约 11%. 上限不是实测结果, 实际收益通常更低.
核对三组物理上限:

- 每秒字节数与磁盘/网络带宽.
- 每秒操作数乘每操作成本与核心数.
- 节省时间与改动段自身耗时.

数字对不上说明测到的不是那段工作.
路径收益超限时, 先按测量错误线索排查:

- 缓存命中, 如第二次直接返回.
- 空操作, 如写入 0 条或跳过工作.
- 错误响应, 如失败请求更快.
- 计时区外的计算.

查完仍超限就判无法下结论.
微基准只说明函数自身. 微结果旁边必须附用户端到端路径的实测. 实测走真实入口, 带与目标规模一致的合成测试数据与并发. 给出微优化占整条路径的比例. 只发函数层结论也须附这组数, 避免读者误当整条路径收益. 授权内补不齐时列缺口, 结论只限函数层. 不宣称整条路径收益.
分析器运行的耗时不进报告, 因为它会拖慢工作. 限制因素单独下结论, 用正式运行数字支撑.
正式数字没变时, 先查计时区, 缓存冷热与机器负载. 再查固定等待与限制因素. 再判断优化是否无效, 不直接断言没用.
应用吞吐停涨而负载生成器 CPU 饱和时, 标为负载生成器饱和. 不算应用测量结果. 授权内改用预生成负载或独立进程等方式, 再测应用. 无法调整就报缺口.
完成标准: 已记录占比, 上限算式与端到端数据规模/并发. 缺端到端时已列缺口, 结论只限函数层. 已剔除分析器数字. 数字没变或生成器饱和时有单独的限制因素结论.

## 分支: 粗估, 选型, 固定基线

三种请求各有专属检查, 命中时才读 [reference/measurement-branches.md](reference/measurement-branches.md): 我只要粗略量级, 两库或两套配置的取舍, 规划或固定基线脚本. 分支只放宽或收紧上面的检查, 不改本文判定节的判定词与缺口情形.

## 判定

先用一个判定词: 更快/更慢/无可测差异/无法下结论. 正式比较附单位, 每侧次数, 极差与实测限制因素. 缺任一项, 读者就无法判断差距在其他环境是否成立.
无可测差异附两组数值, 中位数与波动. 无法下结论须指出具体缺口.
以下任一情况一律判无法下结论:

- 说不出限制因素.
- 两侧条件不可比, 授权内补不齐.
- 单侧未调优且无权补齐.
- 第 4 问的错误计数或正确性缺失.
- 第 7 问的实际工作无法检查.
- 只凭单次, 中位数大小或未经核查的脚本输出选赢家.

这些情形下选赢家, 就是将噪声, 配置差或空转当结论. 各节遇到的拿不到材料, 权限不足, 条件不可比都落到这份清单, 不另立判据.
完成标准: 判定词与证据一致, 正式比较四项材料齐全. 无法下结论时缺口明确.

## 对外报告

PR 正文只放一个主数字, 带单位, 前后对照与证据链接. 不再摆第二组中位数或极差. 避免正文变成测量报告而失去重点.
链接材料保留完整次数, 极差与方法. 失败数, 工作量, 限制因素与机器条件也保留. 内部验收证据不得因对外简短而缩减. 简短主张必须来自完整证据.
本清单只产出草稿与判定. 提交, 推送, 开 PR 与合并由我按自己的流程做.
完成标准: 正文只有一个主数字, 带单位与前后对照. 链接能读取完整次数与极差, 内部证据未删减. 未触发远端 Git 动作.
