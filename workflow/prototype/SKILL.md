# 原型

原型是回答一个设计问题的一次性代码.

## 分支

两个分支, 由问题类型决定:

- **"这个逻辑/状态模型对吗?"** → [LOGIC.md](LOGIC.md). 构建微型交互终端应用, 手动推状态机遍历边界 case.
- **"这个应该长什么样?"** → [UI.md](UI.md). 在单一路由上生成几个截然不同的 UI 变体, 通过悬浮底栏切换.

选错分支会浪费整个原型. 若问题模糊且我不在场, 默认: 后端模块 → logic; 页面或组件 → UI, 并在原型顶部声明假设.

## 通用规则

每条规则即其完成标准.

1. **从诞生就注定被丢弃, 且明确标记.** 原型代码按各类型约定的方式存放. 文件路径符合约定, 路人一眼认出是原型.
2. **一条命令即可运行.** 用我熟悉的运行命令, 我必须能不假思索启动.
3. **默认不持久化.** 状态存内存. 持久化是原型要验证的东西, 不是原型该依赖的. 若问题涉及持久化, 用本地文件, 取醒目名字, 用后即焚.
4. **暴露状态.** 每次操作后打印或渲染完整当前状态, 让我看到什么变了.
5. **完成后捕获.** 原型回答设计问题后, agent 在同一会话中捕获:
   1. 记录结论 — 回答了什么问题和答案.
   2. 归档原型文件 — 具体方式见各类型约定.
   3. 在实现 issue 上留指针 (一次性分支名或 `docs/changes/` 文件路径).
6. **验证止于冒烟, 其余由我驱动.** 冒烟 = 能启动, 能交互, 该展现的能正常展现. 冒烟之后每多一步都是空转: 设计问题只有我驱动才暴露, 实现 bug 会在我遍历 case 时顺路浮现 — 那些 case 我本来就要跑.
