# UI 演示

在单一路由上生成几个截然不同的 UI 变体, 通过悬浮底栏切换.
我在浏览器中翻阅变体, 选一个 (或从各变体中各取一部分), 其余留在原地不选用.

## 子形态

UI 演示贴在真实应用环境里才容易评判 — 真实的 header, sidebar, 数据, 信息密度.
只要存在可托管变体的现存页面, 就默认子形态 A.
仅当演示确实没有邻近宿主时, 才用子形态 B.

### 子形态 A — 调整现有页面 (首选)

变体在同一路由上渲染, 通过 `?variant=` URL search param 控制.
现有数据获取, params, auth 全部保留 — 只有渲染部分切换.
若演示对象还没有独立页面但自然属于某个页面内部 (新 section, 新 card, 新步骤), 仍属子形态 A: 将变体挂载在宿主页面内部.
文件放在 `src/` 内宿主页面附近, 以 `demo.` 为前缀命名, 扩展名跟随项目技术栈.

### 子形态 B — 新页面 (最后手段)

仅当确实没有现存页面可嵌入时使用 (全新顶层界面, 或无法嵌入任何现有位置的流程).
创建一次性路由, 遵循项目已有约定, 命名让人一眼看出是演示 (路径含 `demo`). 同样使用 `?variant=` 模式.
文件以 `demo.` 为前缀命名, 扩展名跟随项目技术栈. 多文件使用 `demo/` 子目录.
选择前 sanity-check: 真的没有现存页面可以嵌入吗? 空路由会隐藏设计问题, 有内容的页面才会暴露它们.

子形态 A/B 的悬浮底栏完全相同.

### 子形态 C — 无现有项目 (降级)

当不存在前端项目可嵌入时使用. 生成独立 HTML 文件, 通过 `present` skill 自包含渲染.
放在 `docs/changes/<feature-slug>/demos/<demo-name>/` 下, 变体和 switcher 内联到单文件.
**注意**: 此模式丧失真实项目上下文, 仅能评估组件视觉外观 — 无法评判信息密度, 与周边元素的关系, 或实际数据下的表现.
若后续项目初始化, 应将变体迁移到子形态 A 重新评估.

## 流程

### 1. 陈述问题并确定 N

默认 **3 个变体**. 上限 5 个 (超过即噪音).
把计划写在一行里, 放在演示文件顶部注释:
"设置页面的三个变体, 通过 `?variant=` 切换, 在现有 `/settings` 路由上."
完成标准: 问题陈述已写; 变体数量已确定.

### 2. 生成截然不同的变体

每个变体符合页面的目的和数据, 项目的组件库/样式系统, 清晰导出名如 `VariantA`.

变体必须结构不同 — 不同布局, 不同信息层级, 不同主要操作入口.
三张微调过的卡片网格不是 UI 演示, 是壁纸.
若两个草稿太相似, 重做其中一个.
完成标准: 所有变体已草拟; 每个变体在结构上可区分.

### 3. 串联 switcher

在路由上创建 switcher 组件:

- 子形态 A: 所有现有数据获取放在 switcher 上方; 仅渲染子树随变体切换.
- 子形态 B: 一次性路由 `/demo/<name>` 挂载同一 switcher.

完成标准: `?variant=` 切换渲染不同变体; switcher 组件可复用.

### 4. 构建悬浮底栏

屏幕底部居中的 fixed-position 栏, 包含左右箭头 (循环切换变体) 和当前变体标签.

行为:
- 点击箭头或 `←` `→` 方向键切换变体, 更新 URL search param (使用框架 router), 使变体可分享且刷新稳定. 输入框聚焦时不拦截方向键.
- 视觉上明显区分于被评估的设计 (高对比度 pill, 微妙阴影).
- 生产构建中隐藏 — `process.env.NODE_ENV !== 'production'` 或等效 gate.

完成标准: 键盘和鼠标均可切换变体; URL 随切换更新; switcher 在生产构建中不可见.

### 5. 交付

给出 URL 和 `?variant=` key. 我随时翻阅.
最有价值的反馈通常是 "我要 B 的 header 加上 C 的 sidebar" — 这才是真正想要的设计.
完成标准: 我已开始浏览变体; 或我确认看到预期效果.

### 6. 捕获

按 [SKILL.md](SKILL.md) 规则 5 捕获答案和材料位置.
胜出变体融入真实代码; 未胜出的变体和 switcher 留在原地, 不主动删除.

- **子形态 A/B**: 完整变体集作为一手材料进入变体分支 `demo/<feature-slug>` (命名冲突时追加时间戳). 提交并 push (纯本地仓库仅本地分支). 这些文件只存在于该分支, 切回工作分支后不在工作树里. 变体分支可留着回看, 你不主动删除; 需要清理时由我点名删除对象.
- **子形态 C**: 演示文件保留在工作分支, 可保留回看, 你不主动删除; 需要清理时由我点名删除对象.

完成标准: 答案已记录; 演示材料位置已记录; 实现 issue 上有指针.

## 反模式

- **仅颜色或文案不同的变体.** 真正不同的变体在结构上不一致.
- **变体之间共享过多代码.** 共享 `<Header>` 没问题; 共享 `<Layout>` 违背目的 — 每个变体应能自由抛弃布局.
- **将变体接入真实 mutation.** 只读演示没问题. 若变体需要 mutation, 指向 stub.
- **将演示变体直接提升到生产环境.** 变体代码在演示约束下编写 (无测试, 最少错误处理). 融入时重新正确编写.
