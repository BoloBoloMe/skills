# 演示

演示材料是让人看清指定样子, 行为或过程的代码或页面.

拿已交付的成品或线上系统演示时不调用本 skill: 直接跑成品即可, 没有材料要造, 也没有一次性文件要清.

## 分支

两个分支, 由要让人看清什么决定:

- **"这个逻辑/状态模型是怎么走的?"** → [LOGIC.md](LOGIC.md). 构建单文件交互网页, 点按钮驱动状态机遍历边界 case.
- **"这个应该长什么样?"** → [UI.md](UI.md). 在单一路由上生成几个截然不同的 UI 变体, 通过悬浮底栏切换.

选错分支会浪费整个演示. 若问题模糊且我不在场, 默认: 后端模块 → logic; 页面或组件 → UI, 并在演示材料顶部声明假设.

## 通用规则

每条规则即其完成标准.

1. **演示材料不进产品, 不承诺交付, 可以保留回看.** 演示材料按各类型约定的方式存放. 文件路径符合约定, 路人一眼认出是演示材料. 代理不主动删除演示材料; 需要清理时由仓库主人点名删除对象.
2. **一条命令即可运行.** 用我熟悉的运行命令, 我必须能不假思索启动.
3. **默认不持久化.** 状态存内存. 持久化是演示要展示的东西, 不是演示该依赖的. 若问题涉及持久化, 用本地文件, 取醒目名字, 用后即焚.
4. **暴露状态.** 每次操作后打印或渲染完整当前状态, 让我看到什么变了.
5. **完成后捕获.** 演示完成后, agent 在同一会话中记录:
   1. 演示了什么.
   2. 想请仓库主人据此判断什么.
   3. 材料位置.
   4. 相关 issue 指针.
6. **验证止于能演示, 其余由我驱动.** 能演示 = 能启动, 能交互, 该展现的能正常展现. 之后每多一步都是空转: 演示是否达意只有我驱动才暴露, 实现瑕疵会在我操作时顺路浮现 — 那些 case 我本来就要跑.
