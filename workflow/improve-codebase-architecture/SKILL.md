# 改进代码库架构

发现架构摩擦, 提出将浅模块重构为深模块的深化机会. 目标是可测试性和 LLM 可导航性. 本流程交付审查, 设计和获准的领域记录; 代码实现需我另行授权.

**1. 探索**

调用 `codebase-design` skill 获取领域模型与设计原则, 沿用既有领域命名和该 skill 的架构词汇.
只读探索本次审查范围, 关注理解一个概念时的跨文件跳转, 调用者承担的规则与顺序约束, 接缝泄漏, 以及测试难以覆盖真实协作等摩擦. 记录实际检查区域与未覆盖部分, 让结论的范围与证据一致.

对每个疑似浅模块应用 `codebase-design` 的删除测试, 结合实际调用者说明结论. 评估候选的依赖与测试策略时, 读取该 skill 的 `DEEPENING.md`.
只保留预期收益值得付出代价, 或有明确验证价值的候选. 每个候选都要有可定位的代码或测试证据, 以及收益, 迁移代价与待验证问题的判断. 把观察事实与设计推测分开, 尚未证实的收益标为待验证.
候选与既有 ADR 冲突时, 只有具体摩擦足以支持重新审视该决策才保留, 并说明冲突与理由; 否则以 ADR 为约束.
完成标准: 检查范围与局限已明确, 每个候选均满足上述要求; 零候选时说明检查范围, 依据与局限后结束本流程.

**2. 呈现并选择候选**

调用 `present` skill 生成和展示报告, 输出放在仓库外的临时目录. 内容结构与前后对比要求读 [HTML-REPORT.md](HTML-REPORT.md), 样式与展示流程由 `present` 负责. 此时只呈现问题与深化方向, 具体接口留待选定候选后设计.
交付报告后, 在 chat 询问我: "你想探索哪一个?"
完成标准: 报告已展示或可访问, 关键结论与选择问题已在 chat 交付, 等待我的选择.
