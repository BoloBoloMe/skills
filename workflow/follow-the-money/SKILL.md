# 资损审查

## 边界

本 skill 只回答一个问题: 这次变更会不会造成资损. 资损有两种载体: 钱被错付, 资产被误发, 对损失同罪. 能否编译运行, 测试覆盖, 风格, 可维护性, 可观测性, 发布策略, 都由工作流其他环节负责.

报任何问题的唯一准入: 触发路径 (见 输出格式) 填得出来.

资损的原因举不完 (精度, 币种, 汇率, 重复退款, 重复发货, 虚拟资产误发, 攻击, ...), 枚举原因注定漏, 所以不枚举: 跟着钱走, 找到 diff 触及的每条价值流, 对每条验证同一组不变量 (三根轴). 这里的 "钱" 指一切离开系统就难以收回的价值: 现金, 余额, 虚拟资产, 实物.

## 输入

- 我给了 diff, PR 或文件范围, 就按范围审; 只说审当前变更, 就看工作区 diff.
- 看不到变更或缺关键文件时, 说明缺什么, 不下结论.

## 流程

1. **跟着钱走.** 从 diff 找出所有被触及的价值流: 钱的流 (代收, 代付, 退款, 结算, 计价) 和 资产的流 (实体发货, 虚拟商品/金币/权益发放). 对每条定位出口: 钱的出口是外部渠道调用或账务落库, 资产的出口是资产入账或履约指令. 完成标准: 每条价值流都能从入口指到出口; 一条都指不出时, 结论即 无资损面, 到此为止.
2. **对每个出口过三根轴.** 完成标准: 出口 × 轴, 每格都是 安全 或 资损问题 + 证据, 无悬空; 不因某个陷阱不在已知例子里就跳过 — 轴是穷举, 例子不是.
3. **审删除.** 逐个看 diff 删掉的守卫, 问: 删掉它, 什么资损变得可能? 重构意图再正当, 拆防线本身就是资损问题. 完成标准: 每个被删除的守卫都有答 — 报出资损, 或明确无害; 无未审删除.

## 三根轴

每笔价值变动 = 一个授权, 一个数量, 一次执行. 三者各有各的错法, 合起来覆盖所有资损:

- **授权** — 这笔变动凭什么发生? 出口只执行已验证的指令: 验签通过的回调, 服务端计算并持久化的金额, 有权限的操作. 验签只证明来源可信, 不证明内容正确 — 出口依据的金额/商品/数量必须来自服务端订单并与回调比对, 照单全收回调字段 (篡改 amount, 移花接木到别家订单) 同样是授权失守. 越权可达的退款/代付, 把渠道的失败或未知响应当成功 — 全是资损入口, 外部攻击主要从这里进来.
- **数量** — 算对了吗? 钱查金额, 资产查件数/面额: 货币单位 (分/元/最小单位), 精度与舍入, 币种与汇率换算, 资产类型与兑换比例, 正负号, 溢出. 金额经浮点计算即是缺陷; 汇率可以浮点, 金额不可以.
- **执行** — 恰好一次? 重试, 乱序, 并发回调, 消息重复投递会让一条指令执行两次 (重复退款, 重复发放, 重复发货); 漏执行则该收的没收上 (发货没扣款). 对每个出口说出保证只放行一次的机制 — 幂等键, 唯一约束, 状态机 — 说不出就是缺陷.

三根轴的校验全部在出口之前完成, 不依赖出口之后的拦截/追回 — 能拦住是运气, 不是设计. 对不确定性一律保守: 验签失败, 状态未知, 金额对不上时, 不发货不入账, 阻塞到主动查询或人工裁决 — 漏发可补, 误发难追.
