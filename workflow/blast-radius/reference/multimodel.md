# 大或宽变更的多模型同题调查

只有变更的实际影响大或宽时才做这一层: 跨多个模块, 跨仓库, 改了被下游共享的线格式, 数据库列或公共接口, 或者失败代价高到值得多一路眼睛. diff 行数, 文件数, "只是个小函数" 都不作数: 几十行改一个共享格式也算宽.

## 开两路

1. 调用 `llm-select` skill 选两款能力达标的模型及 thinking 档位, 记下完整模型名. 只挑当前确实可调用的, 不按名字猜.
2. 调用 `use-herdr` skill 在同一个临时项目里开新 tab 与新会话, 让第二路的模型与第一路不同. 命令形态:
   `herdr tab create --cwd <项目> --label <名字> --no-focus`
   `herdr agent start <短名> --kind pi --pane <窗格> -- --model <provider/model> --thinking <档位>`
3. 每一路拿到同一批关键事实, 同一份问题, 同一批输入, 各自跑自己的证明脚本并保留原始输出. 后一路不看前一路的结论, 否则两路会趋同, 交叉核对就失效.
4. 每一路的报告落在项目外的不同目录, 便于逐条对照.

## 合并

- 逐条事实对齐, 不按整篇报告投票.
- 一致的事实: 保留最高证据级别, 写明是哪一路跑出来的, 给出脚本与输出位置.
- 分歧的事实: 两路结论与各自的证据级别都留下, 标为未决, 写明还需要什么才能定案. 不取平均, 不挑听着更顺的那一路.
- 一路查到另一路没查的地方: 记为新增项, 仍按证据级别标注.
- 合并后的报告照旧走五部分交接与中文整理规则.

## 记录与缺口

- 记录会话名, 模型全名, thinking 档位, 提交时间与各自输出路径, 让读者能核对哪一路说了什么.
- 只有一款模型可用, 或调用方只授权一款时: 在交接里写明这是能力缺口, 说明缺的是第二路同题调查, 不假装多路已经做完. 已经真实证明的事实保留原证据级别, 不改标未证实.
- 影响确实局限 (单个内部函数, 无共享格式, 无其他模块读者), 且调用方选择单路时: 正常交付单路结论, 写明这是单路, 并说明后续可以加查. 单路本身不是缺陷, 少的只是这层交叉核对.
