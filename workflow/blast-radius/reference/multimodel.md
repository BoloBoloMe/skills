# 大或宽变更的多模型同题调查

只在实际影响大或宽时做这一层. 包括跨模块/仓库或改共享线格式/数据库列/公共接口. 失败代价值得多路核对时也算.
不按 diff 行数, 文件数或函数大小判断. 几十行改共享格式也算宽.

## 开两路

1. 调用 `llm-select` skill 选两款能力达标的模型与 thinking 档位. 只选当前确实可调用的模型, 不按名字猜. 完成标准: 两款模型全名与档位已记录.
2. 调用 `use-herdr` skill, 在同一临时项目开新 tab 与会话. 第二路模型必须与第一路不同. 命令形态:
   `herdr tab create --cwd <项目> --label <名字> --no-focus`
   `herdr agent start <短名> --kind pi --pane <窗格> -- --model <provider/model> --thinking <档位>`
   完成标准: 两路会话对应不同模型, 项目相同.
3. 两路使用相同关键事实, 问题与输入. 各自运行证明并保留原始输出. 后一路不看前一路结论, 避免趋同使交叉核对失效. 完成标准: 两路各有独立证明与原始输出.
4. 两路报告存到项目外的不同目录. 完成标准: 各自报告位置可读取并逐条对照.

## 合并

- 逐条事实对齐, 不按整篇报告投票.
- 一致项: 保留最高证据级别, 标产生会话, 脚本与输出位置.
- 分歧项: 保留两路结论与各自证据级别. 标未决并写定案所缺条件. 不取平均, 不挑顺耳的一路.
- 单路独有发现: 记新增项并标证据级别.
- 合并报告仍按主文件的五部分交接与中文整理规则.

完成标准: 每条事实有合并结果与来源. 分歧及各自级别均保留.

## 记录与缺口

- 记录会话名, 模型全名, thinking 档位, 提交时间与各自输出路径.
- 只可用或只授权一款模型时, 交接写能力缺口. 说明缺第二路同题调查. 不假装多路完成. 已证明事实保留原证据级别, 不改标未证实.
- 影响确实局限且调用方选单路时, 正常交付并注明单路. 说明后续可加查. 局限指单个内部函数, 无共享格式或其他模块读者. 单路本身不是缺陷, 只缺这层交叉核对.
