## 借用的依赖, 按 F014 记录的范围

- `why` 只借 Step 2: `git blame -L`, `git log --follow -p`, 近期 `git log`, 从提交消息找 PR, 读 PR 正文与讨论. 不借 `why` 的完整调查者体系. 本技能第 1 节把这些命令写成可直接执行的步骤, 不留下指向上游文档的悬空调用.
- 上游 Step 4 的诚实纪律已内联到第 5 节, 去掉重复的来源指针, 规则本身不减.
- 多模型同题借 `arena` 的意图 (不同模型, 同一问题, 合并答案), 不搬它的 Frame / Fan out / Cross-judge / Pick / Graft / Verify 产物流程与模型指派表. 本环境改用 `use-herdr` 与 `llm-select` 承接, 步骤见 `reference/multimodel.md`.
- `unslop` 是英文写作编辑清单, 对中文报告不是等价替换. 这里改写成中文报告的整理规则, 见 `reference/report-style-zh.md`, 只保留"诚实, 去冗"的意图.

## 没有搬入的部分

- `how` / `why` 的完整体系; `arena` 的产物流程与模型指派表; `unslop` 的英文风格检查; poteto-mode 的提交, 发布, 自动合并流程.
- 上游按 PR 组织的执行形态: 本技能只交接材料, 不自动合并, 不创建 PR.

## 行为差异

- 使用者可以亲自调查并运行证明; 验收指挥者不能借调用本技能亲自验收, 需要派实际验收子会话.
- 大或宽变更要求的多模型同题调查可以委派, 但合并证据与保留分歧仍由交付结论的人做.
- 运行真实代码不等于取得写权限: 只读调查直接做, 需要改仓库或跑有副作用的应用时先问. 一次性实验不成为正式用例, 也不改产品标准.
- 历史材料取不到时写明来源限制, 不编造 PR 或提交讨论.
