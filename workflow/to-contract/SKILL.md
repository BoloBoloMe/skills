`contract.md` 是执行边界契约, 是 issue 拆分, AFK worker 和 reviewer 的权威输入. 它不承担团队汇报, 不写 PRD 式叙事, 不写 issue 拆分, 不写逐文件实现计划.
默认输入已经由 `grill-with-docs` 对齐设计决策. 本 skill 不做需求访谈, 只做执行契约完整性检查和聚焦代码探索. 发现设计决策缺口时停止, 要求退回 `grill-with-docs`.
你应该已获得本地议题跟踪器约定. 如果没有, 使用 `setup-workspace` skill.

## 流程

### 1. 收集输入

读取: 当前对话, 我提供的材料, 原型产物, `DECISIONS.md` (如存在), 既有相关文档.
输出: 我给出输出位置时使用该位置; 否则按 `docs/changes/<feature-slug>/contract.md` 输出, `<feature-slug>` 从功能标题推断.
完成标准: 来源材料清单已列出; 输出路径已确定; `DECISIONS.md` 已读取或已确认不存在/无相关决策.

### 2. 聚焦探索代码库

如果当前会话尚未形成足够代码理解, 读取相关代码, 测试和配置. 探索只服务于确认执行边界是否可落地:
- 高层代码边界提示.
- 允许范围和禁止范围.
- 可用验证入口.
- 已定设计与代码事实是否冲突.

禁止: 不要写逐文件实现计划. 不要把早期猜测写成 worker 必须遵守的实现方案.
完成标准: 已形成模块/目录/行为层面的边界提示; 已找到验证入口或写明需要探索的测试入口; 代码事实没有推翻已定设计.

### 3. 检查缺口

按缺口类型处理:
- 设计决策缺口: 产品/API/架构/范围取舍未定 -> 停止, 要求退回 `grill-with-docs`.
- 执行材料缺口: 没有测试命令, 不知道相关模块, 缺少 issue tracker 约定 -> 本 skill 自己探索或先调用 `setup-workspace`.
- 事实冲突: 对话, `DECISIONS.md` 和代码现状互相矛盾 -> 停止, 报告冲突, 请求我选择权威来源.

假设规则: `未确认假设` 只允许记录非阻塞事实未知. 会影响允许/禁止范围, API, 架构, 产品行为或验收标准的未知不能写成假设.
完成标准: 没有阻塞性设计缺口; 没有未解决事实冲突; 每个非阻塞假设都写明影响和验证方式.

### 4. 编写 contract

写入: 使用下方模板编写 `contract.md`, 发布到本地议题跟踪器.
决策: 如果需要新增, 替代或废弃设计决策, 先退回 `grill-with-docs` 或按 `decision-ledger` skill 规则维护账本.
禁止: contract 只引用和摘要执行必须知道的决策, 不发明新决策 ID, 不复制完整设计树, 不记录执行状态, 不写 `Status:` 或等价状态行.
完成标准: contract 已写入目标路径; 固定章节齐全且顺序一致; 空章节写明"无"或"未发现"; 最终回复展示路径, 目标, 非目标, 允许/禁止范围, 风险/停止条件; 已询问我是否确认该 contract 可作为执行契约.

<contract-template>

# <变更标题> Contract

## 背景
执行者理解任务所需的最少上下文. 不写汇报性叙事.

## 目标
- 可观察交付结果 1
- 可观察交付结果 2

## 非目标
- 不做 X, 它不在本变更范围内

## 行为边界
- 用户可见行为
- 失败/边界场景
- 兼容性要求

## 决策引用
完整决策账本: `DECISIONS.md` (如存在).
列出相关决策 ID 和执行必须知道的约束摘要. 无相关决策时只写"无相关决策".

## 未确认假设
只列非阻塞事实假设. 没有则写"无".
- 假设:
  影响:
  验证方式:

## 代码边界提示
- 可能涉及的模块, 目录或行为边界. 只写高层提示, 不写逐文件实现计划.

## 允许范围
- 可修改的模块, 目录, 文件模式或行为范围.

## 禁止范围
- 不可修改的模块, API, schema, 行为或非目标范围.

## 验证入口
- 推荐测试命令, 测试目标或可观察验收方式. 无法确定命令时写应探索的测试入口, 不编造命令.

## 风险和停止条件
- 需要产品/API/架构决策时停止.
- 需要扩大范围时停止.
- 发现现有行为与 contract 冲突时停止.

## 下游 issue 约束
- issue 必须继承的边界.
- 切片拆分时不能违反的顺序或依赖.

</contract-template>
