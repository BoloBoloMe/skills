开始前, 使用 `domain-awareness` skill 只读感知当前工作目录的领域模型.
生成 `TECHNICAL.md`, 作为当前变更的技术契约和权威索引. 文档只供 AI 使用. 本 skill 不做设计访谈, 不新增产品/API/架构/范围决策, 不要求我阅读或批准文档. 默认输入已由 `deliberate` 确认, `PRODUCT.md` 已存在.

## 1. 收集输入

读取当前对话, `PRODUCT.md`, `DECISIONS.md` (如存在), 相关领域文档/ADR, 原型和机器可读契约. 输出固定为同一 feature 目录下的 `TECHNICAL.md`.
完成标准: `PRODUCT.md` 可读; 已读取所有相关当前决策和长期架构约束; 输出路径唯一.

## 2. 聚焦探索代码库

读取相关代码, 测试和配置, 只为确认已定设计能落地以及定位权威技术资产:

- 当前架构和模块责任.
- API/schema/状态机的现有权威来源.
- 关键流程, 异常和边界行为.
- 安全与非功能约束.
- 可用测试入口和代码边界.

已有机器可读 API/schema/迁移文件时, 它们是对应事实的单一真相源, `TECHNICAL.md` 只引用. 当前变更需要契约但不存在机器可读资产时, 在 `TECHNICAL.md` 中精确定义字段, 类型, 约束, 状态和错误语义, 该章节成为当前变更的权威来源. 禁止同时维护两份完整定义.
完成标准: 技术设计与代码事实可对照; 权威技术资产和验证入口已定位, 或已明确不存在.

## 3. 检查闭合

- 产品/API/架构/范围决策缺失 -> 停止, 请我回到 `deliberate`.
- `PRODUCT.md`, `DECISIONS.md`, ADR 和代码事实冲突 -> 停止, 在会话中说明证据和影响, 请我回到 `deliberate` 处理.
- 只缺非阻塞事实 -> 写入待验证事实, 包含影响和验证方式.
- 阻塞性开放问题不得写进已完成的 Technical Spec.

完成标准: 无阻塞设计缺口或事实冲突; 每项非阻塞未知都有影响和验证方式.

## 4. 编写 Technical Spec

使用下方模板写入 `TECHNICAL.md`. 技术目标使用稳定连续 ID `TG-001`; 非功能要求使用 `NFR-001`. 引用 `PRODUCT.md` 中的稳定 ID 和 `DECISIONS.md` 中的决策 ID.
不写 issue 拆分, 执行状态或逐文件实施步骤. 不复制完整决策树. 不发明新决策.
完成标准: 固定章节齐全; 产品验收项均有技术承载或明确标记不需要技术承载; API/schema 等事实只有一个权威来源; 文档未引入来源中不存在的决定.

<technical-spec-template>
# <变更标题> Technical Spec
## 产品依据
- Product Spec: `PRODUCT.md`
- 覆盖目标: G-001
- 覆盖验收: AC-001
## 技术目标
- TG-001: 支撑产品结果所需的可验证技术结果. 覆盖: G-001, AC-001.
## 架构与组件
模块责任, 交互方式和关键 seam. 无变化时说明沿用的现状.
## 接口契约
引用机器可读契约; 不存在时精确定义端点/方法, 请求/响应字段与类型, 状态码, 错误码和兼容约束. 不适用则写"不适用".
## 数据模型与状态
引用 schema/迁移/状态机权威资产; 不存在时精确定义字段, 类型, 约束, 关系和状态转换. 不适用则写"不适用".
## 关键流程
复杂正常流程, 失败流程和必要时序.
## 边界与异常处理
非法输入, 超时, 并发, 幂等, 一致性, 降级和兼容要求.
## 安全策略
认证, 授权, 隐私, 密钥, 加密和脱敏. 不适用项写理由.
## 非功能要求
- NFR-001: 性能/可观测性/可用性要求及验证口径.
## 测试策略
各 AC/TG/NFR 所需测试层级和验证入口, 不写具体测试实现.
## 技术决策引用
- `DECISIONS.md` 中相关决策 ID. 无则写"无".
- 相关 ADR. 无则写"无".
## 依赖与风险
外部依赖, 关键风险, 影响和防护.
## 代码边界提示
可能涉及的模块, 目录或行为边界. 不写逐文件计划.
## 待验证事实
- 事实:
  影响:
  验证方式:
没有则写"无".
</technical-spec-template>

## 5. 会话交付

只告诉我: 已生成的路径, 是否存在待验证事实, 是否发现冲突. 不展示 Technical Spec 全文, 不让我阅读后确认.
完成标准: 我能从会话回复知道生成是否成功和是否有阻塞, 但无需阅读 `TECHNICAL.md`.
