# 产出物模板

## 目录结构

```
docs/reviews/
└── YYYY-MM-DD-<简短标识>/
    ├── review-plan.md           # 确认后的评审计划
    ├── 代码评审日志.md
    ├── 人审报告.md
    ├── 模块关系图.mermaid       # 交叉密集时生成
    └── subagent/              # 子代理探索产出物
        ├── 目录扫描.md
        ├── 依赖图.md
        └── ...                # 子代理自行命名, 按任务拆分
```

`<简短标识>` 用被 review 目标命名: `auth-module` / `PR-142` / `payment-refactor`.
若仓库无 `docs/` 目录, 退回到当前工作目录.

## review-plan.md

```markdown
# 评审计划

## 基本信息
- 模式: 全量/diff/PR
- 范围: ...
- 时间: YYYY-MM-DD

## 模块关系简图

指向 HTML 载体中的模块关系简图, 或记录 adaptive-presentation 产物路径.

## 文件清单与策略

| # | 文件 | 策略 | 备注 |
|---|------|------|------|
| 1 | path/to/file | 全量/diff | ... |

## 决策核对范围

- 是否启用: 是/否
- 决策账本: `path/to/DECISIONS.md` 或 无
- 覆盖范围: 本次 review 范围内的修改
- 相关决策: D001, D002 或 无

## 走读顺序

1. 入口: ...
2. ...
```

## 代码评审日志.md

```markdown
# 代码评审日志

## 基本信息
- 模式: 全量/diff/PR
- 范围: [文件/目录/commit范围]
- 时间: YYYY-MM-DD

## 已审片段

### 片段 N: [文件:行号范围]
- 要点: ...
- 风险/发现: ...
- 决策核对: 无 / 违反决策 / 未说明偏离 / 隐含决策 / 追踪缺口 + 证据和我的结论
- 我的反馈: A/B/C/D/E + 补充说明
- 状态: ✅已审 / ⏭️跳过 / ❓待定
```
