开始前, 使用 `domain-awareness` skill 只读感知当前工作目录的领域模型.

# 带我评审代码

交互式代码走读的操作规范. 核心目标: 帮我充分理解代码.

## 阶段 1 - 明确边界与模式推断

1. 根据会话内容推断需要 review 的代码范围和模式 (全量/diff/PR), 向我确认.
2. 确定产出物目录: `docs/reviews/YYYY-MM-DD-<简短标识>/` (无 `docs/` 时创建). 见 [REFERENCE.md](REFERENCE.md) 中的模板.
3. 生成代码库探索产物. 完成标准绑定产物, 不绑定执行者. 若我允许且运行时支持子代理, 可委派子代理探索; 否则父会话直接探索并产出同样产物. 子代理产物写入产出物目录的 `subagent/`, 父会话产物直接写入产出物目录:
   - 全量: 目录扫描, 入口识别, import 依赖图, 层级定位 -> 输出模块关系简图 + 文件清单
   - diff: 解析 diff, 对每个变更文件查看变更点所在完整函数/方法体及调用者和被调用者, 识别是否触及接口/契约层 -> 输出变更文件清单 + 每文件变更摘要
   - PR: 读 PR 描述/title/关联 issue + diff 解析 + 按文件性质分类 (新增文件 -> 全量, 变更文件 -> diff) + PR 额外检查 (描述一致性/遗漏文件测试/commit 粒度)
4. 如果 review 范围关联 feature 且存在 `DECISIONS.md`, 调用 `decision-ledger` skill, 读取决策账本和维护规则, 并在 review 计划中加入决策核对范围. 决策核对只覆盖本次 review 范围内的修改; 不盘点全仓库历史决策. 如果不存在 `DECISIONS.md`, 不做决策核对.
5. 向我展示模块关系简图和 review 计划, 确认后将 review 计划写入产出物目录 (`review-plan.md`). 画图规则:
   - 默认用 ASCII box 图, 可混用纯文本箭头链补充细节
   - 交叉密集的局部生成落盘 Mermaid 文件 (路径: 产出物目录/`模块关系图.mermaid`), 主会话用 box 图展示骨架并指引我查看 Mermaid 文件
   - 子模块过多时分层输出, 先顶层后展开

## 阶段 2 - 逐段走读

从执行入口开始, 沿调用链深度优先, 一次一个片段. PR 模式按文件分流: 新文件走全量, 变更文件走 diff.

### 片段选取策略

- 全量: 调用链优先, 自上而下
- diff: 变更影响优先, 从变更点向外扩散
- 我指定入口时从指定位置开始

一个片段必须功能完整. 判断标准: 能否抽成独立代码块? 若不能, 说明片段不完整, 需拆分或与相邻片段合并.

### 文件引用规范

格式: `[文件名:开始行号 ~结束行号](相对路径:开始行号 ~结束行号)`, 行号用 `:` 分隔 (禁用 `#L`). 路径以 cwd 为基准, 不能含空格或特殊字符. 不用 inline code (`path`) 代替链接.

示例: `[Foo.java:32 ~51](src/main/java/com/example/Foo.java:32 ~51)`

### 交互循环

每个片段:
1. 按文件引用规范指引我查看代码位置, 不复述代码内容, 一次只指引一处. 再给出要点提炼 (风险/权衡/隐患/错误/参考资料, 省略次要信息)
2. diff/PR 模式额外关注: 变更是否安全, 是否对原逻辑造成破坏性修改, 是否超出声明边界
3. 若本次启用了决策核对, 对当前片段核对相关决策和隐含决策. 发现项分四类:
   - `违反决策`: diff 与当前有效且必须遵守的决策冲突. 高优先级提示, 必须引用决策 ID 和 diff 片段, 问我这是代码错了还是决策已变化.
   - `未说明偏离`: diff 偏离当前有效且可调整的决策, 但 PR/提交/说明中没有解释. 中优先级提示, 问我偏离是否可接受.
   - `隐含决策`: diff 引入会影响代码, 测试, 外部行为, 边界或后续追溯的取舍, 但账本没有记录, 也没有证据表明我确认过. 逐条问我: A. 认可为决策, 建议补入 `DECISIONS.md`; B. 不认可, 代码应改回或重做; C. 只是实现细节, 不需要记录.
   - `追踪缺口`: 代码实现承载了账本中的决策, 但 `实际影响` 未记录或已过期. 默认记录为建议补账本行动项; 只有代码是否承载该决策不确定时才问我.
4. 询问我的评价, 给出选项. 下列选项供参考, 勿机械模仿, 按实际情况组织. 问题前显示当前进度: `已审片段数/计划总片段数`
   - A. 赞成, 看下一段
   - B. 反对, 补充评论
   - C. 仍有疑问
   - D. 跳过, 这段不重要
   - E. 展开更多细节
5. 将审查结果追加到 `<代码评审日志.md>` (模板见 [REFERENCE.md](REFERENCE.md)). 若结论是改实现, 补账本或讨论过较复杂方案, 记录要具体 (目标/改动点/取舍/遗留问题)

### 中断恢复

启动时先检查产出物目录是否存在未完成日志. 若有, 读日志从最近未审片段继续.

## 阶段 3 - 人审报告

所有片段走完后编写 `<人审报告.md>` (模板见 [REFERENCE.md](REFERENCE.md)), 包含:
- 风险评级 (高/中/低) + 一句话结论
- 发现汇总表 (文件/行号/类型/严重度/描述)
- 决策核对发现 (若启用): `违反决策`, `未说明偏离`, `隐含决策`, `追踪缺口`
- 建议行动项 (编号列表)
- 评审过程统计 (总片段数/已审/跳过/待定)

# 边界

整个审核过程中 **绝不能** 修改项目代码或配置, 也不能直接修改 `DECISIONS.md`.
**唯一能写的文件**: `review-plan.md`, `代码评审日志.md`, `人审报告.md`, `模块关系图.mermaid` 和产出物目录下的探索产物.
