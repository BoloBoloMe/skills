# Fowler 坏味道基线

Standards 轴把这些坏味道作为启发式基线使用. 每条发现都必须引用 diff hunk, 并标记为判断性发现, 例如 `可能是 Feature Envy`. 仓库已记录规范优先于本基线.

每个坏味道按 `是什么 -> 如何修复` 判断:

- **Mysterious Name**: 函数, 变量或类型的名称未揭示其职责或内容. -> 重命名; 想不出诚实的名字说明设计本身模糊.
- **Duplicated Code**: 相同逻辑结构在改动中出现在多个 hunk 或文件. -> 提取共享结构, 两处调用.
- **Feature Envy**: 某方法访问另一个对象的数据多于自身数据. -> 将方法移到它羡慕的数据所在对象上.
- **Data Clumps**: 同一组字段或参数总是一起出现, 像一个等待诞生的类型. -> 打包成一个类型, 传递该类型.
- **Primitive Obsession**: 用基本类型或字符串代替值得拥有独立类型的领域概念. -> 为该概念创建专属小类型.
- **Repeated Switches**: 对同一类型重复出现相同的 `switch`/`if` 级联. -> 用多态替代, 或一处 map 两处共用.
- **Shotgun Surgery**: 一个逻辑变更迫使在 diff 中散落修改多个文件. -> 将一起变更的内容集中到一个模块.
- **Divergent Change**: 一个文件或模块因多个互不相关的理由被修改. -> 拆分, 使每个模块只为一个理由变更.
- **Speculative Generality**: 为 spec 中没有的需求添加的抽象, 参数或钩子. -> 删除; 回退内联, 直到真有需要.
- **Message Chains**: 长链式 `a.b().c().d()` 导航, 调用者不应依赖. -> 在第一个对象上用一个方法隐藏整条链.
- **Middle Man**: 类或函数大部分工作只是转发. -> 去掉它, 直接调用真正的目标.
- **Refused Bequest**: 子类或实现类忽略或覆盖了继承的大部分内容. -> 放弃继承, 改用组合.
