# reviewer 任务简述

code-review 第 5 步派工时原样交给各 reviewer 的指令; 输入清单见 [SKILL.md 第 5 步](../SKILL.md#5-运行各评审方向). 每段都面向独立上下文自包含, 不依赖本文件以外的主文件内容.

## Standards

```
报告按相关文件/hunk 组织. (a) diff 中每个违反已记录规范的位置, 引用规范文件和规则; (b) 你发现的任何基线坏味道, 列出名称并引用 hunk. 区分硬性违规和判断性发现. 违反已记录规范可能是硬性的, 基线坏味道始终是判断性发现, 且仓库已记录规范覆盖基线. 跳过工具链已强制检查的内容. 涉及测试/手动验证代码及其夹具或运行配置时, 读取输入提供的测试编写规范, 追查被测实现与依赖, 不因测试全绿就略过其真实性与分类; 人工抽查是否接受仍由用户决定. 每个发现必须已读取对应 hunk 所在完整函数/方法及必要调用方; 无上下文支撑的坏味道不得报告. 完整列出全部发现, 如有摘要只限制摘要篇幅.
```

## Spec

```
报告 (a) spec 要求但缺失或不完整的实现; (b) diff 中出现了但 spec 未要求的行为, 即范围蔓延; (c) 看似已实现但实现方式有误的需求; (d) issue 的交付证据未覆盖所声明的全部变更类型, 或与验证契约不符. 实现类发现引用 spec 原文, 并读取对应 hunk 所在完整函数/方法及必要调用方; 证据类发现引用 issue 的契约, 验证入口, 实际交付证据 (若有) 及 verification-contract 的对应规则, 区分没有记录证据与检查未通过. 没有 spec 或契约依据不得报告. 完整列出全部发现, 如有摘要只限制摘要篇幅.
```

## 旧行为影响

```
从指定评审起点核对实际差异, 追查可能受影响的既有入口/调用方和旧行为. 共享接口, 数据格式或跨模块路径的变更调用 blast-radius skill 深查. 报告写目标提交, 逐项发现, 已排除项与证据, 包含代码依据, 既有检查及本轮运行结果; 未证实路径写明缺口, 不以搜索命中充当安全证明, 不声称有限检查找到了全部影响. 读上轮报告核对闭环, 将本轮完整记录追加到产物根目录的 IMPACT-REVIEW.md 并提交, 不覆盖旧轮次.
```
