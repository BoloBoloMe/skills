# Navigate 验收参考

只在确认详细验收标准或领取 `acceptance` Milestone 时读取相应部分. 路线图中的验收节点及其阻塞关系由 `SKILL.md` 管, 此处只管验收依据和关闭条件.

## 验收标准

目的地已约定怎样算抵达; 当细节明朗时, 最迟在正式实施前逐项确认可验证的标准. 若目的地仅需决策或文档, 则在产物定稿前确认. 先定标准, 才不会按既成结果倒推什么算通过.
- 调用 `to-spec` 时, 由它在落盘前逐批与我确认 `PRODUCT.md` 的 `验收标准`. 直接以该节的 AC 和场景为依据, 不重复确认相同内容.
- 不调用 `to-spec` 时, 有 Roadmap 就用 HITL Milestone, 无 Roadmap 就在当前会话与我确认逐项可观察标准; 写入 `docs/changes/<feature-slug>/ACCEPTANCE.md`, 有 Milestone 时记入其 `artifacts`. 未经我确认的拟稿不算标准. 后续若生成 `PRODUCT.md`, 比对两份标准, 有差异先找我裁决, 再以已确认的 `PRODUCT.md` 为准.
判据始终取我确认的标准: 有 `PRODUCT.md` 时以其 `验收标准` 节为准, 否则以已确认的 `ACCEPTANCE.md` 或其他明确记录为准. 技术文档和验证报告不增加或改写产品判据; 验证报告只作为验收证据, 是否接受由我决定. 标准需要改变时, 先与我重新对齐并更新权威来源, 再按新标准验收.

## 证据与确认

**呈交材料 (我可离场).** 验收阶段只呈交本轮工作已经产生的材料, 不补跑或制造证据. 每项已确认标准都要能对应到结果和证据, 且材料须对应本轮交付; 验证报告可引用原件, 不必转录. 缺少材料, 版本不符或覆盖不足时, 将该项标为未验证, 写明缺口并交我决定如何补足. 需要新增工作时, 建立阻塞验收的工作 Milestone.
完成标准: 有一份逐项对应标准, 结果和证据的清单; 缺口均已标出并交我决定.

**测试代码验收 (单列).** 按 [测试代码人工抽查验收](../verification-contract/reference/tests.md#测试代码人工抽查验收) 的适用分支处理并记录. 已有绑定本轮版本且满足该规则的记录时引用原件, 不重复检查; 需返工时新增工作 Milestone 并让它阻塞验收.
完成标准: 本项记录满足所引规则的完成标准, 并已纳入验收报告; 否则验收保持进行中.

**逐项确认 (我必须在场).** 向我展示每项标准及其结果和证据, 记录我明确作出的接受决定. 未确认的项目不算通过. 我可以同意页面如实展示缺口供讨论, 但这不等于接受交付. 任何必验项失败, 未验证或未获我确认, 验收都不得关闭; 如需补工作, 让新 Milestone 阻塞验收, 完成后再请我确认. 只有所有必验项都有对应证据且我逐项确认通过, 并完成适用的测试代码验收, 才能关闭验收并正式交付. 我尚未决定如何处理关键缺口时, 不生成最终页面; 同意展示缺口时, 页面必须说明未通过, 不得当作正式交付.
完成标准: 所有必验项均有对应证据且已获我确认, 测试代码验收已完成, 验收报告和关闭摘要均记录我的决定; 有未处理缺口时验收保持进行中.
