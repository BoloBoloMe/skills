# 深化

在给定依赖下, 如何安全地深化一组浅模块. 词汇沿用 [SKILL.md](SKILL.md): **模块**, **接口**, **接缝**, **适配器**.

## 依赖类别

评估深化候选时, 对它的依赖分类. 类别决定深化后的模块如何跨接缝测试.

### 1. 进程内

纯计算, 内存状态, 无 I/O. 始终可深化 - 合并这些模块, 直接通过新接口测试, 不需要适配器.

### 2. 本地可替换

存在本地测试替身的依赖 (Postgres 的 PGLite, 内存文件系统). 替身存在即可深化. 深化后的模块在测试套件中与替身一起运行. 接缝是内部的; 模块的外部接口不需要端口.

### 3. 远程但自有 (端口与适配器)

自己拥有但跨网络部署的服务 (微服务, 内部 API). 在接缝处定义一个 **端口** (接口). 深模块拥有逻辑; 传输作为 **适配器** 注入. 测试用内存适配器, 生产用 HTTP/gRPC/队列适配器.

推荐表述: *"在接缝处定义一个端口, 为生产环境实现一个 HTTP 适配器, 为测试实现一个内存适配器 - 即使跨网络部署, 逻辑仍然位于一个深模块中."*

### 4. 真正外部 (模拟)

不归你控制的第三方服务 (Stripe, Twilio 等). 深化后的模块把外部依赖作为注入端口接收; 测试提供模拟适配器.

## 接缝纪律

接缝的真假判定与内部/外部接缝的定义见 [SKILL.md](SKILL.md) 原则节, 本文件不重述. 深化场景的增量只有一条:

* **内部接缝不进接口.** 不要因为测试用到了内部接缝, 就把它暴露到接口中.

## 测试策略: 替换, 不叠加

* 深化后模块的接口处一旦有了测试, 旧的浅模块单元测试就成了浪费 - 删除.
* 在深化后模块的接口处写新测试. **接口就是测试表面**.
* 测试断言通过接口可观察到的结果, 不断言内部状态.
* 测试要能经受内部重构 - 它们描述行为, 不描述实现. 实现变了测试就得跟着变, 说明测试越过了接口.
