# 深化

在给定依赖下, 如何安全地深化一组浅模块. 词汇沿用 [SKILL.md](SKILL.md): **模块**, **接口**, **接缝**, **适配器**.

## 依赖类别

评估深化候选时, 对它的依赖分类, 决定深化后的模块如何组织接缝. 测试依赖的选择遵守 [验证契约的共用底线](../verification-contract/SKILL.md#共用底线), 避免深化后只验证替身而漏掉真实协作.

### 1. 进程内

纯计算, 内存状态, 无 I/O. 始终可深化 - 合并这些模块, 直接通过新接口测试, 不需要适配器.

### 2. 本地依赖

本地依赖与模块一起运行, 测试沿用项目真实依赖实现, 存储条件按验证契约准备. 接缝可留在内部, 无需为了测试增加模块的外部接口.

### 3. 远程但自有 (端口与适配器)

自己拥有但跨网络部署的服务 (微服务, 内部 API). 在接缝处定义一个 **端口** (接口). 深模块拥有逻辑; 传输作为 **适配器** 注入. 测试通过真实传输实现连接隔离环境中的真实服务, 覆盖跨服务协作.

### 4. 真正外部 (模拟)

不归你控制的第三方服务. 深化后的模块把外部依赖作为注入端口接收; 是否使用模拟适配器及结论范围按验证契约判定.

## 接缝纪律

接缝的真假判定与内部/外部接缝的定义见 [SKILL.md](SKILL.md) 原则节, 本文件不重述. 深化场景的增量只有一条:

* **内部接缝不进接口.** 不要因为测试用到了内部接缝, 就把它暴露到接口中.

## 测试策略: 替换, 不叠加

* 深化后模块的接口处一旦有了测试, 旧的浅模块单元测试就成了浪费 - 删除.
* 在深化后模块的接口处写新测试. **接口就是测试表面**.
* 测试断言通过接口可观察到的结果, 不断言内部状态.
* 测试要能经受内部重构 - 它们描述行为, 不描述实现. 实现变了测试就得跟着变, 说明测试越过了接口.
