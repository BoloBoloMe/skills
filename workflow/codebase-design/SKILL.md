# 代码库设计

设计 **深模块**: 大量行为隐藏在小接口背后, 位于清晰的接缝, 可通过该接口测试. 任何设计或重构代码的地方, 都使用这套语言和原则. 目标: 对调用者的杠杆, 对维护者的局部性, 对所有人的可测试性.

## 术语表

务必使用这些术语 - 不要用 组件/服务/API/边界 等词代替, 语言一致性至关重要. 各词条括注的英文仅供对照, 行文一律用中文.

**模块** (module) - 任何包含接口和实现的实体. 刻意保持规模无关: 可以是函数, 类, 包, 跨层切片. _避免_: 单元, 组件, 服务.

**接口** (interface) - 调用者正确使用模块所需了解的一切: 类型签名, 不变量, 顺序约束, 错误模式, 必需配置, 性能特征. _避免_: API, 签名 (过窄 - 仅指类型层面).

**实现** (implementation) - 模块内部的代码主体. 与 **适配器** 不同: 同一事物可以实现很大而适配器很小 (如 Postgres 仓库), 也可以实现很小而适配器很大 (如内存 fake). 讨论重点是接缝处的替换角色时, 用 **适配器**; 否则用 **实现**.

**深度** (depth) - 接口的杠杆效应: 调用者或测试者每学习一单位接口, 所能触发的行为量. 大量行为隐藏在较小接口背后, 模块是 **深模块**; 接口复杂度几乎与实现相当, 模块是 **浅模块**.

**接缝** (seam, 出自 Michael Feathers) - 无需直接编辑代码即可改变行为的地方; 模块接口所在的位置. 接缝位置本身就是一个设计决策, 与它背后的内容无关. _避免_: 边界 (与领域驱动设计的限界上下文冲突).

**适配器** (adapter) - 在接缝处满足接口的具体事物. 它描述 *角色* (它填补的空缺), 而非实质 (它内部的东西).

**杠杆** (leverage) - 调用者从深度获得的收益: 每单位接口换来的行为更多. 一个实现即可在 N 个调用点和 M 个测试中产生效益.

**局部性** (locality) - 维护者从深度获得的收益: 变更, bug, 知识, 验证集中在一处, 而非散布在调用者中. 一次修复, 处处有效.

## 深模块与浅模块

**深模块** = 小接口 + 大量实现:

```
+-----------------------+
|        小接口         |  <- 少量方法, 简单参数
+-----------------------+
|                       |
|        深实现         |  <- 复杂逻辑藏在内部
|                       |
+-----------------------+
```

**浅模块** = 大接口 + 少量实现 (避免):

```
+-----------------------------------+
|              大接口               |  <- 许多方法, 复杂参数
+-----------------------------------+
|              薄实现               |  <- 只是透传
+-----------------------------------+
```

设计接口时, 问自己:

- 我能减少方法数量吗?
- 我能简化参数吗?
- 我能把更多复杂性藏在内部吗?

## 原则

- **深度是接口的属性, 不是实现的属性.** 深模块内部可以由小的, 可模拟的, 可替换的部分组成 - 这些部分不属于接口. 一个模块可以有 **内部接缝** (由实现私有, 供其自己的测试使用), 以及位于其接口处的 **外部接缝**.
- **删除测试.** 想象把模块整个删掉: 复杂度随之消失, 它是透传层; 复杂度在 N 个调用者中重现, 它有价值.
- **接口是测试表面.** 调用者和测试者经过同一道接缝. 想测试接口之外的内容, 模块结构可能就不合适.
- **一个适配器意味着假想的接缝, 两个适配器意味着真实的接缝.** 除非接缝两侧确实存在差异, 否则不要引入接缝.

## 为可测试性而设计

好的接口让测试变得自然而然:

1. **接受依赖, 不创建依赖.**

   ```typescript
   // 可测试
   function processOrder(order, paymentGateway) {}

   // 难测试
   function processOrder(order) {
     const gateway = new StripeGateway();
   }
   ```

2. **返回结果, 不产生副作用.**

   ```typescript
   // 可测试
   function calculateDiscount(cart): Discount {}

   // 难测试
   function applyDiscount(cart): void {
     cart.total -= discount;
   }
   ```

3. **表面积小.** 方法少 = 要写的测试也少. 参数少 = 测试准备更简单.

## 关系

- 一个 **模块** 有恰好一个 **接口** (它向调用者和测试呈现的界面).
- **深度** 是 **模块** 的属性, 以其 **接口** 衡量.
- **接缝** 是 **模块** 的 **接口** 所在的位置.
- 一个 **适配器** 位于 **接缝**, 满足 **接口**.
- **深度** 为调用者产生 **杠杆**, 为维护者产生 **局部性**.

## 被拒绝的表述

- **深度 = 实现行数与接口行数之比** (Ousterhout): 奖励实现堆行数. 我们采用 "深度即杠杆".
- **"接口" 等同 `interface` 关键字或类的公共方法**: 太窄 - 这里的接口包含调用者必须知道的所有事实.
- **"边界"**: 与领域驱动设计的限界上下文重复. 说 **接缝** 或 **接口**.
