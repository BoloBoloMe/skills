# 决策盘问

本 skill 是方法 skill; 完成标准见 [verification-contract](../verification-contract/SKILL.md).

开始前, 调用 `domain-awareness` skill 感知当前工作目录的领域模型, 调用 `grilling` skill 盘问我.

1. **盘问.** 逐条敲定这次要决定的东西, 每问只问一个决定.
   完成标准: 待定的决定与各自选项已列成清单, 每项都有我的明确答复, 没有留给我事后确认的问题.
2. **落盘.** 我确认结束盘问后, 调用 `domain-modeling` 维护领域语言文件或 ADR; 调用 `decision-ledger` 完整记录会话中明确的事实和决策, 写完整内容与理由, 不写摘要. 落盘后核对完整性与自洽性.
   完成标准: 已确认的术语与决策都在对应文件里, 账本的维护自检逐条满足.
3. **反方攻击.** 账本落盘后, 派未参与盘问与落盘的独立子会话, 调用 `opposing-viewpoint` skill 攻击已确认决策. 给它原始需求的原文或可读取出处, 账本, 已核实的相关代码入口/调用方及依据. 反方找出关键前提或推理的薄弱处, 提出替代主张; 受影响却未入账的旧行为也是攻击面. 子会话继续追查相关代码; 查无旧入口时记录检索范围, 需求不可得或相关代码无法检查时报告缺口. 报告逐项给出论证与依据, 标明未证实之处.
   完成标准: 反方报告已交付, 每项都带论证与依据, 或已标明未证实.
4. **核实并收敛.** 逐项核实反方报告: 驳回项说明依据; 核实的旧行为按 `decision-ledger` 记录为有出处的事实; 需要新增或改变决策的交我裁决, 再按该 skill 更新账本并复查依赖记录. 报告不能直接成为决策.
   完成标准: 每项发现都已驳回并给出依据, 或已入账, 或已交我裁决; 有输入或裁决缺口时已向我说明并停在此步.
