为指定的代码变更生成一份丰富的交互式解释.

包含以下四个部分:

- **背景**: 解释与此变更相关的现有系统. (应广泛探索变更周围的代码.) 读者水平未知, 因此同时包含面向初学者的深度背景 (熟悉者可跳过), 以及直接关联变更的窄幅背景.
- **直觉**: 解释代码变更的核心直觉. 聚焦于本质, 而非完整细节. 使用具体示例和 toy data. 大量使用插图和图表.
- **代码**: 对代码变更做高层走读. 以易于理解的方式对变更分组/排序.
- **测验**: 出五道题, 测试读者对本次变更的理解. 难度中等: 需要真正理解变更实质才能答对, 但不出偏题怪题. 目标是帮助读者确认自己是否真正理解了. 以交互式多选形式呈现, 点击后告知对错并给出反馈.

格式要求:

- 输出单个自包含 HTML 文件, 内嵌 CSS 和 JavaScript. 整页为连续长页面, 含章节标题和目录. 顶层结构禁用 tab 切换. 建议添加基础响应式样式, 手机可读. 将文件放到代码仓库外的全局位置. 文件名始终以当天日期 `YYYY-MM-DD-` 开头, 便于按时间排序且不入版本控制. 例如: /tmp/2026-01-12-explanation-<slug>.html
- 以 Martin Kleppmann 的清晰度和流畅感写作, 引人入胜, 经典风格. 章节间过渡平滑自然.
- 图表建议: 选取少量图表族, 在整个解释中复用以说明各种场景. 常用图表类型:
  - 极度简化的应用 UI 示意图, 用于解释 UI 变更.
  - 系统图, 展示组件间数据流或通信. 务必包含示例数据!
- 禁用 ASCII 图. 始终使用简单 HTML 设计图表, 用 HTML 列表呈现清单.
  - 代码块始终使用 `<pre>` 标签. 若使用自定义样式 div 代替, CSS 中 **必须** 包含 `white-space: pre-wrap`, 否则浏览器会将所有换行压缩为单行. 保存文件前, 逐一扫描 HTML 源码中的代码块, 确认其 CSS 包含 `white-space: pre` 或 `pre-wrap`.
- 对关键概念/定义, 重要边界情况等使用 callout 标注.

HTML 文件生成完毕后, 调用 `access-web` skill 用浏览器窗口展示它, 我会在浏览器窗口中阅读和交互.
