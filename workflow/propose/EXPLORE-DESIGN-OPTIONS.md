# 方案发散

外部参考, 单一真相源. `propose` 在发散点读取并执行本文件, 基线由其盘问流程提供. 相对引用按本文件所在目录 (`workflow/propose/`) 解析.

## 输入

按决策类型条件化.

所有类型都需要:

- 已确认的问题, 受益者, 目标, 硬约束, 明确非目标, 已知事实.

产品方向额外需要:

- 相关领域约束, 既有产品行为.

技术方向/高影响专项额外需要:

- 相关 module/interface/机器契约/ADR/代码基线.

### 基线完成标准

每次发散前, 你必须确认基线已就绪:

- 产品方向: 问题/受益者/目标/硬约束/非目标已明确, 领域约束和既有产品行为已读取.
- 技术方向: 产品结果已确认, 相关代码/契约/ADR 已读取并定位权威来源.
- 高影响专项: 触发条件已验证, 相关技术基线已读取.

缺失时返回 `propose` 对应位置继续探索, 不开始候选生成.

## 评价标准

从输入提炼 3-6 个自适应评价标准, 区分硬门槛和优先级. 不做伪精确数字评分.

## 候选生成

你基线探索后生成自适应 1-5 个实质不同候选. 候选必须在产品行为/seam/架构/风险模型/交付路径中至少一项存在实质差异. 不强凑多方案.

候选生成前, 调用 `lazy-design` skill 跑决策阶梯, 消费其结果: 最早成立的方向作为候选基线. 不做/改描述/沿用现有行为若已完全满足需求, 可以只保留该一个方向. 更复杂方向必须说明更前阶梯为何不足.

每个候选写清: 核心思路, 不做什么, 收益, 代价, 关键风险, 可逆性.

完成标准: 候选数 1-5; 每个候选六要素齐全; 懒设计基线已纳入或已说明不适用.

## 子代理验证

每次发散必须先 `subagent({action:"list"})` 动态发现可用 agent. 默认至少两个独立 child session:

| 角色 | 职责 | context |
|---|---|---|
| 事实探索者 | 验证全部候选的前提和约束, 查代码/契约/依赖/平台能力 | fresh |
| 独立批评者 | 首轮只读问题/约束/标准, 独立发散; 再 resume 获取候选做对照批评 | fresh |

agent 名称动态选取 (优先 `scout`/`researcher`/`context-builder` 做事实探索, `reviewer`/`delegate` 做批评). 两个角色必须由独立 child session 承担. 子代理只读项目源文件, 产物只进 subagent 运行时临时目录, 不写仓库.

### 调用约束

首轮使用 top-level parallel tasks:

```typescript
subagent({
  tasks: [
    { agent: "<事实探索者>", task: "...只读验证全部候选. 禁止修改项目文件.", output: false, progress: false },
    { agent: "<独立批评者>", task: "...只读问题/约束/标准并独立发散. 禁止修改项目文件.", output: false, progress: false }
  ],
  context: "fresh",
  async: true
})
```

- 你无独立工作时调用 `wait()` 等待, 不结束 turn.
- 批评者第二轮通过 run id + child index `resume` 获取候选并做对照批评.
- 不写相对项目输出路径; 报告只留 subagent runtime artifacts.
- 保持 agent 动态发现, 不硬编码 agent 名称.

### 事实证据优先级

1. 本地机器可读契约/测试/代码/配置.
2. 当前有效 ADR/领域文档/Spec.
3. 官方文档和兼容性说明.
4. 非破坏性可复现命令/最小实验.
5. 第三方资料, 只能辅助, 不能单独证明关键可行性.

禁止破坏性验证和设计阶段原型写入. 若必须通过原型才能判定, 将候选标为 `有条件可行`, 把原型列为后续验证动作.

### 防锚定

批评者首轮不看候选, 只基于需求/约束/评价标准独立发散. 独立提出的方向只有满足同一硬约束和可比较门槛后, 才进入候选池. 再通过 resume 获取候选做对照批评.

### 冲突处理

两个子代理结论冲突时, 你先核对双方证据. 冲突不影响候选资格或推荐时, 显式保留分歧; 影响可行性/风险级别/最终推荐时, 增派专项探索者验证争议事实. 事实冲突优先服从代码/机器可读契约/官方文档/可复现验证, 不按票数决定.

### 批评者权限

独立批评者可挑战评价标准和问题框架: 指出遗漏标准/错误假设/冲突目标/伪硬约束, 或认为尚未达到可比较门槛. 不得篡改我已确认的目标/硬约束/非目标. 挑战若改变候选资格或推荐, 你暂停比较, 向我说明影响并一次问一个问题; 只影响局部措辞或不改变决策时, 你自行吸收.

### 失败恢复

子代理失败时:

1. 原 child resume 恢复, 最多 1 次.
2. 恢复失败则用替代 agent 重建, 最多 1 次.
3. 疑似全局故障先执行 `subagent({action:"doctor"})`, 避免无意义重试.
4. 仍失败 -> 你降级评估.

降级时保留已成功子代理的证据. 降级最多给可行懒设计基线 + 一个实质不同的最佳常规方案, 不强凑. 明示验证缺口, 我显式接受后才能继续.

### 验证完成标准

以下两条路径任一完整满足才可进入候选分级/展示.

正常路径:

- 两个独立 child role 已完成.
- 事实探索覆盖每个候选的关键前提.
- 批评者第二轮 resume 已完成.
- 影响候选资格/推荐的冲突已验证闭合.

降级路径:

- 恢复/替代次数已耗尽.
- 保留所有可用证据; 部分角色成功时如实表达其证据覆盖, 不虚构全覆盖.
- 明确失败角色和缺失证据.
- 候选遵守已确认的降级上限: 最多可行懒设计基线 + 一个实质不同最佳常规方案, 不强凑.
- 验证缺口已向我说明且我显式接受.

降级路径不要求失败角色或第二轮 resume 完成.

## 候选分级与收敛

将候选标为: `可行` / `有条件可行` / `不可行` / `证据不足`.

- 只比较前两类, 简述淘汰依据.
- `有条件可行` 必须写清成立条件/验证方式/条件失败后的影响.
- `证据不足` 且影响推荐时增派专项探索者, 不直接淘汰.
- 明显违反硬约束的方向不进入候选, 只简述淘汰原因.

分级后收敛为最终 1-4 个有效候选再展示. 若可行候选超过 4, 按评价标准合并局部变体或淘汰低价值项并简述依据, 不任意截断.

## 我独有事实

候选排序依赖只有我知道的业务事实 (数据规模/操作频率/合规要求/偏好等) 时, 暂停发散, 按 `grilling` 规则一次问一个会改变候选资格或推荐的问题. 得到回答后重新综合; 不影响排序的未知保留为条件.

## 展示

使用 `adaptive-presentation` 自动选择 chat/Markdown 表格/HTML. 采用"结论优先, 异常展开":

- 先给 1 句推荐结论.
- 每个有效候选展示: 核心思路/可行性/最大收益/最大代价.
- 仅展开: `有条件可行`的成立条件, 子代理实质分歧, 高风险证据, 被淘汰方向的关键原因.
- 普通一致结论只标明"双评估一致", 不罗列过程.
- 给出最重要的推荐反转条件.
- 原始报告不主动展示, 我要求时再展开.

## 选择循环

我可执行:

- 选择一个方向.
- 要求对某个候选补充事实探索.
- 修改评价标准或优先级后重新比较.
- 指出两个候选可合并, 由你验证合并后是否仍是独立可行方案.
- 拒绝全部候选, 说明缺失方向后重新发散.

只有我明确选择或取消发散时才返回. 补证/重比/合并/拒绝都不算选择.

## 条件性重开

选定方向后, 出现以下情况时暂停细化并建议重新发散:

- 硬约束违反.
- 核心假设失效.
- 成本或风险级别显著变化.
- 出现明显更优方向.

普通可逆局部细节不触发重开. 重开时保留原选择及失效原因, 避免后续再次提出已被证伪的方案.

## 返回

明确选择时返回:

- 选中方向及关键理由.
- 适用约束和关键假设.
- 主要拒绝方向及拒绝原因.
- 子代理验证是否完整.
- 推荐反转/条件性重开触发项.

取消发散时返回:

- 取消原因.
- 未决问题.
- 建议恢复到 `propose` 的位置.

不伪造选中方向.
