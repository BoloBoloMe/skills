# 决策账本

`DECISIONS.md` 是功能级决策与事实账本, 也是决策到代码的追踪索引. 它不规定实现方案, 只记录我确认过的决策和事实, 以及代码最终如何承载这些决策.
文档只供 AI 使用. 新增, 替代, 废弃或改变约束性前, 必须在会话中向我说明决定含义, 影响和推荐, 再取得确认. 不让我阅读账本后批准.

位置: `<产物根目录>/DECISIONS.md`. 产物根目录默认 `docs/changes/<feature-slug>/`; 调用方可指定其他根目录.

## 不变量

每次维护账本都必须满足这些不变量:

- 中文组织.
- 决策 ID 从 `D001` 起, 事实 ID 从 `F001` 起, 各自在本账本作用域 (账本所在目录) 内连续编号, 分命名空间.
- 语义变化新建 ID, 不覆盖旧条目.
- 状态可辨认: 决策 (当前有效/已替代/已废弃), 事实 (当前有效/已变更).
- 约束性可辨认 (仅决策): 必须遵守, 可调整. 事实无约束性.
- issue 与决策双向引用.
- 代码追踪区分: 预计影响, 实际影响, 需要调整.
- 改变决策内容, 状态或约束性前, 必须得到我确认.

完成标准: 保存前逐条检查上述不变量. 任一不满足, 继续修账本, 不把维护动作视为完成.

## 记录决策

将盘问中形成的决策树, 以同等清晰度记录到 DECISIONS.md 中.
确保没有漏记任何关键信息, 否则后面的会话会丢失这个决策信息.
不写: 临时讨论, 不影响代码且容易逆转的偏好, 单纯措辞选择.

记录步骤:
1. 找到下一个连续 ID.
2. 尽可能详细地写清决策内容和理由.
3. 写依赖的事实 (如有); 无则省略.
4. 标明状态和约束性.
5. 写预计影响; 不确定时写 `待探索`, 不编造代码位置.
6. 写相关 issue; issue 尚未创建时写 `待关联`.

完成标准: 新决策有 ID, 状态, 约束性, 决策内容, 理由, 依赖事实 (如有), 预计影响, 相关 issue 占位或引用.

## 事实

当盘问中确认了会影响代码, 测试, 边界或后续追溯, 但属事实非取舍的信息时, 记录到账本.

写入:

- 环境/技术事实: 现有版本, 能力限制, 已有约束.
- 外部约束: 第三方限制, 协议, 兼容性.
- 领域事实: 状态空间, 业务规则, 不变量.
- 现状事实: legacy 行为, 现有数据形态.

不写:

- 显然事实 (无影响, 众人皆知).
- 易漂移细节 (行号, 临时变量名).

每条事实:

- `F001` 起连续编号, 与决策分命名空间.
- 来源: 可查事实附命令/文件/URL; 业务事实标 `用户陈述`.
- 状态: 当前有效 / 已变更.

事实无约束性. 事实被推翻时新建 F-ID, 旧条目标已变更并附新 ID, 不覆盖; grep 旧 F-ID 找依赖决策, 标待复核.

完成标准: 新事实有 ID, 来源, 状态, 内容.

## 变更决策

语义变化必须保留历史:

1. 新建下一个连续 ID.
2. 新决策写明替代了哪些旧决策.
3. 旧决策标为已替代, 并写明替代者.
4. 如果旧决策已有实际影响, 新决策列出需要调整的代码.

只有文字澄清, 错别字或格式整理可以原地修改.
完成标准: 新旧决策互相可追溯; 旧决策没有被覆盖到失去历史; 已实现旧决策的代码有 `需要调整` 记录; 引用旧决策的下游产物已同步或标记待修订 (见下游同步).

## 标记废弃

当决策不再适用, 且不是被新决策替代时, 标为已废弃.
完成标准: 废弃原因可见; 若已有实际影响, 相关代码进入 `需要调整` 或说明无需调整的事实依据; 引用该决策的下游产物已同步或标记待修订 (见下游同步).

## 下游同步

决策被替代, 废弃或改变约束性后, 检查所有引用该决策的下游产物, 更新受影响内容, 或标记待修订及原因. 只同步引用侧, 不借同步新增决策内容.
完成标准: 每条被变更决策的引用方均已检查; 受影响处已更新或标记待修订及原因; 无悬空引用.
