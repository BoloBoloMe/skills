# 决策账本

`DECISIONS.md` 是功能级决策账本, 也是决策到代码的追踪索引. 它不规定实现方案, 只记录我确认过的决策, 以及代码最终如何承载这些决策.

文档只供 AI 使用. 新增, 替代, 废弃或改变约束性前, 必须在会话中向我说明决定含义, 影响和推荐, 再取得确认. 不让我阅读账本后批准.

位置:

```text
docs/changes/<feature-slug>/DECISIONS.md
```

## 不变量

每次维护账本都必须满足这些不变量:

- 中文组织.
- 每条决策有稳定 ID, 全 feature 连续编号, 从 `D001` 起.
- 语义变化新建 ID, 不覆盖旧决策.
- 状态可辨认: 当前有效, 已替代, 已废弃.
- 约束性可辨认: 必须遵守, 可调整.
- issue 与决策双向引用.
- 代码追踪区分: 预计影响, 实际影响, 需要调整.
- 改变决策内容, 状态或约束性前, 必须得到我确认.

完成标准: 保存前逐条检查上述不变量. 任一不满足, 继续修账本, 不把维护动作视为完成.

## 记录决策

当盘问中形成会影响代码, 测试, 外部行为, 边界或后续追溯的决策时, 记录到账本.

写入:

- 产品行为取舍.
- API, schema, 状态机, 数据模型.
- 模块责任分配, seam 位置, deep module interface.
- 禁止范围和明确不做.
- 有约束意义的测试策略.
- 我明确要求以后记住的决策.

不写:

- 临时讨论.
- 不影响代码且容易逆转的偏好.
- 单纯措辞选择.
- worker 可自行决定的内部实现细节.
- 没有替代方案的显然事实.

记录步骤:

1. 找到下一个连续 ID.
2. 写清决策内容和理由.
3. 标明状态和约束性.
4. 写预计影响; 不确定时写 `待探索`, 不编造代码位置.
5. 写相关 issue; issue 尚未创建时写 `待关联`.

完成标准: 新决策有 ID, 状态, 约束性, 决策内容, 理由, 预计影响, 相关 issue 占位或引用.

## 变更决策

语义变化必须保留历史:

1. 新建下一个连续 ID.
2. 新决策写明替代了哪些旧决策.
3. 旧决策标为已替代, 并写明替代者.
4. 如果旧决策已有实际影响, 新决策列出需要调整的代码.

只有文字澄清, 错别字或格式整理可以原地修改.

完成标准: 新旧决策互相可追溯; 旧决策没有被覆盖到失去历史; 已实现旧决策的代码有 `需要调整` 记录.

## 标记废弃

当决策不再适用, 且不是被新决策替代时, 标为已废弃.

完成标准: 废弃原因可见; 若已有实际影响, 相关代码进入 `需要调整` 或说明无需调整的事实依据.

## 约束性

`必须遵守`: worker 不可自行改变. 实现发现不合适时必须停止上报, 等我确认新决策.

`可调整`: worker 可在不改变产品, API, 边界的前提下采用更好代码方案, 但必须在 handoff note 说明偏离原因.

默认:

- 产品行为, API/schema, 状态机, 跨模块边界 -> 必须遵守.
- 内部算法, 局部封装, 测试组织 -> 按风险选择.

完成标准: 每条当前有效决策都能看出 worker 是否可调整它.

## 双向引用

issue 中引用相关决策 ID; 决策中引用相关 issue.

如果只缺一侧引用, 可以直接补齐. 这是索引修复, 不需要问我.

完成标准: 从 issue 能找到相关决策; 从决策能找到相关 issue. 单向缺失已补齐或记录阻塞原因.

## 实现追踪

AFK 后, 父会话基于真实 diff 更新 `实际影响`. 可写:

- 文件和关键符号.
- 覆盖该决策的测试.
- 实现它的 issue/attempt.
- 审过它的 reviewer 报告.

不写易漂移行号, 除非短期定位确实需要.

完成标准: 实际影响只来自真实 diff, 命令输出或 reviewer 报告; 没有把推测写成事实.

## 职责

- `deliberate`: 在会话中解释并确认决策, 再维护决策内容. 新增, 替代, 废弃前必须得到我确认.
- `to-product-spec`: 只整理已确认产品决策, 不新增决策.
- `to-technical-spec`: 引用和摘要执行必须知道的技术决策, 不复制完整决策树.
- `to-execution-spec`: 在 issue 中引用相关决策 ID, 并维护双向引用.
- worker: 只读账本. 决策不可实现, 成本异常或需要改变时, 在 handoff note 上报.
- reviewer: 只读账本. 报告 diff 违反决策或实际改变决策.
- AFK 父会话: 基于真实 diff 更新实际影响; 不擅自改变决策内容, 状态或约束性.

完成标准: 维护者只做自己职责内的写入; 超出职责的变更已停止并向我确认.
