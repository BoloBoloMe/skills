# 材料与证据类型

verify-change 执行验证方案时的证据复核规则, 由本 skill 的执行方式抵达; 派工时连同回传材料一起交给验证者. 逐场景与审计规则的核对方式见 [SCENARIO-CHECK](SCENARIO-CHECK.md).

先定类型, 再下结论:

- 当前观察: 本轮命令或操作的输出. 记命令, 原始输出与时间.
- 引用的旧观察: 旧轮次或提交的观察. 仅在覆盖与代码, 依赖, 配置, 环境条件仍适用时采用. 记原检查时间, 提交版本, 可复核位置与适用条件. 判断不了有效性就不采用.
- 推断: 只读代码或文档得出. 标为推断, 记位置与推理依据, 结论为未验证.
- 未运行: 记所缺权限, 依赖或环境, 结论为未验证.

作者在实现或修复期间的日志, 截图与自测说明都属旧观察; 关键真实路径的结论只取验证者本轮实跑记录.

逐项核对适用性, 不因机器或路径相同就当条件没变. 检查执行路径, 依赖版本, 配置与依赖服务. 只改不参与构建与运行的说明时, 注明它不影响适用范围. 条件未变的旧观察可直接引用, 不重跑; 条件变化则按影响重跑, 不沿用失效证据或把旧结论当永久保证. 缺少重跑所需服务时, 标受阻并写明缺口. 不将旧观察抄成新观察冒充本轮实跑.

只有摘要而无可读原件时, 要求实际验证者补交脱敏原件. 可用会话记录, 工具记录或适合结果的原始材料. 摘要不算充分证据, 你不亲自补跑.

同目标版本, 同请求的摘要与原生记录冲突时, 拒绝所报通过. 说明原件不支撑结论, 报告差异并交回验证者核实. 只核对路径存在不算复核.

原件可为会话记录, 命令输出, 截图或文件状态. 按结果类型保留, 不强求统一格式, 不写明文密钥.

验证者可共享本轮原件, 不转移判断. 交出方标产生者的会话标识与时间, 目标版本和可复核位置. 接收方核对范围, 实例, 版本与环境适用性, 再独立判定自己的标准, 不照抄通过结论. 重叠检查不必重复昂贵操作.

完成标准: 每项材料都有类型与引用信息, 共享原件标了产生者, 版本与位置; 接收方在材料上留了适用性核对记录; 摘要与原件冲突的项不判通过.
