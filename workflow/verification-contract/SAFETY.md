# 安全底线

所有 skill 共用的安全要求, 只在此处维护. 其他 skill 用指针抵达, 不复述.

## 环境

- 不使用生产环境, 生产服务或真实客户数据.
- 需要实例而缺少时先搭建; 搭不起来就报告未验证, 不用自建服务桩或替身改判通过.
- 涉及费用, 共享资源或不可逆操作, 先获我批准.

## 原始数据

- 实跑产生的原始数据优先放仓库外, 默认保留, 不自动清理或过期; 停止实例也要保留数据.
- 复跑优先隔离. 必须清理旧数据时先保留可查看的副本; 留不了就停下问我.
- 其他删除须经我批准. 截图或日志不能替代原始数据.

## 写入与授权

- 默认只读. 需要写文件, 建实例, 占端口或改配置时, 先说明资源, 对象, 操作, 数据保留位置与访问方式, 交我批准.
- 批准绑定具体资源, 对象, 操作与保留范围. 同范围复跑直接执行并可复查; 换任一范围先停下请求新批准.
- 项目信任, 容器免审批或脚本自称会自动清理, 都不授予写入权限.
- 逐次记录写入对象, 命令, 时间, 结果和可查看的数据位置.

## 删除与不可逆操作

- Git worktree 删除走 `git worktree remove`, 清理走 prune; dirty (含 untracked) 时停下询问.
- 禁止 `--force` 与 `-D` 硬删: 它们会绕过「有未提交改动就失败」这道保险.
- 删除 main worktree 等于删除整个仓库, 一律先确认.

## 脱敏

- 展示命令, 输出和捕获的工件前先脱敏: 凭据, 令牌, 个人信息原地写 `<REDACTED>`.
- 循环尽量基于环境变量构建, 让凭据留在环境里.
- 脱敏后不足以判断时明说并问我, 不猜.

## 无人值守 (AFK) 红线

以 AFK 模式运行时, 以下事项即使能自决也不自行决定, 遇到即停下并在汇总中标记阻塞:

- 破坏性操作 (删除或覆盖数据).
- 超出当前 issue 范围的需求变更.
- 需要外部资源或权限.
