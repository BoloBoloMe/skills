# 验证契约

先按交付结果选一类, 再决定如何验证, 不从"要写多少测试"倒推任务. 改变 agent 实际操作的 skill/提示词/规范按改变的行为归类, 不按文件后缀归类. 修复已知故障选缺陷修复, 承诺提升指标选性能改进; 两者重叠时按本次承诺的主要结果选, 另一侧仍交证据. 其余按外部可观察行为 (含调用方接口) 是否改变归类, 配置/依赖改动同理. 五类无高低顺序, 不能归类就报告缺口.
一个切片可能兼有两类结果: 主类组织验证, 附带结果也须按所属类取证; 只有可独立交付才拆 issue. 纯核验任务不套改动契约, 按 `to-execution` 的纯核验模板写验证入口, 通过标准和证据.

## 共用底线

- **实跑真东西.** 只在隔离测试环境运行真实成品和安全可用的真实服务; 没有环境就搭建, 搭不起来就报告未验证. **绝不在生产环境测试**, 不调用生产服务或使用真实客户数据. 外部第三方无法安全调用时可在系统边界使用受控替代, 但须标出哪些结果尚未得到真实验证; 关键依赖无法验证就不报通过. 可安全保留数据的本地环境可直接搭建; 涉及费用, 共享资源或不可逆操作先获我批准. 静态文档检查不必启动实例.
- **用例来自已确认要求.** 新功能的产品用例取自 PRODUCT.md 已确认的 Gherkin 场景 (格式见 [GHERKIN.md](../to-spec/GHERKIN.md)); 没有 Gherkin 时用已确认的其他文字要求. 另核对已确认的技术/审计要求及受影响的旧行为; 连要求都无法确认时先澄清. 实跑足以取证就不为每条场景补自动化测试; 确需长期重复检查或锁住复杂行为时才写最少的测试, 在公开接缝调用真实测试服务, 不 mock 内部协作者. 已有测试照常运行, 不因此删改; 新用例不能靠猜测补正常/边界/异常分支. 测试通过不等于真实入口已生效.
- **数据也是证据.** 优先把实跑数据放仓库外, 记录可查看的位置, 版本, 操作和占用, 默认不主动清理, 也不设自动过期. 实例可以停止, 但数据不能随之消失. 复跑优先隔离; 无法隔离时先保存可查看的原数据副本, 再清理旧数据. 副本无法保留就停下问我; 其他删除也须我明确要求或批准. 截图/日志不能替代唯一的原数据.

## 行为变更

- 适用情况: 新增或改变外部可观察行为.
- 做法: 在测试环境从真实入口逐项实跑已确认的产品用例, 另核对受影响的旧行为和已确认的技术要求. 只有确需自动化锁住的行为才调用 `tdd` skill; 不用单元测试代替成品实跑.
- 完成证据: 测试环境及数据位置, 输入与入口操作, 所依据的要求, 预期与实际结果 (脱敏输出或截图). 写了测试也须交真实入口的结果.

## 结构变更

- 适用情况: 对外行为不变, 只改结构, 位置, 命名或类型.
- 做法: 改前确定受影响的公开接缝和旧行为, 先运行已有行为检查; 缺少时在接缝处补最少的行为测试. 确认改前通过后才重构, 改后用原用例, 输入和条件复跑, 不因内部结构改变而改测试. 无法观察或运行检查就停下报告缺口; 类型检查/lint 不能单独证明行为未变.
- 完成证据: 接缝与检查路径, 改前版本, 相同输入/条件及前后结果. 同时改变行为时交附带验证或改选主类.

## 缺陷修复

- 适用情况: 消除已知失败现象.
- 做法: 调用 `diagnosing-bugs` skill, 修复前用能抓住原症状的检查证实失败, 修复后用同一检查及原始场景证实消失. 只有正确接缝存在时才把最小复现留成回归测试; 否则保留可复跑命令/脚本并记录接缝缺口, 避免留下抓不住故障的测试.
- 完成证据: 修复前后的检查命令与脱敏结果, 原始场景复跑结果, 留下的回归检查或可复跑步骤及接缝缺口; 有复现提交时注明它先于修复提交.

## 性能改进

- 适用情况: 改善可测的性能指标.
- 做法: 先量基线再改, 在可比条件下复测; 调用 `benchmark-checklist` skill 核对公平性和结论边界.
- 完成证据: 前后数字, 运行条件, 测量方法, 原始输出和清单核查结论.

## 非行为改动

- 适用情况: 注释, 文档或不改变外部行为的配置, 接线和依赖维护.
- 做法: 选与改动直接相关的检查, 不为凑数量写测试.
- 完成证据: 如引用/渲染检查, 构建, lint 或相关入口的结果; 无适用检查则写明核对内容及原因, 不声称未运行的检查已通过.

## 交付边界

拆 issue 时在 `验证契约` 写主类与附带验证, `验证入口` 写预定操作和通过标准; 执行后在 `交付证据` 写实际结果与可复查材料. 无 issue 时也按所属类留证. 分类有误交拆分方修正后再执行. 本契约只用于执行者自证和评审核对, 最终独立验收仍由 `verify-change` 按已确认的 PRODUCT.md 复核.
