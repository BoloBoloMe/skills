# 系统化调试

## 适用时机

遇到测试失败、构建失败、异常行为、性能问题、集成问题或修复多次无效时使用。

## 输入契约

- HILP execution handoff asset_ref。
- 失败命令、完整输出、复现步骤。
- 最近变更范围。
- 禁止越界项和 HILP 回退条件。

## 执行规则

铁律：未完成根因调查前不得提出修复。

四阶段：
1. 根因调查：完整阅读错误、稳定复现、检查最近变化；多组件系统记录边界输入、输出、环境和配置传播。
2. 模式分析：找同仓库工作示例，对比参考实现，列出差异和依赖。
3. 单假设验证：一次一个假设，用最小诊断或最小改动验证，不堆叠猜测。
4. 实现修复：先写失败测试或复现检查，再修根因，最后验证回归。

多组件边界诊断示例，只采集证据，不执行危险修复：

```bash
echo "=== workflow layer ==="
echo "CONFIG_SET=${CONFIG_VALUE:+yes}"

echo "=== script layer ==="
env | grep '^CONFIG_' || echo "no CONFIG variables visible"

echo "=== external command layer ==="
printf 'command=%s input=%s cwd=%s\n' "validator" "<redacted>" "$PWD"
# 下一步只根据三层输出判断配置在哪一层丢失。
```

单假设验证示例：

```bash
# 假设：失败只由 CONFIG_VALUE 未传入脚本造成。
CONFIG_VALUE=known-value ./run-one-check.sh
# 若仍失败，丢弃该假设；不要同时改路径、依赖和配置。
```

第二次同类失败时停止当前调试，转入 failure forensics，取证后回到 HILP 变更重审。

## failure forensics 转入条件

出现任一条件即停止系统化调试，转入 failure forensics；failure forensics 只取证、分类和回退，不继续修复：

- 第二次同类失败：同一命令、同一验证点、同一接口边界或同一根因假设在修复后再次失败。
- 继续定位或修复需要修改当前 execution_unit 的 `allowed_files` 之外文件。
- 修复会改变接口、数据形状、验证口径、发布顺序或禁止越界项。
- 新事实推翻已批准设计、已批准蓝图或有效执行交接。
- 执行者需要在 HILE 执行阶段补做 HILP 蓝图判断。

红旗：快速修一下、先试试、我猜是、多个改动一起上、错误没看完、测试以后补、修复会改变接口却继续做。

常见借口表：

| 借口 | 处理 |
|---|---|
| 问题很简单 | 简单问题也要证据定位根因。 |
| 时间紧 | 系统化比猜测返工更快。 |
| 先试一个修复 | 未完成根因调查前不得修复。 |
| 修复明显 | 明显的是症状，不一定是源头。 |

## 禁止事项

- 不得未查根因就修复。
- 不得一次堆叠多个猜测性改动。
- 不得把症状修补当作根因修复。
- 不得用调试扩大执行范围。
- 不得在修复改变蓝图、接口、数据形状、验证口径或执行范围时继续执行。
- 不得在触发 failure forensics 转入条件后继续修复。

## 输出契约

输出根因证据、模式对比、已验证假设、修复内容、验证命令与输出摘要。若触发 HILP 回退或 failure forensics，输出触发项、受影响资产、停止位置和需写入 Failure Note 的证据摘要。

## 检查清单

- [ ] 根因调查已完成。
- [ ] 复现步骤清楚。
- [ ] 假设逐一验证。
- [ ] 修复有测试或复现检查。
- [ ] 未改变 HILP 批准边界。
