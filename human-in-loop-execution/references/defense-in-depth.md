# 防御式验证

## 适用时机

根因来自无效输入、跨层数据传递、环境误用、危险文件操作或单点验证容易被绕过时使用。

## 输入契约

- HILP execution handoff asset_ref。
- 已确认根因和数据流。
- 可验证的边界层列表。
- 禁止越界项。

## 执行规则

四层验证模型：
1. 入口边界：拒绝明显无效输入、缺失路径、空值、非法状态。
2. 业务逻辑：验证操作前提、状态机、权限、依赖已经满足。
3. 危险环境守卫：在测试、CI、生产、文件系统或外部命令前阻止危险上下文。
4. 诊断记录：记录输入、输出、环境和调用信息，便于复盘。

每层要求测试或命令证据。单点验证可以保留，但不能作为唯一防线。

## 禁止事项

- 不得只在一个容易被绕过的位置验证。
- 不得把防御式验证当作新功能入口。
- 不得添加与 HILP 蓝图不一致的接口或数据形状。
- 不得用宽泛捕获隐藏错误。

## 输出契约

输出数据流、入口边界、业务逻辑、环境守卫、诊断记录、每层失败行为、测试或命令证据和剩余风险。若需要新增蓝图未列接口，停止并回到 HILP 重审。

## 检查清单

- [ ] 数据流已列出。
- [ ] 入口边界有验证。
- [ ] 业务逻辑有验证。
- [ ] 环境守卫已设置。
- [ ] 每层有验证证据。
