# 技能编写

## 适用时机

创建、修改或验证本仓库技能时使用；普通业务开发不得用它替代 HILP 方案设计。

## 输入契约

- HILP execution handoff asset_ref。
- 技能目标与适用场景。
- 至少一个失败压力场景或可复现的误用场景。
- 禁止越界项、安装边界和文件范围。

## 执行规则

核心原则：技能编写是文档 TDD。

铁律：没有失败压力场景，不写或修改技能；“文档小改”也不能跳过压力场景。

RED：运行无技能或旧技能基线，记录失败行为和 rationalization。GREEN：写最小技能内容，只解决已观察失败。REFACTOR：发现新漏洞后补规则并复测，保持既有通过场景。

CSO / 搜索优化规则：

- `description` 只写触发条件，不写完整流程摘要，避免 agent 只读摘要就绕过正文流程。
- 使用具体触发症状、关键词、错误信号和场景词，例如 flaky、越界、未验证完成、压力场景、审查阻断。
- 避免用 description 替代正文流程；正文必须保留强制门、红旗、输出契约和检查清单。
- 引用其他技能时使用技能名和 required marker，不使用会强制加载大型引用的路径写法。

技能测试类型：

| 类型 | 测试方式 | 成功标准 |
|---|---|---|
| 纪律型 | 压力场景、反借口、红旗 | agent 在赶时间、沉没成本、权威压力下仍遵守规则。 |
| 技术型 | 应用场景、边界场景、缺信息场景 | agent 能把技术方法用于新问题并在信息不足时停止提问。 |
| 参考型 | 检索场景、应用场景、缺口测试 | agent 能找到正确段落并按引用内容执行。 |
| pattern 型 | 识别场景、应用场景、反例场景 | agent 知道何时使用、何时不用该模式。 |

压力测试流程：RED 基线失败，GREEN 最小规则让场景通过，REFACTOR 补漏洞并复测。每次复测都记录触发语、agent 旧行为、新规则和验证证据。

反理性化模板：

| 常见借口 | 必须反制 |
|---|---|
| 只是文档小改 | 仍要压力场景；小改也会改变 agent 行为。 |
| 规则显然清楚 | 清楚给作者不等于清楚给未来 agent。 |
| 先写后测更快 | 没有 RED 就不知道技能解决了什么失败。 |
| 只是摘要 | 摘要不能替代触发、停止和输出门。 |

红旗清单：无压力场景、description 写流程摘要、缺少 HILP execution handoff asset_ref、缺少禁止越界项、没有安装边界、把业务审批流程写入执行技能。

文件组织规则：主 `SKILL.md` 放入口、触发、核心纪律和输出；supporting reference 放重型参考；prompt template 只放派发或审查模板。不要复制上游贡献流程、插件、hooks、commands 或测试工程。

部署前 checklist：frontmatter、description、压力场景、验证证据、禁止越界项、安装边界、HILP 回退条件全部明确。

## 禁止事项

- 不得无压力场景直接写技能。
- 不得把业务需求审批流程写入执行技能。
- 不得创建蓝图未批准的新技能入口。
- 不得复制上游插件、hooks、commands、测试工程或贡献流程。
- 不得用元技能替代 HILP 方案审批。

## 输出契约

输出技能文件路径、触发场景、RED/GREEN/REFACTOR 证据、压力场景、验证方式、安装边界、禁止越界项检查结果。若修改会影响规划审批或执行范围，停止并回到 HILP 变更重审。

## 检查清单

- [ ] 这是元技能场景。
- [ ] 已有失败压力场景和验证证据。
- [ ] description 只描述触发条件。
- [ ] frontmatter、部署前 checklist 和安装边界完整。
- [ ] 不替代 HILP 方案审批。
