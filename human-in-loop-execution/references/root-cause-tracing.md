# 根因追踪

## 适用时机

错误出现在深层调用栈、坏值来源不明、文件写入位置错误、状态污染或多层系统边界传递异常时使用。

## 输入契约

- HILP execution handoff asset_ref。
- 症状、错误输出和调用栈。
- 可添加诊断的位置。
- 禁止越界项。

## 执行规则

追踪链固定为：症状点 -> 直接失败点 -> 调用者 -> 参数来源 -> 最早触发点 -> 源头修复。

诊断格式：

```text
TRACE label:
  value:
  cwd:
  environment:
  caller:
  stack:
```

在危险操作前记录路径、当前目录、环境、关键参数和 stack。找到最早触发点后在源头修复，并在关键边界添加验证。只修深层症状点时，必须继续追踪上游。

## 禁止事项

- 不得只修深层症状点。
- 不得跳过调用者和参数来源追踪。
- 不得用日志代替修复。
- 不得在追踪中扩大执行交接范围。

## 输出契约

输出症状点、直接失败点、调用者、参数来源、最早触发点、源头修复、边界验证和命令证据。若根因是蓝图或范围错误，停止并回到 HILP 变更重审。

## 检查清单

- [ ] 已定位直接失败点。
- [ ] 已追踪调用者。
- [ ] 已说明参数来源。
- [ ] 已找到最早触发点。
- [ ] 修复发生在源头。
