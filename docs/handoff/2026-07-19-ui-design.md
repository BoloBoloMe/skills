## 当前认知上下文

### ITEM-04 核心问题

设计插件 UI 交互: 命令形式, 输出格式, 历史会话浏览方式. 需要匹配 pi TUI 的能力边界.

### pi UI 能力概要

- **命令**: `pi.registerCommand("name", { handler })` → `/name` 在 TUI 中可用
- **通知**: `ctx.ui.notify(text, level)` → toast 消息
- **状态栏**: `ctx.ui.setStatus(key, text)` → 页脚持续显示
- **Widget**: `ctx.ui.setWidget(key, lines)` → 编辑器上方区域
- **自定义 UI**: `ctx.ui.custom({...})` → 完整 TUI 组件 (列表, 表格, 输入等)
- **工具**: `pi.registerTool({...})` → LLM 可调用的工具
- **会话持久化**: `pi.appendEntry()` / `SessionManager` append 方法

### 参考交互 (来自 ITEM-02)

Claude Code 三种模式:
1. `/cost` 命令主动查询 → 格式化文本表格输出
2. 会话结束自动展示摘要行
3. Session + All-time 双层统计

### 需要盘问的关键决策

1. **命令命名**: `/cost` vs `/tokens` vs `/stats`?
2. **交互入口**: 纯命令, 纯状态栏, 还是两者结合? 是否做 LLM 可调用的工具?
3. **输出格式**: 纯文本表格, 还是有 TUI 组件 (折线图/柱状图)? pi TUI 组件能力边界在哪?
4. **实时反馈**: 状态栏持续显示当前会话累计? Widget 展示 per-turn 曲线? 每轮结束后自动 notify?
5. **历史会话浏览**: 如何选择目标会话? `/resume` 列表集成还是自定义选择器? 支持当前项目全部历史还是全局?
6. **Layer 分层**: 当前会话统计 vs 指定会话统计 vs 项目级汇总 vs 全局汇总?
7. **导出**: 支持 JSON 输出 (给脚本用)? 支持复制到剪贴板?
