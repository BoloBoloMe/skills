# 信箱 mesh 化: 统一脚本, 全内存, 邻居洪泛路由

> 2026-09-23 修订: 备选方案中 "pi 扩展命令 /swt-relay: 被拒绝" 一条被 ADR-0015 部分推翻 (pi 扩展作为纯连接器合法化, 脚本仍是唯一跨 agent 实现); 信箱随后独立为 mailbox skill. 其余决策不变.

原信箱是 host 常驻单体 (systemd) + pi 专属扩展 + SQLite 持久化. 本变更推翻为: 单一纯 stdlib python 脚本承载全部能力, 信箱实例全互联 (mesh) 洪泛路由, 信件全内存不持久化, serve 手动前台启动. 统一 Session 身份 (容器/host/设备平权), 消息类型不按身份限制 (指令集白名单兜底). 理由: 容器内 agent 不止 pi (扩展覆盖不到), systemd 侵入性强, 中心化拓扑有单点; 用户明确选择简单性优先, 接受重启丢信窗口.

## 备选方案

- hub-spoke (Workstation 总信箱居中): 被拒绝 — 中心单点, 拓扑知识集中, Yoga 离网时本机通信断.
- agent 双端点直连 (本机+总信箱): 被拒绝 — agent 要配两个地址, birth 要跨机 ssh 申领.
- pi 扩展命令 /swt-relay: 被拒绝 — 绑定 pi, codex/kimi 覆盖不到.
- 消息持久化 (SQLite): 被拒绝 — 用户选择即时通信语义, 重启丢信可接受, 换取实现大幅简化.

## 后果

- 信箱重启即丢排队信: 发信方需自行重发; 凭证与配置不受影响.
- 旧 M01 D001 的 "消息存 SQLite 容器删除不丢信" 卖点失效.
- systemd 单元退役, 每台设备需手动 serve.
