# 多挂载目录的 URL 命名空间用扁平并集, 不用每目录前缀

后续约定(已确认, 待实施): [ADR-0028](0028-artifact-mechanization-and-unified-presentation.md) 要求保留现有产物根目录规范, 同时保证工作流文件访问不因扁平挂载丢失根目录差异而同名串读. 具体访问映射未固定, 普通静态页面不因此一律改用前缀. 本次仅记录目标, 当前挂载实现尚未迁移, 下方保留旧决策原文.

常驻展示服务支持动态挂载多个目录, 决策: URL 命名空间为扁平并集 — 请求路径依次在各挂载目录查找, 首个命中返回; 同名冲突按挂载先后静默遮蔽; 顶层 listing 为各目录条目并集去重, 无提示.

备选方案 "每挂载目录一个 URL 前缀" 被拒绝: present 生成的 HTML 文件名语义化且不重复, 各页面存储路径本就不同, 冲突在实践中几乎不发生; 前缀徒增 URL 复杂度且让"交付可点 URL"的主路径多一层心智负担. 后果: 冲突场景无提示, 用户看到的内容来自先挂载目录; 若未来冲突成为真问题, 可加冲突告警而不必改命名空间结构.
