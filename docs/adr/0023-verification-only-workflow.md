# skill 只约束验证, 不约束做法

工作流 skill 只规定「怎么算干完, 怎么证明干完了」, 不再规定实现手段. 拆几个函数, 先写哪层, 用不用红绿循环, 走不走垂直切片, 都由执行者按现场决定. 结论必须来自真实运行, 且实现须留下可从外部入口复跑的路, 否则报缺口, 不把「验不了」当通过.

同时保留两类不属于「做法」的约束, 它们不限制实现手段:

- **协作协议** — worktree 位置, 分支与提交命名, issue 与 spec 的产物路径, 编排队列与交接格式. 放开会让并行派工与中断恢复失去依据.
- **安全底线** — 生产数据, 删除与不可逆操作, 写入授权, 原始数据保留, 脱敏. 统一维护在 `workflow/verification-contract/SAFETY.md`, 其他 skill 只留指针.

代码好不好看归验证: 编码规范与坏味道由 `code-review` 的 Standards 轴核对, 结论须完整列出发现与已检查范围, 主观判断也要可复查, 因此不属被放开的一类.

具体动作: `verification-contract` 成为唯一强制验证权威, 吸收原 `tdd` 的「测试只看行为」与「替身只在系统边界」; `tdd` 重写为缺陷修复专用, 修 bug 且有低成本测试方法时才用, 退回「新增功能默认写测试」的旧口径; `to-execution` 的 issue 模板只强制验证相关三节与范围两节, 垂直切片改为「能从真实入口独立验证且可独立上下文交付」, 不再规定走完哪些层; `to-spec` 删除全局测试接缝表, 可观察点写进各 issue 的验证入口; 结构变更与性能改进把「先建立检查再改」翻译成「交付证据须含改前结果」, 不规定步骤. 完整分类与被降级条目见 `docs/changes/verification-first-workflow/INVENTORY.md`.

对照验证: 同一需求在改动前后各跑一遍, 记录见 `docs/changes/verification-first-workflow/`.
