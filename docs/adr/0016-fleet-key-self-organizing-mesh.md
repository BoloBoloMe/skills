# 无感自组网: 舰队密钥 + 信标发现 + 认证换址

信箱 mesh 的邻居表原为手工配置 (ADR-0014), 换网/新设备接入全靠人工搬密钥改地址 (2026-09-21 三方实操的核心痛点). 本决策引入自组网且对用户全程无感: 舰队密钥 (fleet.key) 作为入群总钥匙, 复用设备间既有 ssh 作信任锚一次性分发 (join-fleet), 之后同网段 UDP 信标自发现 + 舰队密钥互证自动建邻居, 换址经旧链路密钥签名宣告自愈. 信任闸门从 "人工确认每次配对" 前移到 "一次性密钥分发", 满足无感要求的同时拒绝零确认入群 (避免网段任意设备入群触碰 exec 指令面). 完整设计见 `docs/changes/mailbox-standalone/DECISIONS.md` D016.

## 备选方案

- TOFU 人工确认入群: 被拒绝 — 用户要求全程无感.
- 零确认全自动 (LAN 即信任): 被拒绝 — 网段任意设备可入群收信/投信, exec 与 LLM 唤醒面暴露.
- 邀请码配对 (半自动): 被舰队密钥吸收 — 入群后跨网段配对只是告知地址+互证, 不再搬运密钥.

## 后果

- 舰队密钥是单点: 泄露即全群沦陷; 保护等级与现有信箱密钥相同 (0600), 轮换机制缓做.
- 同网段之外不可自发现 (广播不出网段), 跨网段仍依赖换址宣告或人工告知地址; 自动反向隧道缓做.
- 邻居表从纯人工配置变为自动+人工混合, ADR-0014 的 "邻居表每台机器手工配置" 表述自此过时.
