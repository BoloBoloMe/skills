# 工作流产物机械化, 展示后端与统一产物查看器归 present

已确认, 待实施. 工作流中决策账本及规格到验收的结构化产物统一由程序管理, 报告与证据原件保留原有形态; 仅用程序强制可确定判断的结构, 引用, 版本和流程约束, 不用格式检查代替语义检查或用户验收. 完整方案与理由见 [产物机械化方案](../changes/artifact-mechanization/PROPOSAL.md) 和 [决策账本](../changes/artifact-mechanization/DECISIONS.md).

整套 skills 的网页展示复用 present 已有文件读取能力和单例生命周期, 不新增重复的 JSON/Markdown 读取接口, navigate 与 codebase-map 不再各自运行展示后端. 统一网页也归 present: 由现有 navigate 路线图 UI 扩展, 点击里程碑打开全屏产物页, 通过模板显示结构化数据与 Markdown. 产物查看器也必须能直接打开交付单元或单份产物, 不以路线图为前置条件.

## 取舍

- 拒绝只改 to-spec: 格式维护和交接约束会被推到下游, 无法形成整链程序保障.
- 拒绝把所有产物都变成 JSON: 调研/评审论证, PoC 程序与证据原件不适合强拆字段, 保留 Markdown/原件并登记流程需要的数据.
- 拒绝继续维护各 skill 的展示后端: 通用文件托管, 地址交付与恢复能力已经在 present, 重复维护没有收益.
- 拒绝要求所有任务先建立路线图: 路线图是串联和使用产物的入口之一, 独立调用 skill 也必须能展示产物.
- 不维护长期双格式规格/执行模式或专用历史迁移器; 旧资料需要继续使用时由 LLM 核对并通过新程序整理.

## 后续影响

本决策部分替代 ADR-0017 中 navigate 自持展示后端的安排和 ADR-0026 中 codebase-map 自建展示服务的安排; 保留它们其他有效职责. ADR-0006 的扁平挂载不得导致不同产物根目录的工作流文件同名串读, 但本地产物根目录规范不变, 具体访问映射仍是实现选择. 旧 ADR 保留原文并补后续指针, 不因方案落盘声称代码已迁移.

同一运行环境复用一个 present 实例, 宿主同用户与各容器分别保持实例隔离. 需要同步修改现有固定端口恢复, 容器展示说明和各 skill 的停止语义, 避免迁移后旧链接漂移或局部操作误停全部页面.
