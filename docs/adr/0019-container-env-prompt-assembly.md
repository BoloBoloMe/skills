# 容器环境知识经脚本拼装注入 agent 提示词, 配生成式事实文档

sandbox 容器受创建期确定的限制 (网络白名单, 信箱, 端口映射), 容器内 pi/codex/kimi 需要这些知识才能正确工作. 我们决定: birth 时由脚本把母本拼装成三份 agent 系统提示词 (公共核 PUBLIC + 环境纪律 ENV + 生成节触发指针 + 各自专属段), 另生成 4 份本容器事实文档只读挂载到 ~/docs/ (identity/network/web-ports/agents); 容器不设 ~/AGENTS.md, 宿主机不持有 docs 母本. 为什么: 反方攻击证实 codex/kimi 是否自动读 ~/AGENTS.md 无法确证, 提示词是唯一必生效通道, 全量并入直接消灭触达风险; 单一 ENV.md 母本消灭三份漂移; 动态事实 (放行清单, 端口映射) 不写死, 走 env 变量与实测.

## 备选方案

- ~/AGENTS.md 注入 + 提示词强指针: 被否 — 触达链靠 agent 自觉, 用未确证的加载行为承担保命纪律 (反方主战场, 高置信度反驳).
- 三份提示词各写全量: 被否 — 手工三份同步是结构性漂移面, 与容器内追求单一事实源自相矛盾.
- 提示词只装约 5 行安全内核 + 启动校验: 被全量并入取代 (内核是它的特例); 启动校验降级为 birth 验收挂载就位检查.
- 宿主持有 docs 静态母本: 被否 — 事实与创建时点绑定, 静态母本必过期; 生成即投放.

## 后果

- 提示词由约 13 行增至约 40 行, 每会话常驻.
- 母本与生成器的更新只对新 birth 容器生效, 运行中容器不补.
- 生成文档是快照: network.md 声明 "以实际连通性为准"; create 后才知的宿主端口映射/显示直通只走 env 变量.
- 宿主与容器提示词互不同步, 允许不一致 (两环境语境本就不同, 用户裁定).
- 取代 agent-env-followups 账本 P1-6 三母本制的文件组 (三份 *_AGENTS.md → 五份拼装母本 + 生成器); navigate SKILL.md 的容器内展示配方节迁出至环境文档树.
