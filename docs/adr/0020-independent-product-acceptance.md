# 最终产品验收由独立指挥会话按 PRODUCT.md 组织

技术 Spec 已由既有 code-review 的 Spec 轴检查, 最终成品仍需要非作者按产品标准实跑, 因而决定独立建设 verify-change, 只验收 PRODUCT.md 的场景和审计 BR, 不重复验收技术 Spec 或代码库设计.

tdd-as-orchestra 在评审无新须重构发现项后, 于停止并汇报前另开独立会话使用 verify-change; 验收指挥者不亲自验收, 先评估并行/共享资源/共同准备, 再按产品场景组委派未参与实现或修复的验收者, 不固定两人或逐 AC 开会话. 明确实现问题回原重构节点并重新经过实现/合并/评审, 其他权限或标准阻塞按既有停止条件处理; 代理检查不替代最终人工确认.

这是已接受而尚未实施的职责与调用边界, 取代早期产品/技术各一名验收者的方案; 完整决策和替代关系见 [验证 skills 账本](../changes/verification-skills/DECISIONS.md) 的 D002-D003/D007/D018-D019/D027-D035.
