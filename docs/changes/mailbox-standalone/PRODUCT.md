# mailbox 信箱: 独立 skill, pi 连接器与无感自组网 Product Spec

## 背景

信箱 (agent 间传话通道) 原本是沙盒工作树 skill 的内置脚本. 2026-09-21 的三方实操 (office 主机/容器/换网笔记本) 暴露了真问题: 投信方不知道信到底到没到, 邻居表只能加不能改, 设备换网后静默失联, 服务没起时取信方干等无提示. 同时信箱已经是跨设备跨 agent 的通用基础设施, 不该绑在沙盒工作树里; pi 用户也值得一个优雅的会话内收发体验, 而不是手敲长脚本路径. 提出方与受益者: 用户本人, 以及他在各设备/容器里跑的所有 agent 会话.

## 目标

- G-001: 信箱独立为 mailbox skill, 任何 agent 不装 swt 也能 serve/投信/取信/配置
- G-002: swt 经 mailbox 的机器子命令完成容器信箱接线, swt 内不再含信箱实现
- G-003: 投信立刻可见真实处境 (目标与信件 id 分行; 本机排队/已转邻居/部分已转/暂存/未知 五态明示)
- G-004: 邻居与滞留信可管可控 (邻居查/删/改/同名覆盖; 滞留列出/重投/丢弃, 上限+TTL)
- G-005: 取信与服务状态显式 (残留状态文件验活, 服务没起立即明报, 取信支持超时/限量)
- G-006: pi 会话内 `/mail-listen` 后台取信来信自动唤醒, `/mail-send` 投信, `/mail` 总览
- G-007: 发件人获得 best-effort 回执 (送达/已读/失败), 回执不打断会话
- G-008: 容器开箱即有宿主端口与显示状态 env, 且能查 session 名单
- G-009: 拉窗指令按容器名也能命中, 拉窗信携带目标 url
- G-010: 组网全程无感: 新设备一次 join-fleet 后, 同网段发现/建邻居/换址愈合全自动; 跨网段首次接入需一次地址告知, 完全无路由时需反向隧道

## 非目标

- NG-001: 不做消息持久化, serve 重启丢排队信 (沿用既有取舍)
- NG-002: 不做 serve 保活安装, 只给 systemd 文档样例
- NG-003: 不做跨实例签名链/forward 验 from/密钥轮换 (下轮)
- NG-004: 不做邻居健康自动暂停/地址无认证自动学习/配置热重载
- NG-005: 不做邀请码配对/隧道管理/死信队列/代投标注字段
- NG-006: 不做物流查询接口 (回执推送先行)
- NG-007: 不留旧路径兼容 shim (旧容器已清空)
- NG-008: pi 扩展不重实现脚本能力; 非 pi agent 不损失任何功能
- NG-009: 不做零确认入群 (无舰队密钥一律拒); 不做自动反向隧道

## 业务规则

- BR-001: mailbox.py 保持纯标准库单文件. (审计)
- BR-002: 凭证/密钥落盘 0600, 密钥仅创建时下发, 列表永不回显. (审计)
- BR-003: session id 由设备名/容器名派生, 永不含网络地址.
- BR-004: 回执 best-effort: 收到 = 确定发生, 缺席 = 未知.
- BR-005: 容器契约 env 名不变 (SWT_MAILBOX_URL/SWT_SESSION_*). (审计)
- BR-006: 信箱只传控制消息, 单信正文上限 1MB.
- BR-007: pi 扩展禁止重实现脚本能力, 需要能力一律执行脚本. (审计)
- BR-008: 文档含反向隧道配方/换址联动清单/拉窗模板加固/waypipe 版本组合. (审计)
- BR-009: 舰队密钥 0600 落盘, 只经 ssh 分发. (审计)
