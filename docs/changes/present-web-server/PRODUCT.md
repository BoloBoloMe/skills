# present-web-server Product Spec

## 背景

用户通过 ssh 远程登录主机开 agent 会话时, present skill 现有的本地 Chromium 浏览器展示路径不可用 — 浏览器起在远程主机上, 用户在自己的设备屏幕前看不到. 受益者: 以远程方式使用 agent 会话的用户本人. 需求来源: 用户直接提出. 现在处理的理由: 远程会话是该 skill 的高频真实使用形态, 缺失等于远程场景无展示能力.

## 目标

- G-001: 远程 (ssh) 会话中, agent 生成的展示内容 (HTML/文本/图片) 用户可在自己设备的浏览器经 URL 直接访问.
- G-002: 同一主机同一用户的多个 ssh 会话共享一个常驻 web 服务, 重复展示不重复起服务.
- G-003: 远程模式的展示交付不依赖本地浏览器, 且失败时有可落回的出口.

## 非目标

- 不做认证, 不做 TLS, 不做跨机访问控制 (用户已接受"绑定开放时网段内可读全部挂载目录"的取舍, 见 D001).
- 不承诺跨 OS 重启保留服务与挂载 (见 D010).
- 不提供挂载目录的移除端点 (TTL 兜底, 见 D014).
- 远程模式不提供页面交互状态回读 (降级纯展示, 见 D003).
- 不支持 Windows 主机 (见 D018).

## 用户故事

- US-001: 作为 ssh 远程会话的用户, 我想要 agent 把生成的展示页经 URL 交付, 以便在自己设备的浏览器直接打开.
- US-002: 作为同主机多 ssh 会话的用户, 我想要各会话共享同一常驻服务, 以便不需关心端口与实例管理.
- US-003: 作为用户, 我想要把主机上已有目录 (文本/图片资料) 挂进服务, 以便远程翻阅主机资料.
- US-004: 作为用户, 我想要服务在主机重启或长期空闲后不留残余, 以便暴露面有自然终点.

## 业务规则

- BR-001: 绑定地址, 端口, 初始挂载目录为 start 必填, 无默认; 脚本不自动选端口, 端口由 LLM 在 49152-65534 随机选取, 被占 (错误码 `port_in_use`) 换端口重试, 上限 10 次.
- BR-002: 同一主机同一用户单例; start 遇存活实例且 bind 一致时幂等复用 (忽略端口差异仅告警, 并把初始挂载目录挂载进去); bind 不一致报错, 提示先 stop.
- BR-003: URL 命名空间为扁平并集: 请求路径依次在各挂载目录查找, 首个命中返回; 同名冲突按挂载先后静默遮蔽; 顶层 listing 为各目录条目并集, 去重, 无提示.
- BR-004: 允许目录 listing; 目录参数必须绝对路径+存在+是目录, 否则报错拒绝, 不自动创建.
- BR-005: 路径遍历 (`../`, 越界 symlink) 不能逃逸任何挂载目录, 越界一律 404.
- BR-006: 控制端点 (`/__control__/*`) 仅接受本机 (loopback) 来源, 非本机一律拒绝.
- BR-007: 服务 24h 无请求自行退出; 运行时信息落系统临时目录, 重启后服务与挂载归零.
- BR-008: 远程模式判定: `SSH_TTY`/`SSH_CONNECTION` 存在即远程, 用户明示可覆盖; 远程模式不起 Chromium, 交付 URL; 全部失败走既有失败出口 (本地路径+chat 摘要).

## 关键场景

- SC-001: 类型: 正常. 参与者: ssh 远程用户. 前提: 主机无存活实例. 行为: agent 执行 start 并交付 URL. 产品结果: 用户在自己设备浏览器打开 URL, 看到展示内容. 覆盖: US-001, BR-001, AC-001.
- SC-002: 类型: 正常. 参与者: 同用户另一 ssh 会话. 前提: 实例存活. 行为: 再次 start (端口不同, bind 相同). 产品结果: 复用现有实例, 新目录立即可访问, 用户得到同一入口 URL. 覆盖: US-002, BR-002, AC-001.
- SC-003: 类型: 边界. 参与者: 远程用户. 前提: 两个挂载目录含同名文件. 行为: 请求该文件名. 产品结果: 得到先挂载目录的那份, 无冲突提示. 覆盖: BR-003, AC-005.
- SC-004: 类型: 失败. 参与者: 远程用户. 前提: 服务进程已死 (如被 OOM 杀). 行为: agent 执行 status. 产品结果: 服务按原挂载清单自动重建; 原端口被占时换新端口, 用户得到新 URL. 覆盖: US-001, US-002, AC-002.
- SC-005: 类型: 失败. 参与者: 攻击者 (网段内). 前提: 服务绑定 0.0.0.0. 行为: 从局域网请求 `/__control__/add-dir`. 产品结果: 请求被拒绝, 挂载表不变; 但静态内容本身对网段可读 (已接受取舍). 覆盖: BR-006, AC-004.
- SC-006: 类型: 边界. 参与者: 远程用户. 前提: 服务 24h 无人访问. 行为: 空闲计时到期. 产品结果: 服务自退, 暴露面收敛; 用户再来时 agent 重新 start. 覆盖: US-004, BR-007.
- SC-007: 类型: 失败. 参与者: 远程用户. 前提: start 端口被占连续 10 次/服务无法就绪. 行为: LLM 重试耗尽. 产品结果: 走既有失败出口, chat 给出本地路径与内容摘要. 覆盖: G-003, BR-008, AC-007.

## 验收标准

- AC-001: 给定三参齐全且目录合法, 当执行 `start <port> <root> --bind <addr>`, 则服务守护进程化, ssh 断连后存活, stdout 输出含入口 URL (主机名/局域网 IP), 端口, 挂载信息的 JSON; 三参缺一或目录非法则报错不启动. 覆盖: G-001, US-001, BR-001.
- AC-002: 给定实例存活信息, 当执行 `status`, 则报告存活与运行时信息; 给定进程已死, 当执行 `status`, 则按原挂载清单重建, 端口被占时脚本自行更换端口并报告新端口, 运行时文件同步更新; 给定运行时文件缺失, 当执行 `status`, 则报告未启动. 覆盖: G-002, US-002, BR-002.
- AC-003: 给定实例存活, 当执行 `stop`, 则服务终止且运行时文件删除, 后续请求失败. 覆盖: G-002.
- AC-004: 给定实例存活, 当本机 `add-dir` 存在的目录, 则内容立即可访问且同目录幂等; 当非本机来源调用控制端点, 则一律拒绝. 覆盖: US-003, BR-004, BR-006.
- AC-005: 给定多个挂载目录, 当请求内容, 则扁平并集首挂载命中, 顶层 listing 并集去重, `../` 等路径遍历不能逃逸出任何挂载目录. 覆盖: G-001, BR-003, BR-005.
- AC-006: 给定服务运行, 当检查运行时文件, 则其位于系统临时目录的用户级子目录 (`pi-present-web-<uid>/`), 含 pid/port/bind/roots[]/启动时间, 权限 0600. 覆盖: BR-007, US-002.
- AC-007: 给定远程会话 (SSH_TTY/SSH_CONNECTION 存在或用户明示), 当 present skill 展示内容, 则走 web 服务器路径不起 Chromium, 成功时 chat 给出可点 URL, 全部失败时走既有失败出口. 覆盖: G-001, G-003, BR-008.
- AC-008: 给定任意使用, 当审计非目标, 则无认证无 TLS 未意外引入, 重启后服务与挂载归零, 空闲 24h 服务自退. 覆盖: G-003, US-004, BR-007.

## 成功指标

不设指标. 已确认理由: 内部工具型变更, 无观测渠道, 无指标采集面 (D015).

## 待验证事实

- 事实: 系统临时目录被第三方清理 (systemd-tmpfiles 等) 删掉 server.json 时, 存活服务变幽灵 (status 报未启动, 重建出第二实例, 老实例脱离管理).
  影响: 低概率下单例语义暂时失效, 老实例挂载目录继续暴露但不可见.
  验证方式: 真实环境长周期使用观察; 已接受为已知限制 (D028), 不投入防护.
