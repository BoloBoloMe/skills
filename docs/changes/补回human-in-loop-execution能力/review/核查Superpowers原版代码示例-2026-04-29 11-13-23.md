# 核查 Superpowers 原版代码示例

## 结论

原版 Superpowers 在用户提到的第 3 项相关区域中存在代码示例。因此“为 TDD、调试、测试反模式增加少量高质量代码示例”可以纳入补强范围，不需要额外解释为新增设计取舍。

## 核查范围

- `superpowers/skills/test-driven-development/SKILL.md`
- `superpowers/skills/systematic-debugging/SKILL.md`
- `superpowers/skills/test-driven-development/testing-anti-patterns.md`
- `superpowers/skills/systematic-debugging/root-cause-tracing.md`
- `superpowers/skills/systematic-debugging/defense-in-depth.md`
- `superpowers/skills/systematic-debugging/condition-based-waiting.md`

## 证据

- TDD 原版包含多个 TypeScript 示例：失败测试、mock 坏例、最小实现、过度实现坏例、bug fix RED/GREEN 示例。
- testing anti-patterns 原版包含多组 TypeScript before/after 示例：测试 mock 行为、测试专用生产方法、不理解依赖就 mock、不完整 mock。
- systematic-debugging 主文件包含 bash 诊断示例，用于多组件边界证据收集。
- systematic-debugging 的配套参考文件还包含 TypeScript / bash 示例：根因追踪 instrumentation、防御式验证四层示例、condition-based waitFor 示例。

## 对补强范围的影响

第 3 项可以纳入补强范围，但应限定为“少量高信号示例”：

- TDD：补一个好测试 / 坏测试的可运行风格示例，以及一个最小 GREEN / 过度实现对照。
- 系统调试：补一个多组件诊断或调用链 tracing 示例。
- 测试反模式：补一到两个 before/after 示例，优先 mock 行为和测试专用生产方法。

不建议全文翻译原版示例，也不建议引入与 HILP 执行交接无关的长案例。
