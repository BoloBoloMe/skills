### F1 "沿用" 移植缺承接件绑定, 四处上下文断裂

- 位置: 决策33 (沿用两层保障), 决策34 (复查, 修订), 决策35 (覆盖清单), 决策37 (沿用账本与交接); 被引用的 to-spec 侧为决策7, 16, 18, 30.
- 断裂点:
  1. 修文复查的执行者与范围. to-spec 侧决策30 明确 "修文由独立检查会话复查受影响内容与引用"; 决策34 只写 "直接修正并复查", 未说谁复查, 复查范围是否按影响收缩. 若由主会话自查, 与 Q2=A "不由写稿作者自证" (决策33 理由句) 冲突.
  2. 免问与方法归组的严格口径. to-spec 侧决策7 有 "拿不准一律按须问处理 (宁多勿漏)"; 决策32 只写 "已有依据能直接推出的免问", 未移植保守兜底, 也未定义 "依据" 指什么 (判据原文, verification-contract, 权威技术输入?). "每种不同验证方法问一次" 中方法同一性的判定同样是 LLM 裁量, 两种方法被并成一种时, 差异处的选择被静默代答.
  3. 闭环覆盖清单的构造基准. to-spec 侧决策16/20 的清单是对照两份模板节清单逐节呈现已问/未碰; 决策35 只写 "覆盖清单" 三个字, 未说它必须逐项对照权威输入必验项构造. 清单若由盘问进程自产, 漏问的整项不会出现在清单上.
  4. 发现处理三分流的执行者. to-spec 侧决策18 是主会话复核三分流; 决策33/34 对验证方案侧的发现 (成文核对查出问题, 转述错误误分类) 未指定处理者与分流规则.
- 失败路径: milestone-11 落笔时实施者对上述四点各自发挥; 主会话把实质修改分类成 "纯转述错误" 自行修正 (断裂点1+4 合流), 或把构造性入口选择归入 "能直接推出" 免问 (断裂点2), 闭环清单漏项 (断裂点3) 让用户在信息不全下确认.
- 后果: 用户已确认的 "不由作者自证" 与 "信息完整呈现" 两项原则在新流程里没有对应动作, 检查责任悬空或被静默降级.
- 置信度: 缺口存在 = 高 (账本文字可直接核对); 危害量级 = 中.
- 最小处理: 决策33/34/35 各补一句绑定: 修文复查与三分流沿用决策30/18 的执行者与影响范围规则; 免问与方法归组移植决策7 口径并钉死依据源; 闭环覆盖清单须逐项对照权威输入必验项呈现已问/未碰与跳过理由.
- 性质: 已证实缺口; 需用户新增裁决 (或主会话提出默认方案交用户点头).

### F2 免问不留痕在验证方案语境的风险形态未向用户重新呈现

- 位置: 决策37 (免问不留痕); 决策17 记载 to-spec 侧该风险由用户 2026-11-25 知情接受; Q6 用户选A "沿用 to-spec 已定规则".
- 论证: to-spec 侧被接受的失败模式是 "直译藏新决策" (决策17 引 OPP-01/04). 验证方案里免问对象不同: 是构造出来的验证安排 (入口选择, 观察方式, 证据类型). 这里的静默漏检后果不是多写一句规格, 而是弱证据被当有效验证证据放行 -- 直接打击 verify-change 存在的目的. 两种风险形态不同构, 但 Q6 的移植是按引用一揽子完成, 账本未记录用户曾看到 "风险形态在新语境会变形" 这一信息.
- 失败路径: 某判据的入口/观察方式被判定为 "能直接推出" 而免问, 实际是构造选择; 写后核对依据源 (权威输入+决定) 部分能兜住 (决策33), 但免问项无痕, 核对者重构时可能推出同样的构造, 双方同错, 无第三道闸.
- 后果: 验证效力被静默稀释, 且与 to-spec 侧不同, 此处没有一次明确的风险知情接受记录可引用.
- 置信度: 风险形态差异 = 高; 用户是否实际知晓并接受 = 待核实 (本会话未参与当时对话, Q6 选项文字本身未提风险).
- 最小处理: 不恢复留痕 (不重开 Q6), 在规格修订时把 "免问构造验证安排的漏检形态" 作为独立条目呈现给用户点收, 与决策17 的知情接受并列.
- 性质: 待核实疑点; 需用户新增裁决 (一次知情点收, 不是重问).

### F3 决策38 保留非两份spec输入, 但决策34/37 的承接件以 spec 与既有账本为前提

- 位置: 决策38 边界2 (不强制必须存在两份规格) vs 决策34 (退回权威规格补问) 与决策37 (使用现有决策账本).
- 论证: 权威输入不是 to-spec 产出的两份规格时, 可能根本没有决策账本 (账本由 to-spec/deliberate 盘问产生). 此时: 盘问决定入哪个账本 (为本变更新建账本是否算 "新增盘问专用记录"?), 免问推导的 "已有依据" 是什么, 判据缺口向谁补问 (没有 "权威规格" 可退回), 全部无规则.
- 失败路径: 对一份已确认需求文档设计验证方案, 盘问决定无处入账, 写后核对依据源 (决策33: 权威输入+盘问决定) 里 "盘问决定" 一项为空, 检查退化.
- 后果: 决策38 明确保留的场景在新规则集下不可执行, 或执行时现场发明记录方式, 违反决策37 的不新增格式.
- 置信度: 缺口 = 高 (文字冲突可核对); 发生频率 = 未知 (非spec输入的实际使用频率本会话无数据).
- 最小处理: 补一条决策: 非两份spec输入时, 盘问决定入该变更自己的决策账本 (新建账本不算新增专用记录), 判据缺口退回该权威输入的既有确认流程, 免问依据源 = 权威输入原文 + verification-contract.
- 性质: 已证实缺口; 需用户新增裁决.

### F4 Q5 的调查环节与现行 "只读权威输入, 不看实现" 边界冲突, 调查的执行面未定

- 位置: 决策36 (方法能否做成不明仍须先调查); workflow/verify-change/SKILL.md 设计方式第1步 (只读权威输入, 不看实现, 输出待确认方案); 决策38 预计影响 (不扩张执行写入或外部资源的授权).
- 论证: 判断一种验证方法能否做成, 常需要看实现形态 (入口是否真实存在, 观察点是否可达), 这恰好是现行设计阶段禁止的读取. 决策36 只说 "先调查", 未说谁调查, 允许读什么, 调查结论是否入账 (决策37 的事实条目?), 调查后发现方法不可行走什么回路.
- 失败路径: (a) 设计者越界读实现, 独立性边界被静默突破; (b) 设计者遵守禁令则调查无从下手, 方案以 "待调查" 悬空, 无主体无期限; (c) 调查结论只留在会话里, 换会话后丢失, 违反决策37 的可恢复意图.
- 后果: Q5 的 "调查与确认边界" 这半句在规则集里没有落地动作.
- 置信度: 缺口 = 高; 危害 = 中.
- 最小处理: 补规则: 调查主体, 允许的读取范围 (如只读实现入口与配置, 不读作者设计理由, 结果作为事实条目入账并标注来源), 以及调查结论 "方法不可行" 时的回路 (报告缺口停止, 或交用户改判据).
- 性质: 已证实缺口 (规则缺失); 具体边界值需用户新增裁决.

### F5 转述错误修订的版本确认状态与追溯机制未定, 存在状态自证缝隙

- 位置: 决策34 (纯转述错误直接修正, 方案仍升版本, 不重确认); 决策35 (闭环确认即内容确认, 成文后不再采纳整份文件); 现行执行第1步 (workflow/verify-change/SKILL.md: 核对 "VERIFICATION-PLAN.md 已确认") 与 REVERIFY.md 第1步 (方案依据变化时 "更新并重新确认").
- 论证: 闭环确认的是盘问决定, 不是某个版本号; 纯转述修订升版后, 该版本没有任何用户视线, 但执行门槛要求 "已确认" 状态 -- 把 vN+1 标为已确认的动作只能由主会话完成, 即主会话自证一个用户从未逐字见过的状态. 配套问题: 后续验证者如何从版本号区分 "纯转述修订" 与 "实质修订"? 决策34 只说 "保留变更与确认依据的可追溯性", 机制 (变更说明写入方案文件, 还是入账本) 未定. to-spec 侧对应物是决策24 (确认标记 v1 不升版), 语义与这里相反, 不能照搬.
- 失败路径: 主会话把实质修改误分类为转述错误 (F1 断裂点4 无三分流兜底), 升版, 自标已确认; 执行按已确认方案放行; 事后只能靠翻 chat 追溯, 而决策10 已裁定防串版依赖 chat 确认 -- 在 to-spec 侧这是单次闭环, 在验证方案侧是每次修订, chat 依赖被放大.
- 后果: 执行绑定的 "已确认方案" 的确认语义被稀释; 误分类无独立复核点.
- 置信度: 缝隙存在 = 高 (机制未记录可核对); 被利用概率 = 中 (依赖成文核对能查出误分类, 部分兜底存在但执行者未定, 见 F1).
- 最小处理: 补两条: (a) 每次修订的变更说明与分类依据 (转述/实质) 写入方案文件的变更记录节或账本条目; (b) 转述错误的分类与修文由独立检查会话复核 (与 F1 断裂点1 同一裁决).
- 性质: 已证实缺口; 需用户新增裁决.

## 反方立论

替代主张: 把 "按引用沿用" 改为 "逐条重述加绑定". 移植 to-spec 规则到验证方案盘问时, 每条被引规则在新语境重述一遍, 并绑定三要素: 执行者是谁, 依据源是什么, 判错兜底口径是什么. 三处上下文断裂 (非spec输入的账本与补问对象, 可行性调查的读取范围, 修订复查的执行者与状态记账) 在落笔规格前逐项交用户裁决, 不留实施者裁量. 免问不留痕在新语境的风险形态作为独立条目向用户呈现点收. 这一主张不推翻任何 A 选择: 双闸, 不重问, 闭环即确认, 条件确认, 账本复用全部保留; 它只要求把用户已确认的原则 (作者不自证, 信息完整呈现, 检查依据不索证于产物自身) 在新产物上配齐动作. 依据: milestone-10 的任务就是收敛规则, 规则集在绑定点为空正是本阶段应消除的缺陷, 不是留待实施的习惯问题.

## 幸存与比较

正方仍成立的强点:
- 决策33 钉死核对依据源并禁自证, 与 to-spec 决策30 同强度, 直接封死自证循环的主通道.
- 决策38 三条边界原样保留, 方案确认不冒充验收, 不强制固定文件, 判据缺口不就地消化, 结构正确.
- 决策36 把方法可行性与环境就绪分开, 阻止以 "资源待备" 掩盖方法未知, 逻辑成立.
- Q2 的双独立会话与决策33 "分组不减少覆盖行" 保住了检查面.
- 整体上多数缺口有部分兜底 (写后核对的重推覆盖能查出不少免问误判), 体系并非裸奔.

权重比较: 反方发现没有一项能推翻用户的 A 选择, 全部落在 "已确认原则如何在新语境执行" 的绑定层; 影响范围 = milestone-11 规格修订的完整性, 发生概率 = 高 (不做处理则实施者必然现场裁量), 不可逆性 = 低 (补一条决策即可修复). 正方最强的幸存论点是 "多数缺口有写后核对兜底": 但 F1/F5 表明该兜底自身的执行者与分类权在账本里同样未定, 兜底是未接线的 -- 在接线前, 反方在规则完整性上占优; 接线后双方收敛于同一设计, 反方不再反对. 如实声明: 未找到足以推翻决策31-38 方向本身的强反方, 本报告的全部攻击力作用于承接件缺绑定这一层.
