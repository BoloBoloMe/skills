## 正方还原 (steelman)

- **定义**: to-spec 从 "预写草稿 -> 用户逐版审阅确认" 改为 "连续盘问 (grilling 逐条 + decision-ledger 落盘 + opposing-viewpoint 反方攻击, to-spec 自组织) -> 问完才落笔 (主会话) -> 三道常设闸门 (机检/逐场景对账/反向覆盖) 盯忠实". 用户全程只确认盘问闭环, 不读两份 spec 正文, 不碰 Gherkin.
- **前提假设**:
  - A1 账本 (决策/事实条目) + 规则原文足以支撑落笔全部判定性内容, 不需要用户看正文把关;
  - A2 独立子代理逐场景对账能可靠判定 "刺激与结果是否有原文或账本依据", 即 LLM 判忠实可靠;
  - A3 反向覆盖 (子代理按原文重推应覆盖情况清单再比对) 能兜住免问直译部分的查漏;
  - A4 账本 + 按需交接文档足以无损跨会话续问;
  - A5 "chat 明确确认盘问闭环" 的记录足以替代 review_id 的机械版本核对;
  - A6 落笔缺判定会被主会话自觉补问或被对账抓出, 不会悄悄混入.
- **论据**: 事实2 (deliberate 四步落盘不含 spec, 无落笔后修正步骤); 事实6 (机检 7 项全是格式, 无一查内容忠实); m2 侦查 (约一半情况是规则直译可免问, 免问逐条问使问数翻倍); 用户精力经济与 "宁多勿漏" 的方向级要求.
- **推理链**: 机检不查内容忠实 -> 忠实只能靠对账 -> 对账的依据就是账本+原文, 原文本在场 -> 免问情况无需留痕 (决策5) -> 留痕层省掉, 对账与反向覆盖两道闸门常设即可 (决策8) -> 攻击决策放在落笔前 (决策3), 落笔后只修忠实 -> 用户精力只花在决策上 (决策7/11/12), 版本机制简化 (决策10).

四要素中 A1-A3 从决策集陈述可完整还原, A4-A6 有明确机制指向; 无 `未知` 项需要向我确认.

## 主战场

**攻击 A2+A3: "落笔后的 LLM 对账与反向覆盖, 能可靠替代用户审阅与免问留痕, 成为忠实性的唯一承重墙".**

理由: 决策5 (免问不留痕), 决策7 (免问口径), 决策10 (去 review_id), 决策4 (主会话落笔), 决策8 (三道闸门) 的全部省力收益都押在这一前提上; 拆掉它, 免问直译的漏查与新判定混入都没有独立兜底, 决策集的 "省一半问数 + 用户不读稿" 同时失效. 更关键: 用户自己的侦查已对 A3 的可靠性投过反对票 -- 方向 B 被否决的理由正是 "实测靠标签/文本重合判直译不可靠, 被跳过的场景仍含原文没有的新内容, 等于 LLM 替我定" (ROADMAP off_course). A2/A3 把被否决机制的核心环节 (LLM 语义重推判断覆盖与直译) 换了个位置重新启用, 却没有给出它这次可靠的证据.

## 反方反驳 (逐项)

### OPP-01 [主战场] 对账与反向覆盖是开放式生成判断, 被当成判别式比对使用; 用户的否决记录已否定其可靠性
- 受影响要求/事实: destination "忠实性由机检加子代理对账保证"; ROADMAP notes 方向 B 否决理由; 决策5, 7, 8, 10.
- 论证: 方向 B 被否是因为 LLM 判 "直译/覆盖" 不可靠 (已实测). 新流程的对账 (b) 与反向覆盖 (c) 同样是 LLM 凭语义判断 "有没有依据/该覆盖哪些", 且决策5 取消批报留痕后, 对账失去了比对锚, 从 "拿记录行比场景" 的判别任务退化为 "从全部原文重推再判断" 的生成任务 -- 生成任务的漏报与误报率天然高于比对. 决策集没有任何证据 (样张实测, 误报率数据, 多代理冗余) 支持这次同一类 LLM 判断变可靠了.
- 依据: ROADMAP.json#off_course (B 否决理由, 已证实); 决策5/8 原文 (已证实); A2/A3 可靠性无任何实测数据 (未证实).
- 不修正后果: 免问直译部分成为忠实性盲区, 且失败是静默的 (漏报不报错); 用户 "宁多勿漏" 的方向级要求在最容易漏的地方失去保障.
- 置信度: 高 (结构风险已证实; 实际漏报率未证实).

### OPP-02 三道闸门只管 Gherkin, TECHNICAL.md 与 PRODUCT 非 Gherkin 正文失去全部专门闸门 (受影响却未入账的旧行为)
- 受影响要求/事实: 现 to-spec SKILL.md 第2步 (用户审阅采纳含 目标/规则 的暂存稿) 与第3步 (用户审阅采纳 TECHNICAL.md 草稿) 是现行保障; 决策8 原文 "TECHNICAL.md 走 check-tech 机检加现有达标标准检查, 逐场景对账细节管 Gherkin".
- 论证: 现流程中 TECHNICAL.md 与 PRODUCT 正文 (背景/目标/非目标/业务规则条目) 都经用户逐版审阅采纳; 新流程用户不读正文, 而三道闸门中 (b) 逐场景对账与 (c) 反向覆盖明确只管 Gherkin. TECHNICAL.md 只剩 check-tech (格式) 与通用达标标准检查 (LLM 自查), PRODUCT 正文条目连对账都不覆盖. 主会话落笔时在技术段或正文条目引入新判定 (决策4 禁止, 但 A6 说靠自觉+对账兜住), 没有任何一道闸门能抓.
- 依据: 决策8 原文 (已证实); 现 SKILL.md 第2/3步完成标准 "我在 chat 明确采纳" (已证实); destination notes "我不审预写的草稿" 泛指两份 (已证实).
- 不修正后果: 最易藏新决策的位置 (技术设计, 模块接口, 正文条目转写) 恰好是闸门最弱的位置; 下游拿到掺了未经裁决新判定的权威 spec, 违反决策4 与规格约束 "已确认约束不得自行降级" 的本意.
- 置信度: 高.

### OPP-03 三道闸门的 "原文" 数据源未定义, 存在对账自证循环的真实风险
- 受影响要求/事实: 决策8 (b) "核每个场景的刺激与结果是否有规则原文或账本依据"; (c) "子代理按目标/规则原文重推".

- 依据: 决策8 原文未定义数据源 (已证实); 实际实施会否走循环取决于 milestone-07 的提示材料 (未证实).
- 不修正后果: 闸门存在但测不到真差异, 比没有闸门更糟 (虚假安全感).
- 置信度: 文本歧义=高; 危害发生=中.

### OPP-04 样张已实证的 "直译藏新决策" 在新流程中正好从对账的缝隙漏过
- 受影响要求/事实: ROADMAP notes "乙规则4 换端口那条直译里藏着新决策 (状态记录加字段), 不看批报后只能靠对账抓出"; demos/coverage-tree-samples (该场景结果 "旧地址取状态记录旧 URL", 新决策=状态记录加字段).

### OPP-05 决策11 (b) 与其理由自相矛盾, 幻觉事实可无确认入账
- 受影响要求/事实: 决策11 内容 "(b) 代码现状与可查事实由 LLM 查证后写入事实条目...只在拿不准且影响决策时才问用户" vs 同条理由 "成为决策依据的事实必须用户点头".
- 论证: 按内容字面, 一条 LLM 自认 "拿得准" 且影响决策的事实不必问用户 -- 直接违反同条理由. 执行者无所适从; 走宽解释 (都不问) 时, 查证错误或出处标错的事实入账成为决策依据, 用户从未点头. 事实错误在后续闸门中不可见: 对账核 "场景 vs 账本", 账本事实错了, 忠实于错事实的场景照样通过.
- 依据: 决策11 原文两处冲突 (已证实).
- 不修正后果: 账本的 "权威输入" 地位被未经确认的事实污染, 且污染不可被任何闸门发现.
- 置信度: 高 (矛盾确凿); 触发概率=中 (取决于 LLM 查证质量).

### OPP-06 决策11 三分法漏掉技术段判定, 模块接口与接缝的亲答归属缺失

### OPP-09 交接文档落 /tmp, 容器重置即丢; 账本不含进行时状态, 无损续问承诺在跨容器场景失效

- 受影响要求/事实: 决策3 (攻击对象=账本里的决策); 决策8 (c); 决策9 (b)(c) 补问回路; destination "一场连续, 可分段续问的盘问...问完才落笔".

- 依据: 决策3/8/9 原文 (已证实); 补问潮的规模未证实 (反向覆盖实际查出多少缺漏为未知).
- 不修正后果: 更多 "闭环后又来补问" 的体验损耗; 若用户视之为流程失控, 会动摇对整个盘问形态的信任.
- 置信度: 中低 (机制成立, 量级未证实).

## 反方立论

替代主张: **忠实性的锚点应放在盘问末端的一个最小免问判定清单, 而不是全押落笔后的 LLM 重推; 三道闸门须补齐覆盖面并钉死依据源.** 具体主张 (不重做实现设计, 只修决策):

1. **恢复一行式批报留痕 (修决策5)**: 免问情况只落 "条目+直译自规则N" 一行清单 (可进账本事实条目或暂存工作区文件, 依旧不请用户过目), 作为对账的比对锚. 成本一个文件/一节, 收益是把对账从生成任务降回判别任务, 且 m2 样张 (乙规则4) 证明这一层是唯一能对住 "直译藏新决策" 的锚.
2. **闸门覆盖面补齐 (修决策8)**: 逐条对账扩展到两份 spec 的全部条目 (PRODUCT 正文条目 vs 账本; TECHNICAL 判定性内容 vs 账本), 不只管 Gherkin; 补一道书写纪律与跨条目矛盾检查的责任归属 (可并入对账子代理任务书).
3. **钉死闸门依据源 (修决策8 表述)**: 明确对账与反向覆盖的依据 = 账本条目 + 用户原话/原文, 禁止以落笔产物 (PRODUCT.md 自身) 作为 "规则原文" 依据, 杜绝自证循环.
4. **修决策11 的矛盾**: (b) 改为 "成为决策依据的事实, 一律交用户确认后入账", 或把理由降格为与内容一致; 同时给技术段判定 (接口固定, 接缝, 兼容承诺) 在 (a) 中补位.
5. **定义修正回路的落笔路径 (修决策9/10)**: 决策9 (a) 修文必须走与首次落笔相同的原样嵌入机制 (重建暂存稿+草稿再 promote), 并规定修订时确认标记升级 (vN+1), 保证文件标记可追溯到最近一次确认时点.

立论独立于 "正方是错的" 成立: 即使对账可靠性最终实测够高, 留痕锚+覆盖面补齐+依据源钉死也只是把已有的构件放在更稳的位置, 不增加用户精力消耗, 纯减风险.

## 幸存与比较

**正方仍成立的部分**: 决策1 (自组织替代整体嵌套) 有事实2 支撑, 基本幸存; 决策2 的自然流动+闭环对照方向合理, 只需补呈现要求 (OPP-11 是一句话修正); 决策3 的攻击时点与决策4 的落笔归属论证自洽; 决策6 的账本/交接文档分工合理, 只需解决落盘位置 (OPP-09); 决策9 的三分流与决策12 的同判定合并有对账兜底, 幸存; 决策13 用事实条目承载审计证据可行, 幸存; 决策7 的严格免问口径与决策10 去机制化的方向本身是用户的知情选择, 反方不改其方向, 只修其兜底.

**权重比较**: 正方幸存论点的核心是 "省用户精力 + 流程位置按新形态自排" -- 这些反方不否认. 反方最强幸存论点是 OPP-02+OPP-04 的合流: 样张里用户亲自点名的风险实例, 在新决策集下恰好从唯一能抓它的缝隙 (技术侧无闸门, 对账只看产品侧刺激结果) 漏过, 而 spec 是下游执行的权威输入, 忠实缺口不可逆地传给实施与验收. 影响范围: 两份 spec 全部判定性内容; 发生概率: 中 (样张已有一个实证, 免问占约一半情况); 不可逆性: 高 (错 spec 传导到 milestone-04 起的全部下游). 正方要保住 "免问不留痕 + 闸门只管 Gherkin", 必须先给出对账可靠性的实测证据 -- 决策集里没有; 反方只需指出证据缺口即占优.

**结论**: 决策集方向可守, 但 5 处需修 (OPP-02/03/04/05/07 对应的决策5/8/9/10/11 表述), 其中 OPP-04 (样张实例对不上闸门设计) 与 OPP-02 (TECHNICAL/正文无闸门) 不修正则 "忠实性由机检加子代理对账保证" 的 destination 承诺在新流程下不成立.
