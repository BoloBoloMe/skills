覆盖树盘问样张 - 粗细校准

milestone-02 演示材料 · to-spec-grilling-and-chinese-ids · 2026-11-25
要看清什么: 验收标准段以覆盖树为骨架盘问时, "问多细" 各长什么样, 粗细三档用两份现成大 PRODUCT.md 各反推一遍, 供选定档位; 同时核对盘问结论记录八字段草案是否够子代理逐场景对账。 假设: 盘问发生在落笔前, 样张用已写成的 spec 反推; 场景数是情况数的代理口径; "你 (拟答)" 是示例, 展示作答负担, 不规定答法。材料甲/乙是已关闭变更的时点快照, 只作演示材料。 编号口径: 条目按汉化后的编号规则称 目标N/规则N/非目标N; 拉丁标签 (@BR-001 等) 是落笔时机器生成的对账钩子, 盘问阶段不存在; 旧快照编号只在 "旧快照锚" 标注里作历史引用。
粗挂条目层: 每条目 1 问 "覆盖哪几类情况", 直译随问批报 中挂情况层: 每情况 1 问只定 "刺激→结果" 一句话, 直译按条目分批 细挂情况层: 每情况全字段 (前提/刺激/结果/阈值出处/排除项), 失败边界带追问

问数算式 (验收标准段, 不含背景/目标/规则段盘问)

样张 (同一批条目, 三档各问一遍)

怎么读这部分:
  • 样张 = 样品。拿两份已写成的旧 spec, 反推 "当初若用新流程盘问, 验收标准段会怎么问", 演给你看问多细各长什么样。
  • 每张折叠卡片 = 一个条目 (一条目标或一条规则)。卡片里是盘问对话, 三种角色: 问 = 盘问的 LLM 提出的问题; 你 (拟答) = 假想中你的回答, 只是示例, 用来看每问要你打多少字; 批报落盘 = 判定能从已确认规则原文直接抄出来的情况。已裁定 (2026-11-25): 批报不请你过目, LLM 直接记入结论记录 (标 "直译自规则N"), 真实盘问里你不会看到它; 样张里的批报块只是标出哪些情况不问你。
  • 底部悬浮条切粗/中/细 (←/→ 键), "换材料" 切甲/乙 (M 键)。切档不是换条目: 同一批卡片, 换成对应档对它们的问法; 卡片右上角标着当前档和本卡本档的 "问 N · 批报 N" 计数。切档不会把展开的卡片收起。
  • 卡片里问句带编号 (问 1, 问 2...)。注意: 中档每张卡开头是批报落盘块, 问句跟在后面; 乙材料非直译情况少 (21/48), 中档落盘占大头, 问句少是材料特点, 不是页面缺漏。
  • 批报为何存在: 直译情况没有要你拍板的成分, 问你就是浪费; 但机检只查格式不查内容, 直译情况必须留痕 — 全量写进结论记录并标出处, 落笔后子代理对账兜底: 核对 "直译自规则N" 的标注是否真有原文支撑 (不支撑 = 其实需要你决策, 走补问或重开)。裁定 "不看" 的代价 (你知情接受): 直译部分失去现场否决与查漏, 查漏改由子代理反向覆盖检查兑底 (m03 敲定)。
  • 粗 = 每条目只问 1 句 "打算覆盖哪几类情况"; 中 = 每种情况问 1 句 "什么刺激导致什么结果"; 细 = 每种情况问全 (前提/刺激/结果/阈值出处), 失败和边界还要追问。三档问数均已按裁定重算, 见算式表。

对账演练 (记录行 → 落笔场景 → 子代理逐项核什么)

记录行 (示例 1)

规则5 failure: 刺激 = 改共享配置; 结果 = 停止+请求批准+写入不发生; 阈值 = 四元组; 排除 = 只读不触发; 出处 = 现场。

落笔场景 (新格式示意, 文字取自旧快照 AC-011-2)

@AC-011 @failure @G-004 @BR-005
场景: 扩大写入范围需用户重新批准
假定 已批备注未批共享配置; 当 改为修改共享配置以构造场景; 那么 停止并请求用户批准; 而且 未批准的写入没有发生。

子代理逐项核

刺激 ↔ "当" 逐字对齐; 结果两件 ↔ "那么/而且"; 阈值 (四元组) 场景装不下 → 对账单备注 "由记录补"; 排除项不进场景 → 备注核对; 决策出处 → 对账单可回溯到轮次。机检 (check-ac.py) 只查格式与标签↔条目编号对账 (@BR-005 ↔ 规则5), 内容忠实全靠这一步。记录行标 "直译自规则N" 的, 子代理另核原文是否真支撑 (不支撑 = 需补问, m03 敲定回路)。

记录行 (示例 2)

规则4 edge: 结果含 "旧地址取状态记录旧 URL"; 决策出处 = 轮 2 新决策 (状态记录加字段)。

落笔场景 (新格式示意, 文字取自旧快照 AC-003 组)

@AC-003 @edge @G-003 @BR-004
场景: 实例已停机时用显式端口换端口并报告旧地址失效
那么 8091 上的基址与每个数据键的完整 URL 都能打开; 而且 原 8090 不再响应, 旧地址的值取自状态记录里留存的旧 URL, 不默认是 8090; 而且 输出明确报告旧地址已失效。

子代理逐项核

"旧 URL 不默认 8090" 这句如果没记录, 对账时答不出 "谁定的"; 决策出处字段在此直接兜住。反向也成立: 场景里冒出记录里没有的判定 → 判不忠实, 走修正回路 (回路形态是 milestone-03 的题)。

字段压力点 (够不够, 供你裁决)

1 大纲场景: 甲有 8 个场景大纲, 一条情况带参数表 (旧快照 AC-003-1, 按材料类型 4 行例子)。刺激字段装不下 4 组参数。候选: 刺激存 "参数表引用+列名", 对账按行展开; 或一行参数一行记录 (记录数翻倍)。
2 审计核对: 甲乙各 3 条审计规则无场景, 承接靠静态材料核对。情况类型需加 "审计核对" 枚举, 可观察结果填核对单结论; 但对账要引用证据材料路径 (依赖清单/锁文件对照), 现有字段只能挤进 "可观察结果" - 证据材料要不要单列?
3 决策出处的锚点格式: 只记 "现场+轮次" 够回溯吗? 轮次锚点用消息引用, 时间戳, 还是盘问会话内自增序号? 锚点格式不定, 分段续问时对账会断链。
4 批报条目 (正面确认): 直译情况的决策出处记 "直译自规则N 原文", 子代理按原文核对即可 - 现有字段装得下, 无需新字段。裁定 "不看" 后, 这个出处标注是对账核对直译的唯一线索, 更必要。
判断结果 (2026-11-25):
  1. 档位: 选定中档, 两份材料统一, 不按材料分档。裁定后中档问法 = 每种非直译情况 1 问 "刺激→结果一句话" (直译落盘不问), 问数代理口径: 甲 52 / 乙 21。
  2. 批报: 不请用户过目, 全量落盘备查 (已裁定, 见阅读说明)。
  3. 记录字段八字段: 压力点 4 已随批报裁定成立; 压力点 1 (大纲参数), 2 (审计证据单列), 3 (决策出处锚点格式) 拟移交 milestone-03 敲定 (记录格式归 m03 管)。
