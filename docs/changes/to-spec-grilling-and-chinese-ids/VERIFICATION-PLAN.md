## 验证方法与证据

用户确认的五类方法:

1. 流程要求: 非作者读取目标提交的真实技能条文和调用说明, 对照spec逐项核对遗漏与矛盾, 留实际原文位置及必要摘录. 搜索只能找候选位置, 不能用关键词命中代替语义核对. 结论只证明条文符合本次规格, 不证明模型执行稳定性.
2. 脚本功能: 非作者从公开CLI启动真实进程, 使用真实解析库和真实隔离文件, 核对输出, 退出码, 生成文件及错误处理. 保留输入/命令/输出/文件原件, 不能仅给测试全绿.
3. 并发保护: 保持脚本真实运行, 用操作系统级跟踪/进程控制暂停在校验完成而目标替换尚未发生的阶段, 第二真实进程修改同一合成目标, 再恢复并记录行为. 具体工具留给执行者, 必须能从外部事件序列证明控制位置与修改顺序, 不改脚本或替换内部函数. 只在校验前改文件, 替换后改文件或碰运气重复不能证明本项; 无法证明窗口命中记未验证. 方法本身无可行依据时先报方法缺口回前置调查, 不伪装为仅缺资源.
4. 编号与改动范围: 比较基线到最终目标的完整差异, 搜索现行旧编号与旧确认流程并逐命中分类, 判明历史引用/标签/文件名等例外. 留完整范围, 搜索原件及分类依据, 不以命中数充当结论.
5. 回归与格式: 跑既定to-spec测试, 默认全量pytest及改过的SKILL.md格式检查, 留收集范围/原始结果, 失败/未跑/跳过分列. 既有失败不自动豁免, 绕过前置条件的单文件测试不能替代全量.

流程场景的待验对象固定为候选条文, 机械场景从公开CLI实跑, 由PRODUCT与TECHNICAL规定; 不要求真实需求试跑. 本轮盘问和旧规格盘问都不是已实现新版的成品运行证据. 普通说明文字采用相关文本核对, 实际操作技能不按普通文档降低验证要求.
