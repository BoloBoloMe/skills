## 验证方法与证据

实际操作技能的条文和脚本均涉及行为变更, 不按普通文档维护降低验证要求. 产品已把流程场景的待验对象固定为候选条文, 把机械场景固定为公开命令行. 因此:

- 流程场景: 非作者读取目标提交中的真实候选条文和调用说明, 按原场景逐条核对所有预期, 留原文位置与摘录. 此项结论仅表示条文是否符合约定, 不表示模型实际执行稳定性.
- 机械场景: 非作者从目标提交的公开 CLI 启动真实进程, 使用真实解析库和隔离文件目录, 观察退出码, JSON, 文件与页面. 自动化测试作补充, 不代替这些 CLI 记录.
- 审计要求: 核对限定范围的实际条文, 变更差异及必要来源, 对可运行的格式约定实跑机检. 搜索命中逐条判读, 不能把命中数等同于失败数.
- README 等不改变操作语义的说明修改使用直接相关的文本核对. 没有另行承诺结构重排, 缺陷修复或性能改进结论; 若实施出现这些结果, 执行者按验证契约补齐相应开发证据, 不借此修改产品判据.

不要求真实需求试跑, 不把本次方案讨论或 milestone-04 的盘问当作新版成品运行证据.

表内环境和证据约定如下. 它们只是共用检查条件, 不是新增产品编号.

| 记号 | 含义 |
| --- | --- |
| 文本环境 | 检出目标完整提交, 产品文件干净, 只读候选条文和必要引用; 独立验证会话未参与本次实施与修复 |
| 命令环境 | 文本环境加 uv/Python, gherkin-official 与项目既有测试依赖, 仓库外真实隔离目录; 所有 Python 命令用 uv run python |
| 并发环境 | 命令环境加两个真实进程及操作系统级文件事件/进程暂停工具, 能证明修改发生在校验后与替换前; 不改脚本, 不替换内部函数 |
| 差异环境 | 文本环境加完整 Git 历史, 比较基线 182ff1846d0ed310b7f4ed308366d36f6e74b412, 当前目标提交及已安装技能只读记录 |
| 文本证据 | 目标提交, 原场景位置/标题, 候选文件位置与必要摘录, 对每个预期的对应关系及矛盾检查结果 |
| 命令证据 | 目标提交, 环境/依赖版本, 完整命令, 输入原件, stdout/stderr/退出码, 输出原件, 预期与实际逐项比较 |
| 差异证据 | 基线/目标完整提交号, diff 与搜索原始输出, 每个命中的分类理由, 文件清单及必要摘要值 |

同一运行可支持多行, 逐行引用同一原件即可, 不重复执行. 文本证据中不能只写 "有此要求", 须能定位实际条文并核对同文件与引用中的冲突. 原场景内多条 "而且" 全部必验.

## 前提, 限制与安排

1. **目标与独立性.** milestone-08 开始前由调用方提供含全部成品变更的完整提交, 不把当前规格提交当候选成品. 工作区与目标一致, 无未提交产品改动. 所有验证者须是本轮新开的非作者会话, 参与事实可核对. 本次只编方案, 不启动验证会话.
2. **分工与顺序.** 可将只读条文/差异核对与 CLI/测试分给两名独立验证者并行, 只在收益明确且资源可隔离时使用. 同一 CLI 工作区串行, 每种输入独立子目录. 宿主全量测试可在目标相同且目录隔离的条件下并行, 不能与作者修复争用工作区.
3. **依赖.** 所有机械检查用真实 gherkin-official 和真实文件系统, 不替换解析器, 内部模块或持久化操作. 路线图 notes 记录本容器曾缺解析包, 并转述过临时 --with 处理; 这不是本方案对安装的证明. 执行前核实当前镜像依赖, 缺包列清单经 mailbox 交宿主播种. 若继续采用 uv run --with gherkin-official, 必须记录实际解析库版本并确认与项目兼容, 不静默换新版本.
4. **全量测试.** 路线图记录容器缺 podman, 根 conftest 会受阻. 此处不计划在容器运行依赖 podman 的根测试. milestone-07/08 经已登记 host 会话请求具备依赖的隔离环境, 非作者从同一目标提交运行默认全量命令并交原件. 容器的 uv run pytest --noconftest tests/test_skills_codex_metadata.py 只能补充说明单文件结果, 不能替代全量. 测试配置与最终收集范围由执行者在指定目标核实, 本方案未查看实现或配置反推判据.
5. **既有失败.** notes 记录 general/present/tests/test_skill_contract.py::test_no_state_object_requirement 曾失败. 执行时仍收集并运行, 必要时在同条件基线复现以辨别归因, 不自动排除. 仍失败就记失败, 不宣称 pytest 全量通过, 不自行修复范围外产品. 须交调用方处理或交用户明确裁决, 标准若变化则更新方案重新确认.
6. **写入与保留范围.** 本方案确认包含下述验证资源范围: 调用方在仓库外创建本变更专用证据根目录, 路径含目标提交; 其内放合成暂存稿/草稿/隔离正式稿, CLI/pytest 缓存与输出, 页面和系统跟踪记录. 只覆盖为该次实验新建的合成文件, 不覆盖仓库正式规格, 已有证据或用户数据. 并发试验只修改同一实验目录中的合成目标. 实际绝对路径在派工前登记, 每次操作记录时间/命令/对象/结果; 以 git status 和实际写入清单检查范围, 以文件读取与摘要检查保留原件可访问. 额外资源另取授权.
7. **展示与数据.** CLI 预览可直接读取生成 HTML 或在隔离浏览器打开本地文件, 不新增对外服务或占用共享端口. 如确需已存在展示服务, 先查已确认入口并只挂专用预览目录, 按现行规则管理. 证据可读性检查不等于公开整份原始答复. 原始数据默认保留, 不在本轮自动清理; 敏感材料按共用脱敏规则处理.
