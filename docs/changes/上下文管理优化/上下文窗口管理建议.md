# 上下文窗口管理建议

> 基于 12 项独立研究 (2023-2026) 综合编制. 2026-07-15.

---

## 1. 核心概念

| 术语 | 定义 |
|---|---|
| **MCW** (Maximum Context Window) | 厂商宣称的最大上下文窗口, 如 128K/1M tokens |
| **MECW** (Maximum Effective Context Window) | 模型实际能有效利用的窗口, 通常远小于 MCW |
| **智慧区** | 输出质量无明显退化、无需额外工程措施的占用区间 |

**关键事实**: MECW 与 MCW 的差距可达 **5-100 倍** (Paulsen, 2025). 标称是存储容量, 智慧区是可靠处理容量.

---

## 2. 分层智慧区建议

| 任务复杂度 | 智慧区 (占 MCW%) | 128K 模型换算 | 1M 模型换算 |
|---|---|---|---|
| **简单检索** (字面匹配) | ≤50% | ≤64K | ≤500K |
| **常规 QA / 总结 / 代码理解** | ≤30% | ≤38K | ≤300K |
| **多跳推理 / 多步指令 / Agent** | ≤20% | ≤25K | ≤200K |
| **非字面语义关联** (含隐含推理) | ≤10% | ≤12.8K | ≤100K |

**保守策略**: 统一控制在 **20% MCW** 以内.

**依据**:
- NoLiMa (ICML 2025): 11/12 模型在 25% MCW (32K/128K) 时跌至基线 50% 以下
- Chroma Context Rot (2025): 18 个前沿模型全部随输入长度退化
- Du et al. (EMNLP 2025): 即使检索完美, 纯输入长度自身导致 13.9-85% 退化
- Digital Applied (2026): RULER 256K 仅 Gemini 3 超过 80%

---

## 3. 三大退化根因

### 3.1 注意力稀释 (Attention Dilution)

softmax 注意力预算是固定值 **1.0**. token 越多, 每个 token 分到的注意力越薄.

| 上下文大小 | 相关 token 注意力权重 | 稀释倍数 |
|---|---|---|
| N=10 | ~45.1% | 基准 |
| N=100 | ~6.9% | 6.5x |

### 3.2 位置衰减 (RoPE / Lost in the Middle)

- 模型对**开头** (primacy) 和**结尾** (recency) 关注最强
- 中间 30-70% 位置的性能显著下降, U 形曲线
- GPT-3.5-Turbo 20 文档测试: 答案在开头 76.8%, 在中间 53.8%
- 根因: RoPE 远距离衰减 + attention sink 效应

### 3.3 Attention Sink

初始 token (即使无意义) 消耗不成比例的高注意力权重. 删除早期 token 会导致性能崩溃 (Xiao et al., ICLR 2024). 这强化了 primacy bias.

## 4. 监控指标

| 指标 | 建议阈值 | 触发动作 |
|---|---|---|
| 上下文占用率 | >20% MCW | 启动渐进压缩 |
| 上下文占用率 | >50% MCW | 硬性压缩, 停止追加 |
| 关键信息位置 | 在中间 30-70% | 重排到开头或结尾 |
| 干扰物密度 | >30% 内容为无关 | 修剪干扰物 |
| 非字面匹配任务 | 任何长度 | 使用专门的 RAG 策略 |

---

## 5. 缓解策略分层

### 5.1 第一层: 上下文编排 (零成本)

```
优先顺序:
  1. 关键指令 / system prompt → 放在开头
  2. 当前问题 / 最新用户输入 → 放在结尾
  3. 支撑材料 / 检索结果 → 中间, 但检测位置
  4. 无关内容 → 移除或移到外部存储
```

- **开头黄金区**: 系统 prompt, 核心约束, 角色定义
- **结尾黄金区**: 当前任务, 最新问题, 关键证据
- **中间危险区**: 只放可丢失的参考材料

### 5.2 第二层: 压缩与修剪

| 策略 | 适用场景 | 触发时机 |
|---|---|---|
| **摘要压缩** | 对话历史, 工具输出 | 超过 20% MCW |
| **递归摘要** | 超长对话 | 每 N 轮或 token 阈值 |
| **干扰物修剪** | RAG 检索结果 | 每次检索后 |
| **去重** | 重复工具输出/错误重试 | 持续 |
| **硬性截断** | 超过 50% MCW | 强制 |

- 推荐使用 LLM 自身做压缩: "将以下对话历史浓缩为 200 字的摘要, 保留关键决策、错误和未决问题"
- 压缩频率: 每增加 10-20% MCW 执行一次

### 5.3 第三层: 检索增强 (RAG)

| 场景 | 是否用 RAG |
|---|---|
| 上下文 <20% MCW | 不必要 |
| 上下文 20-50% MCW | 可选, 长文档场景推荐 |
| 上下文 >50% MCW | **强烈推荐**, 多数模型此时内联 full text 不如 RAG |
| 非字面匹配任务 | **必须**, NoLiMa 证明 full context 在此场景退化最剧烈 |

- 超过 200K (非 Gemini 模型): RAG 几乎总是优于全量长上下文 (Digital Applied, 2026)

### 5.4 第四层: 架构级

| 策略 | 描述 |
|---|---|
| **分层记忆** | 短期工作记忆 (精简) + 长期向量库存储 + 按需检索 |
| **上下文隔离** | 子 Agent 独立上下文, 避免交叉污染 |
| **检查点/卸载** | 中间状态存外部, 需要时注回 |
| **多 Agent 模式** | 检索 Agent + 合成 Agent 分离, 各自小上下文 |

### 5.5 高级技术

- **证据先读 (Recite-and-Answer)**: 提示模型先复述相关证据再解题, 在 RULER 上提升 GPT-4o 达 4% (Du et al., 2025)
- **注意力校准**: 减去位置偏差, 恢复中间位置的注意力 (Ms-PoE, NeurIPS 2024, 提升 3.8 分)
- **Attention Sink 保留**: 当使用滑动窗口时, 保留前 4 个 token 作为 sink, 避免性能崩溃

## 7. 实施清单

### 日常使用
- [ ] 控制上下文占用 ≤20% MCW (保守)
- [ ] 关键信息放在开头/结尾, 不放中间
- [ ] 超过 30% MCW 时检查是否有可压缩内容
- [ ] 工具输出在引用后及时压缩, 不保留原文

### Agent/自动化系统
- [ ] 实施 token 监控, 在 20/50/80% 分段触发动作
- [ ] 对话历史定期自动压缩
- [ ] RAG 检索结果做 rerank + 剪枝, 控制注入量
- [ ] 错误重试/循环输出限制保存次数
- [ ] 子 Agent 使用独立精简上下文

### 选型决策
- [ ] 按实际任务复杂度选择模型, 而非只看 MCW 数字
- [ ] 非字面推理任务优先选用智慧区大的模型 (如 Gemini 3)
- [ ] 方案设计时假设有效窗口 = MCW × 20% (保守) 到 × 50% (乐观)
