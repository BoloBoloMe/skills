### 待核实疑点

1. **D001 的指针触发范围比被合并的规则窄.** benchmark 当前只写"影响调查的一次性证明脚本"沿用 blast-radius; 其他为测量机制而做的一次性实验是否也必须加载完整边界, 没有明确写出. blast-radius 的现行条款确实覆盖非正式 TC, 临时脚本/数据, 内部函数证明, 停止后台进程, 未运行场景和新正式测试交回; SAFETY 也明确数据默认留存及写入授权. 所以边界内容并非当前缺失, 风险在删除 benchmark 正文后指针是否覆盖所有测量实验分支. 建议 AC-06-01 要求 benchmark 明说任何一次性实验都须读 blast-radius 对应节, 并保留仅属测量的后台进程停止/数据位置记录. 证据: `workflow/benchmark-checklist/SKILL.md:25-38`, `workflow/blast-radius/SKILL.md:72-85`, `workflow/verification-contract/SAFETY.md:11-22`.

2. **D003 的判据隔离条款只部分显式承接.** D008/AC-06-03 保留"不是产品判据"和"不作为 verify-change 输入", 并把旧报告交给下一轮影响审核者核对闭环, 总指挥负责分流, 因而主要读者链仍在. 但 D003 原文的"不作为 code-review 输入判据"未明文保留. 新方向与 Standards/Spec 并列, 理应独立运行; 现有 Spec reviewer 只被要求使用 spec, issue 和验证契约. 这些安排可能足以维持隔离, 但还没核对实现后的 reviewer 提示词和汇总格式, 不能证明旧报告不会影响 Spec 判定. 建议明确允许它作为旧行为方向的闭环材料, 禁止它成为 Spec 判据.

3. **返工后的复查是否仍按新方向执行, 文字承接不够直接.** 旧 drive-execution 明定修复合并且整体验证通过后, 对新集成提交重新做影响复查. 当前 AC-06-02 改写了正常顺序与门槛, 但没有逐字确认返工循环重跑旧行为方向. drive-execution 原有重构段仍写修复需经过"影响复查与评审", 可能自然承接; 迁移实施时如何改写该句尚未发生. 不能判为已丢失, 但应纳入 AC 的可核对条件.

4. **D008 的方向名称并未自动保证评审隔离.** 当前 code-review 固定两名 reviewer, 两份 Standards/Spec 输出, 并禁止跨方向合并排序. D008 增加第三个可选方向并要求结果进入 code-review 汇总. 账本称其并列, 但没有规定 reviewer 是否单独运行, 汇总怎样保留三方向边界. 若实现把影响发现并入 Spec, 会直接违背 D003 的判据来源理由; 现有文本尚不足以证明会发生, 因为 AC 也要求并列方向. 应在实现验收时核对三方向的独立输入, 报告栏目和分流方式.

## 反方立论

应把判断标准定为"共同规则集中维护, 调用入口明确, 原有独立审核与逐轮证据可追踪". 按此标准:

- D001 可保留单一维护点, 但 benchmark 必须指明所有一次性实验均读取 blast-radius 的边界, 测量特有的数据位置与停止结果继续记录.
- D008 可以把调查放进 code-review 的同一次调度, 但必须保持它是独立方向, 每轮由未参与实现与修复者执行, 写足证据和未证实边界, 免做理由有稳定落点, 返工后按门槛对新集成提交重跑. 旧报告只供该方向闭环, 不进入 Spec 判据, 也不进入 verify-change 判据.
- D005 选择人工方式可以成立, 前提是指明调用图的现存权威位置或明确怎样从 skill 正文核对执行调用. 没有图时, 要求维护者核对一份未定义的图无法复查.
- D006 应先按当前安装目录事实修正前提, 再比较保留轻量组合入口与删除后手动执行两步的成本. `deliberate` 的落账和反方职责不能充当轻量入口的等价证据.
- D004, D007 可按现有方向继续: navigate 已保留由用户逐项确认, 术语清单也覆盖账本已知的评审语境位置.

## 幸存与比较

正方仍有充分成立的部分. F001/F002 与两份正文相符: 实验边界有实质重复, `blast-radius` 的清理规则和 SAFETY 的数据/授权规则覆盖共有部分; D001 不把所有测量要求搬进 SAFETY, 职责理由成立. F003/F004 也支持保留旧行为调查而非整段删除; D008 的免做条件与 D002 条件相同, 总指挥分流, 下一轮读取旧报告, 报告不新增产品判据及不进入 verify-change 判据均有文字承接. D004 与 navigate/验收指南/verify-change 的现行分工相容. F011 支持保留 Standards 方向的仓库规范与 Fowler 基线双来源. F012 的用词分布与 D007/AC-06-09 列出的主要文件相符.

权重比较: D006 的错误前提直接影响"删除不损失现存入口"这一理由, 但影响范围集中在一个轻量 skill, 可在裁决前用安装状态和调用步骤修正. D008 的遗漏范围更大, 因为它影响每个经 drive-execution 的集成轮; 若独立性或证据记录弱化, 可能让旧行为回归在产品核验前漏过. 发生概率无法从未实施的规则估计, 但影响代价高于保留一次多余入口. 即使接受 D008 的集中调度和减少空转理由, 反方仍占优: 保留调查本身是对的, 可现在的 D008/AC 没有把它为何可靠的审核独立性和证据合同全部写全. 因此不能以"D002 原样承接,D003 由汇总承接"视为已证明完整.
