## 4. 反方反驳

事实依据:

1. 收录标准原文: "收录标准: ≥2 个 workflow skill 共用, 或单 skill 使用但定义非显然; 一眼自明的词不收. 新词须经用户审定才落盘." (F001 固定提交, 本轮复读一致). [事实]
2. 活跃 workflow 正文当前没有任何 skill 把 MVP, PoC, demo 或 (D008 清理后的) 迭代 当术语使用 (第 1 节第 2/3/4 条). [事实]
3. 实施后格局: milestone-03/04 之后 navigate 将使用 PoC 与 demo 作为里程碑类型名, prototype skill 改名 demo; MVP 在可预见范围内没有任何 workflow skill 使用; 迭代经 D008 清理后反而没有任何 workflow skill 使用. [事实+推断]
4. 推理: "≥2 个 workflow skill 共用" 与 "单 skill 使用但定义非显然" 是两个析取支. MVP 与迭代两个词条按第 3 条格局两个支都不满足; PoC/demo 可勉强经 navigate (单 skill 使用且定义非显然, 盘问已证非显然) 满足第二支. 末句 "新词须经用户审定才落盘" 即便算满足 (Q9/Q16 盘问可视为审定), 字面上也只是必要条件, 不是豁免前两支的例外条款. [推断, 置信度: 高]
5. 正方最好的辩护读法: "单 skill 使用" 可以读作新 skill 自身 — 词条由它定义并将在未来被调用方使用, 且定义经盘问证明非显然, 故第二支满足, 无矛盾. 该读法能自洽, 但它使准入条款自我指涉而空洞化: 任何用户要加的词都能以 "本表定义了它" 自证准入, "≥2 workflow skill 共用" 的防蔓延门槛对通用词永远失效. [推断, 置信度: 中]
6. 后果: 无论采用自然读法 (矛盾) 还是自指读法 (条款空洞化), 账本都没有记录采用哪一种, 也没有记录收录标准对今后新增通用词条是否适用. milestone-02 实施者面对多种合法读法却无裁决可依: 照抄规则写出自相矛盾的文件, 或改动规则文字违反 D003 "迁移不改变含义", 或采取自指读法默默放弃防蔓延门槛. 三选一的裁量权按 D012 都在用户. [推断, 置信度: 高]

明确边界: 本反驳不针对 D004-D007 的概念定义本身 — 我未找到能推翻其中任何一条的论证 (见第 6 节). 也不以 "更喜欢别的名字或更窄触发" 为由攻击 D001/D002: 那是用户 Q1/Q3/Q8 明示偏好.
