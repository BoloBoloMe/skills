# present 统一局域网交付 Product Spec

## 背景

present skill 现在按 SSH 环境变量分两条路: 本地起 Chromium 打开页面并把 HTML 文件路径交给用户, 远程才起 web 服务交付 URL, 而两条路都要求页面提供状态对象供回读. 用户要求统一成一条: 不管 agent 跑在宿主还是容器, 都生成页面, 起或复用常驻展示服务, 把已确认可用的局域网地址交付给用户, 服务长期运行直到显式 stop. 提出方是用户本人; 受益者是拿 agent 会话看展示页的用户, 以及同机器上多个共用展示服务的会话.

## 目标

- G-001: agent 展示内容时只有一条交付路径: 页面挂到常驻展示服务上, 交付的是已确认可用的局域网 URL, 不再是文件路径或本机 loopback 地址.
- G-002: 同一机器同一用户共用一个常驻展示服务, 多页多目录复用同一入口, 调用结束或会话断开后服务仍在, 只有显式 stop 才关闭.
- G-003: 地址和端口来源明确: 宿主按 本次明确指定 → 已确认局域网地址记录 → 探测候选并请用户确认 依次取值; 容器按已确认宿主局域网地址与容器 8800 的宿主映射端口取值; 拿不到值就报告缺口, 不拿未确认地址冒充可用.
- G-004: 去掉本地浏览器分支和页面状态回读通道: 页面仍可按需交互, 反馈和最终确认都在 chat 完成.
- G-005: 端口记录与实际监听一致: 服务重建或换端口后记录同步更新, 交付的 URL 跟着实际端口走.

## 非目标

- NG-001: 不做认证, TLS 或访问控制, 不缩小已接受的局域网开放面. (理由: 用户已确认接受同网段主体可读全部挂载目录, 只要不整棵挂出仓库根或敏感目录.)
- NG-002: 不承诺跨系统重启或容器销毁后的恢复, 不新增系统服务或常驻监控器. (理由: 用户要的是调用不自行退出, 不是跨生命周期持久化.)
- NG-003: 不改多目录命名空间: 不做每目录 URL 前缀, 不新增移除挂载目录的接口. (理由: 用户选择保留既有扁平并集与共享 stop 语义.)
- NG-004: 不改 access-web 自身的浏览器能力, 不改 navigate 的展示服务. (理由: 本次只统一 present 的交付方式; navigate 的稳定性修复属于另一个里程碑.)
- NG-005: 不评估上线后的效果, 例如触发率, 遵从率, token 节省或使用频率. (理由: 本次完成边界是交付方式改造与可复查证据, 没有观测通道.)

## 业务规则

- BR-001: 宿主首次启动的端口由调用方在 49152-65534 内选, 被占返回 port_in_use 后换端口重试, 最多 10 次; 容器固定监听 8800 并锁端口, 被占直接报错, 不换端口.
- BR-002: 宿主交付地址按顺序取: 本次调用明确指定的局域网地址, 其次宿主已确认局域网地址记录, 再次探测候选地址并请用户确认. SSH_CONNECTION, 主机名和 localhost 都不作为交付地址.
- BR-003: 容器内的交付地址取已确认的宿主局域网地址和容器 8800 对应的宿主映射端口; 服务自报的容器视角地址不作交付; 缺值先按当前环境说明自查, 仍缺时经可用信箱向创建容器的宿主会话索取, 信箱不可用才问用户.
- BR-004: 地址或端口映射未确认时报告阻塞缺口, 不用文件路径或 loopback 链接代替交付, 不猜地址和端口.
- BR-005: 同一机器同一用户只跑一个服务和一份运行时记录: start 遇到存活实例且 bind 一致时幂等复用并把新目录挂进去, 同一目录重复增挂不产生重复项; bind 不一致返回 bind_conflict 并提示先 stop, 不静默复用.
- BR-006: 端口真值只有一份: 记录写在系统临时目录的用户级子目录 (pi-present-web-<uid>/server.json), 含 pid, port, bind, roots, started_at, fixed_port, 其中 port 是实际监听端口, 宿主的发布端口不混写进来; 读取记录后仍要真实探活, 残留记录不算存活.
- BR-007: status 在记录存在而服务已死时, 按记录里的原挂载清单重建; 非锁定实例的原端口被占可以换端口并原子更新记录; 锁定实例 (容器) 只试原端口, 被占报 port_in_use.
- BR-008: present 调用结束, 会话断开或收工都不停止服务; 不设空闲自动退出.
- BR-009: stop 关闭该用户全部共用页面, 调用方必须说明这一影响, 不在收工清理里执行.
- BR-010: 多目录用扁平并集: 请求按挂载顺序取首个命中, 同名文件由先挂载者静默遮蔽, 顶层目录 listing 为各目录条目并集去重.
- BR-011: 控制面端点只接受本机来源, 即 loopback 来源或源地址等于服务实际绑定的地址; 其他来源一律拒绝.
- BR-012: 规范化后逃出任何一个挂载目录的请求 (含 ../ 以及指向目录外的 symlink) 一律 404; 落在挂载目录内的合法路径照常返回.
- BR-013: 每次展示前页面都过 check_page.py 自检, 自检失败不交付; 页面不再必须提供 __PRESENTATION_STATE__ 状态对象.
- BR-014: 本变更不新增认证, TLS, 自动到期清理或状态回传接口, 删除 present 专用浏览器脚本与本地打开/状态回读流程, 不修改真实已安装 skills, 不运行会改安装目录的同步, 不声称安装效果或模型行为已验证. (审计)
- BR-015: 测试与验证使用独立运行时目录与端口, 不停止或接管正在展示的真实实例; navigate 等其它服务不与 present 共用实例或运行时记录. (审计)
- BR-016: 验收时必须分别提供宿主与容器两种环境的真实局域网访问证据, 即真实设备打开页面并能与本次展示的请求对上; 一种环境的证据不能代替另一种, 缺哪个环境就记未验证, 不用本机自测或源码推断顶替.
- BR-017: 首次在某个环境使用展示服务时向用户说明一次开放风险, 即同网段主体可读全部挂载目录, 且只挂愿意公开的展示目录, 不挂仓库根或敏感目录.
- BR-018: 同一话题复用同一个展示目录, 每页文件名以当天日期 YYYY-MM-DD- 开头且不重复; 生成新版本时另存新文件, 不覆盖旧版本.
- BR-019: 展示服务默认监听 0.0.0.0, 不按 SSH 环境变量决定是否对外; start 的 --bind 仍是显式必填参数.
