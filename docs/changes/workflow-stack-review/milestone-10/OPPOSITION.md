## 正方还原 (steelman)

- 定义/主张: 执行哲学从「先规定做法再验」转向「实现走最短交付路径, 可验证版本出来后从真实入口跑端到端, 修复后重跑同一端到端, 循环到闭环; 拆任务按垂直切片; 判据重心在交付物经真实运行达到要求, 不在过程顺序」.
- 前提假设:
  - P1 对 LLM 执行者, 规定实现过程 (红绿顺序) 不产出质量, 只产出表演性合规; 质量来自证据口径 (P4 的反面表述).
  - P2 tdd 的可保留内容已在 verification-contract 与 diagnosing-bugs 更权威地存在 (F002), 迁移物只是写法细节 (F003), 删除无行为损失.
  - P3 同义文本必须唯一维护, 否则必然漂移 (milestone-06 D004 的仓库先例).
  - P4 端到端真实入口证据比单元级/分层证据更难造假, 入口层级不限定时弱证据可以冒充 (F005: 现行行为变更证据只说「一条真实运行记录」).
- 论据: F001 (无调用方), F002 (三处重叠), F010 (INVENTORY 早已把红绿降级, 删除是既定轨迹的最后一步), ADR 0022/0023 的演进记录, F005 (四段笼统原文), F004 (起草完成标准缺端到端可判项).
- 推理链: 无调用方 + 内容已收编 (P2) → 删除是纯简化; 红绿顺序属过程规定 (P1) → 与新哲学冲突, 删; 闭环措辞不可落地 (F005) → 改写并唯一维护在 verification-contract (P3); 判据重心转移 (P4) → 证据口径重写 + 完成标准补可判项.

四要素中无无法确定项; 唯一解释自由度是「端到端」的含义, 按 roadmap 原文与 D005/D006 文本取「从真实使用入口的整链验证」, 不按 benchmark-checklist 的性能专用义.

## 主战场

攻 **P2 + P3 的合取**: 「被删内容已在别处更权威地存在」且「唯一维护处能守住不漂移」.

理由: D001 的全部正当性压在 F002/F003 的完整性上 — 若收编/迁移有漏项或本身制造了第二维护处, 「删除无行为损失」变纯损失, 「唯一维护」变三处同文, D001/D002/D008 同时塌. D004 依赖的 F004 也在同一类「事实条目是否与代码一致」的弱点上. 这不是外围措辞问题: 账本的裁决力量恰恰来自「事实准确 + 单点维护」, 攻事实失真等于拆整个账本方法.

- 主张: 「从真实入口验证/端到端」作为判据, 活跃正文里至少还有四处在讲, 闭环机制的唯一维护不等于概念唯一维护.

## 反方立论

替代主张: **把「删除」与「收编」拆成两步, 收编先于删除, 且收编按逐条映射而非原样搬迁.** 具体形态:

1. 收编完整化: 在账本里放一张 tdd 逐条映射表 (每条旧规则 → 落点或「有意丢弃+理由」), O6 的「生产特殊状态」与 O7 的「意外通过/环境归因」两条要么收编要么明示丢弃理由; 这张表是「删除无行为损失」的唯一可查证明, 现在的 F002 三句话承担不起.
2. 迁移改并条: `reference/mocking.md` 的边界清单并进共用底线条后删重复清单, 只留 SDK 风格接口等底线条装不下的细节; 或反向 — 底线只留一句+指针. 二选一, 不允许清单与底线条长期并存 (O4). 设计期指导 (依赖注入) 若保留, 落点应是 codebase-design 或 to-spec 的接缝与依赖说明, 不是验证 skill 的 reference (O5).
3. D004 并条: 新增项并入既有「每个切片能从真实入口独立验证且可独立交付」, 只补「并可演示」; 同时补「预重构/准备类 issue 由其承接 AC/BR 的方式证明价值, 不适用可演示判据」的例外 (O2, O3).
4. D009 配套一句 verify-change: 作者材料仍属旧观察, 但仅对照, 不得作为任何必验项的通过依据 — 与现行「关键真实路径只取本轮实跑」合流 (O9).
5. 程序项: 关闭里程碑前先落 AC-10 (哪怕只有一条「账本与 ADR 0025 已落盘且相互一致」), 消悬空引用 (O1); 顺手裁决 diagnosing-bugs 调用语义 (O8), 或在账本记「维持现状及理由」.

依据: 仓库自己的先例支持这个形态 — INVENTORY 的「协作类: 保留文件, 从强制链摘除」证明降级不等于删除; milestone-06 D008 迁移影响复查时保留了完整证据构成清单作承接证明; milestone-06 D004 证明本仓库把「单点维护」当硬约束执行. 正方自己最有力的部分 (证据口径重写, 闭环改写) 一条都不需要「原样迁入的参考文件」来支撑.
