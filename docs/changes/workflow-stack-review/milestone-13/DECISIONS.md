## 事实

### F001 沙箱容器内没有容器运行时
- 状态: 当前有效
- 来源: 容器内 `docker -v` / `podman -v` 均 `command not found`; 宿主侧 `use-sandbox-worktree` 脚本用 podman
- 内容: 本仓库的 agent 会话跑在沙箱容器里, 容器内既无 docker 也无 podman 且不可安装; 宿主拥有容器运行时. 这是 D003 的前提.

### F002 ccsh 的运行时要求与能力边界
- 状态: 当前有效
- 来源: `docs/changes/workflow-stack-review/milestone-12/FINDINGS.md` 2.1 与 5.1 (官方文档 + 子代理实测)
- 内容: 分析端 `npm i -g codecharta-analysis` 要 Node 22.19+ 与 Java 22+; 官方 Docker 镜像绕过该要求. 只有它的 dependencyparser 直接输出层号 `level`、`isCyclic`、`isPointingUpwards`; 其余候选工具只出图, 层号要自己算.

### F003 CodeCharta 前端资产可独立使用
- 状态: 当前有效
- 来源: `milestone-12/FINDINGS.md` 5.2 实测
- 内容: 官方 `web.zip` (vis-2.9.1, 3.5MB, 解压 46 文件 6.2MB) 是完整离线静态前端, 接受自造 cc.json; 自定义属性 `layer` 可绑成建筑高度. 前端从 `file://` 打开会因 ES 模块 CORS 白屏, 必须走 http.

### F004 本仓库 present 的静态服务没有深链回退
- 状态: 当前有效
- 来源: `general/present/scripts/web_server.py` (grep `404`/静态查找分支)
- 内容: 该服务对未命中路径直接 404, 不做 `index.html` 回退, 也不做 SPA 路由; 因此它不能直接托管 CodeCharta 这类 HTML5 history 前端, 需要自建服务或 nginx 的 `try_files`.

### F005 python http.server 也解决不了深链
- 状态: 已变更 (→ F011, 结论不适用于 vis-2.9.1)
- 来源: `milestone-13/BUILD-PROBE.md` 第 2 节 (curl 实测)
- 内容: 用 `python3 -m http.server` 托管构建产物时, `/` 可进, `/dependency` `/metrics` 返回 404; 页签切换会改路径, 刷新即 404. 上游 Dockerfile 用 nginx 默认配置, 同样有这个坑.

- 来源: 用户陈述
- 内容: 宿主能直连 `github.com` 与 npm registry, 因此首次构建的 clone 与 `npm ci` 不需要代理.

### F007 本节点裁决没有下游 skill 依赖
