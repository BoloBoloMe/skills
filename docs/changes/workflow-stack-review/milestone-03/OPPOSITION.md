## 反方立论

否定 P5 之后世界应该是什么样: 类型切分的轴不该是 "藏在库里还是只能靠跑" (这是查证方式的轴), 而该是两条更硬的轴 — 证据怎么产生 (只读查已有记录 vs 必须新实测) 和结论为什么服务 (给方案可行性判据 vs 描述现状). 按这两条轴:

- research: 暴露已存在的事实, 只读查证, 内外皆可, 不新造数据.
- poc: 必须新实测, 且结论用于判定某个方案的可行性/适用范围, 未证实保持未完成.
- 现状测量类 (必须新实测, 但不为方案判据服务): 显式归 task, 在 task 或 poc 的类型条目里加一句指派, 例如 "需实测产生但不以方案可行性为判据的内部结论 (现状测量, 基线采集) 属 task".

这个立论不推翻用户的任何既有选择: demo/poc 分家, research 删实验半句, 会话粒度的默认值全部保留; 它只要求补一句被遗漏的指派, 和把 D010 的拆分判据明确为结论边界 (会话一句降级为默认描述). 依据: 现有五类型加 poc 的枚举里 task 本来就是兜底的 "实际完成的工作", 指派一句话的成本远低于将来现场每次判错; 且 milestone-01 D012 已立规矩 — 反方发现需要新增或改变决策的点, 交用户裁决, 代理不拍板. 所以本报告的落点是: milestone-04 动 navigate 正文之前, 把上面两处缺口列成待用户确认的新增决策, 不默认按现账本文案实施.
