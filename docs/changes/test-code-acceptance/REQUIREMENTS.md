# 测试编写与人工抽查验收要求

来源: 本次用户指示. 本文件只记录本次要求及其落点, 不修改旧变更的产品标准.

## 已确认要求

1. 禁止 mock 持久层. 用内存假持久层实现测试接口行为, 不能证明项目真实持久层正确.
2. 项目现有技术栈能完成的验证, 不另引 Bash/Python 等新技术栈. 为调查或核实事情而写, 不验证系统真实功能的代码, 属于手动验证代码; 可以放测试目录, 但不算功能测试.
3. 工作流增加必做的测试代码验收. 我抽查是否符合规范, 不要求我通读全部测试代码. 亲审后确认: 测试抽查规则不在 `drive-execution` 中体现, 撤回该 skill 正文与编排参考中的本次新增规则.
4. 亲审后确认: 有/无相关变更的分支与完成标准统一维护在 `workflow/verification-contract/reference/tests.md`, navigate 只引用该规则. 手动验证代码不接入默认测试发现或 CI 的现有规定不改.

## 本次落点

- `workflow/verification-contract/`: 统一维护编写规范与人工抽查步骤, 明确真实实现/存储与内存假实现的区别. 同时补充数据/状态隔离与不得吞异常/删断言变绿的基本检查; 保留原有每个测试只有一个逻辑断言的口径.
- `workflow/code-review/`: Standards 评审携带测试规范, 不把全绿等同于正确, 不代替人工抽查.
- `workflow/to-execution/TEMPLATES.md`: 完成定义保留正式交付前的人工抽查, AFK 不代替人工确认.
- `workflow/navigate/`: 最终人工验收单列测试代码验收结果, 分支与完成标准引用 verification-contract 的规则. 产品功能仍逐项验收.
- `verify-change` 继续只按已确认 PRODUCT.md 做独立产品核验, 不增塞测试代码判据, 不新增 skill/调用边/路线图类型.

## 验证约定

本次改变 skill 的实际操作要求, 按行为变更验证, 不以 Markdown/关键词检查代替行为验证. 用全新非作者会话读取仓库当前 skill, 对持久层替身, 存储差异, 既有技术栈, 手动代码分类, 抽样选择, 返工和未获人工接受的场景实际作答, 保存原始输出并逐项核对. 另检查 diff, 相对链接与流程衔接. 未真实执行整套开发/人工验收流程, 不声称已完成该范围验证.

本次要求, 复核结论与验证材料统一保存在本目录, 验证记录见 [VERIFICATION.md](VERIFICATION.md). 本次只改 Markdown 规则与记录, 无测试/手动验证程序或运行配置变更; 不虚构测试代码抽查或人工接受记录.
