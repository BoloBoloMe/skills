# 产物机械化决策账本

本账本按当前可用流程记录, 不依赖尚未实现的新产物程序. 用户已结束本轮方案对齐, 授权落盘和创建新分支, 未授权开始实现. 原始表述见 [REQUEST.md](REQUEST.md), 已采纳的完整方案见 [PROPOSAL.md](PROPOSAL.md). 下列决定是改造目标, 不代表现有代码已经满足.

## 决策

### D001 整条消费链一起机械化
- 状态: 当前有效
- 约束性: 必须遵守
- 内容: 本次覆盖决策账本及规格, 验证方案, 执行拆分/issues, 实施与评审登记, 独立验证和人工验收记录, 同时适配路线图与所有实际消费者. 不仅改变 to-spec 的输出后缀, 也不允许下游继续依赖旧 Markdown 节名和手工格式交接. 理由是只改上游会把格式维护和错误继续推给下游, 无法保证整条链的引用和状态一致.
- 依赖事实: F007
- 预计影响: workflow/decision-ledger/, workflow/to-spec/, workflow/to-execution/, workflow/drive-execution/, workflow/code-review/, workflow/verify-change/, workflow/navigate/ 及共享约定和相关消费者.
- 实际影响: 本次仅方案及决策落盘, 实现未开始.

### D002 程序与 LLM 和用户的职责分开
- 状态: 当前有效
- 约束性: 必须遵守
- 内容: 程序负责可确定判断的结构, 引用, 版本和状态约束, LLM 负责内容及语义检查, 用户负责裁决与验收. 动作字段存在不代表它只含一个刺激, 覆盖标签存在不代表内容真的覆盖, 证据路径存在不代表证据支持通过. 理由是这些语义不能用确定性格式校验可靠证明, 不能将程序通过或检查记录存在当作用户已接受或内容已正确.
- 预计影响: 共用产物程序及所有 skill 的检查与结论口径.
- 实际影响: 本次仅记录职责划分.

### D003 仅流程需要的内容结构化
- 状态: 当前有效
- 约束性: 必须遵守
- 内容: 决策账本, 产品/技术规格, 验证方案, 执行计划/issues, 路线图, 必要评审登记, 逐项验证及验收记录纳入结构化程序管理. 目标, 非目标, 业务/审计要求, 场景与例子, 约束强弱, 入口/观察依据, 覆盖/依赖和对应版本需要可定位. 不把 Markdown 模板原封不动变成大量无用途字符串字段. 理由是字段应服务于读取, 校验, 引用或展示, 而不是继续承担原先没有实际价值的形式负担.
- 预计影响: 共用数据结构及各生产者/消费者.
- 实际影响: 新格式尚未实现, 本次不手写 JSON 冒充程序产物.

### D004 报告保留 Markdown, 原件保留原形
- 状态: 当前有效
- 约束性: 必须遵守
- 内容: 调研, PoC, 代码评审, 独立验证, 影响调查及运行汇总等报告适合保留 Markdown 正文, 由 LLM 直接读写. PoC 可以交付小程序, 文档或实验数据; 产品/测试代码, 日志和截图保持原有形态. 程序只登记报告位置, 对应版本, 关联任务及流程所需结论, 不解析自由正文自动判通过, 不将全文复制为第二份 JSON 权威正文. 正文与登记结论一致性由 LLM 核对. 登记后修改报告需重新登记, 已用于完成/验证记录的版本保留. 理由是论证和原始材料不适合强拆字段, 但流程仍需可靠知道用了哪份材料.
- 预计影响: 报告生产者, 评审/验证登记, 证据引用及 present 文档模板.
- 实际影响: 报告格式未改, 本次方案本身也是 Markdown 文档.

### D005 输入按类型读取, 输出由环节职责决定
- 状态: 当前有效
- 约束性: 必须遵守
- 内容: 结构化输入通过所属程序查询, Markdown 文档或其他非结构化原件直接读. to-spec 可以独立接收一份足够明确且已确认的需求文档, 再通过程序生成结构化规格, 不要求先给所有信源转换格式. 用户在 Q9 选择 A, 明确修正输入非结构化就一律输出非结构化的歧义. 调研/评审报告仍按自身职责输出 Markdown, 不为规格/计划/issues 建立按输入格式切换的两套执行模式. 理由是读取方式与输出职责不同, 只有这样才能接入真实文档输入又保持新规格链的机械化.
- 预计影响: 独立调用入口, to-spec, verify-change 与所有混合输入消费者.
- 实际影响: 本次记录规则, 未实现读取入口.

### D006 单一权威数据与稳定引用
- 状态: 当前有效
- 约束性: 必须遵守
- 内容: 结构化产物是其内容的唯一权威数据, 页面和需要的导出是程序视图, 不平行手工维护 JSON 与 Markdown 正文. 保存稳定 ID 与来源产物, 条目或范围, 对应版本和引用用途, 区分判据, 操作依据和证据. 不再依赖固定节名或复制全文交接. 外部文档按实际原文位置和内容版本定位, 不强造原文编号. 理由是同一编号不等于同一内容, 重复正文和隐含来源会引入交接漂移.
- 预计影响: 共用产物程序, 账本/规格/计划/报告引用和网页模板.
- 实际影响: 尚未变更现有引用格式.

### D007 保留现有产物根目录规范
- 状态: 当前有效
- 约束性: 必须遵守
- 内容: 本次机械化继续使用现有产物根目录定义: 默认 docs/changes/<feature-slug>/, 调用方可指定其他位置; 同一交付单元可跨多个里程碑并共用根目录, 不按里程碑编号强拆. 产物间相对引用基于根目录解析, 外部信源和账本按实际位置解析. 不为解决展示访问问题另造本地目录规范. 理由是目录已经表达不同需求的归属, 访问映射不能反过来破坏该约定.
- 依赖事实: F003
- 预计影响: 共享约定, 全部产物程序, 路线图引用和展示登记.
- 实际影响: 现有目录定义未改.

### D008 路线图不是其他 skill 的前置条件
- 状态: 当前有效
- 约束性: 必须遵守
- 内容: 保留各 skill 独立使用能力. 路线图只串联和使用产物, 是路线图需要它们, 不是它们需要路线图. 可复用已有合格输入, 不强制每次补走全链; 有无路线图不改变内容要求. 展示交付单元或单份产物也不能要求建立 ROADMAP 或补造里程碑. 理由是查看一份规格或独立处理任务不应承担无关领航手续.
- 依赖事实: F008
- 预计影响: 各 skill 入口, 统一网页路由及产物查看器.
- 实际影响: 当前独立调用能力保留为改造约束.

### D009 共用产物程序取代手写格式
- 状态: 当前有效
- 约束性: 必须遵守
- 内容: 结构化数据读写统一经程序提供的创建/编号, 局部查询, 批量修改, 校验, 冻结, 确认记录, 转正, 登记和状态操作. 查询只返回所需范围, 修改成功返回变动和版本, 失败定位问题且不覆盖上次有效内容. 并发写入防丢失, 跨工作树合并后重核引用与版本. 草稿允许暂时不完整, 在提交审阅/转正/领取时检查对应完整性; 预期输入与已经就绪输入要区分. 理由是机械化应降低内容之外的负担, 不能变成每填一个字段就搬运整份 JSON 或要求草稿一开始就完整.
- 预计影响: 新共用产物程序, roadmap.py 公共能力复用, 所有结构化生产者.
- 实际影响: 程序尚未创建.

### D010 删除纯形式要求, 保留有价值的内容纪律
- 状态: 当前有效
- 约束性: 必须遵守
- 内容: 删除 Gherkin 唯一关键字写法, 固定 Markdown 节名/节序, 确认注释等纯形式要求. 结构中直接表达场景前提/动作/结果, 目标和业务规则关联, 行为与审计分类, 必须遵守与可调整做法, 并保留可观察点和有依据的数据等内容纪律. 结构性规则程序强制, 清晰度, 完整性和语义仍由 LLM 检查, 不用词语黑名单冒充内容检查. 理由是这些形式不是代码生成器的必要输入, 但背后的信息精度和覆盖关系有实际价值.
- 依赖事实: F007
- 预计影响: workflow/to-spec/SKILL.md, TEMPLATES.md, GHERKIN.md 和现有校验/转正脚本及下游模板.
- 实际影响: 本次未删除旧脚本或规范.

### D011 固定版本展示与原版本转正
- 状态: 当前有效
- 约束性: 必须遵守
- 内容: 需确认的内容先完成程序检查和 LLM 内容检查, 冻结后展示, 取得用户对该完整版本的明确采纳, 再用同一内容转正. 修改已展示输入生成新版并重新确认, 不沿用旧确认, 不让 LLM 转写最终正文. 确认绑定本次对象和必要上下文, 不包含无关进度/报告变化. 程序校验版本一致不能证明用户实际看过或同意, 沉默/部分认可不算整版采纳. 理由是展示与最终采用内容必须一致, 同时避免无关变动触发反复确认.
- 预计影响: 共用版本与确认记录, to-spec, verify-change 和网页固定版本入口.
- 实际影响: 当前方案采纳记录仍按现有文档流程保存.

### D012 不新增无价值的人工审批
- 状态: 当前有效
- 约束性: 必须遵守
- 内容: 决策, 产品判据及必要上下文, 验证方案和最终验收沿用现有明确确认要求, 执行拆分/issues 不因结构化或网页可见而新增人工审批. 可调整的内部做法留给实施者选择并验证, 不因未预写内部方法而阻塞. 理由是可浏览与必须审核不同, 机械化不是增加审批层级.
- 依赖事实: F007, F008
- 预计影响: 状态检查, skill 完成定义与统一页面状态展示.
- 实际影响: 本次未改变现有用户确认关卡.

### D013 正式上游变化按影响范围暂停
- 状态: 当前有效
- 约束性: 必须遵守
- 内容: 用户在 Q6 选择 A. 正式采用新版上游内容后, 根据登记的条目依赖和全局约束暂停受影响的下游及其依赖, 不自动暂停未受影响工作. 保留旧结果和对应版本, 更新或复核后再推进新版. 仅编辑草稿不打断使用正式版本的工作. 关联不清时停下核对, 不猜测无影响; 未登记的隐含影响仍由 LLM 调查. 旧证据不能因编号相同而自动沿用, 也不能冒充新提交上的实跑. 理由是既要阻止旧要求继续生效, 又不因局部改动把全部无关工作重置.
- 预计影响: 输入引用, 版本比较, 任务就绪判断, 评审/验证适用性检查.
- 实际影响: 暂停与复核程序尚未实现.

### D014 present 成为唯一展示后端

- 依赖事实: F001, F004, F005
- 预计影响: general/present/, workflow/navigate/ 展示实现, workflow/codebase-map/ 展示服务及相关调用说明.
- 实际影响: 只新增 ADR 并给旧 ADR 后续指针, 现有服务未停止或迁移.

- 依赖事实: F001
- 预计影响: present 静态文件托管和统一网页资源读取.
- 实际影响: 本次未新增任何端点.

### D016 服务按运行环境分别单例

- 内容: 用户在 Q3 选择 A. 同一运行环境只运行一个 present 展示实例, 宿主机同用户共用一个, 各容器在自身环境各一个, 全部使用同一份后端实现. 不要求宿主和全部容器共用一个跨环境进程, 不新增跨容器提供草稿数据的中心服务. 理由是保留现有宿主/容器交付路径即可达到消除同环境重复服务的目标.

### D017 统一网页归 present 并复用路线图 UI

- 约束性: 必须遵守
- 内容: 用户在 Q5 选择覆盖所有工作流数据的统一网页, 并要求网页也做进 present, 不是各 skill 各自开发一套前端. 在现有 navigate 路线图页面上扩展, 保留现有 UI 设计. 点击里程碑打开填满网页的弹窗页, 显示该里程碑的结构化/Markdown 产物列表, 点击一行后读取数据填入模板. JSON 以可读的规格/任务/结果呈现, Markdown 渲染为文档, 不默认铺原始数据. 已知类型用专用模板, 其他 JSON 用通用字段视图, 不能隐藏判据分支或例子或让模板改写原义. 理由是统一浏览整条链并保留现有使用体验, 避免各环节重复造展示页面.

### D018 产物查看器必须可独立打开
- 状态: 当前有效
- 约束性: 必须遵守
- 内容: 路线图只是产物查看器的入口之一. 不创建路线图而独立调用 to-spec 时, 程序生成规格并通过 present 登记可公开资源/启动或复用服务, 返回网页链接给用户直接浏览和确认. 直接入口全页显示产物, 可查看产品/技术内容和关联材料, 不加载空地图, 不创建 ROADMAP 或假里程碑, 不让用户自行拼 URL. 直接入口和里程碑弹窗使用同一套产物模板. 待确认链接绑定固定版本, 普通浏览可指向当前正式版本, 清晰区分草稿/正式与版本. Markdown 报告同样可独立展示. 理由是用户在无路线图时仍明确需要查看 to-spec 内容, 独立使用不能只停留在命令行读取.
- 预计影响: present 独立产物入口, 统一页面路由, to-spec 交付方式及验收用例.

### D019 保留根目录差异并限制公开范围
- 状态: 当前有效
- 约束性: 必须遵守
- 内容: 不同需求的产物根目录仍按现有规范分开, 展示地址不能因扁平挂载丢失目录差异而读取其他需求的同名文件. 具体 URL 映射不作为用户固定的实现方式. 只公开明确登记范围, 不为方便暴露整个仓库/家目录, 不执行 Markdown 中的不可信脚本, 网页只读, 反馈与确认仍在 chat. 理由是磁盘上的目录隔离必须延续到资源读取, 并避免将通用展示能力扩展为任意文件或远程写入能力.
- 依赖事实: F001, F002, F003

### D020 历史只读保留, 不做专用迁移器
- 状态: 当前有效
- 约束性: 必须遵守
- 内容: 用户在 Q2 选择 A. 新流程消费新结构, 历史文件不批量转换或删除, 旧任务需要继续时由 LLM 核对原文并通过新程序重新整理, 不做专用迁移器, 不长期保留两套规格/执行模式. 旧文档仍可作为直接读取的信源, 这与拒绝旧格式自动执行兼容层不同. 重新整理不得把新增或改变内容冒充用户已经确认. 理由是各时期旧格式转换成本和双轨维护成本不应成为本次长期负担.
- 预计影响: 输入检查, 旧产物处理说明及新程序格式错误出口.
- 实际影响: 历史产物均未迁移或删除.

### D021 收拢生命周期与部署说明
