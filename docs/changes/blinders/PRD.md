# 眼罩: AFK 工作流逐步披露改造

## 问题陈述

当前 AFK 父会话在执行 `run-afk-workflow` 时, 一次性读取完整的 `SKILL.md`, 掌握从预检到最终验证的全部流程. 这导致两个问题:

- **抢 worker 的活**: 父会话看到后续有"验证入口"步骤, 在 worker 还在实现时就提前跑验证, 越过 worker 职责边界.
- **跳过细节**: 父会话知道全局流程后急于推进, 对 diff 门禁, review 综合判定等中间步骤投入不足, 过早冲向最终报告.

这就像赛马在场上看到了侧后方的对手而分心. 理想的父会话应该像戴了眼罩的赛马, 只看到正前方的当前步骤, 不知道后面还有几步, 也不知道后面是什么.

## 解决方案

将 `run-afk-workflow` 从"全量披露"改为"逐步披露".

核心机制:

- **路由文件 `_current.md`**: AFK 父会话读它, 获得当前应立即执行的步骤文件名. 父会话不自主决定写什么, 只按当前步骤末尾的指引机械写入.
- **步骤文件 `step-NN.md`**: 每个文件只包含一步操作的指引. 文件名不含语义 (纯数字), 父会话无法从文件名推断全貌. 步骤文件末尾预写分支条件, 告诉父会话成功/失败后各自去哪.
- **步骤生成责任归 `to-issues`**: 对 AFK 任务, to-issues 的父会话一次性生成全部步骤文件. 它可以掌握全貌, 因为生成步骤本身就是需要全貌的操作.

改造后 AFK 父会话的执行循环:

1. 读 `SKILL.md` (极简入口: 检查门禁, 读 `_current.md`)
2. 读 `_current.md` -> 获得当前步骤文件名
3. 读步骤文件 -> 执行 -> 按末尾指引更新 `_current.md`
4. 回到第 2 步

父会话每次只持有两个文件: 入口 + 当前步骤文件. 不知道后面有几步, 不知道全局流程.

## 用户故事

1. 作为 AFK 工作流的使用者, 我希望父会话在执行时不抢 worker 的活, 以便 worker 产出可靠、评审有意义.
2. 作为 AFK 工作流的使用者, 我希望父会话在每个步骤上做足挖掘工作 (diff 检查、review 判定), 不匆忙跳到最终报告.
3. 作为 skill 维护者, 我希望步骤文件生成由一个集中的过程完成 (to-issues 阶段), 而非散落在执行路径上.
4. 作为 AFK 工作流的使用者, 我希望中断恢复时父会话能从断点继续, 不需要重新理解全貌.
5. 作为 skill 维护者, 我希望步骤文件足够通用, 同一个 issue 的多次 attempt 复用同一套步骤文件, 不因 attempt 号不同而需要重新生成.

## 关键取舍

| 决策 ID | 取舍 |
|---------|------|
| D001 | to-issues 父会话可掌握全貌, AFK 父会话不可. 信息隔离边界划在 to-issues 和 run-afk-workflow 之间 |
| D002 | 状态追踪用 `_current.md` 自然语言文件, 不用结构化 YAML/JSON. 内容为当前应执行的步骤文件名. 模型足够理解自然语言 |
| D003 | 步骤文件名为纯数字序号, 放弃语义可读性换取信息屏蔽 |
| D004 | 步骤文件由 to-issues 一次性生成, 不是 AFK 执行时步步生成. 生成者负担集中, 执行者负担最小 |
| D005 | step-gen-guide 作为外部参考材料, to-issues 父会话按需加载, AFK 执行路径不触及 |
| D007 | 分支逻辑放在步骤文件末尾, AFK 父会话只做条件匹配和机械写入, 不感知回退/跳转语义 |
| D008 | 步骤文件不绑定 attempt, 运行时从文件存在性推断 |

## 未确认假设

- 假设: 15 步的粒度足够覆盖所有 AFK issue 的执行路径. 影响: 如果某些 issue 需要更细/更粗的粒度, step-gen-guide 需要调整. 验证方式: 第一个 AFK issue 跑通后评估.
- 假设: AFK 父会话不会主动读取同目录下的其他 `step-NN.md` 文件. 影响: 如果模型出于好奇读了后续步骤文件, 信息隔离被打破. 验证方式: 在步骤文件中加入"不要读其他步骤文件"的纪律约束.

## 范围外

不做 AFK 执行性能或 token 消耗的优化.
不做 subagent 调用机制的修改.
不做其他 workflow skill 的逐步披露改造.

## 补充说明

改造涉及文件:

- `run-afk-workflow/SKILL.md` — 极简入口, `_current.md` 路由 + 硬边界 + 子代理接口
- `run-afk-workflow/prompts/WORKER.md` — 新建. 静态角色定义, 合并 IMPLEMENT + FIX
- `run-afk-workflow/prompts/REVIEWER.md` — 新建. 静态角色定义, 合并 CORRECTNESS + DECISION-BOUNDARY
- `to-issues/references/step-gen-guide.md` — 新建. 15 步生成指引
- `to-issues/SKILL.md` — 步骤 6a: AFK 步骤文件生成
- `docs/changes/blinders/DECISIONS.md` — 本 feature 决策账本

命名来源: 赛马佩戴眼罩 (blinders) 后只能看到正前方, 不被侧后方事物分心. 大模型作为"赛马", 逐步披露就是它的眼罩.
