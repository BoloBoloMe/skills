# swt 并行母体改造方案

日期: 2026-09-13. 性质: 改造方案 (已实验验证可行, 待用户批准实施).
触发事件: 为 "动态加载" 需求开新沙盒工作树时, 发现 swt 强制 "换母体" 才能开第二对 (工作树, 容器), 背离设计初衷. 用户拍板: 不立即改码, 先沉淀本方案.

## 0. 一句话

把 swt 的开放写单位从 "整个主仓同一时刻只放行一个分支" 修正为 "每个母体工作树各自独立配容器, 多对并存"; 手段 = 把分支白名单 (hideRefs) 从主仓共享 config 下沉到各母体工作树的 config.worktree + 每母体一个 git daemon 实例.

## 1. 问题交代

### 1.1 设计初衷 (用户原话语义)

一个主仓下的多个工作树分支各自接各自的容器, 并存互不干扰:

```text
父目录/
  工作树分支A (分支:feature-a) -> 容器A
  工作树分支B (分支:feature-b) -> 容器B
```

用户澄清: "一个主仓同一时刻只能对一个分支开放容器写" 里的 **主仓, 指的是被创建出来的工作树目录**, 不是上层共享 .git 的那个仓库.

### 1.2 现实行为 (swt.py 现状)

- birth 第二个分支: `assert_single_active_mother` 直接拒绝, 报 "已有活动母体 <旧>, 请先使用 switch 切换" (swt.py:480-498).
- switch: 停掉旧母体全部容器 + 标 retired + 删防火墙规则 + 改主仓 config 放行分支; retired 容器不可 resume, 唯一出路 terminate.
- SKILL.md 把 switch 写成 "危险独立入口", 整套流程围绕 "一仓一开放分支" 构建.

### 1.3 实际代价 (2026-09-13 案例)

为 "动态加载" 开新沙盒时, 旧容器 cross-host 正在 swt-cross-host-access 分支干活, 内有 12 个未推送提交 (信箱/中转系统 ISSUE-01~05 的 feat+doc 提交, 只存在容器里). 被迫二选一: 先 ssh 进容器推走保住, 或接受换母体后它们随容器退役终将消失. 开一个新沙盒的人为成本被现状无谓抬高.

### 1.4 根因链

1. `expected_config()` 把 hideRefs 五键 (receive.hideRefs + uploadpack.hideRefs, 值含 `!refs/heads/<分支>`) 写进 **主仓共享 config** (swt.py:312-331, 351-371).
2. 主仓 config 全仓只有一份 → 这组配置只能表达 "放行一个分支" → `configured_mother_branch()` 从它反读 "当前放行分支" (swt.py:473-479).
3. `assert_single_active_mother()` 据此 (config + runtime + 容器 label) 强制单母体 (swt.py:480-498).
4. switch 成为唯一换支通道 (swt.py:2692+), 文档固化.

**结论: 单母体不是 git 的能力边界, 是 hideRefs 放错了配置层 (仓级 vs 工作树级) 的连锁结果.**

## 2. 可行性实验 (2026-09-13 本机实测, git 2.53.0)

### 2.1 设置

/tmp/swt-probe: main 仓 + worktree wt-a (分支 feature-a) + wt-b (分支 feature-b):

- 主仓 config: `receive.denyCurrentBranch=updateInstead`, `receive.denyNonFastForwards=true`, `receive.denyDeletes=true`, `extensions.worktreeConfig=true`.
- wt-a 的 config.worktree (`git -C wt-a config --worktree --add ...`): receive.hideRefs 与 uploadpack.hideRefs 各四条值: `refs/heads`, `!refs/heads/feature-a`, `refs/tags`, `refs/remotes`.
- daemon 直接服务工作树目录: `git daemon --enable=receive-pack --base-path=/tmp/swt-probe --listen=127.0.0.1 --port=9418 --reuseaddr --log-destination=none /tmp/swt-probe/wt-a`.
- `git-daemon-export-ok` 空文件放工作树私有 git 目录: `main/.git/worktrees/wt-a/git-daemon-export-ok`.

完整可复现脚本见附录 A.

### 2.2 结果矩阵

| 断言 | 结果 |
| --- | --- |
| ls-remote 只见放行分支 | 过: 仅 HEAD + refs/heads/feature-a; main/feature-b/tags/remotes 全部隐藏 |
| 往别的分支推 (feature-b) | 拒: "error: 无法推送一些引用到" |
| 推本分支 (feature-a) | 成, 且 updateInstead 推送落地: wt-a 工作区文件亲证更新为 "change" |
| 强推旧历史 (-f) | 拒 (denyNonFastForwards 生效) |
| 其他分支泄露扫描 (ls-remote grep feature-b) | 0 条 |

即: 单分支写门禁, 快进限制, 推送落地 三大机制在 "每母体一 daemon + 工作树级 hideRefs" 形态下全部保持.

### 2.3 实验踩到的坑 (实施须吸收)

1. **git-daemon-export-ok 的位置**: 必须放 `<主仓>/.git/worktrees/<名>/` (工作树私有 git 目录), 放工作树目录本身无效, 报 "access denied or repository not exported: /<目录名>".
2. **git config 多值必须 `--add`**: 裸赋值会覆盖前值 (实验中踩过, 四条 hideRefs 只剩一条).
3. **生效范围判定从严**: hideRefs 的 worktree 级生效已证; deny 三条不依赖 worktree 层, 留主仓共享层即可, 不赌 worktree 级 receive.* 行为.

## 3. 目标语义

- 管理单元 = **(主仓, 母体分支) 对**. 一对 = 母体工作树 + daemon 实例 + git 桥 + >=1 容器.
- 多对并存, 互不可见. 每对内多容器共推同一母体照旧 (git 原生快进串行化).
- 真远端仍对容器零暴露; 写面仍是 "仅母体分支, 快进 only"; 防火墙/镜像/交付包/决策协议全部不动.
- switch 子命令失去存在意义, 删除.

## 4. 方案分项

### 4.1 配置重排

- **主仓 config** (一次性, 跨母体共享): `receive.denyCurrentBranch=updateInstead` / `receive.denyNonFastForwards=true` / `receive.denyDeletes=true` / `extensions.worktreeConfig=true`.
- **母体 config.worktree** (每母体一份): receive.hideRefs + uploadpack.hideRefs 各四条值 (refs/heads, !refs/heads/<分支原文>, refs/tags, refs/remotes), 一律 `--add` 写入.
- 代码: `expected_config`/`configure_repo`/`config_matches`/`config_fingerprint` 拆成 仓级+对级 两处; STATE 的 `config.swt-form` 语义改为对级匹配结果.
- 主仓现存旧 hideRefs 五键值: 迁移时 `--unset-all` 并原样移入对应母体 config.worktree.
- `extensions.worktreeConfig=true` 副作用评估: 仅显式 `--worktree` 读写才碰 config.worktree; 宿主日常 git 操作与 use-worktree skill 不受影响.

### 4.2 daemon 每母体一实例

- `start_daemon(repo)` → `start_daemon(mother_dir)`: base-path 不变 (主仓父目录), 服务目录 = 母体工作树路径; birth 建对时在母体工作树私有 git 目录放 git-daemon-export-ok. **私有 git 目录路径用 `git -C <母体> rev-parse --git-dir` 推导, 禁止拼 `<主仓>/.git/worktrees/<名>`** — worktree gitdir 名与目录名不保证一致 (重名时 git 自动加后缀).
- **`daemon_pids` 匹配串必须加长**: 现在只匹配 `--base-path=<父目录>` (swt.py:647), 同父目录下其他母体的 daemon 会被误伤; 改为匹配含母体路径的完整命令串 (服务路径是 daemon 命令行末参数, 可匹; 兜底 = runtime 记录的 pid + 命令行复核). 注意误伤面现形态已含同父目录的**其他项目仓** daemon, 本次修复一并治愈.
- **按 base-path 全杀 daemon 的调用点共 3 处, 必须同步收窄到本对** (只改 daemon_pids 不够, 要核对每处语义):
  1. `stop_repo_daemons` (swt.py:2977-3001) — terminate (:3119) 与 switch (:3325, 随 switch 删除) 调用;
  2. `collect_resume_daemons` — resume 自愈路径 (:3776);
  3. birth 的 "主仓已有存活 daemon 即拒" 检查 (:2305-2310) — 多对并存下其他对的 daemon 常驻是常态, 此检查缩窄为 "本对 (同母体路径) 已有 daemon".
- 生死: 该母体最后一个容器 terminate 时收该母体 daemon; resume 只重拉本对 daemon. "最后一个容器" 的口径从主仓级改为母体级 (terminate 的 has_siblings 判断本就是 runtime 记录内兄弟, 天然对级, 改动只在收 daemon 的目标收窄).

### 4.3 identity 按对派生

- 现: `identity_for` = slug + sha1(主仓路径)[:8] (swt.py:166-170), 一仓一个记录目录.
- 改: 新对 = slug + sha1(母体目录路径)[:8]; runtime json / git-bridge / ssh / agent-prompts / decisions 各对一套 (目录结构不变, 数量变多).
- **兼容铁律**: 现存 identity `skills-v2-71170aeb` 原地沿用, 绑定到其 runtime 记录的那个母体 — 桥 socket 路径焊死在运行中容器的 bind mount 里, 不可改名不可搬. 判定规则: 旧 scheme 目录存在即按其 runtime 的 mother 归属, 不重算; 该母体未来的新容器也复用同目录.

### 4.4 生命周期子命令

- **删**: switch 全部; `assert_single_active_mother`; birth 的活动母体冲突分支; runtime stage `switched`/`switch-partial` 处理.
- **birth**: `--branch` 直接开新对, 与存量对无关; DECIDE 只剩 网络/镜像/显示栈/容器名. 两处易漏必改:
  1. `fixed_git_remote` (swt.py:858-861): 容器内恒定 remote 的路径段从 `repo.name` 改为**母体目录名** (新对的 daemon 服务母体目录, 请求路径跟着变); 出生 clone 与 resume 的 `remote set-url` (:3626) 都消费它, 是常态代码, 不是迁移一次性动作.
  2. birth 的 daemon 存活冲突检查 (:2305-2310) 缩窄到本对, 见 4.2.
- **status**: 聚合全部 identity (扫 `runtime/*.json`) + podman label (`sandbox-worktree.repo` 过滤本仓全部容器, `sandbox-worktree.mother` 分组 — label 已在打, swt.py:1998-1999, 亲证 cross-host 容器带全). STATE 演进**只加不改名** (遵守 SKILL.md 输出协议 "STATE json 只加字段不改名"): 顶层保留 `mother` (填首个/最近活动对, 兼容旧消费方) + 新增 `mothers[]` 数组 (branch/dir/daemon/containers), schema 升 2. 消费方排查结论 (2026-09-13 已核): 硬代码解析方仅 swt.py 自身 (swt-base-server.py/image-prep.py 的 STATE 是另一套, 不读 swt runtime); 其余消费方是读 status 输出的 agent (含跨主机设备流程, SKILL.md 设备协作节), 随 SKILL.md 文档同步即可.
- **resume**: `--branch`/`--name` 定位对; 缺省 = 唯一记录对; 4.6 迁移逻辑内嵌为自愈路径.
- **terminate**: 容器粒度照旧; 脏检查/审计不变; 收 daemon 按母体口径.
- **image-prep**: 不动 (镜像按项目, 与母体无关).

### 4.5 文档同步

- SKILL.md: 删 "换母体 (switch)" 节; "同一主仓同一时刻只有一个分支对容器开放写" 表述改写为对级语义; "多容器共推同一母体" 节保留并补 "多对并存" 段; 术语表注明 开放写单位 = 母体工作树; exit code 表与 DECIDE 说明中 switch 相关条目移除. **switch 散落 5 处, 不止一节** (:135 整节, :141 单母体语义, :150 terminate 的 retired 语义, :294 决策协议, 及术语/完成标准处的隐含引用), 改完全文再搜一遍 "switch" 与 "同一主仓" 清零.
- reference/ops.md: 手救场 (config/daemon) 章节改 per-mother 形态; 补一句警示: 开 `extensions.worktreeConfig` 后 host 侧在某工作树内跑的普通 git 命令会读该工作树的 config.worktree, hideRefs 只影响 serve 行为无害, 但**禁止手工往母体 config.worktree 写任何值**.
- reference/errors.md: 删 switch 相关译解条目.

### 4.6 运行中容器迁移 (一次性, 以 cross-host 为例)

全部步骤可脚本化并入 resume 自愈:

1. 停旧 daemon (服务主仓路径的那一个).
2. 主仓 config: 开 `extensions.worktreeConfig`; hideRefs 五键 `--unset-all`; 值原样写入母体 config.worktree.
3. 工作树私有 git 目录 (rev-parse --git-dir 推导) 放 git-daemon-export-ok; 起新 daemon 服务母体目录.
4. 重启桥 (socket 路径不变 = 容器挂载不变, 容器内转发器无感).
5. ssh 容器: `git -C ~/Workspace/<clone> remote set-url origin git://127.0.0.1:9418/<母体目录名>` (唯一进容器的改动; daemon base-path 不变, 只是请求路径从主仓名变母体目录名).
6. 验证: 经桥 ls-remote 只见母体分支; 容器试推 + 推送落地.
7. 回滚 = 逆序恢复: 旧 config 写回 + 旧形态 daemon; 桥 socket 未动, 回滚无损.

迁移窗口内容器 git 通道秒级中断; 容器内工作区/会话/登录凭证零影响; 12 个未推提交不受任何影响 (不触碰容器工作区与历史).

## 5. 影响面与工作量

- swt.py (现 4133 行; 本方案 1.2 节散引的行号以 2026-09-13 的 3572 行版为准, 已漂移): 集中在 config/daemon/identity/五子命令, 粗估 300-500 行改写; 桥/防火墙/显示栈/交付包/env 继承基本不动. **实施一律按函数名定位, 禁用行号导航.**
- SKILL.md + reference 两文件同步.
- 测试: 一次性小仓 hideRefs/worktree 探测并入 birth 预检 (沿用 `validate_git_hide_refs_syntax` 模式, 不支持即 exit 4); E2E 验收 = 两对并存下互不可见对方分支 + 各自推送落地 + 单对内双容器共推.
- 风险与对策: (a) 老 git 对 extensions.worktreeConfig 支持差异 → birth 预检兜底 exit 4; (b) STATE schema 2 消费方 → 已排查, 结论见 4.4 status 条 (硬代码解析方仅 swt.py 自身), 采用只加不改名, 剩余动作 = SKILL.md 文档同步; (c) 迁移失误伤运行容器 → 迁移只走 resume 自愈路径, 禁裸手工.

## 6. 否决的备选

- **B. 每母体一个裸镜像 serve 仓 + post-receive 钩子**: host 侧在母体提交后, 容器 fetch 无同步触发点, 镜像仓会脏读; 双向同步引入新状态机. 否.
- **C. 主仓 config hideRefs 放并集** (放行全部母体分支): 任一容器可 fetch/推其他母体分支, 容器间隔离破防. 否.
- **D. 维持现状 + 每次 switch**: 每开新沙盒强制退役旧容器, 未推提交被迫二选一, 背离设计初衷. 否.

## 7. 实施触发与中间态

- 用户批准后实施于本仓库 `workflow/use-sandbox-worktree/`, 经 `sync-to-pi.py` 安装.
- 实施前若需为 "动态加载" 开沙盒, 只能走旧路径 (switch 退役 cross-host) 或等本改造落地后并存开对, 二选一由用户届时拍板.

## 附录 A: 实验复现脚本

```bash
#!/bin/bash
set -e
rm -rf /tmp/swt-probe && mkdir /tmp/swt-probe && cd /tmp/swt-probe
git init -q main && cd main
git config user.email t@t && git config user.name t
echo base > f.txt && git add . && git commit -qm base
git branch feature-a && git branch feature-b
git worktree add -q ../wt-a feature-a && git worktree add -q ../wt-b feature-b
# 主仓: 公共 receive.* + 开启 worktree 级配置
git config receive.denyCurrentBranch updateInstead
git config receive.denyNonFastForwards true
git config receive.denyDeletes true
git config extensions.worktreeConfig true
# wt-a: hideRefs 八条 (receive+uploadpack 各四), 必须 --add
for v in refs/heads '!refs/heads/feature-a' refs/tags refs/remotes; do
  git -C ../wt-a config --worktree --add receive.hideRefs "$v"
  git -C ../wt-a config --worktree --add uploadpack.hideRefs "$v"
done
# export-ok 放工作树私有 git 目录 (坑 1)
touch .git/worktrees/wt-a/git-daemon-export-ok
git daemon --enable=receive-pack --base-path=/tmp/swt-probe \
  --listen=127.0.0.1 --port=9418 --reuseaddr --log-destination=none /tmp/swt-probe/wt-a &
sleep 0.5
git clone -q --branch feature-a git://127.0.0.1:9418/wt-a /tmp/probe-clone
cd /tmp/probe-clone && git config user.email t@t && git config user.name t
git ls-remote origin                    # 应只有 HEAD + refs/heads/feature-a
git push origin feature-b; echo $?      # 应非零, 推他分支被拒
echo change > f.txt && git commit -qam change && git push -q origin feature-a
cat /tmp/swt-probe/wt-a/f.txt           # 应输出 change (推送落地)
git reset -q --hard HEAD~1 && git push -f origin feature-a; echo $?  # 应非零, 强推被拒
git ls-remote origin | grep -c feature-b; echo $?  # 应 0 条泄露
pkill -f "git daemon.*swt-probe"
```

实测输出 (2026-09-13): ls-remote 两行 (0543aa43 HEAD + refs/heads/feature-a); 推 feature-b 与强推均 "error: 无法推送一些引用到"; 推送后 wt-a/f.txt = "change" (117465e); feature-b 泄露 0 条.
