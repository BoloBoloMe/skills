# use-sandbox-worktree 瘦闭环 (MILESTONE-03) Product Spec

## 背景

use-sandbox-worktree 的全部单项机制 (git 拓扑/端口行为/nft 注入点) 已实测, 但完整生命周期一次都没跑过, 集成咬合是唯一未兑现的不确定性 (路线 A). MILESTONE-02 已拍完母体模型与无 hooks 拓扑. 受益者: 用户 (开发者) — 最早拿到一条真实闭环, 后续加固 (M04 网络/M07 镜像/M08 展示链/M09 登录墙) 都建立在它被验证的骨架上.

## 目标

- G-001: 用 podman exec/ssh 实际跑通一次 建 → 干 → 回流 → 拆, 负向断言全部通过, 结果事实记入产物文件.
- G-002: 交付一个可观测/可清理/可重跑的瘦 E2E 编排器雏形 (内部阶段 birth/smoke/cleanup), 不冻结五场景脚本接口 (属 MILESTONE-11).

## 非目标

- 不做 nft 网络访问控制 — M03 为全通网络中间态, 双模式属 MILESTONE-04.
- 不做镜像依赖件推导与制备策略 — 最简镜像手写字段即可, 属 MILESTONE-06/07.
- 不做展示链/登录墙 — 属 MILESTONE-08/09.
- 不做五场景脚本 (诞生/恢复/查询/终结/换母体) 的稳定接口 — 属 MILESTONE-11/12.
- 不做容器内 pi CLI 的 LLM 调用能力验证 — M03 只验二进制可运行.

## 用户故事

- US-001: 作为用户, 我想要一条命令建起瘦闭环 (母体+容器+守护进程), 以便最早验证集成咬合.
- US-002: 作为用户, 我想要容器内成果 push 即落地母体目录, 以便在 host 直接审阅试跑.
- US-003: 作为用户, 我想要容器写面被收敛到仅母体分支 ff, 以便容器 agent 够不到主仓其他 ref 与真远端.

## 业务规则

- BR-001: 真远端对容器永不暴露; 容器唯一 git 通道是每容器专属的 git 守护进程 (base-path 仅含主仓, 不开 --export-all).
- BR-002: 主仓 receive 写面未按 D008 config 收敛并校验通过前, 不得拉起守护进程.
- BR-003: 拆解只删容器与守护进程; 母体留存, 存删由用户自决.
- BR-004: 全通网络是必须显式记录的中间态, 产物文件须声明, 不得当作安全验收.
- BR-005: 主仓 .git/hooks 不新增任何钩子, 写面收敛全靠主仓 config.

## 验收标准

```gherkin
# language: zh-CN
功能: use-sandbox-worktree 瘦闭环 (MILESTONE-03)

背景:
假定 测试夹具主仓已建于临时目录且 main 分支有初始提交

@AC-001 @normal @G-001 @US-001
场景: 首次诞生瘦闭环
假定 主仓无活动母体
当 编排器执行诞生阶段
那么 母体 worktree 已创建且检出母体分支
而且 主仓 receive 与 uploadpack 配置键值与 D008 模板一致
而且 git 守护进程已拉起且 base-path 仅含主仓
而且 容器已运行且宿主端口可经 podman port 查出
而且 ssh 可登入容器
而且 容器内克隆默认检出母体分支而非游离 HEAD

@AC-001 @failure @G-001 @BR-002
场景: 配置校验失败时守护进程不得拉起
假定 主仓配置被写错一个键值
当 编排器执行诞生阶段
那么 诞生阶段中止并报配置校验失败
而且 git 守护进程未拉起

@AC-001 @failure @G-001
场景: 非夹具仓拒绝执行
假定 某目录是无夹具标识的 git 仓库
当 编排器以该路径为 --repo 执行诞生阶段
那么 诞生阶段拒绝执行
而且 该仓库零写操作

@AC-002 @normal @G-001 @US-002
场景: 容器成果推送落地母体
假定 瘦闭环已诞生且容器内克隆检出母体分支
当 容器内 agent 提交新文件并向母体分支 fast-forward push
那么 push 被接受
而且 母体目录中对应文件内容即时变为提交内容

@AC-002 @failure @G-001 @US-002
场景: 母体工作区跟踪文件脏时推送被拒
假定 母体目录中某跟踪文件有未暂存改动
当 容器内 agent 向母体分支 push 新提交
那么 push 被拒且返回原生报错

@AC-003 @failure @G-001 @US-003 @BR-001
场景大纲: 容器越界写操作一律被拒
假定 瘦闭环已诞生
当 容器内 agent 执行 <操作>
那么 操作被拒且返回 git 原生拒绝信息

例子:
| 操作 | 
| push 新建分支 |
| push 新建 tag |
| 对母体分支 non-fast-forward 强推 |
| 删除任意分支 |

@AC-004 @normal @G-001 @US-003 @BR-001
场景: 容器读面与真远端隔离
假定 瘦闭环已诞生
当 容器内 agent 查看 git 远端与远端 ref 列表
那么 远端仅指向 git 守护进程地址
而且 ref 广告仅含母体分支
而且 列表中不存在真远端地址

@AC-005 @normal @G-001 @G-002 @BR-003
场景: 拆解只删容器与守护进程
假定 瘦闭环已诞生且容器内有已 push 的成果
当 编排器执行拆解阶段
那么 容器被删除
而且 git 守护进程已停止
而且 母体目录与母体分支 ref 原样留存

@AC-005 @edge @G-002
场景: 拆解后可整体重跑
假定 编排器已执行过一次完整 建-干-回流-拆
当 编排器再次执行诞生阶段
那么 诞生阶段成功且全部断言通过

@AC-006 @normal @G-002 @BR-004
场景: 编排器产物可观测
假定 编排器已执行完整流程
当 用户查看产物文件
那么 产物含逐阶段日志与结果事实
而且 产物显式声明全通网络为中间态
而且 产物含用户决策点 checklist
```

## 非行为验收

- NB-001: 主仓 `.git/hooks` 未新增任何钩子文件 (审计目录内容).
- NB-002: 镜像内容仅含 git + pi CLI + openssh-server 及系统底座, 无 jdk/maven/playwright/VNC (审计 Containerfile).
- NB-003: 守护进程无认证为已接受取舍, 威胁模型沿用 D008 (审计配置, 不开 --export-all).
- NB-004: 容器内 pi CLI 仅要求二进制可运行, LLM 凭据注入不在本变更 (审计演练记录).

## 成功指标

- 一次性演练: 建 → 干 → 回流 → 拆 全链跑通且 AC-001 至 AC-006 场景断言全过, 即达标 (M03 完成判据本身); 不设长期指标, 理由: 瘦闭环是验证性切片, 非长期运行服务.

- 事实: pi CLI 在容器内首次实际运行 (二进制依赖/启动行为未实测)
