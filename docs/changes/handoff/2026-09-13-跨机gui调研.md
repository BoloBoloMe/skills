# 交接: 跨机 GUI 无感访问 — 调研完成, 转入方案讨论

日期: 2026-09-13
新会话用途: **与用户讨论**如何给 use-sandbox-worktree 在跨主机场景增加一条 GUI 无感访问路径 (设计讨论, 不是直接实施; 决策点由用户拍板)

## 前情摘要

用户局域网双机工作: 主机 A (无桌面服务器) 跑 swt 容器, 人在设备 B (Linux Wayland 桌面) 经 ssh + herdr remote 驱动容器内 LLM. swt 已有两条显示通道 (noVNC 虚拟桌面; D051 本机 wayland 直通), 都到不了 B 的桌面.

本会话完成了跨机逐窗口 GUI 的可行性调研: 用 waypipe 把容器内 chromium 的窗口经既有 ssh 入口转发到 B 桌面, **画面, 交互, 声音 (pulse over TCP) 全部实测通过**. 实验容器为手工起的一次性容器, 已清理, swt 记录未受影响.

## 用户已拍板的决策

1. **要固化进 swt skill** — 但本次会话只做调研; 具体方案形态由新会话与用户讨论后定, 再另行实施.
2. web 服务场景的推荐形态 (端口直达 vs 其他) **明确挂起, 后续单独讨论**, 新会话不要替它下结论.

## 讨论阶段必须覆盖的要点 (从调研报告提炼, 细节全部在报告里)

- headed 选路两态改三态: 宿主直通 / 远程 waypipe / noVNC 兜底; 如何判定 "当前是远程会话".
- 交付包新增 "远程直通命令" 项的形态, 及端口/地址发现自动化.
- 音频通道: 实测的是 pulse TCP 直连 (容器主动外连 B, 与白名单模式冲突); 待讨论是否改 ssh -R 反带 socket 形态 (未实测过).
- base 层 sshd SetEnv 与 XDG_RUNTIME_DIR 目录的保障机制; 注意 base 一动按 D017 级联重建 display/项目镜像, 成本要在讨论中摆给用户.
- B 端前提 (Linux Wayland + waypipe, Atomic 走 distrobox) 如何写入文档与交付提示.
- 远程启动命令必须走容器内启动脚本 (waypipe spawn 不经 shell), 脚本模板的归属 (镜像内置 vs birth 生成).
