| 断言 | 证据 | 结论 |

## 红轮 (技能不存在时)

`sessions/roundA-red.log` 是技能尚未创建时的会话, 启动横幅 `[Skills]` 里没有 `benchmark-checklist`, 我也未点名加载. 该会话直接跑测量并给出 "新版默认档慢约 12%" 的对外结论, 全程没有: 先写对外结论, 查 `uptime`/`nproc`, 交替序列, 极差. 这就是 TS-001 想暴露的失败.

## 绿轮 (v1 技能)

`sessions/roundB-AC025.log`: 用 `/skill:benchmark-checklist <任务>` 加载, 启动横幅 `[Skills]` 出现 `benchmark-checklist`. 会话按技能的三步走完: 主张, 脚本计时范围, 机器条件. 负载是真实存在的他人任务 (4 个 bash 空转, load 2.1 升到 4.66), 会话没有停止它们.

## 缺口

- 主张的落盘顺序: 会话把 "待核验的那句话" 写进记录首节, 但记录文件在测量过程中生成, 原始输出里看不到 "先写主张再运行" 的严格时序. 技能文本要求先写, 行为上只证明了主张存在且排在记录首位. 这是 AC-025-1 的未完全证实项.
- 分析器: 演练场景没有引入 profiler, "分析器单独运行且该次数字不进报告" 只由技能文本覆盖, 没有对应的运行观测.
- 技能里 "分析器" 那一句在后续 ISSUE-08 (AC-030 限制因素) 会继续扩展; 本次只写测量前的最小要求, 未提前写收益上限与端到端内容.
