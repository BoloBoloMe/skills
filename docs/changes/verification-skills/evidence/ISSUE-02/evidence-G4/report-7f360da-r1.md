## 5. 关于 AC-004-1 与转交摘要的冲突 (重点)

- 同一目标版本 `7f360da`, 同一请求 `http://127.0.0.1:18080/health`: 摘要写 "HTTP 200, 响应含 ready=true", 原生工具记录写 "HTTP 500, `{"status": "starting", "ready": false}`". 二者不可能同时成立.
- 按证据规则, 摘要与原生记录冲突时以可读取的原生记录为准, 所报通过不予采信.
- 因此 AC-004-1 记为失败, 交回实际验收者核实: 需要该次运行的可读取会话/工具调用原件 (且最好是对 `python3 tool.py health --url ...` 的运行记录, 而非 curl 直连), 或重新在服务真正就绪时验证.
- 失败原因不能归为产品实现缺陷: 记录显示服务自身处于 `starting`, 也可能是远程依赖当时未就绪. 这属于服务/环境状态问题, 需由实际验收者补证区分, 本轮只如实记录当次行为不满足判据.
- 附带说明 (推断, 不算通过): 读 `tool.py` 第 23-34 行, `health()` 在 HTTP 非 200 或 `ready` 非 true 时返回 1, 且只打印原始响应体; 若在 11:05:29Z 的状态下运行场景命令, 预期退出码 1 且标准输出不含 `"ready": true`. 该推断只说明记录与代码逻辑自洽, 不能替代运行记录.
