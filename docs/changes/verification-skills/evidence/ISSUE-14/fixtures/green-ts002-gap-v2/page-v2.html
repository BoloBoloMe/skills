02思路: 一次调用怎么走到数字

核心想法很小: 词数就是"被空白分隔的字段数". 把这件事交给 awk 的 NF (当前行的字段个数), 逐行累加, 结束时打印总数. 剩下的问题只剩一个: 文本从哪里来. 于是整个程序变成一次按第一个参数的分派: 说 --file 就读文件, 其余情况都读标准输入.

同一个输入, 新旧两种结果

改动前 (cc48f65) / 由源码推出

$ printf 'alpha beta gamma\n' | bin/wordcount
not implemented
$ echo $?
1

改动后 (4187edb) / 本次实测

$ printf 'alpha beta gamma\n' | bin/wordcount
3
$ echo $?
0

左边不是跑出来的旧版记录, 而是从那三行源码直接读出的必然结果: 没有分支, 没有读输入, 无条件打印并退出 1, 所以任何输入都一样. 右边是当前版本的实测输出, 与验收回传的 raw/ac-001.txt 一致. 变化不在"多算了几种情况", 而在"同一次调用从拒绝变成给出计数".

03代码讲解

不关心实现细节的话, 这一节可以整段跳过. 下面的行号对照当前版本 bin/wordcount, 逻辑部分与 beb0ebf 一致.

展开代码讲解 (共五组: 失败方式, 分派, 计数, 文件路径, 对外约定)

1. 先换掉"失败"这个默认结局

旧版把"未实现"当成正常输出, 所以任何调用都带一个非零退出码. 新版删掉 echo 与 exit 1, 换成 set -eu (bin/wordcount:2). 两个开关的意思: -e 任何命令失败就立刻退出, 不再往下走 (判断条件里的命令除外); -u 引用未定义变量就报错, 而不是当成空字符串.

-u 会带来一个副作用: 无参数调用时 $1 未定义, 直接写 $1 就会报错. 代码用 "${1:-}" 解决: 没传就取空串, 交给后面的 case 的 * 分支. 同理 --remote 里用 ${AUDIT_URL:-} 判空, 而不是裸引用.

2. 用第一个参数分派

case "${1:-}" in 只看第一个参数, 三个分支: --file 读文件, * 读标准输入, 以及范围外的 --remote. 这里有个值得记住的取舍: * 不只是"没参数", 它还会接住所有不认识的参数. 所以 printf 'a b\n' | bin/wordcount --verbose 会安静地忽略 --verbose, 仍然读标准输入并输出 2 (本次实测). 好处是管道用法永远可用; 代价是拼错参数不会得到任何提示.

3. 计数只有一句 awk

awk '{ n += NF } END { print n + 0 }'
  • NF 是当前行的字段个数, 默认按空白 (空格与制表符) 切分, 所以它是"空白分词"的词数定义, 不是中文分词.
  • 每读一行就把 NF 加进 n, END 在输入结束时执行一次.
  • n + 0 不是装饰: 输入为空时 n 从未被赋值, print n 会打印一个空行, print n + 0 才会打印 0 (本次实测两者分别输出空行与 0).

同一句统计既处理文件也处理标准输入: 文件分支把 "$file" 当参数交给 awk, 兜底分支不带文件参数, awk 自然就读标准输入. 这是本次改动里最省事的一处复用.

4. 文件路径的失败方式提前固定

file=${2:?缺文件路径}
awk '{ n += NF } END { print n + 0 }' "$file"

${2:?缺文件路径} 的意思是: 第二个参数缺失或为空时, 立刻把"缺文件路径"打到标准错误并非零退出. 所以 bin/wordcount --file 不会悄悄退回读标准输入, 而是以 2 退出 (本次实测, 提示形如 bin/wordcount: 5: 2: 缺文件路径). 文件不存在时错误由 awk 抛出并同样以 2 退出. "$file" 的引号是必需的, 否则带空格的路径会被拆成多个参数.

5. 对调用方的两个约定

第一, 成功时标准输出只有数字本身, 没有单位, 没有前后缀. 因为 tests/run.sh 用的是 [ "$(bin/wordcount --file samples/notes.txt)" = "2" ], 这是整串比较, 多一个空格都会失败. 第二, 错误信息一律走标准错误 (echo ... >&2), 不污染计数那一路, 这样管道里的下游拿到的永远是纯数字.

边界一览

05合并风险与回退

受影响的人很直接: 任何调用 bin/wordcount 的脚本, 以及靠 tests/run.sh 把关的流程. 对他们来说行为是整体翻转: 以前无论怎么调都是"未实现 + 退出 1", 现在会拿到一个数字并正常退出. 这是好事, 但也意味着上游若有"靠退出码 1 判断工具不可用"的异常处理, 那段逻辑从此不会再走到.

  • 没动的部分: tests/run.sh 与 samples/notes.txt 在比较范围内没有任何变化 (git diff --stat cc48f65 4187edb 只列 bin/wordcount), BR-001 的"测试不得改动"是守住的.
  • 新增的隐式契约: 输出必须是纯数字, 未知参数被忽略, --file 缺参时退出 2. 这三条现在没写进 Product, 但已经能被调用方观察到, 将来改动会让依赖它们的人受影响.
  • 回退成本: 低. 改动只是一个文件, 没有数据写入, 没有配置迁移, 范围内也没有任何网络调用. git revert 4187edb 或 git checkout cc48f65 -- bin/wordcount 就能恢复到三行的旧状态.
  • 回退的代价: 回到"永远退出 1"后, 测试立刻变红, 依赖计数的下游全部失效. 所以回退适合用在 确认新版行为造成破坏的时候, 不是常规操作.
  • 撤回代码不等于撤回外部副作用: 范围外的 --remote 一旦真的连通审计服务并成功登记, 那条登记记录不会随代码回退而消失. 本次在本机的调用因缺配置在发请求前就停了, 验收环境也没能访问服务, 所以目前没有这类记录.

一句话判断: 这是个低风险的绿地方案, 但"绿"只覆盖标准输入与读文件两条路; 远端登记那条路还没有任何环境能证明它是绿的.
