变更讲解 · wordcount

从空壳脚本到拒绝猜测的参数入口

这个仓库原本只有一个三行的 bin/wordcount 占位脚本. 这次变更把它做成能统计词数的工具, 并把"命令行输入不合法时怎么办"从随手忽略收敛成一条统一的用法错误出口. 四轮评审反复抓到的都是同一类问题: 非法输入被静默当成标准输入, 悄悄输出一个看似正确的词数.

01背景: 骨架里只有一个会报错的占位

起点 93fcc53 是"项目骨架"提交. 那时 bin/wordcount 全文只有三行: 向 stderr 打印 not implemented, 然后以退出码 1 结束. 也就是说, 这个命令存在, 但不干活. 

#!/bin/sh
echo "not implemented" >&2
exit 1

产品标准写在 docs/changes/wordcount/PRODUCT.md, 带确认标记 <!-- confirmed-flow: v1 -->. 它只要求两件正事和一件纪律:

  • AC-001-1: printf 'alpha beta gamma\n' | bin/wordcount 输出 3, 退出码 0. 也就是从标准输入读.
  • AC-002-1: bin/wordcount --file samples/notes.txt 输出 2, 退出码 0. 其中 samples/notes.txt 的内容是 alpha beta 加一个换行.
  • BR-001: 既有测试 tests/run.sh 一个字节都不许改. 这一条是审计规则, 不是功能.

标准里没有写"用户输错参数时应该怎样". 这个空白不是无关紧要的细节, 后面四轮评审的返工几乎全部来自这里: 没有标准, 实现就容易选一个"看起来没报错"的做法, 而"没报错"恰恰是这类命令行工具最危险的状态.

先说清比较范围里有什么. 这段 diff 一共 22 个文件, 但产品代码只占三个: bin/wordcount (占位脚本换成真实现), 新增的 tests/cli_errors_test.sh, 以及 README.md 的测试说明. 其余是 ISSUE 任务卡与四轮评审记录 (docs/changes/wordcount/), 加上 fixture 提交带进来的 .agents/skills/ (评审与验收流程说明, 属现场装备, 第 2 轮评审已明确不计入产品范围).

02思路: 先数参数个数, 不猜用户想干什么

第一版实现 (6f07cc1) 用的是很自然的 shell 写法: 看第一个参数, 是 --file 就读文件, 否则读标准输入. 代码短, 两条 AC 也都能过. 问题出在"否则"这两个字: 它把 所有 没认出来的输入都归进了"读标准输入"这一支. 于是 --bogus, 多余的路径参数, 重复的 --file, 空路径 --file "", 全都被当成"用户想读标准输入", 照常输出一个词数, 退出码 0. 调用方看到的是成功, 拿到的是一个和输入无关的数字.

现在的想法换了一个方向: 不去猜, 先看参数形状. 合法的形态只有两种, 其余全部fail closed (失败时明确报错退出, 而不是继续往下走):

  • 零个参数: 读标准输入.
  • 正好两个参数, 第一个是 --file, 第二个是非空路径: 读那个文件.
  • 其他任何形状: 打印一行以 用法 开头的提示到 stderr, 退出码 2, stdout 不输出任何东西.

这个判定只依赖参数个数和两个位置, 不需要循环解析选项, 也不需要给每个错误写一段专属文案. 形状判定天然覆盖了"未知选项 / 缺路径 / 多出位置参数 / 重复 --file / 空路径"这一整族输入, 而这族输入正是评审连续三轮抓到的同一个 bug 的不同入口.

一个具体的对比例子: 假设用户打错, 写成 bin/wordcount --file samples/notes.txt extra. 旧实现只看前两个参数, 输出 2 并以 0 退出, 第三个参数被悄悄丢掉; 调用方以为文件多统计了一份, 实际上没有. 现在的实现数到三个参数, 直接落到 *) 分支, 打印用法提示, 退出码 2, stdout 一个字节都不出. 这不是把错误"变严格"这么简单, 而是把"成功"这个信号变得可信.

需要说明的是, 上面对旧实现的描述不是凭代码想象出来的: 它来自第 2, 3 轮评审里的实跑记录 (review/round-2-spec.md 的 R2P-1, review/round-3-spec.md 的 R3P-1). 页面下方"情形对照"逐行标了来源.

04代码讲解

展开: 三处关键代码与跨模块约定不关心具体实现可以跳过, 不影响后面的证据与风险

一. 唯一的用法错误出口 bin/wordcount:6-9

函数 usage() 只做三件事: 向 stderr 打一行固定提示, 以 2 退出, 不碰 stdout. 提示行固定以 用法 开头, 这是测试可以稳定断言的锚点, 也是给用户的第一个信号. 让所有非法路径都调用同一个函数, 好处是退出码与文案不会各写各的, 这正是第 2 轮评审 R2S-1 指出的问题. 

usage() {
  printf '用法: bin/wordcount [--file <路径>]\n' >&2
  exit 2
}

二. 按形状校验参数 bin/wordcount:12-20

case $# in 只看参数个数. 0 个直接放行; 2 个时再校验内容; 其余全部 usage. 两个参数的校验是两个独立的守卫: 第一个必须是字面量 --file, 第二个必须非空. 非空守卫是最后一轮补上的 (46ef5dc), 它拦的是 --file "": 空字符串在 shell 里是合法参数, 但作为路径没有意义, 交给 awk 会触发"没有文件参数就读标准输入"的默认行为. 

case $# in
  0) ;;
  2)
    [ "$1" = --file ] || usage
    [ -n "$2" ] || usage
    set -- "$2"
    ;;
  *) usage ;;
esac

最后一轮的差异只有一行, 但改动位置很关键: 守卫必须在 set -- 之前, 否则参数已经被改写, 空路径就混过去了. 

@@ bin/wordcount
     [ "$1" = --file ] || usage
+    [ -n "$2" ] || usage
     set -- "$2"

三. 只剩一处 awk bin/wordcount:23

set -- "$2" 把文件路径变成唯一的位置参数. 于是统计只需一处 awk ... "$@": 有路径时 awk 打开该文件, 无路径时 "$@" 为空, awk 按默认行为读标准输入. 这消掉了第一版里两段一模一样的 awk 程序文本 (第 2 轮 R2S-2), 也让"读文件"和"读标准输入"共享同一套计数逻辑. n += NF 按空白切分累加字段数, END { print n + 0 } 里的 + 0 保证空输入打印 0 而不是空行. 

awk '{ n += NF } END { print n + 0 }' "$@"

四. 测试: 把出口的三条约定锁住 tests/cli_errors_test.sh:53-62

新增的测试文件不改 tests/run.sh (BR-001), 而是把"用法错误"当作一个可复用的断言模板: 退出码必须是 2, stdout 必须为空, stderr 必须含 用法. 七个非法输入各自只写一行调用. 这不是为了少打字, 而是让"出口的形状"成为测试的一部分: 以后新增非法输入, 也必须满足同样三条, 否则不能复用这个辅助函数. 

expect_usage_error() {
  label=$1
  input=$2
  shift 2
  printf '%s' "$input" | bin/wordcount "$@" >"$out" 2>"$err"
  code=$?
  [ "$code" -eq 2 ]; check "$label: 退出码 2" $?
  [ ! -s "$out" ]; check "$label: stdout 为空" $?
  grep -q '用法' "$err"; check "$label: stderr 有用法提示" $?
}

两个正向场景 (标准输入 3, 文件 2) 仍保留在同一个文件里, 作为回归: 收紧参数校验不能顺手改坏正常路径. 第 4 轮评审记录的断言数是 30 条, 与这里一致.

五. 文档与判定的分工 README.md:10-17

README 原来的测试说明只有一句 sh tests/run.sh, 新增的测试文件从仓库文档里找不到, 这是第 2 轮 R2S-3. 现在 README 列出两条命令, 并用一句话说明后者覆盖哪五类参数用法错误. 这里有一个跨模块约定: README 的描述必须能与测试里的用例逐类对上, 不能写"尚未实现"的行为. 第 3 轮评审发现描述落后于用例, 这份变更同时把漏掉的"多余位置参数 / 重复 --file / 空路径"补进了那句话.

刻意保留的边界

  • 不可读路径不经过用法出口. bin/wordcount --file nope.txt 由 awk 自己报 cannot open, 退出码 2, 但 stderr 里没有 用法 行. 脚本开头注释明确写了这一点, 避免读者误以为"所有退出码 2 都来自 usage()".
  • 纯空格路径同样落到 awk 报错. [ -n "$2" ] 只判非空, 空格算非空; 第 4 轮评审把它记为备注, 不是缺陷.
  • --file - 未处理. 见上一节说明与下一节缺口清单.

  • 没有"旧版本上实跑失败"的日志. 起点 93fcc53 的脚本直接报 not implemented, 谈不上旧行为; 页面里旧实现的表现在依赖评审记录里的实跑描述, 没有独立保留的日志原件. 这是证据强度上的限制.

06合并风险: 变化只发生在"以前不报错"的输入上

受影响的面很窄: 这个仓库里 bin/wordcount 是唯一入口, 代码里能看到的调用方只有 tests/run.sh 和 tests/cli_errors_test.sh, 两者都已通过. 真正需要留意的是仓库外的使用方式: 如果某个脚本一直这样调用 bin/wordcount --file data.txt --verbose, 过去它会拿到一个词数 (顺手忽略 --verbose), 现在会拿到退出码 2 和一行用法提示. 也就是说, 失败会从"静默算错"变成"当场中断". 对批处理或提交摘要这类场景, 当场中断通常比默默少算一份文件更安全, 但它确实是一次行为变化, 不能当成纯重构.

另一个容易被忽略的人群是把 --file "" 当"读标准输入"的写法. 这种写法从来没被文档承认, 但它在旧实现里能跑通. 合并后它会立刻报用法错误. 如果仓库外真有这种调用, 需要改成不传参数.

能否低成本恢复

能. 这次变更没有数据库, 没有网络调用, 没有写文件, 也没有数据格式迁移; 所有副作用都止于进程的 stdout, stderr 和退出码. 回退只需要把 bin/wordcount 恢复到旧版本 (例如 git revert 46ef5dc, 或整段回到 93fcc53 之后任一实现), 不需要清理已写入的数据, 也不存在"代码回退但外部状态改不回来"的问题.

回退的代价要说清: 恢复到宽松实现, 等于重新引入静默统计. 所以合理的回退条件是"确有调用方依赖被忽略的多余参数, 且短期来不及改调用方"; 如果只是不习惯退出码 2, 更合适的做法是改调用方, 而不是回退校验.

合并后仍需记住的三件事

  • 退出码 2 不等于"一定走了 usage()": 不可读路径也会以 2 退出, 但提示来自 awk.
  • --file - 仍会读标准输入. 不要在没有标准依据的情况下把它当已定义行为使用.
  • 参数用法错误目前只有 ISSUE 级依据. 若要把这条行为当成合同, 需要先在 PRODUCT.md 补一条标准.
