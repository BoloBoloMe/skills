# TC-104 加载来源, 同名冲突与未加载 (AC-017 额外用例)

三种错误模式都在真实 pi 会话里跑过, 不是静态断言.

## 同名冲突: 命令成功不代表用了项目当前文件

- 会话: i11-ver2, tab w1J:t2S. 临时项目 `/tmp/orchestra-11/p2-gaps` @5c0dd32, 会话 cwd 是子目录 `web-console/`.
- 布置: 目标项目真实配方在 `.agents/skills/verify-fixture/SKILL.md` (234 行, 覆盖 A/B/C); 另在 `web-console/.agents/skills/verify-fixture/SKILL.md` 放一份同名旧配方 (17 行, 固定端口 8791, 只讲功能 A 命令行), 提交 5c0dd32 固定.
- 宿主启动诊断原文 (`raw/TC-104-ver2-startup-diagnostics.txt`):

  ```
  [Skill conflicts]
    "verify-fixture" collision:
      ✓ auto (project) /tmp/orchestra-11/p2-gaps/web-console/.agents/skills/verify-fixture/SKILL.md
      ✗ /tmp/orchestra-11/p2-gaps/.agents/skills/verify-fixture/SKILL.md (skipped)
  ```

- 会话发 `/skill:verify-fixture` 后的宿主展开 (`raw/TC-104-ver2-collision-notloaded-pane.txt`): location 是 `web-console/.agents/skills/verify-fixture/SKILL.md`, 正文首行是 `# verify-fixture 旧版配方 (v0)`.
- 结论: `/skill:verify-fixture` 成功执行, 但用的不是项目当前配方, 而是 cwd 更近的旧副本, 项目根那份被 skipped. 这条演练直接印证: 只看命令成功就宣称"用了新文件"是错的, 必须核对 location 与正文.

## 未加载: 点名一个不存在的技能

- 同一会话, 发 `/skill:verify-nonexistent`. 宿主原文:

  ```
  ENOENT: no such file or directory, access '/home/bolo/.agents/skills/verify-nonexistent/SKILL.md'
  ```

- 会话报告: 未找到该 skill, 只按约定检查了 `~/.agents/skills/`, 没有在其他位置搜索, 没有生成替代内容.
- 结论: 未加载不会静默变成一次成功调用, 会给出明确失败; 演练里如实记录, 没有靠粘贴正文或改配置掩盖.

## 加载失败: 生成的配方 frontmatter 写坏

- 会话: i11-gen7, tab w1J:t2V, 临时项目 `/tmp/orchestra-11/p3-buildfail` @5cd1f47, 技能版本 v2.
- 生成物 (`generated/TS-003-loadfail-p3-verify-fixture-SKILL.md`) 第 3 行是:

  ```
  description: 按 PRODUCT.md 验收账本命令行 (fixture) 的记账功能: 构建, add/list 操作, 取证, 清理.
  ```

  冒号没有引号包住, 整个 frontmatter 解析失败.
- 宿主启动诊断原文 (会话 i11-ver3 的终端快照):

  ```
  [Skill conflicts]
    /tmp/orchestra-11/p3-buildfail/.agents/skills/verify-fixture/SKILL.md
      Nested mappings are not allowed in compact mappings at line 2, column 14:
  ```

- 后果 (会话 i11-ver3): `/skill:verify-fixture` 没有展开, 消息按原文交给模型, 模型自己去 `~/.agents/skills/` 和项目里翻文件 (`raw/TS-003-loadfail-verifier-transcript-i11-ver3.txt` 里能看到 `ls ~/.agents/skills/` 与 "The user invoked a skill ... but it's not in my available skills list"). 也就是说: 加载失败的会话仍然会"跑起来", 但它跑的不是宿主加载的那一份.
- 处理: 在技能源码里补了两条 (v3): 生成物的 `description` 含冒号要整体加引号; 加载失败时先修配方再重跑, 修不好就把缺口写进报告, 不能把"命令没展开"当成跑过.
- 复跑验证: i11-gen7b 生成的配方第 3 行改成带引号的 `description: "账本命令行 ledger-cli 本轮记账入口的实跑配方: 构建, 空数据起步, add/list 操作, 取证与清理."`; 新会话 i11-ver4 的宿主展开正常 (`raw/TS-003-green-verifier-transcript-i11-ver4.txt` 首条用户消息的 `<skill name="verify-fixture" location="/tmp/orchestra-11/p3-buildfail/.agents/skills/verify-fixture/SKILL.md">`), 启动诊断里也没有该文件冲突条目 (`raw/TS-003-green-ver4-startup.txt`).
- 结论: 错误模式真实可复现, 修法在复跑里验证. 这条本来会是一个被掩盖的缺口: 若不核对 location, 会话照样能给出一份看起来正常的实跑报告.

## 覆盖小结

- 加载来源: 正常加载的 location 与项目当前文件一致 (`TC-017.md`).
- 同名冲突: 旧副本被优先采用, 项目当前文件被 skipped, location 与正文都能看出来.
- 未加载: 点名不存在的技能给出明确 ENOENT.
- 解析失败: 写坏的 frontmatter 让整份文件不进加载集合, `/skill:` 退化成原文消息.
