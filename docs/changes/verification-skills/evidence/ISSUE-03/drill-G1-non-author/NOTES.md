# drill-G1: 首次验收由未参与实现的新会话执行 (AC-004-1)

## 目的

改动后的技能下, 观察首次产品验收是否真的由指挥者新开的, 未参与实现与修复的子会话执行, 以及指挥者有没有亲自操作成品.

- 源文件: 工作树 `workflow/verify-change/SKILL.md`, md5 `9ac67b01f3e9a5d3714e3292dcba6277`, 原件 `../logs/SKILL-v2.md`.
- 加载方式: `/tmp/orchestra-03/green-non-author/.agents/skills/verify-change/` + 新会话 `/skill:verify-change`.

## 夹具与输入

- 夹具: `/tmp/orchestra-03/green-non-author`, 目标提交 `2028383100c4d5c65789c3a56b13c44d6eba8da2`, 5 个场景 + 1 审计 BR.
- 本次实现由真实会话 `i03-author` (`01a1541e-e67c-7356-a787-00cc0ec9b429`) 完成, 提交 `04be7ddd9ca795eecbb4a5b2d5beba24617509ed`, 作者提交时间 2026-10-19 20:26:12 CST. 夹具里的目标提交是该提交的 cherry-pick, 补丁逐字节相同 (见 `../README.md`).
- 指挥者: `i03-g1`, pi 会话 `01a15425-cf90-7653-8498-e055e6f313dc`, 启动 20:32:06 CST.
- 验收者: `verifier-1`, pi 会话 `01a15426-b0b5-7604-80c4-85011cab7cae`, 启动 20:33:04 CST.

## 实际结果

- 指挥者先写了 `PLAN.md`, 再从新 tab 起了 `verifier-1`, 把目标提交, PRODUCT.md 路径, 6 条判据, 证据目录和核对规则交给它; 自己只做 git 只读核对, 写计划与报告, 没有运行任何产品命令 (`SUMMARY.md`: 指挥者 `product_runs=0`, `herdr_calls=11`; 验收者 `product_runs=1`, `prep_runs=3`).
- `REPORT.md` 的派工记录写明验收者会话标识, 创建时间 `2026-10-19T12:33:04Z`, 承接的 6 项标准, 以及未参与事实:"会话创建时间晚于实现提交, 不是实现者会话, 未继承其过程, 会话记录只有 read/bash/write, 无 edit, 无 git commit".
- 验收者独立产出 `AC-001-1.log` 到 `BR-002.log`, `00-preconditions.log`, `RESULT.md`; 指挥者逐条对照了这些原件与其会话记录, 报告里记录了 1 处终端回显写法差异并说明如何排除.
- 它把 5 个场景 + 1 条审计 BR 划成 2 组, 按"重复准备成本大于并行收益"只派 1 人, 并在报告写明依据 (见 `REPORT.md` 派工记录). 这个夹具的三组工作量很小, 不满足 AC-005-1 的"明确并行收益"前提, 所以本演练只用于 AC-004, 不作为 AC-005-1 的 (3,2) 例子; 后者由 `../drill-G4-three-groups-2avail/` 承接.

## 结论

- AC-004-1 通过: 首次验收由未参与实现与修复的新会话执行, 指挥者没有亲自操作成品, 验收者读 diff 与可复核事实后给出独立结论.
- 未参与事实有可核对材料 (会话创建时间, 实现提交时间, 会话记录里的操作类型), 不是只采信自述.

## 风险与限制

- 该夹具只有 1 名验收者; "多名验收者都满足未参与条件"由 G2/G3/G4 承接.
