# drill-G5: 单一不可分组场景, 3 名可用非作者 (AC-005-2)

## 目的

改动后的技能在"整个 PRODUCT 只有一个不可再分的场景组, 但可用 3 名非作者"时, 是否只派 1 人, 且不为用满资源拆组或制造等待.

## 待测版本

- 源文件 md5 `9ac67b01f3e9a5d3714e3292dcba6277`, 原件 `../logs/SKILL-v2.md`.

## 夹具与输入

- 夹具: `/tmp/orchestra-03/green-single-group`, 目标提交 `42c51b8a51c216d5689a1c918c319ae4474aafd6`, 只有 AC-001-1/AC-001-2 两个场景 (同一条 `greet` 命令族, 同一份工作区) + 1 条审计 BR = 3 项.
- 任务输入: "本轮最多可开 3 个验收子会话".
- 指挥者: `i03-g4`, 会话 `01a15432-c5f0-7727-bb88-8498f5dfc506`, 启动 20:46:16 CST.
- 验收者: `acc-verify`, 会话 `01a15433-cd28-77f7-a744-2113227a15f1`, 启动 20:47:23 CST.

## 实际结果

- `plan.md` 写: 可用上限 3 人, 计划 1 人; 理由是"两个场景打同一份成品副本, 同一命令族, 无资源可隔离; 审计 BR 也是同一工作区的静态比对; 总共 2 条 CLI 命令加 1 次版本比对, 每多开一个会话都要重复启动与读判据的固定准备, 重复准备大于并行收益"; 结论"1 组 1 人, 依次做完 3 项", 并写明"不按 AC 逐条开会话".
- 实际只起 1 个新验收会话, 没有为闲置的 2 个名额再拆组; 指挥者 `product_runs=0`, `herdr_calls=12`; 验收者 `product_runs=1`, `prep_runs=1`.
- 3 项必验 / 1 个会话; 计划后直接启动, 无等待批准.

## 结论

- AC-005-2 通过: 单一场景组时只派一名验收者承接全部必验项, 没有为使用闲置资源拆组或制造等待, 依据写在计划里.

## 风险与限制

- 该会话还开过一个只用于查模型列表的小会话 (`01a15433-2a5a-769e-b851-043045c2837f`, 第一条输入是 "models"), 它不是验收者, 未承担任何标准; 见 `../incidents/host-incidents/README.md`.
