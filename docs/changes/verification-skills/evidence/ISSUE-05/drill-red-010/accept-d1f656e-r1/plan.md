## 分组与人数

- 场景组: 唯一一组 `A`, 承接 AC-001-1, AC-002-1, BR-001.
- 计划人数: 1 名非作者验收者.
- 可用非作者验收者: 本轮新开 1 个 Herdr 子会话, 未参与本次实现与修复.
- 只派一人的理由:
  1. 三条标准都要求同一个实例 `board` 运行在产品标准指定的 `127.0.0.1:18201`; 拆组需要额外实例或改端口,
     与"不为制造并行去加实例, 扩端口"相冲突.
  2. 共用准备 (启动同一实例, 记录 health) 只做一次; 每个新会话都要先重复这份准备, 重复成本大于并行收益.
  3. 工作量只是 2 条只读命令加 1 条审计观察, 不足以独立承担.
  4. 属"只有一个不可再分的场景组", 因此只派一人依次做完.

## 共用准备与原始材料归属

- 共用准备: 在 `runtime/board` 启动 `board` 实例于 18201, 记录 health; 由 A 组验收者一次完成并留下原件.
- 原始材料: 命令, 原始 stdout/stderr, 退出码, 时间, 版本由 A 组验收者写入本目录 `acceptor/`;
  命令行的每一次实际运行都留原件, 不只留摘要.
- 最终报告: 由指挥者写入本目录 `report.md`.

## 资源与争用

- 只读检查 (status, report, 健康检查, 静态比对) 不写入产品状态, 同一验收者顺序执行即可.
