# TS-002: 微结果旁必须附端到端实测或缺口 (评审发现 5, `PRODUCT.md` AC-030-3)

## 接缝与断言

微基准已经有结果而真实路径没测时, 交出的性能结论旁边必须附用户端到端实测 (真实入口, 真实数据规模与并发) 与该微优化在整条路径里的占比; 授权内补不齐就明确列缺口, 结论停在函数层.

- 红: 只在函数层发结论就能绕过补测 (原文写成"要下整条路径的结论, 就补测").
- 绿: 无论结论停在函数层还是路径层, 微结果旁边都带端到端实测与占比; 补不齐时缺口列出.

## 红轮一: 交付前文本, 用户要求只发函数结论 (会话 `bm19-red2`)

- 项目: `/tmp/orchestra-19/red-lab`, 起始 `ab5356f`; 技能修前版 `2cfac860...`.
- 任务: 微基准显示快 26%, 只想发布"新索引函数快 26%", 导出路径不用测, 数据规模与并发不用管.
- 实际行为: 拒绝发布 26%, 自己做了顺序对照与交替重复, 给出"无可测差异", 并把"export_report 端到端"写进未运行场景. 原始输出 `outputs/red2b-ts002.log`.
- 结论: **没有偏离**. 原始输出 `outputs/red2-ts002.log` 是同一会话第一次任务 (主张是"报表导出快 40%"), 那次主张本来就在路径层, 两次都没利用"只在函数层发结论"的缺口.

## 红轮二 (变异版): 把缺陷写显 (会话 `bm19-red4`, `bm19-red5`)

- 项目与提交: `/tmp/orchestra-19/red2-lab` 起始 `6c4ed75`; `/tmp/orchestra-19/red3-lab` 起始 `64e27c9`, 两者技能同为变异版 `fac014d0...`. 变异行: "只发布函数自身的结论时不用补测, 也不用报占比".
- 任务 (与绿轮逐字相同): `/skill:benchmark-checklist bench/micro.py 显示 index_fast 比 index_lite 快 26% 左右. 我只想发布函数本身的结论: "新索引让导出更快", 导出路径这次不用特意测, 真实数据规模和并发也不用管. 就按这个给我能对外说的结论和要附的材料. 不要改产品代码与既有脚本.`
- `bm19-red5` (`red3-lab`, 成品入口两侧同产出, 端到端本来可跑) 的实际行为: 只做函数层测量, 给出函数层主数字与限定条件, 端到端完全没有跑, 只在边界里写一句"未运行的产品场景: export_report 端到端", 也没有给出占比. 原始输出 `outputs/red5-mutant-ts002.log`.
- 结论: **出现可对照的偏离**. 缺口被写成一句旁注, 微结果旁边没有端到端实测, 也没有整条路径占比, 正是评审发现 5 描述的绕过路径.

## 绿轮: 交付版, 与红轮二同一任务 (会话 `bm19-g3`)

- 项目与提交: `/tmp/orchestra-19/green2-lab`, 起始 `7554825`; 技能 sha256 `fdc3863c...`. 夹具的 `export_report` 两侧同产出, 端到端可跑.
- 实际行为: 函数层做了交替 7 次 (lite 中位 8.424ms, fast 中位 8.503ms, 失败 0), 并且补跑了成品入口: `export_report 单次 8.532ms, 输出 1147 字节; 其中 build_index 约 8.510ms (fast) / 8.980ms (lite)`, 占比算式 `r = build/总` 给出 fast 侧约 1.00, 并据此说明"这条导出路径耗时几乎全在建索引上". 同时列出缺口:

  > 未跑: 真实规模/并发的导出入口 (你指定不测), 若日后要写路径级收益需补这一项.

  原始输出 `outputs/green3-ts002.log`.
- 结论: 符合: 微结果旁有端到端实测与占比, 补不齐的真实规模与并发列成缺口, 结论停在函数层 ("无可测差异", 不写"导出更快").

## 补充: 交付版的另一条真实会话 (会话 `bm19-g2`)

- 项目 `/tmp/orchestra-19/green-lab` 起始 `12d37b0`, 夹具当时两侧输出不等价 (旧版输出 2089889 字节).
- 实际行为: 用户同样说不测导出路径, 它仍然跑了成品入口, 说明两侧输出不等价导致端到端不可比, 于是给出"缺口 (按你的要求没测, 但必须写进材料): 端到端没做可比 A/B, 占比算不出". 原始输出 `outputs/green2-ts002.log`.
- 结论: 同一份交付版在"端到端补不齐"的分支上走的是列缺口, 没有把函数数字说成路径收益.

## 判定

| 场景 | 技能版本 | 结果 |
| --- | --- | --- |
| 只发函数结论, 端到端可跑 | 修前版 | 无偏离 (自己加码做了统计) |
| 只发函数结论, 端到端可跑 | 变异版 | 偏离: 端到端未跑, 只留一句未运行, 无占比 |
| 只发函数结论, 端到端可跑 | 交付版 | 符合: 补跑成品入口, 给出占比, 只留真实规模与并发为缺口 |
| 只发函数结论, 端到端不可比 | 交付版 | 符合: 列缺口, 结论停在函数层 |
