# TS-003: 悬空引用与文风 (STANDARDS H1, H2, H4 的 benchmark 部分)

## 接缝与断言

正文里出现的问题编号必须能解析到具体节; 正文用 ASCII 标点, 不出现 U+2014; 非警告叙述不用 "被"; 中文子句不超 25 字; 需求方是第一人称 "我", 不写成第三人称 "用户".

## 扫描工具

`check-issue19.py`: 六类规则 (全角标点, U+2014, 被, 中文子句长度, 问题编号与节名引用可解析, 第三人称 "用户"). 自带 `--selftest`: 一份合格样本必须零命中, 一份违规样本必须覆盖五类规则, 否则退出 2. 自检通过记录在 `red-style-scan.log` 末段.

```bash
uv run python check-issue19.py --selftest
uv run python check-issue19.py <SKILL.md>
```

## 绿: 交付版零命中

`red-style-scan.log` 第三段 (退出 0): `workflow/benchmark-checklist/SKILL.md: OK`.

修法:

- 新增一行七问对照, 编号因此可解析: "第 1 问在 `## 测量前`, 第 2 问在 `## 两侧按生产方式调优`, 第 3 与第 6 问在 `## 收益上限与端到端`, 第 4 与第 7 问在 `## 错误计数与工作是否真的发生`, 第 5 问在 `## 重复与波动`." 扫描器同时校验每个反引号里的节名确实存在.
- 破折号改冒号; 被动句改主动 ("被测工作" → "正在测的工作", "被授权可改" → "获授权可改", "结果被用上" → "结果确实用上了", "被改动那一段" → "改动那一段", "工作被跳过" → "跳过了工作", "分析器数字被排除" → "分析器那次数字已剔除", "没有被删减" → "没有删减").
- 两句超长句按动作拆开.
- 需求方改为第一人称: "用户明确只要…" → "我明确只要…", "用户说只要一个大致数字" → "我说只要一个大致数字", "由使用者按自己的流程做" → "由我按自己的流程做".
