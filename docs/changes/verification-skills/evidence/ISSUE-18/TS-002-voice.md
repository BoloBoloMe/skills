# TS-002 正文视角与句子结构 (H3/H4)

- 接缝: blast-radius 正文的写作面, 覆盖评审 H3 (被动句与超长句) 与 H4 (执行者被写成 "我").
- 用例: 无独立 TC, 本切片按 ISSUE 的验证入口做机械扫描, 不新增行为用例.
- 工具: `scan-voice.py` (本 ISSUE 的任务专用审计脚本, 不改产品也不做行为断言).

## 判据

- 第三人称: 正文出现 "用户" 指需求方即命中.
- 视角: 出现 "是我的角色", "我自己", "让我", "我负责", "我先", "我读", "我跑" 等把执行 agent 写成 "我" 的短语即命中.
- 被动: 正文出现 "被" 即命中 (法律/安全警告除外; 本文没有这类段落).
- 句长: 按汉字计, 单句超 25 字即命中. 先去掉行内代码与链接地址, 再按全角句号, `;`, 句末 `.` 切句. 这个阈值来自 translate-a-skill 第 4 节 "中文单句不超 25 字".

工具只做机械审计, 不能替行为结论.

## 绿轮做法

- 视角: 第 4 行改成 "调查与运行证明是你的角色, 你自己做". 需求方用 "我", 只出现在一处 ("先问我"), 其余用 "调用方" 这个既有角色词.
- 被动改主动: "被写成这样" 改 "写成现在这样"; "能被人按写下的方法独立检查" 改 "都能按写下的方法独立检查"; "被下游共享的线格式" 改 "共享线格式" (并把条件拆成 "条件一/条件二").
- 拆长句: 一句一动作. 例:
  - 旧: "读 diff 里新增, 修改, 删除的符号, 以及现在行为不同的地方, 包括 diff 没写出来的部分: 注册时机, 导入顺序, 运行环境."
  - 新: "读 diff 里新增, 修改, 删除的符号. 也读现在行为不同的地方. diff 没写出来的部分同样要看. 例如注册时机, 导入顺序, 运行环境."
  - 旧: "要查的范围: 调用库的源码, 固定的库版本与本地补丁, 运行时机 (...), JSON 返回, 数据库列, 线格式, 另一种语言读同一批字节, feature flag, 以及三跳之后的下游."
  - 新: 拆成 "要查的范围: 调用库的源码, 固定版本与本地补丁. 运行时机 (...). JSON 返回, 数据库列, 线格式. 另一种语言读同一批字节. feature flag, 以及三跳之后的下游."
- 新增第 5 节 "一次性实验的边界" 也按同一写法: 每条规则一句, 完成标准一句.

## 缺口

- 句长按汉字计, 英文标识符 (例如 `file:line`, `feature flag`) 不计入 25 字; 若按全字符计, 个别句子会长于 25. 口径写在 `scan-voice.py` 顶部, 本切片不把英文术语算作中文句子长度.
- 扫描只看 SKILL.md 正文, 不看 `reference/*.md` (本 ISSUE 未改参考文件) 与会话产物. 绿轮演练报告里有一处 "与用户补充 ... 一致", 那是会话自己写的报告, 不是技能正文; 本 ISSUE 不改原始材料.
- 这只是写作面机械审计. 行为差异证据在 `TS-001-oneoff-boundary.md`.
