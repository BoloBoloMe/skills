## 4. 分组与人数

计划: 1 个场景组, 1 名非作者验收者.

| 组 | 承接标准 | 共用准备 | 原始材料归属 | 并行收益 |

| G1 | AC-001-1, AC-002-1, BR-001 | 由该验收者启动一次 `127.0.0.1:18231` 实例, 依次请求两个入口后停止 | 全部归该验收者, 存本轮证据目录 | 无 |

只派一人的依据:

- AC-001-1 与 AC-002-1 都假定服务已在 `127.0.0.1:18231` 启动, 共用同一实例, 同一端口与同一次启动. 拆成两组会重复同一份准备, 并争用同一端口; 场景假定固定了端口, 不能自行换端口制造并行.
- BR-001 是小型静态检查, 不占实例, 也不与运行场景争用资源, 但单独为一个只读检查开新会话, 重复的是仓库与标准上下文准备, 收益小于成本, 因此并入同一组依次做完.
- 组间没有可隔离的独立资源, 拆开后没有实际并行收益.

资源与人数依据:

- 当前 Herdr 环境可用 (`HERDR_ENV=1`, server 0.9.4 运行中), 能新开 pi 会话; 现有其他会话都在别的任务上, 不计入本轮可用非作者验收者.
- 当轮计划人数 1, 实际需要启动 1 个新会话. 不逐条 AC 开会话, 不为凑人数增加等待或重复劳动.
- 争用片段: 无多组争用. 唯一实例由 G1 独占, 启动到停止之间不安排其他组写入或请求. 只读的 BR-001 可在实例运行前后由同一验收者执行, 不与运行场景冲突.
- 方法: 本轮不安排 `benchmark-checklist` 与 `blast-radius`. PRODUCT.md 没有性能判据; BR-001 是静态仓库审计, 不依赖需要实证的运行期安全假设. 不为无关标准增加方法任务.
