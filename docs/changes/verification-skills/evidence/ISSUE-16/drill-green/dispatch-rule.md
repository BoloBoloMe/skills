## 规则: 先定材料类型, 再定结论

派工单给每条必验项都必须写明来源, 只能是这三档之一:

1. **本轮实跑** — 验收者本轮自己走成品入口, 留下命令, 原始输出, 时间.
2. **引用旧观察** — 用上一轮或旧提交的观察, 必须逐条核对适用性, 并写原检查时间, 提交版本, 可复核位置, 适用条件.
3. **未验证** — 缺权限/依赖/环境, 写清缺什么.

只读代码或文档得出的东西标"推断", 结论仍是未验证, 不能当通过. 没有原件只有摘要的, 要补可读取原件; 补不上就是没证据.

## 引用旧观察而不叫验收者重跑的条件

四条全满足才引用, 缺一条就重跑:

1. 材料是真观察, 不是作者的自我评价: 有命令, 原始输出, 时间, 提交版本, 可复核位置.
2. 覆盖范围对得上这条标准, 且实例, 版本, 环境与当前目标一致.
3. 四项适用性逐条核对通过, 不因"同一台机器, 同一份路径"就当作没变:
   - 代码是否动了该场景的执行路径;
   - 依赖版本是否变了;
   - 配置项是否改了;
   - 环境里原来依赖的服务是否还在.
4. 判断不了有效性就不采用, 改成本轮实跑或记未验证.

另外, 重复跑一条已经足够的非关键观察只是烧成本, 换不来更强结论, 所以本来就有的有效旧观察按原件引用, 不重抄成新观察.

## 例外: 有, 而且只朝一个方向

引用旧观察这条规则有一个硬例外, **受影响的关键真实路径一律本轮实跑, 没有豁免**:

- 本次改动碰到的地方, 就是作者的会话过程浸过的地方. 拿作者在实现或修复期间的通过日志, 截图, 自测说明替验收者下结论, 首次验收就退化成作者自证.
- 作者材料不因"出自作者"而无效, 只是它的类型固定是**引用的旧观察**, 只能作对照材料, 不能顶这项的实跑结论.
- 首次验收与复验同一条, 修复过也不等于可以用作者的通过记录顶替本轮记录.
- 实跑结果与作者材料冲突时, 按摘要与原件冲突处理: 拒绝所报通过, 说明该记录不支撑结论, 交回实际验收者核实, 不反过来拿作者材料把实跑改成通过.
- 例外不反向放宽: 不受影响的项不因改动存在就全批重跑. 条件已失效而当前环境又缺依赖服务时, 该项记未验证/受阻, 既不沿用失效旧证据, 也不改判通过.
