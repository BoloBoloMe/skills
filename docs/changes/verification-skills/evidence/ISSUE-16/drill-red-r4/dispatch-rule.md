## 1. 规则本体: 每条必验项先定材料来源, 再定做法

派工前对每条必验项只允许两种来源, 没有第三种:

- **A 引用旧观察**: 已经有了这个场景的观察, 且按第 2 节五条逐项核过仍适用, 就不叫验收者重跑一遍, 派工单标"引用旧观察"并附原检查时间, 提交版本, 可复核位置, 适用条件.
- **B 本轮实跑**: 条件变了, 或者本来就没有观察, 就交给验收者本轮自己操作取证, 派工单写明哪一处变了.

材料类型四分, 只有前两类能作为结论依据:

- 当前观察 (本轮实跑得到的命令, 原始输出, 退出码, 时间) → 可判通过/失败.
- 引用旧观察 (旧提交或上一轮的非作者观察, 条件仍适用) → 可判通过/失败.
- 推断 (只读代码或文档得出) → 结论是未验证.
- 未运行 (缺权限, 缺依赖, 环境不可达) → 结论是未验证.

为什么要有 A: 已足够的观察重跑一遍只烧验收成本, 换不来更强的结论. 为什么必须有 B: 条件变了还引用旧结论, 等于用失效证据给通过.

## 2. 引用旧观察的五个条件 (全部满足才可引用)

1. **原件可读取**: 有命令, 原始输出, 退出码/截图/文件状态等可复核原件. 只有一句"通过"的摘要不算, 摘要与原件冲突时直接拒绝该次通过.
2. **版本对齐**: 原观察的目标提交与本轮目标提交一致, 或差异已被证明不触及该场景的执行路径.
3. **执行路径未变**: 逐项核对代码是否改了这条场景走的路, 依赖版本是否变了, 配置项是否改了. 不能因为"同一台机器, 同一份路径"就默认没变.
4. **环境仍成立**: 原观察依赖的服务, 端口, 凭据, 运行时版本是否还在.
5. **判断不了就不采用**: 有效性核不清时改成本轮实跑, 不拿模糊判断赌通过.

引用时报告行内必写: 原检查时间, 提交版本, 可复核位置, 适用条件, 以及本轮哪处改动不影响它. 原件按原件引用, 不重抄成"本轮实跑"冒充新观察.

## 3. 例外: 有没有可以绕过上面条件的情况

规则本身没有"条件不全也能引用"的口子, 只朝更严的方向有五个明确的不可引用/必须实跑情形:

1. **首次验收没有可引用的旧观察.** 本次是首轮, 除作者自测外没有任何独立观察. 作者自测属于作者自证, 按派工规则不作为通过依据, 也不作为"作者结论"交给验收者 (传的是提交, 输入路径, 标准, 证据目录, 核对规则, 不传实现过程与自证结论). 作者材料可以当引用材料做交叉核对, 但该项的通过与否只能由本轮实跑决定.
2. **关键真实路径必须本轮本人实跑.** 作者留下的通过日志, 截图, 说明只当材料引用, 不能顶替验收者在最终版本上自己操作并留下记录. 这条是为复验写的, 首次验收同样成立: 没有本轮观察就没有结论.
3. **断言运行过程的审计项 (写入范围, 清理) 不能用静态材料顶替.** 必须用本轮实际的资源, 对象, 操作与清理记录; 代码阅读和配置文件不能算运行记录.
4. **条件已失效又缺运行所需依赖** → 该项记受阻/未验证并写明缺什么, 既不沿用失效旧证据, 也不改判通过, 更不用自建桩把它改判通过.
5. **共享材料不转移判断.** 别人的原始材料可以共用, 但接收方要自己核覆盖范围与实例, 版本, 环境是否仍适用, 自己下自己标准的结论; 引用方法材料 (benchmark-checklist, blast-radius) 也不新增判定, 结论仍回到 PRODUCT.md 原文.

另有一处容易误判但不是例外: 项目自带验证配方, 执行计划的勾选状态, 作者说"已自测", 都不构成证据; 配方只提供操作线索, 不产生判据.
