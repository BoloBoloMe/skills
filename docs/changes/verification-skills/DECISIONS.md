### D001 补强既有流程, 建立五个通用 skill
- 状态: 当前有效
- 约束性: 必须遵守
- 来源: 用户最初的 deliberate 请求及交接目标.
- 内容: 新增 `verify-change`, 名字固定使用这个拼写; 同时建设 `create-verification-skill` 和 `maintain-verification-skill`. `blast-radius` / `benchmark-checklist` 使用 `translate-a-skill` 在本仓库建立汉化适配复刻版. 目的在于补强既有 Spec/TDD/评审/人工确认流程, 不是替换整套工作流或迁入 Cursor 生态. 不将既有的提前定义完成标准/测试追溯/真实证据纪律当成缺失能力重建.
- 依赖事实: F002, F003, F006, F008.
- 预计影响: `workflow/verify-change/`, `workflow/create-verification-skill/`, `workflow/maintain-verification-skill/`, `workflow/blast-radius/`, `workflow/benchmark-checklist/` 及相关流程指针. 这些是按仓库布局预计的源目录, 本轮不创建它们.
- 实际影响: 本轮仅记录设计, 尚未实施五个 skill.

### D002 verify-change 只组织验收, 不组织修复

- 约束性: 必须遵守
- 来源: Q1A.
- 内容: 使用 `verify-change` 的会话是验收指挥者, 不亲自执行验收. 它组织任务/核查证据完整性/汇总结论, 发现失败后将结果交还原实现流程. 不在这个 skill 内派发产品修复任务并循环修到通过. 指挥者可以检查输入和阅读材料来派工, 不能用自己操作最终成品代替子会话验收. 验收与修复职责分开, 后续失败回路由 D030 规定.
- 依赖事实: F005, F009.
- 预计影响: `workflow/verify-change/SKILL.md` 的角色/停止条件/输出契约.
- 实际影响: 仅落账, 未实施.

### F013 benchmark-checklist 的核心和例外
- 状态: 当前有效
- 来源: [固定原文](https://github.com/cursor/plugins/blob/4382e687a50b8d2c5ce4d141d001186589cff8d5/pstack/skills/benchmark-checklist/SKILL.md), 主会话全文复读.
- 内容: 适用于前后对比/回归结论/持续优化测量脚本/库或配置选型等性能数字. 每问用真实运行证据回答, 不靠读代码猜. 运行前先写准备对外给出的具体结论, 读测量脚本看计时/计数/忽略什么, 查机器负载与核心数. 忙碌且不能停止其他工作时交替测量双方并报告噪声, 不能因此擅自停别人的任务. 源命令是示例, 适配时保留检查意图和平台限制.
- 七问: 1 说清限制因素, 分析器单独运行且该次不作报告数字, 留意负载生成器先饱和, 数字没变先找原因再断言优化无用. 2 每边按生产方式/版本/数据/缓存/构建/批处理/连接等调优, 单边默认是在比配置不是实现, 调不动不得据该轮选赢家, 选型不能靠缩窄措辞掩盖. 3 用带宽/核心时间/占比计算上限, 删除占时 10% 部分最多约 11% 加速, 超限可能测到缓存/空操作/错误. 4 计失败/非成功响应并核输出正确性, 不只存在, 无错误计数要补. 5 每边至少 5 次交替 A/B, 报中位数与极差, 差距小于波动为无可测差异, 接近时用秩和检验或测量工具统计. 6 微结果旁实际测用户端到端路径及真实数据/并发, 报占比, 不把微优化夸成整条路径收益. 7 证明工作实际发生于计时区且结果被使用, 排除未消费生成器/未 await promise/JIT 丢弃/超时的假数字.
- 报告与例外: 结论先行, 为更快/更慢/无可测差异/无法下结论, 附单位/次数/极差/限制因素. 声称差异却说不出限制因素/单边未调优/第 4 或 7 问无法检查时须无法下结论并写缺口. 用户只要粗估可单次, 仍查第 4/7 问并声明单次, 异常时继续检查; 选项取舍永远不算粗估. 只有 PR 正文限制一个主数字, 完整次数/极差/方法证据放链接材料, 不据此缩减内部验收证据. 性能基线用于规划前及后来每个数字都检查; 持续优化测量脚本固定前检查, 并自带错误数/工作量输出.
