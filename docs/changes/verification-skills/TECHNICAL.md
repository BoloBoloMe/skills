# 验证 skills 与独立产品验收 Technical Spec

## 模块划分

- verify-change: 接收产品标准和最终版本, 隐藏完整覆盖/非作者分工/资源冲突安排/证据适用性/结果汇总. 删除后这些复杂度会散回每个调用方, 不是消失.
- create-verification-skill: 从当前产品范围与项目事实形成可复用操作配方, 隐藏启动/实例识别/驱动/取证/清理知识及新会话自验安排. 删除后每个项目调用方都要重复探索和证明.
- maintain-verification-skill: 隐藏配方与当前事实的核对/漂移分类/范围内修正和证明, 不承担修产品职责. 删除后文档漂移/驱动缺口/产品缺陷的区分会散回各调用方.
- blast-radius: 隐藏 diff 以外读者追踪/关键安全事实选择/真实代码证明/多模型答案合并, 用一个点名接口交回有证据的影响判断. 删除后各调查者必须重新组合这些工作.
- benchmark-checklist: 隐藏测量公平性/限制因素/上限/错误/重复性/端到端相关性/工作实际发生的核查, 通过一个点名接口交回可复核结论. 删除后这些检查会散回每个性能数字的使用处.
- tdd-as-orchestra: 沿用既有实现/工作树/合并/评审/重构模块, 只增加独立产品验收节点及失败回路, 不把验收细节内联回实现指挥者.
- 共享能力沿用已有 domain-awareness/codebase-design/use-herdr/llm-select/mailbox/writing-for-llm/translate-a-skill 和验收指南. 本变更不为这些调用另建包装模块, 不修改调度/模型网关/信箱协议或自动评测平台.

涉及的模块/目录: workflow/ 下五个新增 skill 及其必要参考材料, workflow/tdd-as-orchestra/, 必要的目录入口说明/本变更验证材料和任务专用测试夹具; 不改既有 Spec/TDD/双轴评审规则或部署副本, 不建设额外上游技能体系.

## 模块接口

公开接口是用户点名 skill 或已有流程明确提名调用, 输入由调用上下文和实际文件提供, 不是新增应用服务或统一运行平台. 五个通用 skill 及生成的项目级 skill 均使用 name/description 单行人类摘要/disable-model-invocation: true, 名称与其目录一致. 相对参考材料和辅助脚本按 skill 所在目录解析, 项目事实按实际项目位置解析, 不绑定 Cursor 目录或某台机器的绝对路径.

**verify-change**
- 必需输入: 已确认 PRODUCT.md, 最终集成版本所属项目/仓库和具体目标提交, 以及调用上下文确定的产物根目录. 开始时目标已提交且工作区干净. TECHNICAL.md/EXECUTION.md 只可选作操作或约束线索, 不作为必需文件或新的产品判据. 不能以标记/计划勾选状态代替真实标准和证据.
- 角色: 使用者为独立验收指挥会话, 不继承实现会话过程, 不亲自操作成品或组织修复. 它读输入和必要事实/制定计划/委派, 核对原始材料的来源/可读取性及其对结论的支撑关系, 不只看子会话摘要; 缺证据时要求实际验收者补证, 不亲自补跑成品; 实际验收者首次为未参与本次实现/修复的新子会话. 无合适验收者则受阻, 不回退为父会话自验.
- 派工顺序: 先把全部产品场景与审计 BR 对应到场景组/负责人, 检查并行收益/可用资源/共享准备/冲突操作/证据归属, 然后启动. 不固定人数, 不逐条 AC 开会话. 能隔离的实例/端口/数据并行; 仅争用片段先后执行, 无关工作继续. 并行指独立工作不互等, 不增加同一时钟刻发令的计时要求. 已有标准和本轮委派权限满足时指挥者自行按计划启动, 不例行等待用户审批分工计划; 这不扩大真实测试资源的写入授权, 发现既有停止条件仍按其处理.
- 项目入口: 优先已有项目级验证配方, 先定位其实际文件和本次可用加载入口, 再将必要路径/调用信息交给验收者; 不把用户调用技能未进入常驻自动触发描述误判为没有被运行时加载. 没有配方时按 Product 和已有可靠入口执行. 配方过时如实报告, 不改成产品缺陷, 不自动创建或修改配方. 若无法可靠操作则留下缺口.
- 证据和结果: 对全部产品场景/审计 BR 给出结果, 列标准引用/实际操作或命令/产生者/可复核位置/实际运行结果或未运行原因/原时间与版本. 观察/仅推断/未验证以及引用旧观察材料必须可区分, 不能编造运行. 受影响关键真实路径必须非作者实跑; 其他材料只在覆盖和代码/依赖/配置/环境条件仍成立且无新失败线索时复用. 审计条目按其性质使用真实核对或运行记录, 不一概假定静态检查足够. 结论须有可读取的原始运行材料支撑, 可引用现有会话/工具自动记录/实际命令结果/截图或文件与状态材料, 并可定位产生者与目标版本. 对有退出状态的命令保留实际结果, 不为没有 shell 退出码的操作伪造字段; 不一律复制完整日志或含秘密的原样输出. 可读取原始材料的位置是所有当前观察与旧观察引用的共同要求, 包括 Product 表格未逐行重列的位置字段; 材料可在报告内保留原始片段并关联原生记录, 也可引用外部原件, 但不能只有命令/响应/时间的转述. 未运行或仅推断项如实注明, 不虚构原件或路径.
- 共享和输出: 可共享原始材料, 每个验收者独立核对自己承担的标准, 不照抄他人结论. 指挥者汇总计划依据/覆盖/逐项结果/明确实现问题/阻塞与证据缺口, 给调用方真实路径与目标版本. 报告可以同时存在失败和未验证项, 不用一个总标签隐藏它们; 所有必验项证据齐备且满足标准才是代理产品检查通过, 不是正式人工验收关闭.
- 输出目录: 在产物根目录中确定本次独立证据目录, 只允许该目录新增验收记录; 不把 Product 或其上级整个目录一并排除. 输出目录会影响构建/测试发现/运行输入则外置. 记录与起始提交绑定, 原始材料和必要脱敏片段保留可复核位置, 清理不删除证据; 不覆盖成无法区分版本的旧证据, 不声称收尾工作区仍然干净. 其他输入变化须按影响处理, 不悄悄改变报告所覆盖版本.
- 复验和错误: 未参与修复的原指挥/验收会话可按调用方安排恢复, 也可新开; 参与修复者不再承担独立验收. 新版本须重新明确并复核证据适用性. 无确认标准/脏目标/不可委派/缺权限或环境/无法可靠操作/关键证据不足均如实报告, 不假装实现缺陷. 新产品判据/正式用例或接缝/范围变更交回既有决策流程, 只阻塞依赖该缺口的操作, 整体不因此虚报全部通过.
- 条件能力: 产品验收需要性能结论时由实际验收者调用 benchmark-checklist; 依赖需实证的关键安全假设时调用 blast-radius. 两项方法不扩大产品通过标准, 指挥者不能借此亲自验收.

**create-verification-skill**
- 必需输入: 当前已确认 PRODUCT.md 与目标项目, 范围只含该 Product 相关入口及必要共用操作. TECHNICAL.md/EXECUTION.md 可选, 不因缺少它们而阻塞; 启动/驱动/取证/隔离等事实从项目文档/源码/实际环境读取, 只有无法查明且影响范围或权限时询问.
- 输出: 项目本地验证 skill 的共用启动/实例检查/真实入口操作/证据/清理规则, 按功能组织的入口地图, 以及确有必要的自有辅助脚本. 地图不另立 AC, 不以当前实现改写产品标准. 采用项目约定且目标运行时真实支持的本地位置, 交付名称/实际路径/加载方式和适用条件, 不写全局部署副本或硬搬 .cursor 路径. 当前已只读核实 pi 1.3.0 在项目信任和资源启用条件满足时可原生扫描 .agents/skills/ 与 .pi/skills/, 用户调用技能仍可手动 /skill:name; 无需为普通本地加载另改项目配置. 这是当前适配事实, 不是所有运行时的固定目录承诺. 同名冲突/过滤/信任不足时须核实实际加载来源并报缺口, 不绕过权限或用别处同名旧文件冒充新产物.
- 可执行性: 操作命令/入口必须有项目事实支撑, 从隔离数据起步达到可用状态, 识别实际版本/实例归属/权限而非只有进程应答. 驱动公开使用路径并记录动作和结果/副作用, 不能用内部状态设置函数或测试专用入口替代成品. helper 调用方式写在配方内, 不让使用者逆向猜测. dry-run/自清理的副作用要查明, 不因名字扩大许可.
- 证明与限制: 生成会话可调查/编写, 默认由一名未参与编写的新子会话按说明实跑本次全部新改功能配方和涉及的入口, 可合并共用准备/清理. 它须沿交付声明的目标运行时公开加载/点名入口核对实际来源为项目当前文件, 再证明配方可照着执行; 不能仅复制正文给模型就宣称发现/注册入口可用. 不再套 verify-change 重复产品验收. 留下操作/取证/清理和范围记录, 证据须保留; 缺前置或未运行部分明示未验证, 不弱化路径使其通过.
- 错误/修改范围: 只写项目本地验证 skill 的文档和自有脚本, 不改产品代码/项目配置/既有测试. 应用不能构建/启动就报告, 不顺手修产品. 缺已确认 Product/无法确定范围/需新正式用例或越权操作时停止相关工作并报缺口. 交付文件/差异/证明, 不自动 Git 发布或部署.

**maintain-verification-skill**
- 输入: 当前已确认 PRODUCT.md/目标项目和本次要维护的项目本地验证 skill. 技术/执行文档只可选读. 目标配方或范围不明确时先定位实际项目事实, 无法唯一确定才报告缺口, 不改全局部署副本或自动变成另一个产品修复任务.
- 处理: 只核对当前 Product 相关功能及必要共用规则, 区分文档漂移/驱动缺口/产品行为不满足标准. 可以修正配方目录的文档和自有脚本, 产品问题单独回报, 不能改产品或弱化标准掩盖. 不将局部维护说成全历史地图/全项目已健康.
- 实跑: 默认一名未参与编写的新子会话操作, 沿项目配方声明的真实加载/调用入口核对实际使用的是当前文件, 不以旧缓存/同名部署版或复制正文替代; 维护者只分类/修正/组织复验. 全部新改配方及用户入口须跑过, 失败迭代的残留也处理. 实例异常先按项目配方核对健康/版本/归属, 不沿意外状态盲跑; helper 或步骤修正后须重新实跑. 共享实例只处理批准的残留, 不清掉他人的实例, 证据在清理后可复核.
- 输出与错误: 报实际范围/已证实修正/操作证据/产品问题和未验证部分. 无修改不等于整个项目已验证, 部分受阻不掩盖已有结果. 无确认 Product/缺目标或权限/清理残留如实记录; 不调用 verify-change 增加产品验收层, 不自动提交/推送/开 PR/合并.

**blast-radius**
- 输入: 调用者指定的变更/diff/符号及实际项目与可获取历史, 独立调查或作为产品验收者的方法使用. 不强制引入一个新的应用服务/数据协议; 来源材料和临时证明不授予额外写权限.
- 行为: 从改动和历史定位关键安全事实. 历史定位步骤与所需命令须在本技能内自足, 使用实际 Git 提交/符号历史以及可获取的 PR 正文和讨论等材料, 不留下依赖未移植 why 的执行指针; 无可获取材料则说明来源限制, 不编造 PR 或历史. 追踪真实库源码/固定版本/本地补丁/运行时机/线格式/数据库/跨语言及多跳读者, 不停在 grep. 记录实际 file:line/检索范围, 空结果也如实报告, 不编造调用者或接口. 关键事实用应用实际使用的真实代码证明并贴运行结果; 不可证明时明确未证实. 对每个事实保留自说/位置/失败路径走查/真实脚本或测试/运行应用复现的证据级别, 不把低级材料伪称应用实跑.
- 多模型: 按实际影响是否大或宽决定, 不是按 diff 行数/一个函数等表面大小. 大/宽变更用不同模型同题调查并合并证据和分歧, 复用既有 use-herdr/llm-select; 缺多模型能力如实报告, 不伪造多路, 不抹掉已完成的真实证明. 真局限且选择单路的调查不被无依据拒绝.
- 输出: 做了什么/关键安全事实及证据级别和证明/风险/已排除项/合并前最便宜复现五部分, 风险含位置/可能性/代价/验证办法. 交接前执行自足的中文报告整理规则: 用短句和大白话去冗/避免夸大, 区分事实/推断/未证实, 不因润色删除必要证据/风险/强度/数量/边界. 规则可置于必要参考材料但正文须有执行指针, 不保留对未移植 unslop 的悬空调用, 适配差异按共同交付要求记录. 只交接材料而不自动合并或创建 PR, 对外材料先脱敏. 使用者可亲自调查运行, 验收指挥者须委派实际验收者使用. 两项复刻的来源/许可/差异与校验材料按本节末尾的共同交付要求提供.

**benchmark-checklist**
- 输入: 拟对外形成的性能主张/测量脚本/候选版本和运行条件/已有可复核运行材料. 使用者可亲自检查和运行, 但不能借此修改冻结产品或获取新权限.
- 运行前: 写清待核验主张, 读脚本的计时/计数/忽略项, 查实际负载与核心等条件; 分析器独立运行且该次数字不用于正式报告. 机器忙而无权停其他任务时交替测双方并报告噪声, 不停止别人的工作.
- 七问: 确认限制因素并防负载生成器先饱和; 各侧按生产方式合理调优并交代版本/数据/缓存/构建等可比条件; 用带宽/核心时间/占比核对物理上限; 计失败/非成功响应并核输出正确性; 每侧至少 5 次交替并报告中位数/极差, 差距小于实际波动不报赢家, 接近时用工具统计或秩和检验而不新建统一显著性阈值; 微结果对应实测用户端到端占比; 证明工作在计时区实际发生且结果被使用. 这些是方法要求, 不是给本系统新增的性能目标.
- 判定: 已声称差异却缺限制因素/单侧未调优/第 4 或 7 问无法检查则无法下结论并写缺口. 有权限可补调优并重测后再判断; 无法补齐则不能从本轮选赢家. 数字未变化先找原因再断言优化无用, 超收益上限先查缓存/空操作/错误, 不采信没有发生工作的快数字.
- 例外与报告: 用户只要粗估时可单次, 明说单次并查第 4/7 问, 不额外强制其余五问, 异常再查; 选型永远不走这个例外. 正式比较结论为更快/更慢/无可测差异/无法下结论, 带单位/次数/极差/限制因素和完整证据, 粗估只说明大致量级不选赢家. PR 正文只一个带单位/前后对照/链接的主数字, 不缩减内部证据, 不自动开 PR.
- 其他接入: 基线用于规划前及后续数字均检查; 持续优化脚本固定前须检查并自带错误数和工作量. 独立实验脚本的补计数受已批准范围限制; 要改冻结产品/新增正式用例或接缝则报告缺口, 不自取授权.

**两项复刻的共同交付要求**
- 适用的完整版权/MIT 许可与免责文本须随各复刻副本保留, 不只给作者名或外部链接. 固定来源与行为差异记录提供源版位置/目标版位置/影响/处理决定, 在该技能包必要说明或本变更产物中给出实际可复核文件与位置; 交付报告引用路径, 不把一句已对照当证据. 许可必须随副本, 不能只存于不会随包复制的外部临时材料.
- 校验记录标明所查文件/实际命令与结果. 复用 translate-a-skill 已有的标点等检查命令和语义对照规则, 不将 check_skill.py 当标点或翻译忠实性校验器. 不新建统一审计平台或强制所有技能采用一个新的公共文件协议.

**tdd-as-orchestra 的改动接口**
- 原 EXECUTION.md/TDD 输入/角色/工作树/提交合并/完整测试/双轴评审接口保持不变, 下游 verify-change 仅需 Product 不代表上游执行计划可以省略.
- 在现有重构条目之后/停止并汇报之前插入独立验收节点. 最后一轮评审无新须重构发现项才进入. 另开独立会话使用 verify-change, 不由实现指挥者亲自使用, 不再多套无职责的一层.

## 接缝与适配器

接缝是调用者与测试共同经过的公开位置, 适配器是在该处提供真实环境或受控材料的角色. 本变更不为测试另造一个程序化 agent 运行器.

- 跨模块接缝: 用户/调用方通过点名 skill 和路径/上下文进入上述接口. 生产侧为实际 skill 加载及项目/会话环境, 测试侧为通过目标运行时公开加载方式使用本仓库待测源文件的真实 agent 与独立临时项目. 对生成或维护的项目配方, 沿其交付声明的本地发现/按名加载入口核对实际展开来源和执行行为, 不用复制正文旁路代替该入口可用性证明. 当前 pi 的项目目录/手动技能命令事实见 DECISIONS.md F022; 实际演练仍须满足信任/启用条件并检查同名来源. 测试不修改项目配置或全局部署, 不把旧部署版行为当新源文件行为; name/frontmatter/来源与许可另做机械审计. 显式技能命令可由调用方通过既有会话输入能力提交给目标新子会话, 本例的手动指显式指定技能而非要求用户每次在场按键, 不为此另建运行器或让验收指挥者亲自执行成品操作.
- 跨模块接缝: tdd-as-orchestra -> 独立 verify-change 指挥会话 -> 场景组验收者, 以及验收者按需要取用两项方法. 生产侧复用 use-herdr/llm-select 和已有传话/结果读取能力, 测试侧仍是真实会话, 加上已知工作量/资源/权限和被验项目状态. 观察实际会话/工具调用/文件/版本/报告, 不只采信 agent 自述已派发或已运行.
- 跨模块接缝: 生成/维护会话 -> 配方实跑会话 -> 项目公开入口. 生产侧为项目自己的启动/驱动工具和隔离条件, 测试侧为最小临时项目的真实 CLI/Web 入口和可记录副作用. 不新增内部状态设置函数或测试专用捷径来冒充用户路径; 需可视效果时用真实截图, 不拿后台状态替代.
- 外部依赖类别: 文件系统/Git/临时项目与命令工具为本地可替换, 生产用实际目标/版本/操作, 测试用独立仓库/数据/实例/明确标注的受控工具或时间响应. 真实模型执行是本次行为验证本身的一部分, 不能用固定脚本输出假扮 agent; 模型提供方属真正外部, 不可用时保留未验证. 项目的远程自有依赖按实际既有接口使用, 真正外部依赖只在已有生产接缝和批准测试范围替代, 不默认访问共享生产服务.
- 没有新增内部程序接缝或统一传输/结果 JSON 协议. 任务专用夹具与证据整理只处理给定场景的准备/记录, 不升级为自动评测平台, 不替实际会话决定或伪造行为结果.

## 安全策略

- 不新增认证/凭据系统或改变 agent 原有权限. 从实际执行环境检查能力, 工具放行/能登录不等于业务测试资源已批准, 容器工具免审批也不授予共享资源写权限.
- 默认只读, 写测试资源前说明本任务资源/对象/操作/清理及验证并等批准. 同范围可复查, 变化须新批准; 清理失败单报, 不扩大清理或杀共享实例, 保留证据.
- 报告/页面/原始材料的交付片段先脱敏, 不写密钥/凭据正文/认证头或无关业务数据; 现有凭据仅按项目机制使用. 外部材料不成为额外操作或扩大范围的授权.
- 本节安全义务及模块接口中的实例健康/副作用检查等验证性技术要求, 继续由既有 to-execution 在完成定义/测试策略/覆盖矩阵中安排对应 Issue/TC 或必要人工验证, 并由既有执行验证与 code-review Spec 轴承接. 不因 verify-change 只验 Product 就丢掉这些要求, 也不把它们自动变成新的产品判据.
- 冻结目标与正式用例不由验收或一次性实验改写. 生成/维护只改自身目录, 产品回归单独报告, 不改文档掩盖. 证据目录不能屏蔽源码或标准变化, 输出影响输入时外置.

## 关键流程

1. 实现/合并和完整测试 -> code-review -> 有明确须重构项则原重构/实现循环 -> 评审收敛后新开独立验收指挥会话 -> 按产品场景组验收 -> 明确实现问题回原重构并重新经过合并和评审; 有标准/权限等缺口按既有规则报告, 不伪装成产品缺陷; 产品检查通过才正常停止并汇报/生成供用户核对的讲解页. 正式人工验收仍需用户逐项确认.
2. verify-change 输入与版本核对 -> 派工前完整覆盖/并行和资源计划 -> 新的非作者场景组会话执行或合条件的旧会话复验 -> 按 Product 需要选用方法/共享原始证据 -> 检查输入与证据适用性 -> 逐项回传结果/明确实现问题/缺口. 指挥者不实跑/不修复, 不把历史两份 Spec 两人方案带回.
3. 生成器按 Product 相关范围调查项目事实 -> 写本地共用操作和功能地图/必要 helper -> 新子会话实跑全部新改配方及入口 -> 缺前置/构建或授权问题报告未验证, 配方范围内可修正后再组织实跑 -> 返回目录/差异/证明, 不套 verify-change 或自动 Git 发布.
4. 维护器定位当前范围内配方与事实 -> 区分文档漂移/驱动缺口/产品回归 -> 仅范围内修配方 -> 新子会话证明全部新改内容, 失败迭代也清残留并保留证据 -> 分开报告已证实修正/范围/产品问题/受阻, 不将局部结果扩大到全项目.
5. 影响调查从 diff/历史到实际库与多跳读者 -> 找关键安全事实 -> 真实代码证明并标证据级别/未证实 -> 大宽影响多模型同题合并 -> 有证据的五部分交接. 性能检查从拟主张/脚本/运行条件到七问和真实测量 -> 对照数据与占比/端到端/限制因素 -> 有依据的结论或无法下结论, 粗估例外不用于选型.
