## 要构建什么

在 `workflow/verify-change/SKILL.md` 增加并行执行与修复后复验切片: 可隔离的实例/端口/数据并行, 争用同一记录的片段先后执行且无关检查继续; 共享原始证据保留产生者, 版本与位置, 每个验收者独立判断自己的标准; 修复后可按调用方安排恢复未参与修复的原会话或新开非作者会话, 绑定新提交并按影响重验. 交付后, 临时项目中的实际执行顺序, 重叠区间, 证据产生者与复验承担者可核对.

## TDD 切片

- TS-001:
  接缝: verify-change -> 并行执行与原始证据共享接口 (TECHNICAL.md 测试接缝 AC-006 行); 适配器为独立实例与共享记录夹具.
  测试用例: TC-006.
  先写的失败测试: `drill-parallel-and-shared-evidence` 在当前技能没有并行/争用规则时, 两组要么互相等待, 要么同时写同一条记录, 共享材料也可能丢掉产生者; 预期失败于执行顺序或证据归属不可核对.
  最小绿色实现范围: 可隔离资源并行; 同一记录写入片段先后执行并留顺序记录; 无关只读检查继续; 共享原始材料保留产生者/版本/位置; 各验收者独立判断, 不照抄通过结论.
  不得测试: 固定并发数或计时精度; 不测未确认的调度算法.
  覆盖: AC-006.
- TS-002:
  接缝: verify-change -> 恢复或新开复验接口 (TECHNICAL.md 测试接缝 AC-007 行); 适配器为初次失败与修复后的真实目标提交, 会话参与事实与新旧原始证据.
  测试用例: TC-007.
  先写的失败测试: `drill-reverify-after-fix` 在当前技能没有复验规则时, 修复版本会沿用旧通过结论, 或让参与修复的验收者继续验收; 预期失败于未绑定新提交或未按影响重验.
  最小绿色实现范围: 复验绑定新目标提交; 未参与修复的原会话可恢复, 原会话关闭时新开非作者; 参与修复者被替换; 作者日志只作材料, 受影响关键真实路径由验收者本人重跑; 复核旧证据适用性.
  不得测试: 强制每次重开全部会话; 不测未确认的会话恢复技术.
  覆盖: AC-007.
