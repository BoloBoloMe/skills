# MILESTONE-04 网页访问决策账本

盘问日期: 2026-09-14. 输入: [交接](../../handoff/2026-09-14-m04-网页盘问.md), [路线图](../roadmap/ROADMAP.md), [网页侦查](../recon/02-present-web.md), [M01 账本](../milestone-01/DECISIONS.md). 用户确认完成标准, 同意独立反方检查, 确认补充的当前设备规则, 最后明确同意结束盘问并落盘/提交/推送.

本文是设计结论, 不是实现或真机验收记录. 实施归 [M05](../roadmap/MILESTONE-05.md), 真机验收归 [M09](../roadmap/MILESTONE-09.md). M03 由另一会话并行实施, 在本轮落盘期间已关闭; M05 消费其交付能力, 本文不虚构它尚未提供的接口.

## 决策

### D001 容器对外网页端口固定为 8800, 直达局域网
- 状态: 当前有效
- 约束性: 必须遵守
- 内容: 沿用已拍定方向, birth 增加 `-p 8800`, 宿主监听所有 IPv4 地址并动态分配端口; 容器对外 web 服务监听 `0.0.0.0:8800`. 用户再次确认接受无认证 web 服务对同网段开放, 包括将链接分享给同事的用途. 监听约定写入本仓库 use-sandbox-worktree skill, present 容器分支与之对齐. 宿主本机和局域网访问共用这一映射, 不增加认证/TLS. 不重开回环-only/纯手工隧道/固定宿主端口/pasta 自动转发等已排除方向. 本决策承接旧账本 D053 的展示端口需求, 替代其回环-only 形态.
- 依赖事实: F001
- 预计影响: `workflow/use-sandbox-worktree/scripts/swt.py`, 对应 skill 与 present 容器分支; ADR [0012](../../../adr/0012-container-web-direct-access.md).

### D002 多张展示页复用现有 present 单实例
- 状态: 当前有效
- 约束性: 必须遵守
- 内容: 同一容器环境的多张展示页复用现有 present 常驻展示服务, 通过现有目录挂载能力提供内容, 始终使用 D001 的端口. 不为每张页面另起服务. 用户指出单实例设计后, 核查确认当前组件没有启动 Vite/Next.js 的流程; 侦查中的 dev server 是未来项目应用的例子, 不能据此假定当前存在两个服务争抢端口. 撤回让用户选择停网站/轮流展示的建议, 不引入反向代理, 不为验收另建 Vite/Next.js 应用. 此澄清不撤销 D001 对容器对外 web 端口和局域网暴露的约定, 也不宣称 present 能运行任意动态应用. present 非容器模式及服务自身的通用改造不属于本轮范围.
- 依赖事实: F002, F003
- 预计影响: present 容器分支, M05 的范围与验收场景.

### D003 一母体一个活跃容器, 每次交付只列自身双 URL
- 状态: 当前有效
- 约束性: 必须遵守
- 内容: 用户明确一容器对应一母体, 一母体同一时刻只有一个活跃容器; 一台 host 可以有多个母体, 各自独立. 每次交付只给当前母体对应容器的本机 URL 和局域网 URL, 不汇总其他母体, 不做多容器总览页. 不同容器使用不同的动态宿主端口, 地址和内容不得串到其他母体. swt 将实际映射登记为 STATE 容器记录的 `web-port`, birth/status/resume 对本次新建容器给出一致的映射信息. 原代码和旧约定允许同母体多个容器, 已列为 M05 需要修正的差异; 旧账本承接见 [D054](../../use-sandbox-worktree/DECISIONS.md#d054-一母体一个活跃容器-2026-09-14-m04). 本轮不改动现有容器, 也不取消同一主仓只能有一个活动母体的原约束.
- 依赖事实: F004
- 预计影响: swt 新建检查/STATE/交付函数, skill 文档, 领域语言.

### D004 分享链接不保证跨容器重建稳定
- 状态: 当前有效
- 约束性: 必须遵守
- 内容: 用户接受容器删除重建后宿主端口变化, 需要取得并重新分享新 URL. STATE 和交付包提供当前容器的实际入口, 不承诺旧链接永久有效. 不增加稳定域名/固定宿主端口/转发层, 不另立 URL 稳定性 Milestone. 此决定关闭路线图的分享 URL 稳定性迷雾; 不授权重建用户现有容器.
- 预计影响: M05 交付说明, ROADMAP 未决迷雾.

### D005 页面就绪后在用户当前设备打开一次
- 状态: 当前有效
- 约束性: 必须遵守
- 内容: 页面或 web 服务就绪后, 在用户当前使用的设备上用默认浏览器自动打开一次; 无法代开时给可点击链接. birth 只发布端口并交付入口, 不因容器出生就打开尚不存在的页面. `xdg-open` 是 Linux 用默认程序打开网址的命令, 在哪台机器执行就打开哪台机器的浏览器; 容器执行它不等于打开宿主浏览器. 宿主有桌面会话也不等于用户坐在宿主前, 不以此选自动打开位置. 当前设备的确定方式由 D012 补齐.
- 预计影响: 展示就绪流程与设备侧开页指引.

### D006 容器通过信箱询问设备 agent 取得网址
- 状态: 当前有效
- 约束性: 必须遵守
- 内容: 用户选择复用信箱, 不新增给容器挂载的只读 URL 文件. 正常路径为容器 agent 发信询问当前设备上的 agent, 设备 agent 取得当前容器的正确网址, 经既有回话通道回告, 并按 D005 代开页面. 沿用 M01 的单向信箱和设备到容器的 ssh/herdr 回话, 不新增回程队列. 复用已有 request/open_url 能力, 不假定 M03 已有一个未定义的 URL 查询端点. 信中须说明来自哪个容器/会话, 使接收方能够定位该容器的宿主交付资料或状态, 查到网址并回到原会话; 不能把仅有容器名的消息误当作完整的寻址信息. 不让用户充当两边 agent 的传话人, 不把密钥或 token 写进消息或受版本控制的文档.
- 依赖事实: F005
- 预计影响: 容器/设备 agent 的信箱使用指引及 M05 与 M03 的集成验证.

### D007 信箱只增强自动沟通, 不承担网页可达性
- 状态: 当前有效
- 约束性: 必须遵守
- 内容: 信箱未运行时, 用户仍可点击 host 事先交付的 URL 访问已就绪页面, 无须信箱提供网络通道. 本轮不要求断信箱时容器 agent 仍能自动查询宿主映射, 因此不需要 D006 已拒绝的额外 URL 文件. 不把提供链接的降级路径写成已成功自动打开. 端口发布/STATE/双 URL 可先实施, 不依赖 M03; 信箱代问/回话/代开部分须在 M03 可用后验证.
- 预计影响: 交付包, 展示失败/降级说明, M05/M09 依赖说明.

### D008 旧容器先恢复终端, 网页需要时询问重建
- 状态: 已替代 (→ D009)
- 约束性: 必须遵守
- 内容: 盘问曾建议旧容器正常恢复终端, 需要网页访问时说明缺少 8800 映射, 经用户同意再重建. 用户先回答是, 随即明确现有容器不用管, 因此本方案不进入实施, 完整由 D009 取代.
- 预计影响: 无; 被替代前未实施.

### D009 只处理改动后新建的容器
- 状态: 当前有效
- 约束性: 必须遵守
- 内容: 替代 D008. 用户明确已经启动的容器不用管, 随后接受范围澄清为改动前已创建的容器全部不处理. M05 不为它们补发布/迁移/重建, 不增加旧容器恢复提示或自动改造流程. 本次只处理改动后新建的容器及这些新容器后续的正常状态查询/恢复/交付. 新规则进入未来容器不等于改动现有容器.
- 预计影响: M05 范围, 新建/恢复实现中的适用对象, 验收环境选择.

### D010 局域网地址先用已确认值, 无法确定才问用户
- 状态: 当前有效
- 约束性: 必须遵守
- 内容: 宿主可能有多个网卡/VPN, 有 IP 不等于用户设备可达. 优先沿用已确认可用的宿主地址, 无法确定时再问用户, 不把猜测的地址当成可用链接交付. 对齐旧图 M14 的 LAN IP 问题, 不把当前代码取首个非隧道地址的做法当成可达性证明.
- 依赖事实: F006
- 预计影响: swt 地址选择和交付流程, host/设备 agent 指引.

### D011 六项完成标准
- 状态: 当前有效
- 约束性: 必须遵守
- 内容: 以下六项用大白话向用户完整解释后, 用户回答"挺好", 作为完成标准. 所有容器均指 D009 范围内新建的容器. 当前只确认用例, 尚未执行或通过验收.
  1. TC-001: 当新容器的展示页就绪时, 用户在宿主机或局域网另一台电脑点击交付链接, 都能看到实际页面.
  2. TC-002: 当连续生成多张展示页时, 它们都能访问, 共用 present 服务和 8800, 不启动一堆重复服务.
  3. TC-003: 当同一宿主上有不同母体/项目的容器时, 每次交付只包含自身的两条 URL, 打开后内容不指向其他项目.
  4. TC-004: 当信箱可用且页面就绪时, 两边 agent 自行沟通取得网址, 回到原容器会话, 在用户当前电脑打开一次, 不要求用户传话.
  5. TC-005: 当信箱未运行而页面已就绪时, 用户仍能点击事先交付的 URL 访问页面.
  6. TC-006: 当无法确定该使用宿主的哪个地址时, agent 询问用户, 不交付猜测地址.
- 预计影响: M05 通过 swt birth/status/resume 输出和真实 HTTP 访问验证端口/交付, 通过 present 公开命令与 HTTP 验证复用; M03 可用后经真实设备会话/信箱检查沟通与代开; M09 完成双机真跑. 以外部可观察结果为准, 不以仅存在 STATE 字段或提示文字代替真实访问.

### D012 当前设备由工作会话确定, 发信明确指定目标
- 状态: 当前有效
- 约束性: 必须遵守
- 内容: 反方检查与自扫均发现, 最近来取信的设备不一定是用户正在使用的电脑. 用户确认补充规则: 每次开始工作时明确本次使用的电脑, 能从会话信息确定就自动记录, 不能确定才问用户一次; 换电脑时更新. 本次展示相关信件明确指定该设备, 不靠最近轮询顺序猜测. 本规则补齐 D005/D006 及 TC-004, 不更改 M01 通用信箱的缺省路由: 其它未指定目标的信件仍按原协议处理. TC-004 必须包含两台设备同时取信和用户切换电脑的验证条件, 才能证明满足已确认的当前设备语义.
- 依赖事实: F007
- 预计影响: 工作会话的设备记录/传递, 投信时填写已有 `to`, 设备切换后的目标更新, M05 集成与 M09 真机验收.

### D013 实施必须补齐寻址/单容器限制/新规则入容器
- 状态: 当前有效
- 约束性: 必须遵守
- 内容: 反方结果汇报时明确以下是实施必须补齐的内容, 用户接受当前设备修正后确认整体结束并落盘: (1) D006 的信中携带原容器/会话信息, 接收方确实能取得网址并回话, 不以一段提示词存在即算打通; (2) 新 birth 遵守 D003, 修正旧文档允许同母体多个活跃容器的说法; (3) 未来新建容器实际拿到更新后的 present 规则, 不能只改仓库文件. 镜像中 skills 为构建期 COPY, 母本为 birth 时留档挂载, 两种分发方式要按实际修改对象处理. 不再承诺 M05 "无镜像层改动/无级联重建"; 若更新镜像, 沿用既有镜像更新/级联流程并与后续路线协调, 不擅自替换现有容器. 本盘问没有固定新的配置文件路径/URL 查询端点/镜像热更新机制, 实施不得把这些未提出的接口伪装成已确认设计.
- 依赖事实: F004, F005, F008
- 预计影响: M05 实施任务书和交付验证; 如涉及镜像更新, 与 M08/M09 协调生效验证.

## 事实

### F001 8800 只有镜像元数据, swt 未发布
- 状态: 当前有效
- 来源: [侦查](../recon/02-present-web.md), `workflow/use-sandbox-worktree/scripts/image-prep.py` 的 EXPOSE 与 `swt.py` 的容器创建参数, 本轮只读核查.
- 内容: 镜像声明 `EXPOSE 22 8800 6080`, swt 创建参数只发布 22 和 6080. EXPOSE 不会自动创建端口映射. pasta 下不能拿容器看到的宿主 IP 当成独立可直达的容器 IP. 新建时发布 8800 是本轮实际缺口.

### F002 present 已支持单用户单实例和多目录复用
- 状态: 当前有效
- 来源: [present 账本](../../present-web-server/DECISIONS.md) D002/D005/D006/D008, `general/present/scripts/web_server.py` 的 `run_start`/`run_status`.
- 内容: 同环境同 uid 的 start 会复用存活实例并挂载目录, 提供静态文件与目录列表. 该能力足以承载多张展示页, 不是通用应用运行器. 另有需要实施留意的现存差异: 容器分支文档禁止换已映射端口, 通用 status 恢复代码仍可能随机换端口. 这不是已发生的多服务冲突, 也不构成恢复停网站方案的理由; 新容器的实际运行结果必须满足 D001/D002.

### F003 当前组件不要求启动 Vite/Next.js
- 状态: 当前有效
- 来源: 2026-09-14 在 `general/`, `workflow/`, `pi/` 搜索 `vite|next.js|nextjs|next dev|npm run dev|pnpm dev|yarn dev`, 无匹配; 相关例子只见本路线 recon 文档.
- 内容: Vite/Next.js 是侦查用于说明未来项目开发服务的例子, 不是当前容器基础组件实际启动的服务. 事实范围限此次仓库核查, 不推断任意未来项目都不会使用它们.

### F004 当前 swt 契约允许同母体多个容器
- 状态: 当前有效
- 来源: [旧账本](../../use-sandbox-worktree/DECISIONS.md) D009/D010/D031, `workflow/use-sandbox-worktree/SKILL.md` 的多容器共推段, `swt.py` 新建逻辑.
- 内容: 现行实现允许以不同容器名创建同母体的多个容器, 与 D003 的新要求不同. 文档决策生效不代表代码已经实现限制, M05 需要处理新 birth 检查, 不对现有容器追溯执法.

### F005 信箱消息本身不等于完整的网址/回话地址
- 状态: 当前有效
- 来源: [M01 账本](../milestone-01/DECISIONS.md) D003/D004/F003, `pi/extensions/swt-mailbox-relay.ts` 的 `renderMessage`, `swt-base-server.py` 的 `try_deliver`, swt 交付包及 ssh/herdr 委派配方.
- 内容: 信箱提供消息传递; 设备侧收到来自容器名的正文, 回信仍需既有 ssh/herdr 入口和原会话. host 能查 Podman/runtime 状态, 远程设备上的 agent 不能因收到信就自动拥有 host 本地状态. 因此 D006 要求实施补齐设备侧可用的地址来源和原会话定位, 不把未定接口或凭证可用性当成已验证事实. 同一 Podman 环境容器名不能重复, 反方提出的"同 host 多项目同名容器"不是本缺口成立的必要条件.

### F006 当前 LAN 地址算法不能证明用户设备可达
- 状态: 当前有效
- 来源: `workflow/use-sandbox-worktree/scripts/swt.py` 的 `lan_ip`, [旧账本](../../use-sandbox-worktree/DECISIONS.md) F022.
- 内容: 当前代码取第一个非隧道/非虚拟接口的全局 IPv4, 找不到时回退默认路由源地址. 它不判断用户设备实际可达哪个接口, 也未保存 D010 要求的已确认地址选择.

### F007 信箱缺省目标依赖轮询时刻, 不代表人在该设备
- 状态: 当前有效
- 来源: `workflow/use-sandbox-worktree/scripts/swt-base-server.py` 的 `verify_poller`/`_default_device`/`_deliverable`, 独立反方与自扫一致结论, 高置信.
- 内容: 每次设备取信都会更新 last_poll, 缺省目标取最近轮询的设备. 两个取信会话长期同时运行时, 消息落在哪台设备受轮询时序影响, 无法据此保证浏览器开在用户当前电脑. D012 使用现有显式目标能力解决本轮用途, 不替通用队列改默认规则.

### F008 skills 随镜像构建复制, 母本随 birth 留档挂载
- 状态: 当前有效
- 来源: `workflow/use-sandbox-worktree/scripts/image-prep.py` 的 `stage_context` 和 Containerfile 模板, `swt.py` 母本留档/挂载, [旧账本](../../use-sandbox-worktree/DECISIONS.md) D018/D020/D039/D050/D052.
- 内容: skill 库 COPY 进 base; 仅改仓库 present 文档不会使旧镜像新建的容器得到该版本. 三份 agent 母本则 birth 时复制留档并只读挂载, 仓库母本变化也不自动传播进既有容器. M05 原文"无镜像层改动/无级联重建"只考虑端口 EXPOSE, 漏掉规则分发, 已由 D013 更正. 当前未构建镜像或部署真实 agent skills.
