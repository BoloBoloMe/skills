地图 · 已拍板 · 未决迷雾 · 范围外 · 里程碑清单

◆目的地

三类场景 (弹浏览器过登录墙 / 展示网页 / 容器里起网站) × 两个位置 (宿主机本机 / 局域网内另一台 Linux 电脑), 全部零手工命令. Linux 桌面 = 原生体验; Mac/Windows 继续用 noVNC 网页兜底. 路线图排到实施与真机验证完成, 不是只到方案定稿.

◈地图

三条小径上山. 信箱是另外两条的加速器: 有了它, "开窗/开网页" 这类动作由桌前常驻 AI 代劳. 网页直达与窗口直飞互不相干, 可并行推进.

图例: 红圈 = 需要你在场的讨论; 墨圈 = 代理独立干活; 虚线小径 = 待走的路; 灰虚线 = 跨小径依赖.

✓已拍板 (本次会话)

  • 三方向都立项: 信箱通道 / 网页与网站直达 / 窗口直飞, 一图排完.
  • 网站服务直达局域网: 不要密码, 方便随手发给同事看. 取舍 (网段内任何人可访问) 用户明示接受.
  • 零手工命令: 一切命令由桌前常驻 AI 或自动化代执行; 手工命令只作底层零件存在, 不经人手.
  • 排除项: 容器直驱桌前 herdr (凭证+防火墙双违背) / pasta 自动端口转发 (暴露面隐性扩大) / 固定宿主端口 (多容器必撞) / 容器主动拨出建隧道 (白名单冲突).

?未决迷雾

  • 信箱实时性: 先定时取 (5-10 秒延迟), 不够用再升级长连推送 — 实时性诉求暴露时回访.
  • 新版 waypipe: Debian 现在装的 0.8.2 有断线重连, 未来换 Rust 版该功能消失 — base 换发行版时回访.
  • Mac/Windows 的 noVNC 隧道也要手工: 目的地已排除, 但信箱落地后可顺带自动化 — 用户改主意时回访.
  • 分享给同事的 URL 稳定性: 端口每次重建会变, 链接会失效 — 先由 M04 盘问消化, 消化不掉再立里程碑.

✕范围外

  • Mac/Windows 无感化 — 目的地明确排除, noVNC 网页兜底.
  • 跨互联网访问 — 只覆盖局域网.
  • 网站服务加认证/TLS — 与 "直达开放" 的拍板相反.
  • present 常驻展示服务自身的改造 (另一会话跟踪), 本路线只消费其结果.
