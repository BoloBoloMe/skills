# 沙盒维护公共改进 Product Spec

## 背景

我在多个项目中通过 sandbox-worktree 交付和维护容器. 原会话暴露了三类可重复发生的问题: 手拼白名单漏掉自动条目导致 SSH 失联, 容器可登录却缺少任务所需的依赖/认证/外部操作条件, 以及取证范围过大或输出截取掩盖原命令失败. 我希望提炼公共改进, 受益者是维护者与宿主/容器内 agent. 本变更沿用原复盘编号 2/4/5, 不继续原 Stripe 任务或改造其项目检查脚本.

## 目标

- G-001: 我能通过正式入口增删指定容器的用户白名单, 不必重拼完整规则, 未涉及条目/自动条目/其他容器保持不受影响.
- G-002: 我能在地址旁查询和补写用途, birth 与运行期新增用户条目必须有理由, 旧记录不会仅因缺理由而失去使用能力.
- G-003: 每次实际执行的目标/理由/权限效果与我批准的预览一致, 未批准或相关状态变化时不会误执行, 网段重叠的实际效果明确可见.
- G-004: 规则与运行记录一致, resume 保留更新, 修改失败或中断后有可识别的恢复状态, 不靠自动停容器/重启/清表救场.
- G-005: 宿主 agent 在依赖任务条件之前验证所需操作, 交付时区分容器可登录与任务条件具备, 如实分项报告且不阻塞独立工作.
- G-006: 写入探测只在我批准的任务/测试资源/操作/清理范围内执行, 同范围可复查, 清理失败与残留不会被当作通过.
- G-007: 沙盒维护取证先使用最少充分信息, 已知来源查找不扩成默认全家目录搜索, 同分支完整提交 ID 相同不再为比较而完整克隆.
- G-008: 输出截取保留原命令的真实成功失败, 过滤命令成功不再掩盖前置命令失败.

## 非目标

- NG-001: 不继续 Stripe 订阅/SDK 升级, 不修改/提取 cz_sdk 项目的构建或检查脚本, 项目材料只作为问题证据.
- NG-002: 不增加运行期网络模式切换/黑名单修改/按端口过滤/整份白名单覆盖入口; 现有 blacklist 生命周期不借此改造.
- NG-003: 不迁移旧的多容器共用一份网络配置的记录, 不提供停止态的新名单编辑, 不把 recover 做成通用网络修复工具.
- NG-004: 不建设跨项目自动探测框架, 不将原项目域名/IP/服务矩阵变成公共默认要求.
- NG-005: 不以本次规格或后续实现验收为授权自动同步部署/修改现有业务容器或运行记录/探测共享服务. 正式使用新命令仍逐次审批.

## 业务规则

- BR-001: 现行新建流程一母体至多一个活跃容器, 已停止但未终结的容器仍占用该名额; 旧兼容记录不因此自动迁移.
- BR-002: 白名单按 IPv4 地址/CIDR 放行全部端口; 自动 DNS 放行仅 udp/tcp 53, 现有 IPv6 兜底丢弃语义不变.
- BR-003: resume 必须按运行记录重新注入网络规则, 不能把停止前规则当成恢复后的有效依据.
- BR-004: 本次实现与验证仅涉及技能源仓库及独立临时测试资源, 不修改实际部署的 skills/原业务项目/现有业务容器/共享服务, 分发与使用现场验证另行授权. (审计)
- BR-005: 原 4/5 的公共要求放在沙盒 skill 与按需操作参考中, 不引入通用探测框架或项目专用检查改造, 不复制项目放行清单为公共默认配置. (审计)
- BR-006: 原 5 先限沙盒维护, 不扩成宿主/容器全局常驻 AGENTS.md 纪律; 继续复用已有防火墙应用实现, 不因临时管道问题无故替换已保留返回码的公共 run 封装. (审计)
