# 沙盒维护公共改进 Technical Spec

## 模块划分

- **网络维护模块**: 新增 `network_update.py`, 对外承担 network 命令族的行为, 隐藏规范化/差异与覆盖计算/收据核对/事务协调/失败恢复. 删除测试: 删除后这些复杂度会散回 CLI/birth/恢复调用点和宿主 agent, 不是消失, 因而保留为深模块.
- **生命周期接入模块**: 沿用 `swt.py`, 承担 CLI 解析/目标定位适配/birth 输入/resume 元数据保留及未完成状态检查, 隐藏已有母体/容器身份和启动细节. 不把网络事务主体继续堆入该模块.
- **防火墙模块**: 沿用 `net-firewall.py` 的应用/合并/移除语义, 增加按网络空间串行写入. 继续隐藏 nft 规则生成和原子换表, 不复制规则引擎, 不改变既有三链/回程/IPv6/DNS 语义.
- **公共指导模块**: 沙盒 SKILL 与交付/操作参考承担任务条件检查和取证约束. 任务条件细节按需披露, 项目现有入口承担项目操作; 不增加公共自动探测程序. 新按需参考的删除测试: 删除后同一检查/授权/分项交付规则会散回各维护会话, 因而需要一个权威位置, 主 SKILL 只留触发指针.

涉及的模块/目录: `workflow/use-sandbox-worktree/` 的脚本与参考文档, `tests/` 的公共测试和独立夹具, 本变更规格; cz_sdk 项目/实际部署副本不在修改范围.

## 模块接口

### 生命周期接入与 network 命令

在 skill 目录执行, Python 统一由 uv 运行:

```text
uv run python scripts/swt.py network show --name NAME [--repo REPO] [--records-root ROOT]
uv run python scripts/swt.py network update --name NAME [--repo REPO] [--records-root ROOT]
    [--add CIDR REASON]... [--remove CIDR]... [--reason CIDR REASON]...
    [--confirm RECEIPT_ID]
uv run python scripts/swt.py network recover --name NAME [--repo REPO] [--records-root ROOT]
    [--confirm RECEIPT_ID]
uv run python scripts/swt.py birth ... [--allow-entry CIDR REASON]...
```

`--name` 必填, 不依据焦点/首条记录猜目标. `--repo` 沿用从 cwd 推导主仓的既有规则, `--records-root` 缺省为 `~/.agents/sandbox-worktree/`. 目标必须唯一对应主仓/母体记录与完整 Podman ID, 以当前 inspect 的 SandboxKey 定位网络空间, 不退回全机首个 pasta 实例. 网络空间身份包含路径及其设备号/inode, 防止同一路径已指向另一空间.

`show` 只读, 展示记录/可取得的实际规则/理由/自动项/未完成摘要; 停止目标明确表示实际规则不可取得, 不拼出健康结论. 发现不一致只报告. 对旧记录或非 whitelist 模式的查询不授权修改.

`update` 仅适用于运行中/非 retired/身份可核对/whitelist/独占本记录网络配置的目标. 旧记录中多个可用或可恢复容器共用一份 network 时拒绝更新, 不迁移; 缺理由本身不是拒绝条件. 存在 `network-change` 时先拒绝并指向 recover. 未知实际用户规则或无法解释的规则结构也先拒绝, 不以记录覆盖或收编未知规则. 这种不一致的处置由我另行决定, 对应规则/运行记录修正属于另行授权的人工救场; 新命令不提供收编或绕过一致性检查的入口. 人工收敛后仍须重新核对一致性并走正常预览/审批.

共同输入规则:
- 用 IPv4 网络规范形式比较和显示, 单地址规范为 `/32`; 带主机位的 CIDR 显示实际网络地址/范围, 由预览揭示其含义, 不展开为逐 IP 清单.
- 新增理由去掉首尾空白后不能为空. 同一操作的完全相同重复输入合并, 不同理由或同一地址冲突操作整次拒绝. 地址等价比较发生在冲突检查之前.
- 已存在地址/理由都相同, 删除不存在的用户条目, 或理由没有变化均为无变化. 给不存在的条目改理由拒绝; 以 --add 更正已有理由也拒绝并提示 --reason.
- 自动项不作为用户删除对象. 有显式用户条目同时被自动项或大网段覆盖时, 预览说明删除用户条目后的权限仍然存在, 不擅自收缩其他条目.
- 合法 `/0` 不偷偷拒绝或改小, 预览醒目说明全部 IPv4/全部端口. 重叠计算采用 CIDR 关系, 不按网段大小枚举地址.
- 单纯理由更正遇到自动项变化按前置不足返回 2 且不写理由, 提示先执行无用户条目变更的 update 同步自动项. 真正增删时可把自动项变化并入预览; 无用户条目变更时只同步由当前目标事实产生的自动项. 连自动项也无变化则直接返回无变化.

新 birth 将 --allow-entry 交给共同条目规范化接口, 将地址列表和理由同时保存. 新 birth 的裸 --allow 因缺理由拒绝并提示新写法, blacklist 的既有输入不改. 已有 born 记录和旧失败创建的重入不借 birth 修改已固定网络; 继续沿用原重入约束, 不强制替旧条目编理由. 原 birth 模板/镜像/主机名等审批不改.

resume 继续按原生命周期恢复, 但先检查未完成网络事务, 并在重建 network 字典时保留理由对应表. 用户地址/理由不因自动项重算丢失. 普通 status/查询仍可报告异常; 对本工具留下的未完成事务, 任何要继续修改或恢复该目标的路径不得绕过处理. 显式 terminate 仍走原有检查和批准流程, 不是网络模块可自行调用的补救动作.

### 请求/结果与收据

网络维护模块接受结构化请求: `action: show|update|recover`, 主仓路径, 记录根, 目标名, `add: (CIDR,理由)[]`, `remove: CIDR[]`, `reasons: (CIDR,理由)[]`, `confirm: string|null`. birth 只复用无 I/O 的条目规范化接口. 网络维护请求所需的进程/存储/目标事实适配器由生命周期接入模块提供, 核心不反向导入整个 swt 模块.

新命令除帮助输出外, 最后一行均为 `NETWORK <JSON>`, 既有命令的 STATE 格式不改. JSON 的稳定信息为:

| 字段 | 类型与含义 |
| --- | --- |
| schema | 整数 1, network 结果格式版本, 不替换现有运行记录 schema |
| action | show/update/recover |
| container | name 与完整 id, 尚未定位时 id 为 null |
| stage | observed/noop/decision-required/updated/recovered/rolled-back/recovery-required/rejected/unsupported |
| policy | 当前可确认的 network 配置, 不可确认时为 null; 理由表不解释成授权名单 |
| diff | 用户增删/理由变化/自动项变化和网段覆盖提示, 不夹带未展示的修改 |
| checks | rules/ssh/git/dns-rules 的通过/失败/未检查及事实摘要, 不将 DNS 规则核对说成上游 DNS 已实测 |
| pending | 未完成事务 id/phase 摘要或 null, show 成功不等于该字段为空 |
| decision-id | 当前预览收据 ID 或 null |
| error | 脱敏的错误名/说明或 null |

查询/无变化/成功提交/成功恢复为 0. 待首次审批或相关状态变化后重批为 1. 非法输入/前置不足/未知规则/不支持目标/缺失或错误确认票据为 2. 执行已开始后的失败为 3, 即使回退成功也不伪装成本次修改成功. 工具或环境不支持为 4. 保存事务前失败不得改网络; 保存阶段留下未完成状态而无法清理时明确报告 3 和 recovery-required. CLI 语法错误也不触发执行.

预览复用现有 DECIDE 行/收据目录与字段协议, kind 区分 network-update/network-recover. 指纹包含主仓/对身份, 完整容器 ID, 网络空间身份, 相关旧配置与理由, 目标受管实际规则, 自动项事实, 规范化请求及新理由. 计数器/规则 handle 等不决定权限的变化不作名单变化; 其他容器不影响目标语义的规则不作为该目标批准内容. 真正相关变化重新审批, 未知规则优先拒绝, 不能以重新批准为借口收编未知状态.

确认必须查找并消费参数指定的那张尚有效收据, 校验 kind/指纹/ID. 不允许通过旧 helper 的 answered=True 无票路径跳过预览, 也不能验证一张票却消费另一张同指纹票. 未知/已消费 ID 拒绝执行. 无变化不生成新票, 回放同一已完成请求不会重做网络动作.

### 运行记录与存储接口

沿用现有 runtime schema 与 `network.allow: string[]`, 新增可选 `network.allow-reasons: {规范CIDR: string}`. 缺理由时查询明确显示历史未记录, 不从地址猜用途. 理由表不是第二份授权源, 其中的键本身不能使地址放行. 更新/恢复只调整本次相关字段, 保留不相关 runtime 字段; rollback 保存并恢复旧配置原值, 不借回退迁移历史表示.

涉及实际规则修改时在同一 runtime 中保存:

```text
network-change:
  schema: 1
  id: 本次事务唯一标识
  phase: prepared | applied | recovery-required
  container: {name, id: 完整Podman ID}
  netns: {path, device, inode}
  before: {network: 原配置, context: 原自动项事实, rules: 原目标规则快照}
  after: {network: 拟提交配置, context: 批准的新自动项事实}
  decision-id: 本次已确认的收据ID
  created-at: UTC时间
```

context 至少包含容器源地址/网关/路由网关/解析器列表. before.rules 是受管目标规则与必要公共链语义的可核对快照, 不是可任意执行的 nft 文本. 新配置由现有应用实现生成, 不另建规则生成器. phase 仅表示进度, 不代替重入时读取实际规则并与 before/after 核对.

存储接口负责读取/验证/持久化原子写入. 新写文件与临时文件权限 0600, 临时文件位于同目录, 文件内容同步后原子替换, 再同步目录. prepared 持久化成功前禁止改网络. 成功提交一次性将 network 改为新配置并移除 network-change. 只改理由在全部前置/批准/核对满足后单次原子写入, 不建立网络事务, 不重建规则.

规则应用成功后可记录 applied, 再执行提交前检查; 任一步保存失败均进入失败处理, 不把原子替换当作已经获得持久化保证. 持久化故障时尽力保留恢复依据, 无法确认写入/回退则如实报告, 不假定旧文件或新文件必定落盘. 本接口依赖本地文件系统正常工作, 不提供损坏文件系统上的备份/灾备保证. 新事务格式由识别它的管理脚本处理, 旧记录可读不等于旧脚本能安全处理新事务.

### 有限恢复接口

recover 无对应未完成事务时返回 0 和 noop, 报告无待恢复内容, 不生成审批收据或修改规则/运行记录. 有事务时只识别同一完整容器 ID 与本工具 schema. 首次恢复预览返回 1 和 decision-required, 提供旧配置恢复差异与收据 ID, 在确认前不改变规则/运行记录或清除标记. 运行目标必须能将实际受管状态解释为已保存的旧状态/本次拟应用状态, 不能解释则报告差异并等待人工决定. 恢复预览的收据另绑定当前实际状态/事务/目标与旧配置, 确认后回到旧规则和旧记录, 检查通过再清标记.

停止目标的特殊分支只在确认原完整 ID 仍存在且原规则不可用时恢复旧记录并清标记, 不 start. 同名新 ID/未知改动/无法核对的事务都拒绝. 恢复执行中失败返回 3 和 recovery-required, 保留现场/恢复依据/未完成标记, 不自动 stop/start/restart/clear, 不替用户选择终结容器. 恢复不尝试替代 m10 或其他项目的检查/修复流程.

### 防火墙与进程接口

应用继续通过已有 `apply_network(NetworkPlan)`/net-firewall apply --merge. 为冻结批准内容与恢复旧 DNS, 内部适配调用需能传入本次已核对的解析器及有界进程执行器; 既有生命周期未传覆盖值时保持现有推导方式. 目标事实变化导致冻结计划失效则重新核对/审批, 不在应用时悄悄换解析器或网关. 规则观察可由只读 nft JSON 查询适配取得, 不改变已有 show 的默认文本输出.

防火墙模块的 apply/remove/clear 都按实际网络空间身份使用同一写锁, 从读现状/合并到写入/验证串行完成. 锁位置按当前 UID 的运行期目录和网络空间设备号/inode 生成, 不按项目 records-root 分裂, 新锁目录私有/锁文件 0600. 上层顺序始终为现有仓级锁在先, 防火墙写锁在后; 不倒序取锁或无限等待. 写锁协调本版本管理入口, 不宣称能阻止同 UID 的手工 nft/旧版工具绕过锁.

每次 apply/回退按目标源地址修改并合并保留其他容器当前规则, 不用整张旧表覆盖别人期间的合法更新. 不认识的目标/公共链结构不得静默丢弃. 基线核对与写后核对只承认已知受管语义, 不把规则 handle/计数器当授权内容.

内部进程接缝输入 argv 列表/stdin/单次超时, 输出 returncode/stdout/stderr 以及超时后是否已收尾的事实. 不默认套 shell 管道. 规则观察/SSH/只读 Git 单次预算 10 秒; apply/回退 30 秒. SSH 只建立连接, Git 使用既有本对本地桥做 ls-remote 等只读验证, 不运行会改 remote/fetch 的完整 resume_probe, 不碰真远端. DNS 检查验证实际解析器的 udp/tcp 53 规则, 不选择默认公网探测域名.

写规则命令由适配器在本次独立进程组中运行. 超时先终止并等 2 秒, 再强制终止并等 2 秒, 确认没有迟到写进程后才核对/回退. 无法确认时保留事务并报告, 不同时抢写. 只管理自己启动的进程组, 不停止容器. 已有公共 run() 保持其返回码语义, 不因本功能无故全局替换.

### 公共指导的输入与输出

任务条件参考在已知任务首次开展/增加依赖或操作/环境变化/交付核对时触发, 对现有健康容器承接新任务同样适用. 我未给出具体任务时只交付基础入口与任务条件未检查, 不能猜一份项目服务矩阵. 主 SKILL/交付参考提供必达指针, 具体判定只维护一份按需参考.

输入来自本次任务操作与项目现有 AGENTS/构建指南/依赖声明/测试要求. 宿主 agent 优先采用已有适用检查, 先审清其副作用; 检查从实际执行环境验证网络/认证/指定操作, 不拿宿主可达或凭据文件存在替代容器可用. 每项执行前确定有限超时, 不用无界构建/重试作为默认探针. 这里不增加检查配置语言/执行框架/自动凭据注入.

输出按操作列任务与目标环境/必要条件/检查方式和事实证据/检查时间/通过或受阻或未检查/缺口与下一步; 写入项另列批准的测试资源/操作/清理方式及实际清理结果. 三种结论按事实使用, 不把缺检查说成通过. 同任务证据只有覆盖仍适用且无条件变化/新失败线索时复用, 标原时间, 不当永久可用保证. 条件不足只阻塞依赖它的操作.

写入探测默认不执行, 先取得范围明确的批准; 同任务同范围复查不再问, 资源/操作/清理范围变化重新问. 清理失败或残留独立报告, 不计为整项通过. 现有项目脚本不因名叫 preflight/自清理而获得默认写权限.

取证参考从沙盒维护中的凭据查找/远端提交比较/命令结果截取触发. 已知配置与相关仓库内继续定向查找, 扩到整个家目录先说明必要性和范围等我决定, 不回显秘密值. 已核实同一分支且成功取得的完整提交 ID 相同即可结束该问题, 不外推其他分支/脏文件. 输出截取先独立保存原命令退出码, 不以 head 的 0 代替前置失败, 也不凭失败查询的空输出判断提交一致.

## 接缝与适配器

| 接缝位置 | 依赖类别 | 生产侧适配器 | 测试侧适配器 |
| --- | --- | --- | --- |
| 生命周期接入 -> 网络维护模块的结构化请求/结果 | 进程内 | CLI 解析和 birth 共同条目输入 | 通过 main(argv) 或共同规范化接口提交请求, 断言返回协议/持久化可见结果 |
| 网络维护模块内部: 地址/理由/覆盖与快照核对 | 进程内 | 标准库 IPv4/CIDR 与 JSON 处理, 不需传输适配器 | 直接经该模块接口覆盖规范化/冲突/重叠, 不断言私有函数或内部调用顺序 |
| 网络维护模块内部: 目标观察/应用/通道检查 | 本地可替换 | 已有 Podman/身份定位/网络应用函数及本机 SSH/Git 桥适配 | 可控进程/目标事实适配器, 加独立 rootless Podman 夹具验证真实三链/DNS/SSH/隔离 |
| 网络维护模块内部: 进程执行与超时收尾 | 本地可替换 | 有界子进程组适配器 | 可控退出/超时/迟到写入/收尾失败适配器, 独立进程合同验证 |

## 安全策略

认证依赖现有宿主 OS 身份/rootless Podman/容器记录与 label/完整 ID 核对, 不新增登录或共享 root 凭据. 收据是本机维护协议, 不能把对话里用户确认的义务说成能防止恶意宿主用户自行调用 nft. 维护委托不代替逐项网络或写入授权.

授权内容是目标与具体差异, 不是任意站点扩大授权. 自动放行事实从目标实际环境取得, 原 IP 文档不参与默认授权. 不跟随同名替换目标, 不自动迁移/接管未知规则, 不把理由对应表当允许表. 预览显示全端口/CIDR 覆盖及 /0 含义.

事务/收据/临时记录按私有文件方式保存, 不把原始密钥/密码/凭据文件内容写入理由/事务或输出. SSH 使用已有私钥路径和本对端口, 不回显私钥. 项目认证检查只报告结果与必要来源, 不输出秘密值, 不把业务凭据复制进公共仓库. 本次无新增加密协议, 存储保护沿用宿主文件权限与既有密钥机制.

写入探测必须先说明副作用与清理范围, 我批准之后才执行. 真实共享服务不作为默认验收资源. 源文件修改/规格机检/独立文档校验不等于部署或生产探测授权.

## 非功能要求

- 有界执行: 观察/SSH/Git 单次 10 秒, 应用/回退单次 30 秒, 超时进程收尾额外最多 2+2 秒, 无法确认结束就不并发回退. 验证口径为进程适配器合同与 AC-017 的可控时间/调用记录, 不是对全部网络请求总时长作未测量承诺.
- 一致性与可恢复性: 正常文件系统上 prepared 先持久化, 成功提交将新配置与清标记放在一次原子替换中, 停止/中断后不丢恢复依据. 验证口径为各持久化/应用阶段失败与中断注入及 AC-012-AC-016, 不承诺硬盘损坏后的恢复.
- 并发隔离: 同一网络空间所有受管写操作共享锁, 回退不覆盖其他目标当前规则. 验证口径为并发 apply/回退与第二目标快照比较, 不是只断言单线程成功.
- 可观察性: NETWORK/DECIDE 与实际状态一致, 3 不伪装成 0, 查询成功不等于网络或任务健康. 验证口径为 CLI JSON/退出码和任务分项报告的场景对账.
- 低开销: 不枚举网段地址/默认全家目录搜索/为相同完整提交 ID 克隆/重复未变化的任务检查. 验证口径为覆盖提示/工具调用记录与 AC-007/AC-019/AC-022-AC-024.

## 关键流程

**普通预览与执行**: 解析并规范化 -> 取得仓级锁并定位唯一目标 -> 检查运行态/身份/配置形态/未完成事务 -> 核对记录与受管实际规则, 读取当前自动项 -> 规划用户/理由/自动差异与覆盖提示 -> 无变化返回 0, 未批准返回 DECIDE/NETWORK 和 1 -> 指定收据重入时重新观测并比对, 相关变化重批/未知变化拒绝 -> 消费准确票据 -> 持久保存 prepared -> 用冻结计划原子应用目标规则并保留别人的当前规则 -> 核对新规则/SSH/Git/DNS 规则 -> 持久化一次提交新 network 并清标记 -> 返回 0.

**仅理由**: 同样核对目标/当前规则/自动项与批准内容 -> 自动项已变则先停止并指向独立同步 -> 检查满足后单次原子更新理由 -> 返回查询可见的新理由, 不建立网络事务或写防火墙. 无用户变更的 update 只允许当前自动项同步, 也须完整预览/审批.

**失败与中断**: 已开始后失败先确认本次写进程已结束 -> 已核对状态可回退时, 只恢复目标旧规则并保留别人的当前规则 -> 核对旧状态并持久恢复旧记录/清标记 -> 返回 3 且说明已回退. 不能收尾写进程/未知实际状态/回退失败/无法确认持久化则保留现场与恢复信息并报告 recovery-required, 不停容器/重启/清表. 后续 update/resume 不继续执行, 查询仍可读出异常.

**显式恢复**: 读取本工具事务并核对原完整 ID -> 展示旧配置恢复差异并生成恢复收据 -> 重新核对后确认. 运行目标按已知 before/after 识别并恢复旧规则/记录; 停止目标只恢复旧记录而不启动; 不能识别或同名替换则拒绝. 本流程只解决自己的未完成变更, 更深救场仍先报告我并另行决定.

**公共指导**: 先确认任务需要的操作 -> 找项目既有入口并辨认读取/写入副作用 -> 取得必要范围批准 -> 在实际执行环境作最小有界验证 -> 按事实记录通过/受阻/未检查与清理结果 -> 只阻塞依赖缺口的操作 -> 条件变化补查, 交付复用仍有效的证据并标时间. 取证按最小来源/真实退出码规则完成, 不借交付表述掩盖未验证项.
