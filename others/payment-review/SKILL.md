# 支付审查

## 目标

审查支付网关或支付链路变更是否影响正确性, 安全性, 幂等性, 可观测性, 可回滚性和长期可维护性.

只输出关键问题. 不泛泛而谈. 不做风格化挑刺. 不扩大到与支付风险无关的重构建议.

## 输入处理

1. 如果用户提供 PR 说明, diff, 文件列表或变更范围, 优先按该范围审查.
2. 如果用户只要求审查当前变更, 先查看工作区 diff 和相关上下文.
3. 如果无法看到变更或缺少关键文件, 明确说明缺失证据, 不编造结论.
4. 审查时以资金风险, 数据一致性和生产可恢复性为最高优先级.

## 审查流程

1. 定位支付入口, 状态机, 回调处理, 退款/补偿, 渠道适配, 数据写入, 消息边界和系统边界.
2. 对照必查项逐项找阻塞风险, 只记录有具体证据的问题.
3. 将外部依赖从隐含假设还原为显式契约, 判断旧功能兼容性和新功能正确性是否都可证明.
4. 区分必改问题和建议优化. 必改必须影响正确性, 安全性, 资金风险, 数据一致性或生产可恢复性.
5. 给出合并前最小验证集, 优先覆盖高风险路径和可复现生产风险.

## 必查项

### 支付正确性

- 检查金额, 币种, 精度, 舍入, 手续费, 汇率, 状态流转是否正确.
- 检查成功, 失败, 取消, 超时, 退款, 拒付是否覆盖, 异步通知与主动查询是否一致.

### 幂等与并发

- 检查支付创建, 确认, 回调, 退款, 补偿是否幂等.
- 检查重试, 乱序, 重复回调, 并发请求, 锁, 唯一键, 状态机, 事务边界是否安全.

### 安全与合规

- 检查密钥, token, 签名, 证书, Webhook 验签, 鉴权, 权限, 租户隔离是否安全.
- 检查敏感数据是否避免日志泄露, PCI/PII 数据是否最小化处理.

### 外部渠道集成

- 检查渠道错误码映射, 超时, 限流, 熔断, 重试策略是否明确合理.
- 检查渠道差异是否隔离, 是否污染核心域模型, 新渠道/新能力是否保持扩展边界.

### 系统边界与外部契约

- 检查接口变更, 回调协议, 消息 schema, API 语义, 错误码, 幂等键和版本兼容是否显式定义.
- 检查新旧功能是否依赖外部系统隐含约束, 并要求契约测试, fallback/降级, 灰度, 回滚和观测证据.

### 数据一致性

- 检查本地订单, 支付单, 渠道流水, 账务记录是否一致.
- 检查事务, 消息, Outbox, 补偿任务边界, 失败中间态恢复/追踪/人工处理能力.

### 可观测性与运维

- 检查日志定位字段, metrics, trace, 告警是否覆盖关键路径且不泄露敏感信息.
- 检查是否支持灰度, 回滚, 重放, 对账和审计.

### 测试与验证

- 检查成功路径, 失败路径, 边界金额, 重复请求, 乱序回调覆盖情况.
- 检查渠道 mock, 契约测试, 状态机测试, 集成测试和生产风险复现成本.

### 架构可维护性

- 检查职责, 依赖, 接口稳定性, 变更局部性, 人和 agent 安全修改难度.
