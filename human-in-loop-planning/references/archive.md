# 规划资产归档模块

## 模块元信息
- internal_module: `hilp-archive`
- 原触发描述：用于在执行交接成功后，或用户手动要求基于有效执行交接资产重新生成归档索引时，整理当前变更目录内的 HILP 阶段资产，生成只读 `archive-manifest`。它只解决阅读入口和历史版本混杂问题，不参与业务设计、蓝图编制或执行交接有效性判断。

# 概览

你负责规划链闭环后的文档阅读治理。

你的职责是：
- 枚举当前变更目录内的 HILP 资产
- 识别最终执行交接资产及其引用链
- 生成版本化归档索引
- 标注最终阅读入口、当前基线、支撑上下文、历史过程资产和外部引用
- 报告归档失败原因

你不负责：
- 不移动文件
- 不生成 `CURRENT.md`
- 不修改上游资产状态
- 不把 `approved`（已批准）资产改为 `archived`（已归档）
- 不新增设计判断
- 不新增蓝图约束
- 不改变执行交接范围
- 不治理当前变更目录之外的资产
- 不验证真实代码执行结果

## 入口条件

### 自动归档入口

执行交接阶段成功产出正式 `stage-6/execution-handoff@vN` 资产后，自动尝试进入规划资产归档阶段。

自动归档必须同时满足：
1. 执行交接资产已成功落盘。
2. 执行交接入口检查为“无阻断项”。
3. 执行交接资产绑定 `stage-4-5/implementation-blueprint@vN [state=approved｜中文状态=已批准]`。
4. 执行交接资产绑定仍有效的 `stage-3/design-choice@vM [state=approved｜中文状态=已批准]`。
5. 执行交接阶段没有新增、修订、补齐或解释性扩展蓝图内容。
6. 当前没有新的变更重审触发事件。
7. 当前变更目录可枚举且可写入新归档 manifest。

### 手动重新归档入口

用户可以手动重新触发规划资产归档。手动归档不要求刚刚完成执行交接，但必须满足以下条件之一：

1. 用户明确指定一个有效执行交接资产。
2. 当前变更目录中存在且只存在一个可唯一识别最终链的有效执行交接资产。

手动重新归档必须生成更高版本 `archive-manifest@vN`，不得覆盖旧 manifest。

## 有效执行交接资产判定

有效执行交接资产必须同时满足：
- 文件存在且成功落盘。
- `owner_skill=hilp-execution-handoff`。
- artifact 为 `stage-6/execution-handoff`。
- 当前阻断项为“无阻断项”。
- 执行入口检查为“已通过”。
- 引用了已批准设计：`stage-3/design-choice@vM [state=approved｜中文状态=已批准]`。
- 引用了已批准蓝图：`stage-4-5/implementation-blueprint@vN [state=approved｜中文状态=已批准]`。
- 没有同轮更新后的重审事件推翻该交接资产。

归档入口不要求执行交接资产自身为 `approved`（已批准）。执行交接资产是规划出口记录，归档只要求它成功落盘、无阻断、入口检查通过，并绑定已批准设计与已批准蓝图。

## 失败条件

命中以下任一条件时，不生成正式归档 manifest：
- 找不到有效执行交接资产。
- 执行交接资产显示有阻断项。
- 执行交接资产没有引用已批准蓝图。
- 执行交接资产没有引用仍有效的已批准设计。
- 多个候选执行交接资产无法唯一确定最终链。
- 当前变更目录无法枚举。
- 归档 manifest 写入失败。
- 发现新的重审触发事件。

归档失败不阻断执行交接。失败时必须说明原因、影响和恢复方式，不得声称归档已经完成。

## 资产与文件规则

归档资产使用：

```text
asset_ref: stage-7/archive-manifest@vN [state=archived｜中文状态=已归档]
owner_skill: hilp-archive
approval_marker: no-approval｜中文状态=无需审批
```

归档文件名使用：

```text
06-规划资产归档_no-approval_archive-manifest@vN.md
```

规则：
- `06` 服务目录阅读排序。
- `stage-7` 服务资产语义，表示该资产位于执行交接之后。
- 同一变更目录下，版本号最高的 `archive-manifest@vN` 是当前阅读入口。
- 新归档 manifest 不覆盖旧 manifest。
- 旧 manifest 在新 manifest 中标为 `superseded`。

## 阅读角色

归档 manifest 只写阅读角色，不回写原资产状态。

| 阅读角色 | 中文含义 | 使用规则 |
|---|---|---|
| `final-entry` | 最终阅读入口 | 当前目录中最终执行交接资产。每个 manifest 最多一个。 |
| `active-baseline` | 当前基线 | 最终交接链中的已批准设计、已批准蓝图和最终交接资产。 |
| `supporting-context` | 支撑上下文 | 支撑最终链理解的需求事实、路由或重审记录。 |
| `superseded` | 已被替代 | 被最终链中更高版本或新版 manifest 替代的同 artifact 旧版本。 |
| `process-only` | 仅过程记录 | 不影响最终阅读主线的草稿、过程记录和临时材料。 |
| `needs-revision-history` | 待修订历史 | 状态为 `needs-revision`（待修订）的当前目录资产。 |
| `archive-index` | 归档索引 | 当前归档 manifest 自身。 |
| `external-reference` | 外部引用 | 被最终链引用但不属于当前变更目录的资产。 |

## 阅读角色判定顺序

1. 当前归档 manifest 自身标为 `archive-index`。
2. 最终执行交接资产标为 `final-entry`。
3. 最终交接链中的设计、蓝图和交接资产标为 `active-baseline`。
4. 状态为 `needs-revision`（待修订）的当前目录资产标为 `needs-revision-history`。
5. 被最终版本替代的同 artifact 旧版本标为 `superseded`。
6. 被最终链引用、但不是基线的需求事实、路由和重审资产标为 `supporting-context`。
7. 其他当前目录资产标为 `process-only`。
8. 目录外引用资产标为 `external-reference`。

最终链优先于最高版本。不得仅凭文件名版本号最高就把资产标为当前基线。

`needs-revision`（待修订）优先警示。资产同时符合“待修订”和“被替代”时，标为 `needs-revision-history`。

## 极简工作流

1. 确定自动归档或手动重新归档入口。
2. 枚举当前变更目录内 HILP 资产。
3. 识别或验证有效执行交接资产。
4. 若候选最终链不唯一，停止归档并报告失败。
5. 从最终执行交接资产提取引用链。
6. 按阅读角色判定顺序标注当前目录资产。
7. 将目录外资产列入“外部引用资产”。
8. 生成下一个版本的 `archive-manifest@vN`。
9. 用户可见输出中，成功时简短展示；失败时详细说明。

## 成功时用户可见摘要

执行交接成功后，默认只追加简短摘要：

```text

已自动生成归档索引：
- 文件路径：`项目根目录/docs/hilp/变更概述/06-规划资产归档_no-approval_archive-manifest@vN.md`

该索引用于标明本次变更的最终阅读入口、最终有效资产、历史过程资产和后续重审入口；不改变任何已批准资产状态。
```

## 失败时用户可见摘要

归档失败时必须详细说明：

```text
## 规划资产归档

归档未完成。

原因：
- <失败原因>

影响：
- 执行交接资产本身不受影响。
- 已批准设计和蓝图状态不变。
- 本次失败只影响阅读索引生成，不阻断执行交接。

建议：
- 明确最终执行交接资产后，可重新触发归档。
```

## 硬约束

- 不得把归档写成新的业务规划结论。
- 不得在归档阶段新增、修订、补齐或解释性扩展蓝图内容。
- 不得修改任何上游资产状态。
- 不得把 `approved`（已批准）资产改为 `archived`（已归档）。
- 不得移动文件或生成 `CURRENT.md`。
- 不得治理当前变更目录之外的资产。
- 多个候选执行交接资产无法唯一确定最终链时，不得猜测最终入口。
- 归档失败不得阻断执行交接，也不得声称归档完成。
