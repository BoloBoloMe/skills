用户要求做一次**复盘**. 你为编码 agent 的**环境**提改进, 让以后的运行更顺.

## 步骤

1. 调用 `writing-for-llm` skill, 取写作风格指南.

2. 读用户指定会话的原始记录, 这是复盘的一手来源. 未指定会话时, 默认复盘当前会话.
   pi 把会话保存为日志记录: 按会话标识或会话头定位目标会话, 复原时读其中的消息与工具记录; 访问细节随 pi 版本变化, 以 pi 自身机制为准, 不写死路径与命令.
   找不到指定会话 (已被清理, 或用户记错) 时, 如实说明无法分析. 严禁用别的会话或关键词命中冒充目标会话.

3. 按以下类别找改进候选.

- **导航**: agent 找对文件有多难? 文件间有没有隐藏依赖? 加一个**上下文指针**会不会更容易? _适用时机_: 会话里找一条信息花了很长时间.
- **自动检查**: 有没有能拦住 agent 所犯错误的自动检查? 比如 lint, 类型检查, 测试, 文件系统检查. 先读仓库自己的检查入口 (任务/构建脚本, 测试命令, CI 配置), 按仓库实际语言与工具来. 已有却未接线或悄悄坏掉的检查, 发现就是"接上它", 不是重造. 仓库完全没有**护栏** (既无 pre-commit hook, 也无跑 lint/类型检查/测试的 CI job) 本身就是一条发现: 没有 lint 的仓库是长期错失的机会, 不是中性默认. _适用时机_: agent 犯了本可被自动检查拦住的错, 或仓库根本没有护栏.
- **编码规范**: 要不要给**审核者**加一条要执行的规则? 已有规则要不要删掉或澄清? 先给违规分类: **机械性**违规 (固定句式, 禁用 API, 导入形状, 文件位置规则) 一律做确定性检查, 没有例外: 仓库自身 linter 的自定义规则, 新的 pre-commit hook, 或新的 CI job, 取仓库语言与既有护栏下最便宜者. 默认建检查, 不写规则. 仓库中给评审者读的规范文档 (如 `CODING_STANDARDS.md` / `CONTRIBUTING.md`, 无则提议新建) 只留给真正靠判断的规范 (跨文件一致性, "与周围风格一致"之类, 任何护栏都替代不了的东西). _适用时机_: 审核者没能抓住一个错误.
- **全局 AGENTS.md / CLAUDE.md**: 有没有引导指令该挪到编码规范 (或自动检查) 去? _适用时机_: AGENTS.md 或 CLAUDE.md 文件特别大, 仓库级或全局作用域都算.
- **工具开销**: agent 有没有做出本可精简的高开销工具调用? 有没有特别费 token 的自定义工具 (CLI, MCP)? _适用时机_: agent 做了高开销的工具调用.
- **空操作**: 找出引导文件里不改变 agent 行为的指令. _适用时机_: 引导文件又大又难用.
- **信息获取**: 找出扩大 agent 信息获取面的机会. 例如把 dev server 日志 tee 到文件, 给第三方服务只读访问. _适用时机_: agent 拿不到一条关键信息.

4. 把候选按严重度排序列给用户. 只列不落盘, 不改代码; 由用户挑中后才谈落地.
   每条候选写清三样: 所属类别; 会话里的具体出处 (哪次会话的哪一刻); 建议动作. 建议动作必须指向真实存在的文件或机制.
   完成标准: 每条候选都必须能追溯回会话的某一刻, 不是通用最佳实践; 追溯不了的候选直接丢弃. 严重度排序也是初稿, 可以推翻.

## 参考

### 执行 vs 审核

记住, 所有工作都经过两个阶段: 执行与审核. **执行者**的**上下文压力**最大, 负责探索, 写代码, 调试失败.
**审核者**的上下文压力最小: 它拿到的是 diff, 无需探索, 常常不用写代码或调试.
因此, 编码规范应由**审核者**施加, 不归**执行者**.

### 文件

仓库里有几种文件可用:

- `CLAUDE.md` / `AGENTS.md`: 任何在本仓库工作的 agent, 上下文窗口里都会推入这两个文件. 用法要极其克制, 通常只放指向其它文件的**上下文指针**. 仓库级与全局作用域都算.
- 给评审者读的规范文档 (如 `CODING_STANDARDS.md` / `CONTRIBUTING.md`): 在审核阶段读, 不在执行阶段读. 规范文件超过 1000 行时, 往文档目录加**上下文指针**.
- 文档: 当参考文件用, 由其它文件指过来. 写新文档前先找已有文档.
- Skill: 可放文档 (因为它的 description 会进入 agent 的上下文窗口), 也可放用户主动调用的命令. 写法遵循 `writing-for-llm` skill.
