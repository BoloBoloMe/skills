# pi 会话收发信

pi 中启用收信或准备本会话投信身份时读本文件. 公共投信与授权规则以 [SKILL.md](../SKILL.md) 为准.

## 收信与地址

1. **开启本会话收信**: 需要反馈时就在委派/请求前调用 `mailbox_listen(action="start")`; 要在交付后收信也在交付前开启. 由你直接调用工具, 不让我的手动操作或 bash 阻塞长轮询代替守护. 完成标准: 工具成功且 `running=true`, `mailboxSessionId` 等于当前 `piSessionId`; 不相等或失败就报告, 不将共用地址交作本会话地址.
2. **交出收信地址**: 对端 `send --to` 用成功返回的 `mailboxSessionId`, 它就是 pi 会话 id. 不从 Herdr 名称, 窗格或目录推算. 宿主/容器一律每个 pi 会话独立注册, 不共用容器地址. 完成标准: 对端拿到明确地址, 定向协作的各收件人地址独立.

守护收到信会唤醒空闲会话; pi 忙时排队, 本轮结束后再取下一封, 因而不保证即时反馈. 无其他工作可做时结束当前回复, 由来信唤醒, 不占着前台等待. 处理完守护转交的信, 由守护续取, 不再另起取信 CLI.

`status` 查询本会话运行态, `stop` 停止本会话并清除其监听标记. `/new` 停旧会话取信, 新会话用新 id 且默认不开启; `/quit` 关闭取信进程. 两者保留旧会话监听标记, 恢复同一会话时按标记恢复原 id. 其他会话不受影响. 需要后续反馈时保留守护; 只管理自己的守护.

## CLI 投信身份

宿主/容器统一操作:

1. 仅投信时用工具的 `status` 取得 `piSessionId`, 需收信则先完成上面的开启步骤.
2. 执行 `uv run python <脚本> ensure-session <piSessionId>`, 从 JSON 应答取 `config` 路径. 命令幂等, 不轮换活跃会话密钥或丢待取信.
3. 执行 `presence`/`send` 时为该命令设置 `MAILBOX_CONFIG` 指向此路径. 显式配置优先于容器接线环境变量; 配置缺失/损坏时拒绝操作, 不退回共用身份. 不手算路径或复制密钥.

完成标准: CLI 使用的配置属于本 pi 会话, 而非机器级 `<hostname>-host` 或容器接线 session.

开启守护只给其子进程设置环境, 不会让另一次 bash 的裸 `send` 自动改用本 pi 会话身份. `/mail-send` 自动选择本会话凭据, 准备失败就拒绝投信; `/mail` 查看总览, `/mail-listen` 管理守护.

## 容器注册与升级

birth 注入的 `SWT_MAILBOX_URL`/`SWT_SESSION_*` 是接线凭据, 不是 pi 收件地址. `ensure-session` 用它向宿主的 `/mailbox/sessions/ensure` 认证注册本 pi id, 凭据存本会话独立的 0600 配置. 不向容器下发 admin token. 服务核对注册归属, 不允许抢占其他身份的已有 id, 不复活已吊销的 pi 信箱. terminate 注销容器接线身份时一并注销其 pi 信箱.

需同版 mailbox 脚本/服务与 pi 扩展. 旧服务缺注册接口时明确失败, 不回退共用信箱. 已有容器可继续用原接线凭据注册, 不需因此重建容器; 旧共用地址里的信不自动转投到某个 pi. 升级需按维护授权同步/重启服务和重载扩展, 服务重启会丢内存中的信, 不擅自操作.

独立信箱避免误收/抢信, 不构成同账户进程之间的安全隔离: 同一容器账户仍能读取自己的接线凭据和会话配置.

工具缺席, 凭据准备失败或接口不兼容时, 读 [配置与排障](mailbox.md). Herdr 协作的地址交换和推送优先纪律由 `use-herdr` skill 的 `PI.md` 维护.
