# 展示页地址与设备代开

查询容器展示页地址, 或请我当前设备打开网页时读本文件. 投信身份, 在线检查和授权规则沿用 [SKILL.md](../SKILL.md).

1. **确定收件人**: 查宿主映射发给有宿主访问权限的会话; 代开发给我当前设备的收信会话. 当前设备从已有会话信息或我的说明确认, 缺失才问我; 我换设备时更新. 最近取信者不等于我正在用的电脑, 所以展示相关信件使用明确的 `--to`. 完成标准: 已明确本次是查地址还是代开, 并确认对应会话地址.
2. **提交请求**: 已有可靠 URL 时, 用 `open_url`, 正文只放 URL; 先利用环境/交付包提供的已确认入口, 不必为已知地址再问一轮. 缺地址时用 `request`, 正文带容器名, 宿主定位线索, 任务/原会话标识, 实际回信地址及所需动作. 容器所报路径只是线索, 收信方应在宿主核实; 不要求容器猜 `records_root`. 完成标准: 请求已带齐定位/回话信息, 或 `open_url` 正文是确定 URL, 投递状态已记录.
3. **查验并反馈**: 按下列查址/代开规则办, 把结果送回原会话; 无法操作就交付可点击链接或具体阻塞. 完成标准: 原会话得到已核实的地址/操作结果或明确失败, 没把"已发信"说成"已打开".

**查址**: 收信方经已有的宿主访问通道核实容器. 调用 `use-sandbox-worktree` skill, 优先用其 `scripts/swt.py status --repo <已核实主仓>` 输出的 web URL. status 只给运行中容器附 URL; 缺输出时查容器 STATE 或实际端口映射, 使用请求对应的容器服务端口, 而非一律取 8800. 局域网地址也必须取已确认记录. 页面是否可用需另行核实, 映射记录不证明服务在运行.

**回话**: 优先 mailbox 投回明确的回信地址, 正文带原任务/会话标识. mailbox 不可用而需 Herdr 送达时, 调用 `use-herdr` skill 按目标 agent 的提交方式操作. 曾出现只向输入框写字却未提交, 原会话实际没收到的失败; 因而要核实已提交, 失败就如实报告.

**代开**: 核对当前任务授权及 URL 后, 用设备的默认浏览器打开一次, 只报告可确认的实际结果. 设备不在线或无法打开时, 把链接交给我, 不报告已自动打开.
