## 步骤

1. **定候选与底线**: 按任务必需能力和失败代价确定质量底线, 从当前 agent 的工具或配置核实可调用的完整 `provider/model` 名称. 评分表不是可用名单, 无法核实的候选标为待核实. 完成标准: 已列出候选及可用性状态, 任务必须满足的能力要求已写明.
2. **取评分**: 在本 skill 目录运行 `uv run python score.py --scope 'provider/model1 provider/model2'`, 将候选的完整名称传入 `--scope`, 避免通配符漏掉未评分模型. 算分以脚本为准; 报错按提示修正, 无法修正时报告阻塞并停止; 建表/补评/更新数据时读 [bootstrap.md](bootstrap.md). 完成标准: 脚本成功返回候选评分, 或已报告错误原因与数据缺口.
3. **选模型**: 按下方读表规则查看贴近任务的画像, 先核对相关单项能力是否达到质量底线, 再在可调用且达标的候选中选成本较低者. 审查任务另读 [review.md](review.md). 完成标准: 已选模型有关键能力依据; 若没有可证实达标的候选, 已列出缺口并停止推荐.
4. **选 thinking 并交代依据**: 只从已确认支持的档位中选, 目录与实际支持不符时以实际为准. 失败代价高的任务优先深档, 简单或批量的低风险任务选浅档; 拿不准时选第二深档, 仅一档则选该档. 表中的 `off` 可能只是目录缺项的回退值, 须核实. 完成标准: 已给我模型全名, thinking, 所用画像, 质量达标依据和成本理由; 无法确认支持档位时已说明缺口.

## 读表规则

- 表按 `general` 总分排序, 不是推荐顺序. 能力比率分以基准 1 比较; 基准为纯文本模型时, `multimodal` 使用绝对能力档, 不作比率解读.
- `N/A` 不代表达标, 通常不计入总分; `vision` 的 `multimodal` 为 N/A 时无总分. `部分评分`/`弱依据` 涉及任务关键维度时先核实; `[未评分]` 的画像总分不能用于比较.
- 价格分是目录单价的估算, 不是实际账单. `[免费]` 的价格分已封顶, 价格 N/A 不等于免费; 输出或缓存用量影响成本判断时查目录原价.
