在独立会话中复盘我的一场或多场其他编码会话. 我未指定目标会话时先问我; 如果目标包含当前会话, 请我移除它或另开独立会话再调用此 skill.

## 步骤

1. 先确认每场目标会话都不是运行本 skill 的会话, 再读每场的原始消息和工具记录; 不靠关键词命中猜测目标. 会话记录的存放和访问方式以当前环境为准. 完成标准: 每场目标均已确认并读完, 能指出行为及其后果发生在何处; 找不到目标会话就说明无法复盘该场, 读不完就说明未覆盖的范围, 不把片段当作完整会话.
2. 对照下面九类寻找环境问题, 只在适用时机提出候选, 不为凑齐类别编造建议. 候选涉及引导文件, skill 或上下文指针的写法时, 调用 `writing-for-llm` skill 核对写作原则. 完成标准: 九类都已按适用条件检查.

- **导航**: agent 是否为找一条信息花了很长时间, 或被文件间的隐藏依赖绊住? 若是, 考虑在会被实际读取的地方加**上下文指针**: 写清何时去读哪份已有材料.
- **自动检查**: agent 的错误能否被 lint, 类型检查, 测试或其他确定性检查拦住? 先查仓库已有的检查入口, 区分检查缺失与已有检查未运行或失效; 优先接好已有检查. 会话暴露了护栏缺位的后果时, 完全没有可用检查也可成为候选.
- **编码规范**: 审核时是否漏掉靠判断才能发现的问题? 固定句式, 禁用 API, 导入形状等机械性违规交给确定性检查, 不写成要求审核者记住的规则. 跨文件一致性等确需判断的规则, 才建议放进审核时读取的规范文档; 先找已有文档, 没有再提议新建. 这样不会把审核规则压在负责探索和调试的执行者身上.
- **全局 AGENTS.md / CLAUDE.md**: 会话是否因过长的引导文件而受阻? 核实实际加载范围, 把只在部分任务需要的材料改成有明确触发条件的指针; 属于审核规则或机械检查的内容, 分别交给审核规范或自动检查.
- **工具开销**: 会话里是否有耗时或耗 token 的工具调用, 结果却可用更便宜的方式取得? 指明是哪次调用, 省去它会失去什么信息.
- **空操作**: 会话是否显示某条引导指令没有改变 agent 行为? 指明原指令与对应行为, 再考虑删除; 不凭篇幅长就断言指令无用.
- **信息获取**: agent 是否因拿不到关键信息而受阻? 考虑现有环境能否提供所需的只读信息, 例如保存服务日志; 不凭想象推荐不存在的访问方式.
- **可复用做法**: 被复盘会话是否反复临时拼装同一套多步做法, 因而重复劳动或漏步骤? 先找现成的做法; 固定输入与规则就能得出结果的操作考虑脚本, 仍需 agent 判断但过程可复用的工作考虑 skill, 只是需要找到已有知识则用文档指针. 一次性的做法不因可封装就提出封装.
- **会话交接**: 仅当复盘至少两场会话, 且其中确有会话之间的交接时适用. 对照交出时留下的信息和接手会话的实际行为: 是否因交接遗漏或误导而重复探索, 做错决定或漏掉工作? 候选应改善交接所用的现有文件或机制, 不能仅凭有交接就提出改进.

3. 核对每条候选在目标会话中的证据和建议落点. 会话交接须有交出与接手双方的证据; 落点须是现有文件或机制, 拟新建的文件明确标为提议. 完成标准: 留下的每条候选都可追溯到具体行为与后果, 建议落点也可核实.
4. 按问题对后续会话的影响排序, 把候选交给我. 每条列出类别, 对应的目标会话及具体出处, 问题后果和建议动作; 排序只是初稿, 由我决定是否采纳. 完成标准: 只交付候选, 不改文件或代码.
