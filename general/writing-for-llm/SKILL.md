为 LLM 消费的任何文档而写的参考材料: skill, `AGENTS.md`/`CLAUDE.md`, 由 *指针* 抵达的文档. 包装不同, 写法相同: 同一批杠杆让每一份都可预测 — agent 每次运行走相同的*过程*, 而不是产出相同的结果.

当你写的文档是 skill 时, 额外读 [`SKILL-MECHANICS.md`](SKILL-MECHANICS.md).

称呼 LLM 或为概念定名时, 读术语表 [`GLOSSARY.md`](GLOSSARY.md).

## 捕捉意图

动手写之前, 先弄清要记录什么. 不确定的目标产出不确定的文档, 违背可预测性. 当前对话往往已包含我想固化成文档的内容, 例如我说过 "把这个变成一项技能". 如果如此, 先从对话历史提取答案: 用过的工具, 步骤顺序, 我做过的更正, 观察到的输入/输出格式. 我可能还需要补充信息, 继续之前先向我确认.

## 上下文指针

**上下文指针** 是存在于 agent 上下文中的引用. 它命名某份上下文外材料, 并编码抵达那份材料的条件. Skill 的 描述字段 是一个; `AGENTS.md` 中命名某文档的一行, 是同一个对象. 决定 agent 何时抵达材料, 以及多可靠地抵达的, 是 指针 的*措辞*, 不是它的目标. 必达材料藏在措辞很弱的 指针 后面, 就是方差 bug: 先锐化措辞, 只有锐化失败时才把材料拉回内联.

指针 做两件事: 说明材料是什么, 并列出应该触发抵达的 **分支** (分支 是文档处理的一个不同 case, 不同运行会走不同路径). 常驻 指针 的每个词每轮都在付费, 所以它比正文更需要激进剪枝:

- **引导词前置** — 指针 是触发真正发生的地方.
- **每个 分支 只留一个触发器.** 给同一个 分支 写同义触发词, 就是把一个 分支 写了两遍; 折叠它们, 只留真正不同的 分支.
- **删掉正文已经携带的身份信息.**

## 两种负载

你添加的每份文档和每个 指针, 都花费两种预算之一:

- **上下文负载** — 常驻材料对 agent 上下文窗口的成本: 一行 `AGENTS.md`, 一个 skill 描述字段, 任何每轮都待在上下文里的东西. 无论是否触发, 都在消耗 token 和注意力.
- **认知负载** — 对我的成本: 哪些文档存在, 何时该取哪一份. 我是索引. 这不是要最小化的成本, 而是人类能动性的代价: 在人类判断重要的地方花费它, 在不重要的地方移除它.

只通过 指针 抵达的材料, 以 指针 自身一行的代价逃脱 上下文负载; 没有任何 指针 的材料, 完全由 认知负载 承担.

## 信息层级

文档由两类内容构成: **步骤** (agent 执行的有序动作) 和 **参考材料** (按需查阅的定义, 规则, 事实). 两者自由混合: 全是 步骤 (一份食谱), 全是 参考材料 (一次 review 的规则, 本 skill), 或两者兼有. 核心决策是每块内容坐在 **信息层级** 的哪一级. 信息层级 是按 agent 需要材料的紧急程度排名的梯子:

1. **文件内 步骤** — 主要层级: agent 做什么, 按什么顺序做.
2. **文件内 参考材料** — 按需查阅. 常是合法的平级集合 (一次 review 的每条规则同坐一级), 是合理组织, 不是坏味道.
3. **已披露 参考材料** — 推到单独文件, 由 上下文指针 抵达, 只在 指针 触发时加载. 跨度从同目录 sibling 文件, 到住在任何地方, 任何文档都能指向的完全外部参考.

向下推得太少, 顶层臃肿; 推得太多, 会藏起 agent 真正需要的材料. 这股张力就是整个决策.

**渐进披露** 是沿梯子向下的移动: 离开主文件, 藏到 指针 后面, 让顶层保持可读. 它主要不是 token 优化, 而是保护层级的方式. 分支 是最干净的披露测试: 每个 分支 都需要的内联; 只有部分 分支 触及的, 推到 指针 后面. 当文档有 步骤 时, 本该披露的文件内 参考材料 会掩埋 步骤, 让注意到 步骤 变成抛硬币 — 这是方差杠杆, 不只是可读性杠杆.

**就近放置** 是文件内部的搭档: 梯子决定一块内容放得*多深*, 就近放置 决定它抵达后*旁边放什么*. 把一个概念的定义, 规则和注意事项收在同一标题下, 不要散落各处, 这样读到一部分时会顺带读到相邻内容. 测试标准: 文档应读起来像为 agent 写的文档 — 聚拢的材料像, 散落的不像. (区别于 重复: 重复 是一个意义重复出现在两个地方; 散落是把一个意义碎成许多片.)

**膨胀** 是这里的失败模式: 文档单纯太长, 即使每行都活着且唯一. 注意力在过量材料中变薄, 每多一行就多一行要保持 相关. 治法是梯子: 把 参考材料 披露到 指针 后面, 按 分支 或 顺序 拆分, 让每条路径只携带自己需要的.

## 步骤 与 完成标准

每个 步骤 以一句 **完成标准** 结尾: 告诉 agent 这一步何时算做完的条件, 也就是它用来判断的目标. 它有两个属性, 使它不只是质量要求, 而是控制行为的杠杆.

**清晰性** — agent 能区分 done 和 not-done 吗? 模糊边界, 例如 "达到理解", 会让 agent 宣告完成并滑到下一步; 清晰边界, 例如 "每个修改过的文件都列出改动原因", 漏一个就是没做完. 模糊性诱发 **过早完成**: 当前 步骤 在真正完成之前就结束, 因为 agent 的注意力从工作滑向了完成感. 这是两股力量的拉扯: 后面可见的 后续步骤 向前拉, 标准的清晰度提供阻力. 有两个防御, 按顺序使用: 先锐化边界, 这是局部且便宜的修复; 只有当标准不可避免地模糊, 且你确实观察到 过早完成 发生时, 才隐藏 后续步骤. 隐藏只有在真实上下文边界上有效 (hand-off 或 subagent 派发); 同一份文档里的内联调用不会清除上下文, 后续步骤 仍然留在上下文里.

**要求量** — 它要求多少工作. "每个修改过的 model 都被说明" 会强制彻底工作, 而 "产出变更列表" 不会. 要求量驱动 **挖掘工作**: agent 在 步骤 内部幕后完成的探索和核对, 它藏在措辞里, 由 agent 执行, 而不是由文档逐条控制; 不要把它写成自己的 步骤. 这个属性不绑定 步骤: "应用每条规则" 同样可以约束一团平铺的规则, 这就是没有 步骤 的纯参考文档仍能携带详尽性标准的方式.

最强的完成标准既可检查, 又有足够 要求量.

写 步骤 时, 每个 步骤 只写两样东西: 期望达到的*结果*与不可违反的*约束*. 不写执行机制. 把 步骤 写成脚本是 **过度脚本化**: 机制细节绑定在对环境的预设上, 现实与预设冲突时, 细节失效甚至误导, 最终仍要靠 agent 自行决策, 先前细节全部沦为无效指令; 而约束不绑定预设, 冲突时仍是决策依据.
过度脚本化 难以靠审读自查: 空操作 测试只能靠运行文档裁决, 编写时没有真实环境, 每条机制细节读起来都像有用. 编写期的防线是另一条可执行的规则: 机制细节只在默认行为确实犯过这个错, 且代价真实时才写, 并标注它来自哪次失败. 失败史是细节的发票; 没有发票的细节是想象出来的保险, 删.
对预期中的冲突, 写一条元规则 ("指令与现实冲突时, 以 X 为准" 或 "先问我"), 比预先规定每种意外便宜且可靠.

## 何时拆分

把一个文档拆成两个, 会花费两种负载之一, 所以只在切口能赚回成本时拆:

- **按 顺序** — 拆分一串 步骤: 当 后续步骤 诱使 agent 过早完成 当前 步骤 时. 把它们移出视野, 能驱动当前任务上的更多 挖掘工作. 警惕反向操作: 合并序列会把每个 步骤 的 后续步骤 暴露给前面的步骤, 邀请 过早完成.
- **按 调用** — skill 专属: 见 [`SKILL-MECHANICS.md`](SKILL-MECHANICS.md).

## 叙述视角

始终站在我的第一视角写. 读取文档的 agent 是 "你", 触发和指挥 agent 的人是 "我". 写 "我在使用 skill 时可能遇到的问题", 不写 "用户在使用 skill 时可能遇到的问题". 讨论调用机制时保留固定术语 用户调用, 但不要把我写成第三人称.

## 写作要求

正文 Markdown 保持**紧凑**: 空行只用于章节边界, 独立正文块之间, 以及正文与列表/代码块/引用块的边界; 同一正文块的连续行不加空行. 新章节只用于可独立导航的主题; 流程阶段, 例子和短说明优先用连续正文, 列表或加粗标签, 不新增标题.
写出**为什么**, 不只是**做什么**. 向 LLM 解释某条行为为何重要, 而不是只下 "必须" 的命令. 运用心智理论, 像向有能力的读者解释一样向 LLM 解释, 而不是向执行器下令: LLM 理解理由时, 会更可靠地遵循规则, 也能把规则迁移到文档没有预见的场景. 规则要表达普遍意图, 不要绑死在具体例子上; 例子是抵达理由的阶梯, 不是理由本身.
先写草稿, 再用全新视角重写. 第一遍起草不求完美, 先让内容落下来; 完成后, 假装自己从未见过这份文档, 逐行重新审视它是否达到上面的标准. 这个冷眼能看到起草时被作者盲区掩盖的 空操作 和 重复.

## 引导词

**引导词** 是已存在于 LLM 预训练中的紧凑概念, agent 运行文档时用它思考 (*lesson*, *fog of war*, *tracer bullets*). 它作为 token 重复, 绝不作为句子重复, 以此积累分布式定义, 通过招募 LLM 已有的先验, 用最少的 token 锚定一整片行为. 自造词在定义清楚时也能工作, 但自造词招募不到先验: 你要为定义支付 token, 而预训练词免费给你这些. 先找已有词.

它锚定两次. 在正文中锚定*执行*: agent 每次遇到这个词就触及同一组行为; 在平铺 参考材料 中, 它把注意力聚焦到要找的一类对象上. 在 指针 中锚定*调用*: 当同一个词住在我的 prompt, 文档和代码库里, agent 会把这套共享语言连接到材料, 更可靠地抵达它.

引导词 不限于过程概念. 知名人名或作品也是预训练先验, 可锚定一整片*输出风格*: 写 "以 Martin Kleppmann 的清晰度写作" 比堆 "清晰/流畅/生动" 更准, 因为 LLM 对知名作者文风有稳定先验. 这类风格 引导词 在控制语气或体裁的文档里尤其有效.

寻找用 引导词 重构的机会. 一个三元组在三个位置展开, 一个 指针 花一句话比画一个想法 — 每一段都是乞求折叠成单个 token 的段落:

- "快速, 确定, 低开销" → *紧凑* (一个*紧凑*循环).
- "一个你信任的循环" → *red* — 模糊闸门变成二元可观测状态 (循环在这个 bug 上变 *red*, 或者不变).

你赢两次: 更少 token, 以及一个更锋利的 hook, 让 agent 把思考挂在上面. 假设每份文档都携带着 引导词 可以退休的重述 — 去找出它们.

**否定** 是这个杠杆旁边的失败模式: 用禁令引导, 会把禁令中的行为拖进上下文, 让它*更*可得, 而不是更不可得. "不要想大象", 大象就是全部; 否定是个弱修饰语, 强激活的概念会碾过它, 所以禁令半读起来像执行指令. 提示**正向**: 陈述目标行为 ("写一行注释"), 让禁令中的行为永远不被说出口. 禁令只在作为无法正向表述的硬护栏时才配占位; 即便如此, 也要配上正向目标, 让注意力落在该做什么上.
相邻失败模式是 **反向激活**: 提及一个不存在的工具或 skill 名来告诫 "不要用它", 反而把 agent 注意力引向它, 诱发幻觉调用. 声明能力时只列已有的: 提了要用的, 它就会用; 提了不存在的, 它反而想用.

## 剪枝

- 让每个意义住在 **单一真相源**: 一个权威位置, 改变行为只需一处编辑. **重复**, 即同一个意义出现在多处, 花费维护和 token, 还把一个意义在层级上的权重吹过它的真实排名. (它是 引导词 的意外反面: 引导词 有意重复 token, 绝不重复意义.)
- **环境** 也是真相源: `package.json` scripts, 配置文件, 目录布局, `--help` 输出. 复述环境的文档是 **缓存**: 一份查找结果的拷贝, 只有当查找昂贵时才配花费负载. 缓存 agent 通过查看找不到的东西: 未成文的约定, 选择背后的理由, 没有配置会招认的坑. 把单文件单命令的查找留给环境, 它们在那里不会过期.
- 路径与操作保持**环境无关**: 不写与当前环境绑定的绝对路径, 路径应相对或由运行时解析. 不规定特定系统特有的操作; 以平台无关的操作意图表达需求, 无法避免时明确该文档的操作系统限制.
- 逐行检查 **相关性**: 这行还关系到文档要做什么吗? 一行失去 相关性, 要么因为从未关系到任务 (纯叙述, 或本该披露的 分支), 要么因为它描述的行为或世界变了而过期. 更短的文档更容易保持 相关. 没有剪枝纪律, 默认命运是 **沉积**: 过期层不断沉降, 因为添加感觉安全, 删除感觉危险, 直到我必须钻过沉积物才能找到仍活着的内容.
- 逐句猎杀 **空操作**: LLM 默认就遵守的指令, 是在付负载说废话. 测试方法: 相对默认行为, 它有改变吗? 这是相对 LLM 的判断, 不是相对读者的: 两个人对 空操作 的分歧, 是对默认行为的分歧, 通过运行文档解决, 不靠辩论. 一句话测试失败时, 删除整句, 不要只在句内修剪单词. 这个测试也给 引导词 打分: 弱到打不过默认行为的词 (agent 已经大致 thorough 时写 *be thorough*) 是 空操作, 修法是换更强的词 (*relentless*), 不是换技术.
