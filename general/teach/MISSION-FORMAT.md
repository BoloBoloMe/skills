# MISSION.md 格式

`MISSION.md` 位于教学工作区根目录. 它记录我学习这个主题的真实原因. 每个教学决策, 包括下一步教什么, 推荐哪些资源, 设计什么练习, 都必须能回扣到这里.

## 模板

```md
# 学习使命: {主题}

## 为什么学
{1-3 句. 我正在追求的具体真实目标. 当我学会这项能力后, 工作或生活会发生什么变化? 避免 "理解 X" 这种抽象表述, 继续追问背后的真实结果.}

## 成功是什么样
- {一个具体且可观察的能力或结果}
- {另一个具体且可观察的能力或结果}
- {...}

## 约束
- {时间, 预算, 已有承诺, 学习偏好, 或任何限制教学路径的条件}

## 暂不关注
- {我明确暂时不想追的相邻主题, 用来保护最近发展区}
```

## 规则

- 一块工作区只放一个使命. 如果我想学两个无关主题, 拆成两个工作区.
- 具体优先于抽象. "10 月前跑完半马" 优于 "变健康". "给团队交付一个 Rust CLI" 优于 "学习 Rust".
- 对空泛表述要追问. 如果我说不清为什么, 先访谈, 不要急着写文件. 糟糕使命比没有使命更危险.
- 现实变化时修订. 使命会变. 目标移动时更新此文件, 不要让过期使命继续驱动教学.
- 修改前先确认. 除非我明确授权, 不要自行改写使命.
- 保持短. 如果 `MISSION.md` 超过一屏, 它就不再是罗盘, 而是在冒充计划.
- 全文中文组织. 外部固有名词可以保留原文, 但解释和成功标准必须让中文母语者一眼明白.
