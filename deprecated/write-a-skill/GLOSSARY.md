让 skill 变好的领域模型. 本文件是 [`write-a-skill`](SKILL.md) 的 已披露 参考材料.

任何定义中的 **粗体术语** 也都在本术语表中定义. 通过对应标题查找即可.

## 术语

### 可预测性

Skill 让 agent 每次运行都以相同*方式*行动的程度: 相同过程, 不是相同输出. 一个头脑风暴 skill 应该*可预测地*发散: token 会变, 行为模式不变. 这是所有其他术语服务的根本价值. 成本和可维护性是它的症状, 不是它的对手.

*避免*: consistency, reliability, robustness, output-determinism

### 模型调用

保留 **描述字段** 字段的 skill. Agent 能看到它, 因此可以自行触发它. 人类仍然可以输入名称调用它, 所以 模型调用 总是*包含*用户可达. 不存在 仅模型 的状态: 描述字段 只会*增加* agent 发现能力, 不会移除人类调用能力.

代价是每一轮都支付永久 **上下文负载**, 换取可发现性. 它也能被其他 skill 抵达, 因为让它对 agent 可发现的 描述字段, 也让它可被调用.

一个内容全是 **参考材料** 的 模型调用 skill, 也可以作为共享 参考材料 的家. 另一个 skill 可以调用它, 所以多个 skill 都需要的 参考材料 可以只放在一个地方.

只有当 agent 必须自行抵达某个 skill 时, 才选择 模型调用. 如果它只会被手动触发, 就删除 描述字段, 支付零 上下文负载.

*避免*: ability, tool, capability

### 用户调用

**描述字段** 被剥离的 skill. 它对 agent 不可见, 只能由人类输入名称抵达. 也就是 仅用户. 相比之下, **模型调用** 是 用户和agent.

它用 agent 可发现性交换零 **上下文负载**. 因为它没有 描述字段, 除了人类之外没有任何东西可以抵达它: 其他 skill 不能触发它.

*避免*: procedure, workflow, command

### 描述字段

在 SKILL.md frontmatter 中的正式字段名是 `description`. Skill 的机器可读触发器, 也是 **模型调用** skill 被迫始终加载的那个 **上下文指针**. 它是否存在, 就是调用轴本身: 保留它, skill 就是 **模型调用**, 并且可被其他 skill 抵达; 删除它, skill 就是 **用户调用**, 只能由人类抵达.

描述字段 是 模型调用 skill **上下文负载** 的来源.

*避免*: frontmatter, summary

### 上下文指针

存在于 agent 上下文中的引用. 它命名某份上下文外材料, 并编码何时应该抵达那份材料. **描述字段** 是顶层 上下文指针, 从上下文窗口指向 skill. 指向披露文件的 指针, 是下一层的同类对象.

决定 agent *何时*抵达材料, 以及*多可靠地*抵达材料的, 是 指针 的措辞, 不是它的目标. 如果必达材料藏在一个措辞很弱的 指针 后面, 那就是方差 bug. 先修 指针 措辞, 只有当锐化措辞失败时, 才把材料拉回内联.

*避免*: link, reference, import

### 上下文负载

**模型调用** skill 加在 agent 上下文窗口上的成本: 它的 **描述字段** 始终加载, 同时消耗 token 和注意力. 这是 **用户调用** skill 因为没有 描述字段 而避免的成本, 也是拆出更多 模型调用 skills 时的制动器.

*避免*: token cost, context bloat

### 认知负载

**用户调用** skill 加在人类身上的成本: 人类必须在脑中记住哪些 skills 存在, 以及什么时候该触发哪一个. 换言之, 人类成了索引.

**模型调用** 通过 agent 可发现性移除这项成本. 认知负载 是拆出更多 用户调用 skills 时的制动器. 它不是必须最小化的成本: 它是人类能动性的代价, 也是某些 skill 应该保持 用户调用 的原因. 在人类判断重要的地方花费它; 在不重要的地方移除它.

*避免*: human index, burden, overhead

### 粒度

我把 skills 切得多细. 更细的切分会消耗两种负载之一: 更多 **模型调用** skills 会消耗 **上下文负载**, 因为更多 描述字段 会挤进上下文窗口并争夺注意力; 更多 **用户调用** skills 会消耗 **认知负载**, 因为人类要记住和触发更多东西.

有两种切分方式:

- 按 **调用** 切分: 当我有一个不同的 **引导词** 应该触发它, 也就是一个我确实会在 prompt 中使用的触发词时, 拆出 模型调用 skill.
- 按 **顺序** 切分: 当某个 步骤 的 **后续步骤** 需要被隐藏时, 拆分 **步骤**. 把后续步骤隔离到自己的上下文里, 可以清除它们对当前步骤的牵引.

反向操作也要小心: 合并 顺序 会把每个 步骤 的 后续步骤 暴露给前面的步骤, 从而邀请 过早完成.

*避免*: chunking, modularity

### 路由 skill

一种 **用户调用** skill, 工作是指向我的其他 用户调用 skills: 命名每一个, 并说明何时使用它. 这样人类只需要记住一个 skill, 而不是许多个.

它只能建议, 不能触发那些 skills. 用户调用 skills 没有 **描述字段**, 所以除了人类以外没有任何东西可以抵达它们. 当 用户调用 skills 数量增长时, 路由 skill 是 **认知负载** 的解法.

*避免*: dispatcher, menu, registry, index, router procedure

### 信息层级

按 agent 紧迫需要程度排列的 skill 内容. 这是单一梯子, 由两种切分共同形成: 内容在文件中还是在 指针 后面, 内容是 步骤 还是 参考材料. 梯子如下:

- **步骤** - 在文件中, 主要层级
- **参考材料**, 在文件中 - 次要层级
- **参考材料**, 已披露 - 在 **上下文指针** 后面

没有 **步骤** 的 skill 只使用后两个层级. 这通常是合法的平级集合, 例如 review skill 中每条规则都在同一层级. 这是良好组织, 不是坏味道.

层级独立于 调用: 一个 skill 可以是 模型调用 或 用户调用, 无论它全是 步骤, 全是 参考材料, 还是两者都有.

当 skill 有 步骤 时, 本该披露出去的文件内 参考材料 会掩埋 步骤, 让 agent 是否注意到 步骤 变成抛硬币. 这不只是可读性杠杆, 也是方差杠杆. 保持梯子顶部可读. 能向下推的内容, 尽量向下推.

*避免*: structure, organization, layout

### 就近放置

把 agent 一次需要的材料放在同一个地方: 一个概念的定义, 规则和注意事项放在同一个标题下, 而不是散落在文件各处. 这样 agent 读到其中一部分时, 会顺带读到相邻内容.

它是 **信息层级** 在文件内部的搭档: 层级决定一块内容放得*多深*; 就近放置 决定 agent 抵达后, *旁边放什么*.

没有一种公式能保证 **参考材料** 格式正确. 测试标准是: 这个 skill 是否读起来像给 agent 写的文档. 聚在一起的材料通常像; 散落的材料通常不像.

它不同于 **重复**. 重复 是一个意义重复出现在两个地方. 散落则是把同一个意义碎成很多片, 分散在许多地方.

*避免*: grouping, clustering, cohesion

### 分支

Skill 可以被调用的不同方式, 也就是 skill 处理的不同 case. 不同运行会走不同路径. 有许多 **步骤** 的 skill 可能携带许多 **分支**. 线性 skill 没有 **分支**.

*避免*: path, case, fork

### 渐进披露

把 **参考材料** 移下梯子: 从 `SKILL.md` 移到 **上下文指针** 后面, 让顶层保持可读. 它主要不是 token 优化, 而是保护 **信息层级** 的方式.

渐进披露 由 **分支** 许可: 只有部分 分支 需要的内容可以披露出去; 每条路径都需要的内容保留内联. 如果 指针 没有稳定触发必达材料, 先锐化 指针 措辞. 只有失败时, 才把材料拉回内联.

*避免*: lazy loading, chunking

### 步骤

Agent 执行的有序动作. 当 skill 有 步骤 时, 步骤 是主要内容层级, 值得留在 `SKILL.md` 中.

不是每个 skill 都有 步骤. Skill 可以全是 步骤, 例如 `tdd`; 可以全是 **参考材料**, 例如 review skill; 也可以两者都有. 这与 调用 方式无关.

每个 步骤 都应以一个 **完成标准** 结束. 这个标准可能清晰, 也可能模糊.

*避免*: workflow, instructions, choreography

### 完成标准

告诉 agent 一个工作单元何时完成的条件, 也就是它用来判断的目标. 它有两个属性, 使它不只是质量要求, 而是控制行为的杠杆.

第一个属性是 **清晰性**: agent 能区分 done 和 not-done 吗? 它抵抗 **过早完成**. 模糊边界, 例如 "达到理解", 会让 agent 宣告完成并滑到下一步. 这个轴需要 *步骤* 才能发挥作用, 因为 过早完成 是 步骤 之间的失败.

第二个属性是 **要求量**: 它要求多少工作. "每个修改过的 model 都被说明" 会强制彻底工作, 而 "产出变更列表" 不会. 这个轴不绑定 步骤: 它也可以约束一团平铺的 参考材料. 这就是没有 步骤 的 skill 仍能携带详尽性标准的方式, 例如 "应用每条规则".

最强的完成标准既可检查, 又有足够 要求量.

*避免*: done condition, exit condition, stopping rule

### 后续步骤

跟在当前 步骤 后面的 **步骤**. 当它们可见时, 会把 agent 拉向 **过早完成**. Agent 看得越多, 拉力越强. 防御方法是把 步骤 序列拆成两段, 从而隐藏后续步骤.

*避免*: horizon, fog of war, lookahead

### 挖掘工作

Agent 在单个 步骤 内部幕后完成的工作: 读取文件, 探索代码库, 修改代码, 自己挖出需要的信息, 而不是把工作转嫁给我.

挖掘工作 位于 步骤 结构之下: 不要把它写成自己的 步骤. 它藏在措辞里, 由 agent 执行, 而不是由 skill 逐条控制. 它是 **后续步骤** 跨 步骤 牵引力在 步骤 内部的对应物.

可以通过 **引导词** 提高 挖掘工作, 例如 *comprehensive*, *thorough*; 也可以通过要求详尽工作的 **完成标准** 提高, 包括作用于平铺 参考材料 的 要求量 轴. 这就是驱动纯 参考材料 skill 覆盖所有规则的东西.

当 要求量 缺失, 或 **过早完成** 切断 步骤 时, 挖掘工作 会变薄.

*避免*: scope, effort, diligence, coverage

### 参考材料

Agent 按需参考的材料: 定义, 事实, 参数, 示例, 条件指令. 当 skill 有 **步骤** 时, 参考材料 次于 步骤. 当 skill 没有 步骤 时, 参考材料 就是全部内容. 它也可以完全生活在任何 skill 之外, 见 **外部参考**.

参考材料 可以通过 **上下文指针** 抵达, 是 **渐进披露** 的首要候选.

*避免*: supporting material, docs, background

### 外部参考

生活在 skill 系统之外的 **参考材料**: 一个普通文件, 没有 **描述字段**, 没有 **步骤**, 不可调用, 但任何 skill 都可以指向它.

它是不需要自行触发的共享 参考材料 的家. 它也是两个 **用户调用** skills 共享材料的唯一方式, 因为两者都没有 描述字段, 也就不能触发对方.

*避免*: doc, resource, knowledge base

### 引导词

一个紧凑概念, 也叫 *Leitwort*. 它已经存在于模型预训练中, agent 运行 skill 时会用它思考. 它借用模型已有先验, 用尽可能少的 token 编码行为原则, 例如 *lesson*, *proximal zone of development*, *fog of war*, *tracer bullets*.

它作为 token 重复, 而不是作为句子重复. 它会在 skill 中积累分布式定义, 并锚定一整片行为. 自造词在定义清楚时也能工作, 但它不会招募预训练先验. 我需要支付定义 token, 才能得到已有词免费给我的东西. 先找已有词.

引导词两次服务于 **可预测性**. 在正文中, 它锚定 **执行**: agent 每次遇到这个概念, 都会触及同一组行为. 在平铺 参考材料 中, 它会聚焦 agent 对某类对象的注意力, 每次运行都招募正确的检查.

在 **描述字段** 中, 它锚定 **调用**. 这不只发生在 skill 内部: 当同一个词存在于我的 prompt, 文档和代码库中, agent 会把这套共享语言连接到 skill, 并更可靠地触发它. 用我真正希望触发该 skill 时会使用的 引导词 来写 描述字段.

*避免*: keyword, term, motif

### 单一真相源

每个意义都只生活在一个权威位置的理想状态. 这样改变 skill 行为时, 只需要修改一个地方. **重复** 是对它的破坏.

*避免*: home, canonical location

### 相关性

一行内容是否仍然关系到 skill 要做什么. 这是决定保留什么的镜头.

一行失去 相关性, 可能因为它从未真正关系到任务, 例如纯叙述, 或者本应披露到某个 **分支** 后面; 也可能因为它已经过期, 随着它描述的行为或世界改变而漂移.

更短的 skill 更容易保持 相关, 因为每一行都更便宜检查. 相关性 不同于 **空操作**: 相关性 问一行是否关系到任务; 空操作 问它是否改变行为.

*避免*: load-bearing, staleness, freshness

## 失败模式

### 过早完成

当前 步骤 在真正完成之前就结束, 因为 agent 的注意力滑向了完成感, 而不是继续工作.

这是 步骤 之间的失败: 它需要 **步骤** 才会发生. 一个没有 步骤 的 skill 如果太早退出, 不是 过早完成, 而是 要求量 不足导致 **挖掘工作** 变薄.

它是两股力量的拉扯: 可见的 **后续步骤** 向前拉; **完成标准** 的 清晰性 提供阻力. 锐利, 可检查的 bar 能撑住; 模糊 bar 会让步. 模糊性是必要条件: 如果边界足够锐利, 无论后面有多少 步骤 可见, 它都能抵抗拉力. 所以, 一个从不向前冲的 步骤 不需要防御.

有两个杠杆可以撑住会前冲的 步骤, 但要按顺序使用:

1. **先锐化边界**. 这是局部且便宜的修复.
2. 只有当标准不可避免地模糊, 且我确实观察到 agent 冲向后续步骤时, 才**隐藏后续 步骤**.

隐藏只有在真实上下文边界上才有效, 例如 用户调用 hand-off 或 subagent dispatch. 内联 模型调用 调用不会清除上下文, 后续 步骤 仍然留在那里.

过早完成 是 挖掘工作 变薄的一个原因, 但两者不同: 即使 步骤 跑到完成, 挖掘工作 也可能很薄.

*避免*: premature closure, the rush, rushing, shortcutting

### 重复

同一个意义拥有多个 **单一真相源**. 它会增加维护成本, 因为改一处就必须改其他地方; 增加 token 成本; 还会夸大重要性, 因为重复的意义在层级中获得了超过真实排名的权重.

它有点像 **引导词** 的反面. 引导词 是有意重复 token 来提高注意力; 重复 是无意重复意义, 导致维护和权重问题.

*避免*: repetition, redundancy

### 沉积

Skill 中从未清除的旧内容层沉积下来. 添加内容感觉安全, 删除内容感觉有风险, 所以过期和无关的行会不断累积. 我必须从这些沉积物里钻过去, 才能找到仍然活着的内容.

这是任何缺少剪枝纪律的 skill 的默认命运. 它是 **相关性** 的缓慢侵蚀, 不同于 **重复** 所说的意义重复.

*避免*: accretion, bloat, cruft, rot

### 膨胀

Skill 单纯太长: `SKILL.md` 中行数太多, 与这些行是否过期或重复无关. 即使一个 skill 每一行都有效且唯一, 也可能 sprawl.

它消耗可读性, 因为 agent 在行动前必须涉过更多内容, 注意力在过量材料中变薄. 它消耗可维护性, 因为每多一行, 就多一行需要保持 **相关**. 它也消耗 token.

治法是回到 **信息层级**: 把 **参考材料** 推到 **上下文指针** 后面, 或按 **分支** / 顺序 拆分, 让每条路径只携带自己需要的内容.

膨胀 不同于 **沉积** 和 **重复**. 沉积 是过时内容造成的长度. 重复 是重复意义造成的长度. 膨胀 是长度本身, 无论原因是什么.

*避免*: bloat, length, size, verbosity

### 空操作

一条不改变任何行为的指令, 因为模型默认就会这么做. 我支付负载, 告诉 agent 它本来就会做的事.

测试方法: 这一行相对默认行为有改变吗? 一行可以完全 **相关**, 但仍然是 空操作. 让 **引导词** 免费发挥作用的同一套先验, 也让 空操作 没有价值.

引导词 是一种*技术*. 空操作 是对某一行的*裁决*. 它们会交叉: 一个太弱, 不足以击败默认行为的 引导词, 就是 空操作. 例如当 agent 已经大致 thorough-ish 时, 写 *be thorough* 就没有价值. 修复不是换一种技术性说法, 而是换一个能通过裁决的更强词, 例如 *relentless*.

因此, 空操作 测试, 也就是 "它相对默认行为有改变吗?", 同时也是我判断 引导词 是否值得重复的方式. 这是相对模型的判断, 不是相对读者的判断. 如果两个人对一行是否 空操作 有分歧, 真正的分歧在于他们对模型默认行为的判断不同. 通过运行 skill 解决, 不要靠辩论解决.

*避免*: redundant instruction, restating the obvious, belaboring

### 绝对路径引用

在文档中编写与当前环境绑定的绝对路径来引用文件. skill 要保证跨环境可用, 路径应相对或由运行时解析.

*避免*: hardcoded path, environment-specific reference

### 与具体平台绑定的操作

Skill 要追求跨环境可用, 不应规定 AI 使用特定系统上特有的操作. 例如 "当需要盘问时运行 `/grilling`" 错误, `/grilling` 只在 claude code 上可用, 在 pi 中不可用; 应以平台无关方式描述, "当需要盘问时调用 `grilling` skill" 正确, 无论什么环境, AI 都知道这是在调用一个叫 grilling 的 skill.

*避免*: platform-specific command, tool-coupled instruction

### 反向激活

提及一个不存在的工具或 skill 名来告诫 "不要用它", 反而把 agent 注意力引向它, 诱发幻觉调用. 声明工具时只列已有的: 提了要用的, 它就会用; 提了不存在的, 它反而想用.

正向: "用 access-web skill 做搜索与抓取." 反向: "你没有 web_search/fetch_content, 改用 access-web skill."

这与行为禁止不同: "不要写 cwd 外文件" 禁止一个动作, 不引入不存在的对象, 不在此列.

*避免*: ghost tool, negative mention, forbidden fruit, ironic priming
